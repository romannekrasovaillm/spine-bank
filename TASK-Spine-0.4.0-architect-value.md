# Задание: spine-bank 0.4.0 — «ценность для архитектора, доказанная на чужом коде»

> Положи файл в корень форка рядом с `AGENTS.md` и начни сессию словами:
> «Прочитай `TASK.md` и действуй по нему. Сначала план, потом код».
> Основа: **живые прогоны** `romannekrasovaillm/spine-bank` на коммите `8e5f9d6` (v0.3.16, 2026-10-09),
> выполнены 2026-10-10 на чистой машине (Linux, 2 vCPU, Rust 1.97, JDK, Node 22, без API-ключей
> моделей; LLM-судья — `kind = "cli"` поверх Claude Code). Все цифры раздела 2 сняты реально,
> команды и скрипты — в приложении A; эталонная разметка — в приложении B.

## 0. Суть в одном абзаце

На собственных кейсах Spine работает так, как обещает README: эталонный кейс ТСП даёт заявленные
11/14 = 79 % в контур-бенче, синтетический монолит `legacy-survey` даёт 34 подтверждённые находки байт-в-байт,
дог-фуд реестра зелёный. **На чужом коде ценность почти не видна.** Восстановление архитектуры по коду
на четырёх публичных репозиториях с известной архитектурой нашло **0 из 23 межсервисных связей**
(Online Boutique — 0/17, PetClinic Microservices — 0/6). Multi-module Maven схлопнулся в один компонент,
а вызов `arch-be survey .` молча выдаёт почти пустую карту из `[gap]`. Корпоративный стандарт
из 12 требований выражается правилами Spine только на 7/12. Правило гексагональной архитектуры,
написанное в привычной Java-нотации (`io.reflectoring…`), **молча не срабатывает никогда**. Тех-радар не видит
Gradle, npm и NuGet. Архитектурный дифф на 140 реальных коммитах дал 6 непустых диффов, и все шесть — шум
или неверное описание. Единственный по-настоящему архитектурный коммит (новый микросервис с внешним
LLM-провайдером) показан как «новая связь с tracing-server». Контур-бенч измеряет **1 кейс из 14**. Сам
проект честно пишет в `benchmarks/platformv-arch-bench/README.md`: «Ценность Spine — контур…, который
бенчмарк не измеряет». Цель 0.4.0 — сделать три функции, ради которых архитектор берёт Spine:
**(1) восстановление архитектуры по коду, (2) проверку соблюдения корпоративных стандартов,
(3) контур, ловящий архитектурные дефекты**. Они должны работать на чужом коде, и это надо доказать
бенчмарками с пререгистрацией и эталонами, а цифры — подтвердить живым прогоном.

**Критерий успеха (одной строкой):** таблица «до → после» из раздела 9 заполнена живым прогоном
`benchmarks/architect-value/run_all.sh` на закреплённых SHA, и каждая строка «после» не хуже порога.

## 1. Правила работы

1. **Сначала воспроизведи.** Каждая находка раздела 2 воспроизводится командой из приложения A.
   Для каждой — падающий тест (unit или `tests/*.rs`) **до** фикса. Не воспроизводится — запиши в
   `docs/experiments/live-0.4.0-repro.md`, что пробовал, и не чини.
2. **Соглашения репозитория** — `AGENTS.md`, `docs/RUST_CONVENTIONS.md`, находки — по-русски в формате
   `[error] <код> — <что> → <fix_hint>`.
3. **AD-2 не трогаем:** восстановление, стандарты и контур — детерминированные, без LLM. LLM допускается
   только в слое `[inferred]` (заметки, рубрики) и никогда не порождает `[confirmed]`.
4. **Без новых зависимостей** в `[dependencies]`. Новые форматы (Gradle, package.json, csproj, k8s YAML)
   разбираются построчно/через уже подключённые `serde_yaml_ng`/`serde_json`/`toml`.
5. **Обратная совместимость:** `arch-be/arch-diff/v1`, `gate-verdict/v1`, exit-коды `0/1/2/3`, смысл
   `CONSTRAINTS.yaml` сохраняются; новые поля — аддитивно. Ужесточение, способное покраснить чужой
   пайплайн, — по схеме «warn → error по флагу» с ADR.
6. **Один пункт — один коммит** (`fix(B1): …`, `feat(R2): …`), тесты в том же коммите. Перед коммитом:
   `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test && cargo test --no-default-features --features core`
   и дог-фуд `./target/debug/arch-be control check . --constraints CONSTRAINTS.yaml`.
7. **Ешь свою еду:** решения — ADR начиная с **ADR-069**; правки спайна и реестра — через дельту.
8. **Бенчмарки — пререгистрация до прогона:** эталоны и пороги замораживаются хэшами
   (`PREREGISTRATION.md` + `prereg_hashes.txt`) **до** первого прогона новой механики. Подкручивать
   эталон после результатов запрещено; отклонения — в `DEVIATIONS.md`.
9. **Стоп-условия:** нужно сломать `*/v1`-контракт; нужно ослабить порог, чтобы пункт «прошёл»; пункт
   помечен **[РЕШЕНИЕ ЧЕЛОВЕКА]**.

## 4. Волна B — P0: дефекты, найденные живыми прогонами

Каждый пункт: репродукция → падающий тест → фикс → тест зелёный.

**B1. `survey .` молча обследует пустоту.** `WalkDir::new(".")` отдаёт корень с именем `.`, и фильтр
`name.starts_with('.')` срезает весь обход. Получается карта из `[gap]` с вопросами владельцу, которые
выглядят как честный результат. В `model/drift.rs` эта же ошибка исправлена (`e.depth() > 0`),
в `survey.rs` — нет.
- Фикс: guard `e.depth() > 0` + **проверка пустоты**: если в обход попало 0 файлов при непустом каталоге,
  это `[error] survey_empty_walk`, а не `[gap]`.
- Аудит: все `WalkDir` в `src/` с фильтром dot-каталогов прогнать на `.`, `./`, `..`/sub, абсолютном пути и
  symlink. Добавить тест-матрицу и фитнес-правило «`filter_entry` с `starts_with('.')` без `depth()`» в `CONSTRAINTS.yaml`.
- Приёмка: `survey .` и `survey $PWD` на четырёх репозиториях из приложения B дают одинаковый набор находок.

**B2. `reverse_survey` в MCP не вызывается по своей схеме.** Схема: `path` (required), реализация:
`args.get("repo")`.
- Фикс: читать канонический `path` с синонимами из `PATH_ARG_ALIASES`, как остальные инструменты.
- **Контрактный тест на весь орган** (по образцу `mcp_schema_probe.py` из приложения A.7): для каждого
  инструмента вызов с минимальными аргументами по объявленной схеме не должен давать
  «нужен параметр X», если X нет в схеме. Тест — в `tests/mcp_serve.rs`, в CI.

**B3. `arch-be selftest` красный из коробки.** С 0.3.13 хук — тонкий shim `arch-be hook stop`, слова `gate`
в `settings.json` нет. Инвариант 8 ищет подстроку `gate` и ложно падает (exit 1), то есть
самотест вердикта сам выдаёт неверный вердикт.
- Фикс: проверять вызов `arch-be hook stop` (или резолвер `control::resolve_constraints_path`) и
  отсутствие гарда по расположению реестра.
- `arch-be selftest` — отдельная джоба CI (поломка живёт с 0.3.13 — четыре релиза — незамеченной).

**B4. `dependency_direction` молча невыполнимо в Java-нотации.** Префиксы `forbid`/`allow` сравниваются
с путями вида `io/reflectoring/…`. Привычная Java/Kotlin/Python-нотация `io.reflectoring.…` не совпадает
никогда, и правило зеленеет при любом коде.
- Фикс: нормализовать префиксы по языку glob'а (`.` → `/` для `*.java|*.kt|*.py`), **и** добавить
  проверку «вакуумности»: префикс, которому за прогон не совпал ни один импорт ни одного файла репозитория
  (ни разрешённый, ни запрещённый), даёт `[warn] rule_vacuous_prefix — префикс '…' не встречается среди
  импортов → проверьте нотацию`.
- Приёмка: засев C.2 с Java-нотацией даёт тот же счёт, что со слэшами.

**B5. Wildcard-импорт Java невидим.** Regex `^\s*import\s+(?:static\s+)?([A-Za-z_][\w.]*)\s*;` не
допускает `.*;`. Фикс: `([A-Za-z_][\w.]*(?:\.\*)?)` + нормализация префикса. Для FQN-обращений без import
текстовая проверка честно слепа: в находке/паспорте вердикта писать «FQN не анализируется — для JVM
используйте ArchUnit-мост (`type: archunit`)».

**B6. Образец корп-спайна противоречит документации.** Добавить `examples/corp-spine/product/docs/adr/ADR-041-*.md`
со статусом Accepted (или поправить сценарий в `docs/corp-spine.md`). Образцы из `examples/` и демо-сценарии
документации — **тестами** (`tests/examples_as_tests.rs`): ожидаемый итог зашит рядом с командой.

**B7. Контур-бенч непригоден на машине без `pytest`.** Эталон краснеет «обязательной fitness без входа (SKIP)», а
причина (`pytest не найден`) видна только в `doctor`. Фикс: `redteam` при неизмеримом эталоне печатает
**недостающие раннеры** и команду установки. Режим `--hermetic` исключает из знаменателя мутаторы,
которым нужен отсутствующий раннер (по образцу «пропущен: нет входа»).

**B8. Шум и неверные основания в диффе и обследовании.**
- Lock-файлы, лицензии, метаданные чартов (`package-lock.json`, `yarn.lock`, `*.lock`, `Chart.yaml`
  `home`/`sources`, URL `www.apache.org/licenses`, `semver.org`, funding-ссылки) не являются интеграциями.
  Нужен денилист путей и доменов с конфигом `[survey] ignore_hosts/ignore_paths`.
- Строки `"engines": {` из lock-файлов — не «версии платформы»; версии брать из манифестов
  (`<java.version>`, `<parent>` Spring Boot, `go 1.x`, `engines.node` корневого `package.json`,
  `TargetFramework`), иначе честный `[gap]`.
- Python-маршрут не помечать `axum`.
- Основание `new_component` указывает на каталог/манифест нового компонента, а не на первый попавшийся
  файл (`Hipster_WandIcon.svg`, `FallbackController.java`). `new_vendor` для `pom.xml` разбирает
  `<groupId>:<artifactId>` вместо «`<нераспознанная строка: <dependency>>`».

**B9. Пользовательские ошибки с бэктрейсом.** При `RUST_BACKTRACE=1` в окружении (типично для CI)
ошибка CLI печатает стек `<unknown>`-кадров. На краю CLI печатать `Error: …` + `Caused by`, стек — только
с `ARCH_BE_DEBUG=1`.

## 5. Волна R — восстановление архитектуры по коду (главная)

Цель: из любого репозитория банка за минуты получить **черновик C4-container-модели с доказательствами**:
компоненты, связи между ними, хранилища, внешние системы, контракты. Каждый элемент с `файл:строка` и
уровнем уверенности. Для архитектора это ответ на вопрос «что у меня на самом деле в проде».

**R1. Компоненты в многомодульных сборках.** Корневой манифест не должен поглощать вложенные:
- Maven `<modules>` (рекурсивно), Gradle `settings.gradle(.kts)` `include(...)`, .NET `*.sln`, npm/pnpm
  workspaces, Go multi-module (`go.work`). Модуль сборки — кандидат в компонент; агрегирующий корень —
  не компонент, а система.
- Тестовые проекты (`*/tests/*.csproj`, `src/test`) — не компоненты.
- Деплойная единица — **сильнее**, чем каталог: k8s `Deployment`/`StatefulSet`, compose `services:`,
  helm-шаблоны. Компонент = модуль сборки ⨝ деплойная единица (сопоставление по имени образа/контекста
  сборки `skaffold.yaml`/`build.context`/`Dockerfile` пути).

**R2. Межсервисные связи по runtime-конфигурации и коду (главный пробел: 0/23).** Новые извлекатели
(каждый — отдельная функция с тестом и `confidence`):
- k8s/helm/kustomize/compose: переменные окружения `*_ADDR|*_URL|*_HOST|*_ENDPOINT` со значением
  `<имя>:<порт>` или `http(s)://<имя>`, где `<имя>` — сервис/деплойная единица того же репозитория → ребро
  `calls` от владельца контейнера к владельцу сервиса (`confirmed`, основание — строка манифеста);
- Spring: `spring.application.name`, `lb://<имя>` в маршрутах gateway, `@FeignClient(name=…)`,
  `discoveryClient.getInstances("<имя>")`, литералы `http://<имя>/…` в `WebClient`/`RestTemplate` (имя без
  порта и точки — кандидат во внутренний сервис);
- gRPC: определения `service X` в `.proto` → провайдер; клиентские стабы (`pb.NewXClient`,
  `XGrpc.newBlockingStub`, `new X.XClient`, `grpc.ServiceProxy`) → потребитель;
  ребро `calls(grpc:X)`;
- брокеры: топики Kafka/Rabbit (`@KafkaListener(topics=…)`, `basic_consume(queue=…)`,
  `producer.send("<topic>")`) → рёбра через узел-топик.
Каждое ребро несёт `via` (env/route/stub/topic), `evidence[]`, `confidence: confirmed|inferred`.
Неразрешённое имя превращается в `[gap]` «вызов `customers-service` — нет компонента с таким именем».

**R3. Хранилища и внешние системы.**
- Хранилища: строки без схемы, если в том же манифесте есть образ хранилища (`REDIS_ADDR=redis-cart:6379`
  + `image: redis`), `spring.datasource.url`/`jdbc:`, `spring.data.mongodb.*`, AlloyDB/Cloud SQL
  коннекторы в зависимостях; владелец — компонент, в чьём конфиге строка.
- Внешние системы: каталог известных провайдеров по ключам конфигурации и зависимостям
  (`spring.ai.openai.*`, `spring.ai.azure.openai.*`, Vertex AI/Gemini SDK, платёжные шлюзы) — расширяемый
  YAML в `assets/recover/providers.yaml` (банковские провайдеры — в слое `banking/`).
- Фильтр шума из B8 применяется и здесь.

**R4. Пакетный уровень для монолитов.** Для одного модуля сборки — кластеры пакетов
(`component_globs` в конфиге или авто: первый уровень под базовым пакетом / Python-пакетом), рёбра —
по импортам (с B4/B5). Результат для buckpal: `adapter.in.web → application.port.in`,
`adapter.out.persistence → application.port.out`, `application.domain → ∅`.

**R5. Команда `arch-be recover` + MCP `recover`/`as_built_graph`.**
- `arch-be recover <repo> [--rev REV] [--format md|json|mermaid|structurizr|c4-plantuml] [--model-out model/]`
  выдаёт полный граф ревизии (без диффа и merge-base). Опционально — **черновик `model/`**:
  `SYS`/`CMP` с `code_roots`, `INT` с `contract`, `status: inferred`, `source: recover@<sha>`, плюс список `[gap]`.
  Повторный прогон не затирает правки архитектора: сущность со `status`, отличным от `inferred`, не трогается.
- Детерминизм: два прогона на одном SHA дают байт-в-байт одинаковый JSON (схема `arch-be/recover/v1`).
- MCP: `recover` (read-only) и `arch_diff` (read-only, тот же контракт `arch-be/arch-diff/v1`).
- `survey` ссылается на `recover`: секции 1/4/5 карты строятся из того же графа (одна механика, не две).

**R6. `[inferred]`-слой с LLM, отделённый от `[confirmed]`.** Плейбук/скилл `recover-review`: модель
хоста читает `recover --format json` и пишет **только** в `survey-notes.md`/`model/*` со `status: inferred`
предположения о назначении компонентов и пропущенных связях. Механика проверяет, что ни одно
`[confirmed]` не создано моделью: у каждого `[confirmed]` есть `evidence`, разрешимый в существующую строку файла.

## 6. Волна S — проверка соблюдения корпоративных стандартов

**S1. Применимость правил (`applies_to`).** Корп-правило объявляет условие применимости:
`stack: [java-maven, java-gradle]`, `when_exists: ["**/pom.xml"]`, `when_glob_nonempty: true`.
Неприменимое правило получает статус **N/A** (не FAIL, не PASS) и попадает в отчёт `control report --level corp`
отдельной строкой. Пустой набор файлов для **собственного** правила репозитория остаётся находкой
(текущая семантика).

**S2. Тех-радар, пригодный для банка.**
- Форматы: Gradle (Groovy/KTS: `implementation|api|runtimeOnly|compileOnly|testImplementation`
  `'g:a:v'` и `group:/name:`), `package.json` (`dependencies`/`devDependencies`/`peerDependencies`),
  `*.csproj` `PackageReference`, `pyproject.toml` (PEP 621, Poetry), `go.mod` — в auto.
- Версии и диапазоны: `deny: [{name: log4j-core, below: "2.17.1"}, {name: "com.h2database:h2", scopes: [runtime, compile]}]`.
- Скоупы: test-скоуп отдельно от runtime (Maven `<scope>`, Gradle-конфигурация, npm `devDependencies`).
- Точный `pom.xml`: собственный `artifactId` проекта и `<parent>` не считаются зависимостями.

**S3. Типы правил для требований, которые сейчас `unverifiable`** (из 12 требований приложения C):
- `conditional`: `if: {glob, pattern}` → `then: {must_contain|deny_dependency…}` в пределах модуля
  (S5 «исходящие вызовы → circuit breaker»);
- `each_module`: требование к каждому модулю сборки (из R1), а не к glob'у каталогов (S3/S4 без хрупких глобов);
- `outbound_allowlist`: исходящие хосты/сервисы из графа R2/R3 сверяются с реестром интеграций
  (`model/INT-*` или YAML-реестр) — S10;
- `data_ownership`: хранилище из R3 читают/пишут только компоненты-владельцы — S9;
- `multiline: true` у `must_not_contain` / Java-аннотации через ArchUnit-генерацию — S12;
- S2 закрывается S2-радаром.
Цель: **≥ 11/12** требований стандарта выражаются механически (оставшееся — осознанный `unverifiable` с владельцем).

**S4. Отчёт покрытия стандарта и флот.**
- `control report --level corp --coverage` для каждого требования показывает: механизировано / `unverifiable` /
  **вакуумно** (правило ни разу не могло сработать — B4-проверка + «0 файлов по glob») / N/A.
- `arch-be control fleet-report <root>` (позиция Roadmap corp-spine): агрегирует `report --json` набора репо
  в сводку ДКА «N репо PASS / M override / K EXPIRED / L N/A» + топ нарушаемых требований. Только файлы, без сервиса (ADR-033).

**S5. Зубья структурных правил.** `rules teeth` расширить на `dependency_direction`/`deny_dependency`:
синтезировать нарушающий импорт/зависимость в копии репо и проверить, что правило краснеет
(вакуумное правило ловится за один прогон).

**S6. JVM — ArchUnit по умолчанию, когда есть классы.** Если в репо найдены скомпилированные классы и JDK,
`control check` предлагает (warn) включить `type: archunit`. Паспорт вердикта показывает расхождение
«текст: 1/5, байткод: 5/5», а не только зелёный текстовый слой.

## 7. Волна K — контур-бенч, который меряет защиту от реальных дефектов

**K1. Измеримость кейсов.** Цель — **≥ 6/14** кейсов зелёные на своём объявленном маршруте и измеримы
`redteam`. Кейсы, по построению не являющиеся пакетом Critical (`jvm-archunit-gate`, `legacy-survey`…),
объявляют маршрут в `CASE.yaml`, и `redteam` меряет их на нём. `arch-be redteam --all кейсы/` печатает
сводку «измерен / не измерен: причина».

**K2. Redteam для «репозиторий + стандарт», а не только для пакета кейса.**
`arch-be redteam --repo <repo> --standard <CONSTRAINTS.yaml> --mutators java-hex,radar,secrets,config`
засевает нарушения стандарта в реальный код (каталог мутаторов из приложения C.2 + обходы из 2.4: wildcard,
FQN, static import, Gradle, scope). Карта обнаружения раздельно: текстовые правила / ArchUnit / радар.

**K3. Внешний корпус дефектов.** Добавить в `--corpus` патчи реальных архитектурных нарушений: инвертированные
архитектурные фиксы из истории закреплённых репо (revert «вынесли вызов БД из контроллера»), 180
генераций `experiments/openspec-vs-spine` (с разметкой S-01…S-10) и засевы K2. Отчёт — доля обнаружения
**и** доля ложных срабатываний.

**K4. Ложные срабатывания на чистой истории.** Реплей гейта (`gate --base <h>~1`) по 100 последним
коммитам закреплённых репо со стандартом приложения C: доля красных вердиктов без нарушения ≤ 3 %.

## 8. Волна D — архитектурный дифф, которому верят на ревью

**D1. Бенч `arch-diff-replay`.** `arch-be bench arch-diff-replay <repo> --last N --labels labels.yaml`.
Метки — коммиты с архитектурным изменением (новый компонент, новое ребро, новое хранилище/внешняя система,
ломающий контракт) с эталонным составом. Метрики: recall «непустого» на значимых коммитах,
precision «непустого», **точность состава** (рёбра/узлы F1), шум в непустых.
Стартовая разметка — приложение B.3 (PetClinic: 60, Boutique: 80 коммитов; значимые — `79b527a`, `2932624` + доразметить).

**D2.** Дифф строится на графе R1–R3, поэтому `79b527a` должен показать: `+CMP genai-service`,
`+SYS openai/azure-openai`, `+api-gateway → genai-service (lb route)`, `+genai-service → vets-service`,
`+genai-service → customers-service`; а `2932624` — `+datastore alloydb`, `+frontend → shoppingassistantservice`,
`+productcatalogservice → alloydb`.

**D3.** Ящик ревью (`review inbox`) сортирует ещё и по `confidence` рёбер. Рёбра `inferred` не поднимают маршрут
выше Standard без подтверждения.

**A.3 Полный граф «как построено»** (обход отсутствия `recover`): двухкоммитный репозиторий
«пустой → полное дерево», затем дифф.
```bash
mkflat(){ rm -rf "$2"; mkdir -p "$2"; git -C "$1" archive HEAD | tar -x -C "$2"; cd "$2";
  git init -q; git commit -q --allow-empty -m empty; git add -A; git commit -q -m full; }
mkflat ~/microservices-demo /tmp/flat && arch-be arch-diff --repo /tmp/flat --base HEAD~1 --format json
```

**A.4 Реплей диффа по истории** (`replay.py`): для каждого из N first-parent коммитов
`arch-be arch-diff --base <h>~1 --head <h> --format json`; считаем непустые и состав.
PetClinic N=60 → 4 непустых; Boutique N=80 → 2 непустых.

**A.5 Корп-стандарт** — `CONSTRAINTS.corp.yaml` приложения C подключается продуктовым файлом
`extends: ["<путь>/CONSTRAINTS.corp.yaml@2026.4"]`; `arch-be control check . --constraints CONSTRAINTS.yaml --json`.

**A.6 Засев нарушений** (`seed_buckpal.py`): копия чистого репо → одна правка → `control check --json` →
поймано ли правилом-владельцем (ожидаемое имя правила). Для ArchUnit — кейс `jvm-archunit-gate`:
`javac -d classes $(find src -name '*.java') && arch-be archunit check . --constraints CONSTRAINTS.yaml`.

**A.7 Проба MCP** (`mcp_schema_probe.py`): `tools/list` → для каждого инструмента `tools/call` с
обязательными аргументами по схеме (`"."` для строк) → ищем «нужен параметр `X`», где X не в схеме.

**A.8 Квалификация судьи**

## Приложение C. Стандарт «Java-сервисы» (12 требований) и засевы

**C.1 Требования** (статус выразимости на 0.3.16):
S1 тех-радар Hold: встраиваемые СУБД (h2, hsqldb) не в runtime прода — *частично* (нет скоупа, нет Gradle);
S2 log4j-core < 2.17.1 запрещён — *нет* (диапазоны); S3 каждый бизнес-сервис публикует OpenAPI — *да*
