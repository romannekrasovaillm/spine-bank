# Задание для Claude Code: Spine Core 0.3.4 — «зелёный, которому можно верить»

> Положи этот файл в корень репозитория `spine-bank` рядом с `AGENTS.md` и начни сессию словами:
> «Прочитай `CLAUDE-TASK-Spine-Core-0.3.4.md` и действуй по нему. Сначала план, потом код».

## 0. Суть в одном абзаце

0.3.3 научила гейт не зеленеть, когда у проверки **нет входа** (INCOMPLETE, exit 3). Исследование 2026-09-19 на новом
кейсе «Приём оплаты ЦР для ТСП» показало ту же болезнь уровнем глубже: гейт зеленеет, когда вход **есть, но пустой**.
`evidence verify` отвечает «PASS — выпуск разрешён» при `DECISION.md` = «TODO» (5 байт) и ревью с `VERDICT: NOT-READY`.
Цель 0.3.4 — чтобы зелёный вердикт удостоверял **что именно проверено, на каком состоянии репозитория и кем принято
решение**, и чтобы архитектор видел это за одну команду. Проверок «ради проверок» не добавляем: меняем то, что зелёный означает.

**Критерий успеха релиза:** на red-team наборе из 14 засеянных дефектов (раздел 7) гейт ловит **не меньше 11** (в 0.3.3 — 6),
а оставшиеся честно названы в паспорте вердикта как «механикой не проверяется». Счёт 11 = D1–D5, D7, D8, D11b, D12, D13 и D9 при включённой
составляющей `decision_quality`; не ловятся и не должны — D6, D10, D11.

## 1. Правила работы (прочитай до первой правки)

1. **Сначала воспроизведи.** Каждая находка ниже получена одним исполнителем за один прогон. Для каждой сначала напиши
   падающий тест или shell-репродукцию. Не воспроизводится — не чини: запиши в `docs/experiments/0.3.4-repro.md`, что и как пробовал.
2. **Сначала план.** Первым сообщением выдай план по волнам с оценкой затрагиваемых файлов. Жди подтверждения человека
   только там, где помечено **[РЕШЕНИЕ ЧЕЛОВЕКА]**; остальное делай без вопросов.
3. **Соглашения репозитория** — `AGENTS.md`, `docs/RUST_CONVENTIONS.md`. Сообщения находок — по-русски, в стиле существующих
   (`[error] <код> — <что> → <fix_hint>`). Каждая новая находка несёт `fix_hint` и, где уместно, `skill`.
4. **Без новых зависимостей** в `Cargo.toml` (SHA-256 уже свой — `src/hash.rs`). Без LLM в ядре: Spine остаётся детерминированным.
5. **Обратная совместимость:** новые поля отчётов — аддитивные, `#[serde(default)]`; старые `EVIDENCE.yaml` и конверты
   `gate-verdict/v1` читаются. Exit-коды `0 / 1 / 3` не меняют смысла. Любое ужесточение, способное покраснить чужой зелёный
   пайплайн, идёт по схеме «warn в 0.3.4 → error по флагу/маршруту» (см. Н1, Н2) и описывается в ADR.
6. **Один пункт — один коммит** с префиксом `fix(Н1): …` / `feat(W2): …`; тесты в том же коммите. Перед каждым коммитом:
   `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test`.
7. **Ешь свою еду.** Репозиторий сам под гейтом (`ARCHITECTURE-SPINE.md`, `CONSTRAINTS.yaml`). Правки спайна и реестра
   правил — только через `arch-be delta new …`. Правила не ослаблять. Решения — новыми ADR начиная с **ADR-041**.
8. **Не трогай:** лицензионную границу (`banking/`, `LICENSE.banking`), матрицу моделей (AD-BE2), TUI, агентный цикл.
9. **Стоп-условия** (остановись и спроси): нужно сломать контракт `gate-verdict/v1`; нужно изменить смысл exit-кода;
   тест из существующих 1301 пришлось удалить или ослабить; находка не воспроизводится, но «очевидно есть».

## 3. Волна A — P0: что удостоверяет зелёный

### Н1. Бандл проверяет наличие файла, а не содержание  ← главная
**Репродукция.** В любом Critical-кейсе: `echo TODO > docs/DECISION.md; echo TODO > docs/WALKING-SKELETON.md;
printf '# R\n\nVERDICT: NOT-READY\n' > docs/REVIEW.md; arch-be evidence pack . --route critical; arch-be evidence verify .`
→ сейчас «PASS — выпуск разрешён», exit 0.

**Требуемое поведение.** В `src/evidence.rs` добавить детерминированную **семантику артефакта** — третий класс исхода
наряду с «отсутствует» и «изменён»: **«пустышка/не готов»**.
- Общие для всех ключей: файл меньше порога (по умолчанию 200 байт, конфиг `[evidence] min_bytes`), либо содержит
  маркеры-заглушки. Переиспользуй детектор `stub_marker` из `src/delta.rs` (вынеси в общий модуль) + `TODO`, `TBD`, `<…>`.
  Находка `evidence_stub`.
- `adversarial_review`: обязана быть строка `VERDICT: READY` или `VERDICT: NOT-READY` (регистр и кириллица `ВЕРДИКТ` допустимы).
  Нет строки → `review_verdict_missing`. `NOT-READY` → `review_not_ready` — **выпуск заблокирован**.
- `decision_a3`: обязательные непустые поля `choice`, `rationale`, `rejected`, `expiry`, `decided_by`
  (формат `- **choice**: …` и `choice: …`). `decided_by` пустой, `—`, `-`, `TBD` → `a3_not_signed`. `expiry` в прошлом → `a3_expired`.
  Spine не может проверить, что подписал человек, — и **не притворяется**: в выводе печатать
  «подпись A3: заявлена (<значение>), подлинность механикой не проверяется».
- `rollback_rehearsal`: `REHEARSAL.json` с итогом PASS и baseline, совпадающим с `ROLLBACK.yaml` (логика уже есть в `rehearsal.rs` — переиспользуй).
- `validation`, `fitness_report`, `walking_skeleton`: должны содержать строку итога (`Итог: PASS` / `PASS (N из M)`); `FAIL` внутри → `evidence_reports_fail`.

**Совместимость [РЕШЕНИЕ ЧЕЛОВЕКА].** Предложение по умолчанию: на маршруте **Critical** новые находки — `error` сразу
(там выпуск и так под гейтом), на Standard/Fast — `warn` в 0.3.4. Ключ конфига `[evidence] semantics = "off|warn|error"` перекрывает. Оформить ADR-041.

**Приёмка.** Тесты в `src/evidence.rs`: `verify_flags_stub_artifact`, `verify_blocks_not_ready_review`,
`verify_flags_unsigned_a3`, `verify_flags_expired_a3`, `verify_passes_on_complete_bundle`, `semantics_off_restores_033_behaviour`.
Существующий кейс `кейсы/digital-ruble` остаётся FAIL по прежним причинам; его README дополнить.

### Н2. `gate` не включает целостность модели
**Репродукция.** В зелёном кейсе заменить в любом `model/CMP-*.md` ссылку `depends_on` на `CMP-099`, закоммитить,
переупаковать бандл → `arch-be gate --route auto` PASS, тогда как `arch-be model validate model` и `arch-be review .` — FAIL (`broken-link`).
Следствие: битая модель проходит pre-push и Stop-хук.

**Требуемое.** Десятая составляющая `component_model_validate` в `src/gate.rs` (переиспользуй код секции из `src/review.rs`,
не дублируй). Нет каталога `model/` → SKIP. В матрице `[gate.required]`: обязательна для Standard и Critical. `review` после этого
= gate + контракты; проверь, что секция не считается дважды. Обнови `selftest`, README-таблицы составляющих, `docs/control.md`, `docs/verdict.md`.

Заодно: на маршруте Critical находка `nfr-without-verification` повышается с warn до error (дефект D12) — NFR без способа проверки на критическом маршруте не цель, а пожелание.

**Приёмка.** `gate_fails_on_broken_model_link`, `gate_skips_model_validate_without_model_dir`; конверт содержит компонент `model_validate`.

### Н3. Аттестация не различает состояния репозитория
**Репродукция.** Три разных мутанта (бюджет hop'а, цель доступности, дефицит ёмкости) дают одну аттестацию `015a2906…`;
безвредная правка текста сущности — аттестацию эталона. Причина: `inputs` = только хэш реестра правил.

**Требуемое.** В `compute_attestation` и конверт добавить:
- `inputs`: SHA-256 спайна, рекурсивный SHA-256 `model/`, хэш каждого проверенного `EVIDENCE.yaml`, хэш `ROUTE.lock`,
  `base` (коммит базы диффа, если есть). Пути — относительные, без времени и абсолютных путей (идемпотентность сохраняется).
- `components[].findings_digest`: SHA-256 отсортированного списка `(код находки, путь)` — два разных FAIL различимы.
- Схема остаётся `arch-be/gate-verdict/v1` (поля аддитивны). Если считаешь, что нужна `v2` — **стоп-условие**.
- Добавь `arch-be gate --verify-envelope <файл.json>`: пересчитывает входы на текущем дереве и отвечает
  «вердикт относится к этому состоянию / состояние изменилось: <что>». Это и есть «воспроизводим по конверту» из якоря «5» шкалы П9.

**Приёмка.** `attestation_differs_for_different_findings`, `attestation_changes_when_model_changes`,
`attestation_stable_across_path_spelling` (не сломать П2/П8), `verify_envelope_detects_drift`. В `selftest` — седьмой инвариант
`attestation_sensitivity`.

## 4. Волна B — P1: вердикт не зависит от способа вызова

### Н4. `delta guard` зависит от git-индекса и требует дословного пути
**Репродукция.** Новые файлы `model/AD-009-*.md` до `git add` guard не видит (PASS), после — FAIL. Упоминание `model/NFR-005`
в DELTA.md не засчитывается, нужен полный путь файла.
**Требуемое** (`src/delta.rs::guard`): (а) учитывать неотслеживаемые защищённые файлы — `git ls-files --others --exclude-standard`
наряду с диффом; вердикт до и после `git add` обязан совпадать; (б) файл считается покрытым, если в активной дельте упомянут
полный путь, **или** путь без расширения/суффикса-слага (`model/NFR-005`), **или** идентификатор сущности из frontmatter (`NFR-005`) как отдельное слово.
В отчёте печатать, чем именно покрыт: `← 'recovery-rto-rpo' (по id NFR-005)`.
**Приёмка.** `guard_sees_untracked_protected_files`, `guard_verdict_same_before_and_after_git_add`, `guard_accepts_entity_id_mention`,
`guard_does_not_match_id_substring` (`NFR-0051` ≠ `NFR-005`).

### Н5. Ослабление правила после коммита не видно хукам
**Репродукция.** Понизить severity правила, закоммитить → `gate --route auto` PASS; с `--base HEAD~1` — FAIL `rule_weakened`. CI-джоба базу передаёт, pre-push — нет.
**Требуемое** (`src/connect.rs::pre_push_hook_block`): pre-push читает stdin git'а (`<local ref> <local sha> <remote ref> <remote sha>`)
и передаёт `--base <remote sha>...HEAD`; для новой ветки (remote sha из нулей) — `merge-base` с основной веткой, как уже делает `check_anchored`.
Повторный `connect git-hooks` обновляет блок между маркерами. Stop-хук: базой брать `merge-base` с основной веткой, если он существует.
**Приёмка.** Интеграционный тест в `tests/cli.rs` с bare-remote: ослабленное и закоммиченное правило → `git push` отклонён.

### Н6. `control gate A4` без handoff-пакета — io error со стектрейсом
**Требуемое** (`src/rehearsal.rs`): находка `handoff_missing` с `fix_hint`: «сначала `arch-be handoff <harness> --repo . --task … --route critical`»,
exit 1 без backtrace. Заодно пройдись по `main.rs`: ни одна пользовательская ошибка ввода не должна печатать `Stack backtrace`
(оставь его под `RUST_BACKTRACE=1`). Это тот же класс, что П10.
**Приёмка.** `a4_without_manifest_is_a_finding_not_io_error`; grep по выводу всех CLI-тестов на `Stack backtrace` — пусто.

### Н7. Оценка качества решений живёт вне гейта
**Контекст.** `rubric_verify` различает сильный и слабый ADR (3,90 против 1,30) и обнуляет выдуманные цитаты, но гейт
пропускает ADR с 1,30. LLM в ядро не добавляем — добавляем **проверку отчёта судьи как артефакта**.
**Требуемое.**
- `rubric_verify` (CLI и MCP) пишет машиночитаемый отчёт `reports/rubric/<target-slug>.json`: рубрика, SHA-256 оценённого файла,
  `judge_model`, `author_model` (новый необязательный аргумент), взвешенный итог, флаги `unstable` / `evidence_not_found`.
- Необязательная составляющая гейта `decision_quality`: для каждого `docs/adr/ADR-*.md` со статусом Accepted ищет отчёт;
  отчёт есть и хэш файла совпал → сравнить итог с порогом (`[gate.decision_quality] min_score = 3.5`, как в чек-листе скилла `adr-authoring`);
  хэш не совпал → `rubric_report_stale`; `judge_model == author_model` или `author_model` не указан → warn `judge_is_author`.
- По умолчанию составляющая **не обязательна** ни для одного маршрута (SKIP не даёт INCOMPLETE). Включение — `[gate.required]`. ADR-042.
**Приёмка.** `decision_quality_fails_below_threshold`, `…_flags_stale_report`, `…_warns_when_judge_is_author`, `…_is_skip_by_default`.

## 5. Волна C — P2: трение, которое видит каждый архитектор в первый час

- **Н8. Имена аргументов MCP.** Сейчас `path` / `case` / `dir` / `repo` / `change_dir`. Сделай `path` каноническим для всех
  инструментов, старые имена оставь синонимами (`#[serde(alias)]`), в `inputSchema` описывай только `path`. При неизвестном
  аргументе ошибка перечисляет допустимые. Тест в `tests/mcp_serve.rs`: каждый инструмент с путём принимает `path`.
- **Н9. `adr registry` и формат прозы.** Парсер ждёт `- Status:`; заголовок `- **Статус**: Accepted` даёт 7 из 7
  `prose_model_divergence`. Распознавай: `Status|Статус`, с `**` и без, `Date|Дата`, секцию `## Статус`. Если поле не распознано
  ни в одной форме — отдельная находка `prose_header_unparsed` с примером ожидаемого формата, а **не** «расхождение». Приведи к
  тому же шаблон `control adr` и скилл `adr-authoring`.
- **Н10. Правила «документ содержит слово».** В `rules-suggest` добавь эвристику: если в репозитории есть исполняемые тесты
  (`skeleton/`, `tests/`) и нет ни одного правила `command_succeeds` — кандидат `executable-invariants`. В скиллы
  `fitness-functions` и `spine-content-bootstrap` — абзац «правило на упоминание — звено трассировки, а не проверка смысла».
  В `rules-report` — метрика «доля правил, проверяющих поведение» (`command_succeeds`, `dependency_direction`, `context_boundary`, `archunit`).
- **Н11. Число скиллов.** `arch-be init` даёт 62 скилла в 9 плагинах, отчёт 0.3.3 называл 86. Выясни, откуда разница
  (редакция бинаря? скиллы хоста?), и сделай так, чтобы `doctor` и `plugin_list` печатали одно число с расшифровкой.
- **Шаблон CI.** `RELEASES_URL` с заглушкой `<org>/<repo>`: добавь `connect ci --releases-url`, без него — явная строка
  в «Следующих шагах» и warn в `doctor`.
- **`handoff`**: предупреждение «6 REQ, 2 пункта задач» полезное — добавь `fix_hint`, как покрыть.

## 6. Волна W — вау-эффект: то, что архитектор покажет коллегам

Вау здесь — не новые проверки, а **момент, когда архитектор за минуту видит то, на что раньше уходил день**. Четыре вещи, строго в этом порядке приоритета.

### W1. Паспорт вердикта: `arch-be gate --explain` (и MCP `verdict_explain`)
Одна страница markdown рядом с любым вердиктом, три блока:
1. **Проверено** — составляющие с числами («модель: 55 сущностей, 0 битых ссылок; NFR: 3 цели p99, минимальный резерв 1200 мс»).
2. **Заявлено, но механикой не проверяется** — подпись A3, семантика ссылок, адекватность решения, судья = автор.
3. **Не проверено** — SKIP и необязательные составляющие с причиной.

Внизу — аттестация и команда `--verify-envelope`. Это превращает главную претензию исследования («зелёный ≠ выпускать») в фичу:
Spine сам говорит, чего его зелёный **не** означает. `evidence verify` печатает ссылку на паспорт. Приёмка: снапшот-тест на зелёном и красном кейсе.

### W2. Мутационное тестирование архитектурного пакета: `arch-be redteam <кейс>`
Продуктовая версия того, что исследование делало скриптом. Команда клонирует кейс во временный каталог, засеивает по одному
дефекту (каталог мутаторов — раздел 7), гоняет гейт и печатает **карту обнаружения**: поймано гейтом / поймано другим
инструментом / не поймано никем, с итоговой долей. Read-only к исходному кейсу, без сети, детерминированно.
Для архитектора это ответ на вопрос «насколько мой пакет вообще защищён правилами?» — и лучший довод усилить правила.
`--format json|markdown`; exit 1, если доля ниже `--min-detection`. Добавь в `selftest` как расширенный режим `--redteam`.

### W3. Первый зелёный за 15 минут: `arch-be bootstrap <имя> [--domain payments]`
Исследование дошло от пустого каталога до зелёного Critical за ~50 ручных шагов. Сделай проводник: создаёт каркас
(спайн с 2 примерами AD, 2 правила, SYS/REQ/NFR/CMP/AD-сущности, `ROUTE.lock`, первый ADR по шаблону, скелет бандла с явными
заглушками) и после каждого шага печатает **следующую красную находку с `fix_hint`** — «дорожка до зелёного».
`arch-be bootstrap --status` показывает прогресс: `спайн ✓ · правила ✓ · модель ✗ (2 находки) · бандл 7/13`. Заглушки каркаса
обязаны ловиться Н1 — иначе проводник производит ложнозелёные пакеты. MCP-плейбук `spine-bundle` для сценария ③ (сейчас плейбука нет).

### W4. Метрика доверия `arch-be trust` (П9 из прошлой волны)
Теперь есть из чего считать: журнал `.arch-handoff/mcp-calls.jsonl`, регистр ложных срабатываний, конверты, результат `redteam`.
Печатает положение на шкале 1–5 **с якорями и доказательствами**, а не число: какие якоря выполнены, какие нет и почему.
Честное правило: якорь «5» недостижим, пока есть неподписанное A3, `judge_is_author` или доля обнаружения `redteam` ниже порога.

**Не делай** в этой волне: дашборды, HTML-отчёты, интеграции с площадками, новый TUI. Вау — это W1–W4, сделанные до конца.
