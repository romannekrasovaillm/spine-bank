# ARCHITECTURE-SPINE-BE — Spine Banking Edition (продуктовые инварианты)

Продуктовый спайн Spine BE поверх унаследованного `ARCHITECTURE-SPINE.md`
(инварианты ядра, синхронизируется с апстримом — ADR-010). Этот файл —
инварианты продукта: правила, нарушение которых двумя независимо
развивающимися частями форка (ядро ↔ banking-зона ↔ переносы апстрима)
приводит к несовместимости — лицензионной, регуляторной или
эксплуатационной.

Унаследованный спайн — read-only относительно этого файла: продуктовые AD
не переопределяют инварианты ядра, а добавляют ограничения поверх.
Конфликт эскалируется владельцем продукта (ADR-011).

## AD-BE1: Граница лицензий — по директориям, проверяемо

- **Binds**: `LICENSE` (MIT) ↔ `LICENSE.banking` (proprietary) ↔ `src/`, `banking/` ↔ CI
- **Prevents**: смешение MIT и proprietary в одной директории — лицензионные дыры при переносе патчей апстрима и передаче исходников заказчику
- **Rule**: лицензия файла определяется путём: всё вне `banking/` — MIT-ядро; всё в `banking/` — proprietary. Каждый файл `banking/**` несёт заголовок proprietary-лицензии (JSON-манифесты — plugin.json, mcp.json, каталоги *.json — комментариев не держат и покрываются `LICENSE.banking` на уровне директории; стражи заголовка — по md/yaml). Ядро собирается и работает без `banking/` (запрет зависимостей `src/` → `banking/`). Стражи: must_contain-заголовок по `banking/**` в CONSTRAINTS BE-контура; CI-сборка без banking-зоны. (ADR-013)
- **Статус**: [ADOPTED]

## AD-BE2: Модельная матрица — закрытый список провайдеров

- **Binds**: `src/llm/` ↔ `config.example.toml` ↔ продуктовые пресеты `banking/presets/`
- **Prevents**: появление провайдера конкурента (YandexGPT) или утечку данных архитектурных сессий банка через внешний API в продуктовом пресете
- **Rule**: разрешённые группы провайдеров — GigaChat и self-hosted open-source модели (open weights) за OpenAI-совместимым шлюзом; обе — внутри периметра банка в продуктиве. YandexGPT запрещён безусловно (продукт конкурента — ADR-012). Внешние облачные API (api.deepseek.com, api.z.ai, api.kimi.com и т.п.) допустимы только вне контура заказчика и только в конфигах разработки, не в продуктовых пресетах. Страж: must_not_contain `(?i)yandexgpt|yandexgpt` по коду/конфигам/пресетам; продуктовые пресеты не содержат внешних base_url. (ADR-012)
- **Статус**: [ADOPTED]

## AD-BE3: Переносы апстрима — только в ядро, атомарными коммитами

- **Binds**: апстрим Spine (`b2088cf0`+) ↔ MIT-зона форка ↔ `NOTICE.md`
- **Prevents**: молчаливый дрейф форка от апстрима и лицензионное загрязнение ядра банковским контентом
- **Rule**: патчи и улучшения апстрима переносятся только в MIT-зону, каждый перенос — отдельный коммит со ссылкой на апстрим-коммит в сообщении; перенос контента из/в `banking/` — отдельное решение с проверкой истории файла. `NOTICE.md` — обязательный файл, фиксирующий точку форка и зонирование; удаление или устаревание его данных — нарушение. (ADR-010, ADR-013)
- **Статус**: [ADOPTED]

## AD-BE4: Продуктовое позиционирование — без research-фрейминга

- **Binds**: `README.md` ↔ упаковка/релизы ↔ обещания продаж
- **Prevents**: расхождение публичного позиционирования («исследовательский проект») с фактическим статусом продукта, продаваемого в регулируемый контур
- **Rule**: README и продуктовые материалы Spine BE не содержат фрейминга «research project / not for production»; статус зрелости заявляется через артефакты (релизы, тесты, кейсы), а не через приписки. Ограничения и допущения заявляются явно и честно. Страж: must_not_contain `not for production|research project` по README и banking/**. (ADR-011)
- **Статус**: [ADOPTED]

## AD-BE5: Egress-дисциплина — нечему звонить наружу из контура банка

- **Binds**: банк-профиль `banking/presets/bank-profile/` ↔ `[models.*]`/`[web]`/`[mcp]` конфигурация ↔ стражи CONSTRAINTS ↔ reg-map
- **Prevents**: тихий исходящий трафик продуктовой сборки в контуре заказчика — поиск, внешние LLM, публичные регистры MCP; утечку данных сессий архитектора за периметр до того, как её увидит ИБ банка
- **Rule**: продуктовые пресеты banking/ содержат только внутренние endpoint'ы: LLM — внутри периметра (AD-BE2), веб-канал в банк-профиле выключен кодом (`[web].enabled = false` — инструменты web_search/web_fetch/web_arch_sites не регистрируются в сессии; GAP-C1 закрыт 2026-08-31), MCP-шаблоны без публичных регистров. Телеметрии, бэконов и автообновлений в коде нет — появление любого из них — architecture exception с ADR. Стражи: BE-07/BE-08 (внешние URL и публичные регистры в пресетах — error), BE-09/BE-10 (наличие банк-профиля и reg-map). (ADR-016)
- **Статус**: [ADOPTED]

## AD-BE6: Библиотека правил — карточки, неретроактивность, срок жизни

- **Binds**: `banking/library/` (fitness-волны, каталог источников) ↔ пресет PAY (доменные инстанциации) ↔ CONSTRAINTS проекта ↔ движок fitness (типы проверок, вкл. max_age)
- **Prevents**: разрастание библиотеки правил без проверок и владельцев — «правило живёт до первого дедлайна»; дублирование формулировок генеральных и доменных правил; ретроактивное «покраснение» существующих систем ДИТ в день появления нового правила
- **Rule**: каждое правило библиотеки несёт карточку дистилляции (Trigger/Rule/Rationale/Check/Evidence/Reversibility/Owner/Expiry); карточка без Check или Owner не попадает в библиотеку. Одно правило — одна формулировка: генеральная — GEN-*, доменная — PAY-*, кросс-ссылки обязательны, дубли запрещены. Новые правила вводятся в режиме аудита (warn→error) и не применяются к существующим системам задним числом; каждое правило имеет Expiry и владельца; правило, реализуемое платформой, не становится правилом команды. Стражи: BE-16/BE-17 (существование и карточность волн), BE-18 (каталог источников). (ADR-019)
- **Статус**: [ADOPTED]

## AD-BE7: Имя бинаря — `arch-be`, единообразно во всех поверхностях

- **Binds**: `Cargo.toml` (`[[bin]]`, `default-run`) ↔ README/docs/пресеты/CI ↔ упаковка релизов ↔ скрипты ДИТ
- **Prevents**: расхождение имени бинаря между сборкой, документацией и упаковкой — коллизию с апстримным бинарём `arch` в PATH/ps на одной машине (спутать редакции в контуре заказчика)
- **Rule**: исполняемый файл продукта называется `arch-be`; все команды в README, docs, пресетах banking/, CI-workflows и cron-конфигах вызывают `arch-be` (упоминания апстримного `arch` допустимы только в контексте переносов AD-BE3). Crate `arch-harness`, конфиг-пути и MCP-имена НЕ переименовываются (ADR-011). Страж: must_contain `name = "arch-be"` в Cargo.toml. (ADR-026)
- **Статус**: [ADOPTED]
