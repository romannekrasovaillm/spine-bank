1. ЗАПРЕЩЕНО использовать `f64`/`f32` для денег, комиссий, лимитов и остатков. Проверка: сумма и комиссия — только `i64` (minor units) или `Decimal`; комиссия 1% считается в целых копейках без плавающей точки.

2. ЗАПРЕЩЕНО выполнять mutating-операции без обязательного параметра `idempotency_key`. Проверка: сигнатура `authorize` содержит ключ идемпотентности; повторный вызов с тем же ключом возвращает сохранённый результат без повторного изменения состояния.

3. ЗАПРЕЩЕНО использовать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!` в продуктовом коде. Проверка: все ошибки — через `Result` с явным пробросом `?` или обработкой; grep по перечисленным конструкциям даёт пустой результат.

4. ЗАПРЕЩЕНО записывать в логи PAN, ФИО, паспортные данные, телефоны и адреса. Проверка: номера карт логируются только маской (BIN + последние 4 цифры, остальное — `*`).

5. ЗАПРЕЩЕНО возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`). Проверка: ошибки — типизированный enum (в стиле thiserror, с `Display` + `Error`), вариант на каждый класс сбоя.

6. ЗАПРЕЩЕНО использовать `static mut`, `lazy_static!`, `static ref` и глобальные `static Mutex/RwLock` с состоянием домена. Проверка: состояние (журнал, хранилище идемпотентности) передаётся явно через параметры/владение/конструктор.

7. ЗАПРЕЩЕНО нарушать контракт публичных функций домена. Проверка: `authorize` возвращает `Result<T, DomainError>`; набор вариантов ошибки — часть контракта; каждое денежное событие журналируется с ключом идемпотентности, суммой в minor units, валютой и результатом.
