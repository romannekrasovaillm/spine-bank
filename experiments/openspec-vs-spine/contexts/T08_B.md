# Spec

## Требование: Денежные суммы без плавающей точки
Система ДОЛЖНА хранить и вычислять денежные суммы (сумма события) только в minor units (целое `i64`) или через десятичный тип Decimal. Система НЕ ДОЛЖНА использовать `f64`/`f32` для суммы события.

## Требование: Ключ идемпотентности при записи в журнал
Каждая операция записи события в журнал ДОЛЖНА принимать обязательный ключ идемпотентности (`idempotency_key`). Повторный вызов записи с тем же ключом ДОЛЖЕН возвращать сохранённый результат без повторного изменения состояния журнала.

## Требование: Запрет unwrap/expect/panic
Продуктовый код модуля НЕ ДОЛЖНА содержать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!`. Все ошибки ДОЛЖНЫ обрабатываться через `Result` с явным пробросом (`?`) или обработкой.

## Требование: Отсутствие PAN и ПДн в журнале
При выводе журнала и любых записях в него НЕ ДОЛЖНЫ попадать полный номер карты (PAN), ФИО держателя, паспортные данные, телефоны, адреса. Допустима ТОЛЬКО маска карты (BIN + последние 4 цифры, остальное — `*`).

## Требование: Типизированные ошибки
Ошибки ДОЛЖНЫ быть представлены типизированным перечислением (enum, вариант на каждый класс сбоя, реализация `Display` + `Error`). Возврат ошибок строками (`Err("...")`, `String`, `Box<dyn Error>`) НЕ ДОЛЖЕН применяться в продуктовом коде.

## Требование: Запрет глобального мутабельного состояния
Код НЕ ДОЛЖЕН содержать `static mut`, `lazy_static!`, `static ref` и глобальные `static Mutex/RwLock` с состоянием домена. Состояние журнала (вектор записей) ДОЛЖНО передаваться явно (владение, параметры, конструктор).

## Требование: Публичные функции возвращают DomainError
Публичные функции домена ДОЛЖНЫ возвращать `Result<T, DomainError>`; набор вариантов ошибки является частью контракта функции.

## Требование: Журналирование денежных событий
Каждое денежное событие (запись события в журнал) ДОЛЖНО журналироваться с фиксацией: ключа идемпотентности, суммы в minor units, валюты, результата. Журнал ДОЛЖЕН подчиняться запрету на PAN/ПДн.

# Design

Модуль журналирования — часть платёжного домена, поэтому все решения вытекают из зафиксированных организационных стандартов, а не из локальных удобств реализации.

Деньги. Сумма события хранится как `i64` в minor units. Плавающая точка исключена даже для «простого вывода на печать»: накопительные ошибки округления в платёжном ядре недопустимы, а единообразие представления снижает риск случайной конвертации через `f64`. Это соответствует S-01.

Идемпотентность. Запись в журнал — mutating-операция (изменяет вектор записей), поэтому она обязана принимать `idempotency_key` и сохранять результат: повторная запись с тем же ключом не дублирует событие, а возвращает ранее зафиксированный результат. Это защищает журнал от дублей при ретраях клиентов и транспортных повторах, что критично для финансовой отчётности (S-02).

Обработка ошибок. Код не должен падать в рантайме: `unwrap`/`expect`/`panic!` в прод-коде запрещены. Все сбои (невалидная сумма, неверный формат карты, дубликат ключа идемпотентности, отсутствие события при поиске) выражаются через типизированный enum `DomainError` с реализацией `Display` и `Error` — это одновременно упрощает диагностику и делает контракт ошибок частью публичного API функций (S-03, S-05, S-10).

Персональные данные. Событие по условию задачи содержит PAN и ФИО, но журнал — это внешняя проекция: при печати и записи в журнал поле карты маскируется (BIN + последние 4 цифры), а ФИО не выводится вовсе. Хранение исходных полей в памяти домена допустимо, но граница вывода проходит строго по маске (S-04).

Состояние. Вектор записей — обычное поле структуры, создаваемой явно; никаких глобальных синглтонов и `static`. Это делает журнал тестируемым, а владение состоянием — прозрачным (S-06).

Журналирование денежных событий. Каждая запись события фиксирует ключ идемпотентности, сумму в minor units, валюту и результат операции — это обеспечивает восстанавливаемую историю денежных движений без ПДн (S-09).

# Rules

- Суммы — только `i64` (minor units) или Decimal; никаких `f64`/`f32` для денег.
- Запись в журнал — mutating-операция: обязательный `idempotency_key`, повтор с тем же ключом возвращает сохранённый результат без изменения состояния.
- Запрещены `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!`; ошибки — через `Result` с `?` или обработкой.
- При выводе/записи в журнал: PAN только маской (BIN + последние 4 цифры), ФИО, паспорт, телефон, адрес — не логируются.
- Ошибки — типизированный enum (thiserror-стиль) с `Display` + `Error`; строковые ошибки запрещены.
- Никаких `static mut`, `lazy_static!`, `static ref`, глобальных `static Mutex/RwLock`; состояние журнала передаётся явно.
- Публичные функции возвращают `Result<T, DomainError>`.
- Каждое денежное событие журналируется: ключ идемпотентности, сумма в minor units, валюта, результат — без ПДн/PAN.
