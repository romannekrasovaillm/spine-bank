1. ЗАПРЕЩЕНО использовать `f64`/`f32` для денег, комиссий, лимитов и остатков. Проверка: суммы хранятся и вычисляются только в minor units (`i64`) или Decimal.

2. ЗАПРЕЩЕНО выполнять mutating-операции без ключа идемпотентности. Проверка: каждая операция, изменяющая состояние, принимает `idempotency_key`; повторный вызов с тем же ключом возвращает сохранённый результат без повторного изменения состояния.

3. ЗАПРЕЩЕНО использовать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!` в прод-коде. Проверка: все ошибки обрабатываются через `Result` с явным пробросом (`?`) или обработкой.

4. ЗАПРЕЩЕНО попадание в логи и журналы полного PAN, ФИО держателя, паспортных данных, телефонов и адресов. Проверка: карта в логах — только маска (BIN + последние 4 цифры, остальное — `*`).

5. ЗАПРЕЩЕНО возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`) в продуктовом коде. Проверка: ошибки — типизированные enum (вариант на каждый класс сбоя, реализация `Display` + `Error`); публичные функции домена возвращают `Result<T, DomainError>` с набором вариантов ошибки как частью контракта.

6. ЗАПРЕЩЕНО глобальное мутабельное состояние (`static mut`, `lazy_static!`, `static ref`, глобальные `static Mutex/RwLock` с доменным состоянием). Проверка: состояние передаётся явно через владение, параметры или конструктор.

7. ЗАПРЕЩЕНО выполнять сетевые вызовы без явно заданного таймаута и хранить секреты литералами в коде. Проверка: каждый HTTP/TCP/queue-вызов выполняется с таймаутом; ключи, пароли и токены читаются только из `std::env::var`. Каждое денежное событие журналируется (ключ идемпотентности, сумма в minor units, валюта, результат) с соблюдением маскирования по инварианту 4.
