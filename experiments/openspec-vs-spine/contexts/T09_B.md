# Spec

## Требование: миграция данных

Система ДОЛЖНА прочитать записи платёжного хранилища схемы v1 (id, сумма, статус-строка), сконвертировать их в записи схемы v2 (id, сумма, статус-перечисление, метка времени) и записать результат в хранилище v2.

## Требование: представление денежных сумм

Система ДОЛЖНА хранить и вычислять денежные суммы только в minor units (целые копейки, `i64`) либо через десятичный тип Decimal. Система НЕ ДОЛЖНА использовать `f64`/`f32` для денег, комиссий, лимитов и остатков.

## Требование: запрет unwrap/expect/panic

Продуктовый код системы НЕ ДОЛЖЕН содержать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!`. Обработка ошибок ДОЛЖНА выполняться только через `Result` с явным пробросом (`?`) или обработкой.

## Требование: типизированные ошибки

Ошибки системы ДОЛЖНЫ быть представлены типизированными перечислениями (по одному варианту на каждый класс сбоя) с реализацией `Display` + `Error`. Система НЕ ДОЛЖНА возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`) в продуктовом коде.

## Требование: контракт ошибок публичных функций

Публичные функции домена системы ДОЛЖНЫ возвращать `Result<T, DomainError>`; набор вариантов ошибки ДОЛЖЕН являться частью контракта функции.

## Требование: запрет персональных данных и PAN в логах

В логи и журналы системы НЕ ДОЛЖНЫ попадать: полный номер карты (PAN), ФИО держателя, паспортные данные, телефоны, адреса. Допустима только маска карты (BIN + последние 4 цифры, остальное — `*`).

## Требование: журналирование миграции

Система ДОЛЖНА залогировать число успешно мигрированных записей и ошибки конвертации.

## Требование: запрет глобального мутабельного состояния

Продуктовый код системы НЕ ДОЛЖЕН содержать `static mut`, `lazy_static!`, `static ref` и глобальные `static Mutex/RwLock` с состоянием домена. Состояние ДОЛЖНО передаваться явно (владение, параметры, конструктор).

## Требование: сетевые вызовы с таймаутом

Любой сетевой вызов системы (HTTP, TCP, очередь) ДОЛЖЕН выполняться с явно заданным таймаутом. Блокирующие вызовы без таймаута запрещены.

## Требование: секреты из окружения

Ключи, пароли и токены системы ДОЛЖНЫ читаться только из переменных окружения (`std::env::var`). Секреты литералами в коде запрещены.

## Требование: идемпотентность mutating-операций

Каждая операция системы, изменяющая состояние (в том числе запись в журнал), ДОЛЖНА принимать обязательный ключ идемпотентности (`idempotency_key`). Повторный вызов с тем же ключом ДОЛЖЕН возвращать сохранённый результат без повторного изменения состояния.

## Требование: журналирование денежных событий

Каждое денежное событие системы ДОЛЖНО журналироваться с указанием: ключа идемпотентности, суммы в minor units, валюты, результата. Журнал ДОЛЖЕН подчиняться запрету на ПДн/PAN в логах.

# Design

Миграция v1 → v2 — это пакетная, но state-mutating операция, поэтому к ней применяются те же гарантии, что и к любому другому продуктовому коду платёжного домена, без исключений «на один скрипт».

Основная смысловая граница задачи — переход от статус-строки к типизированному статусу. Строка в v1 — это непроверенные данные на границе системы, поэтому парсинг строки в enum рассматривается как точка возможного сбоя, и каждый сбой конвертации должен быть отдельным типизированным вариантом ошибки, а не паникой или строкой. Именно поэтому код ошибок строится как enum с реализацией `Display`/`Error`, а публичные функции миграции возвращают `Result<T, DomainError>`: контракт ошибок — часть контракта функции, и вызывающая сторона должна знать весь спектр сбоев заранее.

Ошибки конвертации не должны прерывать миграцию целиком: задача требует залогировать и число мигрированных записей, и ошибки, что означает сбор и накопительный отчёт, а не fail-fast. При этом ни один путь выполнения не имеет права завершиться паникой — запрет на `unwrap/expect/panic` гарантирует, что повреждённая или неожиданная запись v1 превращается в значение ошибки, а не в падение процесса.

Денежная сумма мигрируется как есть, без промежуточных преобразований: она уже хранится в minor units (`i64`), и любые арифметические операции или переводы в плавающую точку запрещены стандартом. Метка времени добавляется при конвертации как новое поле v2.

Запись результатов в хранилище и журналирование — это mutating-операции, поэтому они принимают ключ идемпотентности, а каждое денежное событие (включая события миграции) журналируется с ключом, суммой в minor units, валютой и результатом. Логи не содержат ПДн и PAN — если в записи v1 окажутся маскированные данные карты, в журнал допускается вывод только маски.

Состояние миграции (хранилище-источник, приёмник, журнал) передаётся явно через владение или конструктор: никаких глобальных `static`/`lazy_static`-структур. Это делает миграцию тестируемой и воспроизводимой. Если миграция обращается к внешним хранилищам по сети, каждый вызов оснащён явным таймаутом; секреты, если они нужны (например, для доступа к хранилищу), читаются только из `std::env::var`.

Результатом является один самодостаточный файл `src/main.rs`, содержащий: чтение записей v1, типизированную конвертацию в v2, явную обработку ошибок через `Result`/`?`, журналирование с требуемыми полями и финальный отчёт о числе мигрированных записей и ошибках конвертации.

# Rules

- Все суммы — только `i64` (minor units) или Decimal; `f64`/`f32` для денег запрещены.
- Никаких `.unwrap()`, `.expect()`, `panic!`, `unreachable!`, `todo!`, `unimplemented!()` в продуктовом коде.
- Ошибки — только типизированный enum (`Display` + `Error`); никаких `Err("...")`, `String`, `Box<dyn Error>`.
- Публичные функции домена возвращают `Result<T, DomainError>`.
- Mutating-операции (включая запись в журнал) принимают `idempotency_key`; повторный вызов с тем же ключом возвращает сохранённый результат.
- Денежные события журналируются: ключ идемпотентности, сумма в minor units, валюта, результат.
- В логах — никаких PAN, ФИО, паспортных данных, телефонов, адресов; допустима только маска карты (BIN + последние 4 цифры).
- Никаких `static mut`, `lazy_static!`, `static ref`, глобальных `static Mutex/RwLock` с доменным состоянием; состояние передаётся явно.
- Любой сетевой вызов — только с явно заданным таймаутом.
- Секреты — только через `std::env::var`; литералы в коде запрещены.
- Результат — один самодостаточный файл `src/main.rs`; залогировать число мигрированных записей и ошибки конвертации.
