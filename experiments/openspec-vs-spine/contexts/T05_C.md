1. ЗАПРЕЩЕНО использовать `f64`/`f32` для денежных сумм, комиссий, лимитов и остатков. Проверка: все денежные значения — `i64` в minor units или `Decimal`; поиск по типам в сигнатурах и структурах.

2. ЗАПРЕЩЕНО выполнять mutating-операцию (списание, зачисление, возврат, обновление статуса, запись в журнал) без обязательного `idempotency_key`. Проверка: повторный вызов с тем же ключом возвращает сохранённый результат и не изменяет состояние повторно.

3. ЗАПРЕЩЕНО использовать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!` в продуктовом коде. Проверка: ошибки обрабатываются только через `Result` с явным пробросом `?` или обработкой.

4. ЗАПРЕЩЕНО писать в логи полный PAN, ФИО держателя, паспортные данные, телефоны и адреса. Проверка: в логах допустима только маска карты (BIN + последние 4 цифры, остальное — `*`).

5. ЗАПРЕЩЕНО возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`). Проверка: ошибки — типизированные enum с вариантом на каждый класс сбоя и реализацией `Display` + `Error`.

6. ЗАПРЕЩЕНО использовать `static mut`, `lazy_static!`, `static ref` и глобальные `static Mutex/RwLock` с состоянием домена. Проверка: состояние передаётся явно — через владение, параметры или конструктор.

7. ЗАПРЕЩЕНО выполнять сетевые вызовы (HTTP, TCP, очереди) без явно заданного таймаута. Проверка: каждый блокирующий сетевой вызов имеет явное значение таймаута; секрета в виде литерала в коде быть не должно — только `std::env::var`; каждое денежное событие журналируется с ключом идемпотентности, суммой в minor units, валютой и результатом; публичные функции домена возвращают `Result<T, DomainError>`, набор вариантов ошибки — часть контракта.
