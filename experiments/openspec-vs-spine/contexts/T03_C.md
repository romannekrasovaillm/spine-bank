1. ЗАПРЕЩЕНО хранить и вычислять деньги, комиссии, лимиты и остатки через `f64`/`f32`. Проверка: денежные значения — только `i64` (minor units) или `Decimal`.
2. ЗАПРЕЩЕНО выполнять mutating-операции (списание, зачисление, возврат, обновление статуса, запись в журнал) без `idempotency_key`. Проверка: повторный вызов с тем же ключом возвращает сохранённый результат без повторного изменения состояния.
3. ЗАПРЕЩЕНО использовать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!` в продуктовом коде. Проверка: ошибки — только через `Result` с `?` или явной обработкой.
4. ЗАПРЕЩЕНО писать в логи/журналы PAN, ФИО, паспортные данные, телефоны, адреса. Проверка: карта в логах — только маска (BIN + последние 4 цифры, остальное `*`).
5. ЗАПРЕЩЕНО возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`). Проверка: ошибки — типизированные enum (по классу сбоя на вариант, `Display` + `Error`).
6. ЗАПРЕЩЕНО использовать `static mut`, `lazy_static!`, `static ref`, глобальные `static Mutex/RwLock` с состоянием домена. Проверка: состояние передаётся явно (владение, параметры, конструктор).
7. ЗАПРЕЩЕНО выполнять сетевые вызовы (HTTP, TCP, очередь) без явно заданного таймаута; ЗАПРЕЩЕНО хранить секреты литералами в коде (только `std::env::var`); денежное событие обязательно журналируется с ключом идемпотентности, суммой в minor units, валютой и результатом; публичные функции домена возвращают `Result<T, DomainError>`. Проверка: греп по `Duration`/`timeout` при сетевых вызовах, греп по литералам секретов, наличие журналирования события, сигнатуры публичных функций.
