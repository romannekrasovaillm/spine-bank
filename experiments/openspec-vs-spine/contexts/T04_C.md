1. ЗАПРЕЩЕНО использовать `f64`/`f32` для денег, комиссий, лимитов и остатков. Проверка: суммы хранятся и вычисляются только в minor units (`i64`) или через Decimal.

2. ЗАПРЕЩЕНО выполнять mutating-операцию без ключа идемпотентности. Проверка: списание, зачисление, возврат, обновление статуса и запись в журнал принимают `idempotency_key`; повторный вызов с тем же ключом возвращает сохранённый результат без изменения состояния.

3. ЗАПРЕЩЕНО использовать `.unwrap()`, `.expect(...)`, `panic!`, `unreachable!`, `todo!`, `unimplemented!` в продуктовом коде. Проверка: обработка ошибок только через `Result` с явным пробросом (`?`) или обработкой.

4. ЗАПРЕЩЕНО писать в логи и журналы полный PAN, ФИО держателя, паспортные данные, телефоны и адреса. Проверка: для карты допустима только маска (BIN + последние 4 цифры, остальное — `*`).

5. ЗАПРЕЩЕНО возвращать ошибки строками (`Err("...")`, `String`, `Box<dyn Error>`) в продуктовом коде. Проверка: ошибки — типизированные enum (вариант на каждый класс сбоя, реализация `Display` + `Error` в стиле thiserror).

6. ЗАПРЕЩЕНО использовать `static mut`, `lazy_static!`, `static ref` и глобальные `static Mutex/RwLock` с доменным состоянием. Проверка: состояние передаётся явно (владение, параметры, конструктор).

7. ЗАПРЕЩЕНО выполнять сетевые вызовы (HTTP, TCP, очередь) без явно заданного таймаута. Проверка: каждый сетевой вызов выполняется с таймаутом.

8. ЗАПРЕЩЕНО хранить секреты (ключи, пароли, токены) литералами в коде. Проверка: секреты читаются только из переменных окружения (`std::env::var`).

9. ЗАПРЕЩЕНО проводить денежное событие без журналирования. Проверка: каждое событие журналируется с ключом идемпотентности, суммой в minor units, валютой и результатом; журнал без ПДн/PAN согласно инварианту 4.

10. ЗАПРЕЩЕНО публичным функциям домена возвращать что-либо кроме `Result<T, DomainError>`. Проверка: набор вариантов ошибки — часть контракта функции.
