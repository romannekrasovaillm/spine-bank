# Дельта: декомпозиция крупных модулей (волна B1 ревью 0.3.6)

## Что меняется

- `CONSTRAINTS.yaml` — новое правило `C-33 prod_file_length_limit`
  (`command_succeeds`): прогон `bash scripts/check_file_length.sh` — падает,
  если продовый `src/**/*.rs` длиннее 3000 строк. Плюс точечные правки
  комментариев шапки (пути `src/control.rs` → `src/control/…`,
  `src/mcp_server.rs` → `src/mcp_server/` после разбиения); смысл правил
  не менялся, состав и паттерны — без ослаблений.
- `scripts/check_file_length.sh` — исполняемая проверка порога.
- Кодовая часть уже в коммитах: `src/control.rs` → `src/control/*`,
  `src/main.rs` → `src/cli/*` (main.rs ≤ 300 строк), `src/gate.rs` →
  `src/gate/*`, `src/mcp_server.rs` → `src/mcp_server/*`,
  `src/connect.rs` → `src/connect/*`, `src/rubric.rs` → `src/rubric/*`,
  `src/contract_diff.rs` → `src/contract_diff/*`, `src/tui/app.rs` → вынос
  `src/tui/input.rs`. Всё — чистые перемещения с реэкспортами `pub use`:
  публичные пути `crate::control::…` и т.д. сохранены, число тестов
  неизменно (1579 default / 1235 core до и после каждого коммита).

## Зачем

Ревью на `c5f94ea` (волна B1): модули за 3–8 тысяч строк не ревьюируются,
конфликтуют при параллельной работе агентов и прячут регрессии в монолитных
диффах. Критерий успеха задания — «ни один продовый `.rs` не длиннее 3000
строк»; без исполняемого правила граница продержалась бы до первого роста.
Правило `error`-уровня: распад границы должен краснеть в CI, а не в отчёте.

## Чем подтверждается

- `arch-be control check . --constraints CONSTRAINTS.yaml` — PASS, включая
  C-33 (49 правил).
- Контрпроба: скрипт краснится на искусственно раздутом файле > 3000 строк.
- Тестовые суммы до/после каждого коммита разбиения идентичны
  (1579+6 ignored default, 1235+2 core).
