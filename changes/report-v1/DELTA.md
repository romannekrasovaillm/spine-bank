# Дельта: report-v1
- Route: Standard (significance 2: new_component + api_contract_change; ADR-080)
- Created: 2026-10-12

## Проблема

Бенчмарк `spine-architecture-report-format.md` требует от Spine отчёт о
восстановленной архитектуре (14 разделов + приложения + лист экспертной
оценки) с трассируемостью, уверенностью A/B/C, стабильными ID и
автопроверкой перед выдачей. Такого артефакта нет: `recover` даёт граф,
`survey` — карту обследования; сведения в отчёт каждый делает руками и
по-разному. Решение — ADR-080: строитель отчёта `src/report/`, схема
`arch-be/report/v1`, команда `arch-be report`, fail-closed автопроверка.

## ADDED

- When вызывается `arch-be report <repo> [--rev R] [--format md|json]`, the
  система shall построить модель `arch-be/report/v1` (элементы с report-ID
  CTX/CNT/CMP/INT/RISK/ADR, уверенностью A/B/C, evidence) и выдать отчёт в
  запрошенном формате.
- When модель отчёта построена, the система shall назначить уверенность
  детерминированно: model_id/confirmed → A, inferred → B, gaps и LLM-блоки
  → C; LLM-слой не может назначить A/B.
- When модель готова к выдаче, the система shall прогнать автопроверку:
  каждый элемент имеет evidence и уверенность; ID на диаграммах = ID в
  таблицах; evidence разрешается в файлы ревизии — при нарушении выдача
  блокируется (exit ≠ 0), флага обхода нет.
- When агент вызывает MCP-инструмент `report`, the система shall вызвать тот
  же строитель `src/report/` (SSOT), что и CLI.
- **AD-11 в ARCHITECTURE-SPINE.md:** SSOT строителя отчёта (см. ниже).
- **docs/REPORT.md:** формат отчёта, конвейер PDF (Typst/Pandoc — внешние
  бинари), разделы детерминированные vs интерпретационные.

## План отката

Дельта аддитивна: удалить `src/report/`, команду `Report`, MCP-регистрацию,
AD-11 (следующей дельтой), docs/REPORT.md. Существующие контракты
(`recover/v1`, survey) не затронуты. Откат — `git revert` коммитов дельты.

## Критерии приёмки

- [ ] `arch-be report <fixtures-repo> --format json` выдаёт валидную
      модель `report/v1`: у каждого элемента report-ID, A/B/C, evidence.
- [ ] `--format md` — все 14 разделов + приложения A–D, G + лист экспертной
      оценки; детерминированные разделы наполнены, интерпретационные —
      помечены блоками `[Интерпретация Spine]`/`[gap]`-промптами.
- [ ] Автопроверка: подложенный элемент без evidence / ID вне таблиц /
      битая ссылка → отказ выдачи с находкой (тест на каждой инвариант).
- [ ] Детерминизм: два прогона одной ревизии — байт-в-байт равный JSON.
- [ ] MCP `report` (ро-мост) отдаёт тот же результат, что CLI (тест).
- [ ] Дог-фуд: `arch-be report .` на самом spine-bank — автопроверка
      зелёная, A/B/C-распределение в §1 осмысленно.
- [ ] `cargo test` зелёный; fmt/clippy чисты; счётчики MCP-справки
      синхронизированы (тест реестра); spine_lint зелёный (AD-11).

## Открытые вопросы scoped overrides (П4 0.4.8, от добивочного прогона)

- **Анти-ослабление не видит `override.exclude_glob`**: rule_weakened
  перечитывает SOURCE через rules_snapshot, а RuleSnapshot.excludes выводится
  только из `rule.exclude_glob` — сужение/расширение охвата исключения
  гейтом не отслеживается (зафиксировано тестом
  `rule_weakened_ignores_override_exclude_glob` как текущее поведение).
  Закрытие — отдельная задача: расширить snapshot полем override-глобов и
  включить «добавление exclude_glob к существующему override» в
  анти-ослабление как расширение исключения.
- **Старый бинарь молча расширяет узкий override**: OverrideEntry без
  deny_unknown_fields → бинарь <0.4.8 игнорирует `override.exclude_glob`
  и отключает правило ЦЕЛИКОМ (шире задуманного). Реестры с узкими
  overrides требуют 0.4.8+; кандидат на механическое «минимум-версии
  реестра» (поле `requires: "0.4.8"` в шапке CONSTRAINTS + warn при
  несоответствии) — отдельное решение.
