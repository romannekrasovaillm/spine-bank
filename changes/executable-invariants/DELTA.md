# Дельта: шаблоны исполняемых правил — проверка зубов в догфуд-реестре

## Что меняется

- `CONSTRAINTS.yaml` — новое правило `C-31 rule_templates_have_teeth`
  (`command_succeeds`): прогон `arch-be rules template verify --all` по
  библиотеке шаблонов. Правило закрывает нашей же механикой то, о чём говорит
  строка паспорта «правил, судящих по тексту, — N из M»: у каждого
  поставляемого шаблона тест обязан падать на нарушающей реализации.

## Зачем

Реестр репозитория сам состоит из правил, доказывающих наличие текста
(`cargo fmt --check`, `cargo test`, `must_contain` по именам модулей и строк
документации). Библиотека шаблонов (ADR-050) поставляет исполняемые проверки
поведения — и первое, что должно быть проверено исполнением, это она сама:
беззубый шаблон в поставке хуже отсутствующего, потому что попадает в счёт
«проверяют поведение».

Правило `error`-уровня: библиотека — часть поставки, её регресс должен краснеть
в CI, а не в отчёте.

## Чем подтверждается

- `arch-be rules template verify --all` — 32 проверки (эталон и нарушение на
  каждый из двух языков), 0 провалов, одна честная пометка о заготовке.
- Тесты модуля `rule_templates` (`templates_are_embedded_and_manifests_valid`
  требует нарушающую реализацию у каждого исполняемого шаблона).
