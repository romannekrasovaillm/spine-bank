# Сервис цифрового рубля для физических лиц

Проектирование сервиса банка-участника платформы цифрового рубля (ПЦР) Банка
России для физических лиц: открытие кошелька на платформе, ввод/вывод,
переводы C2C, оплата C2B по QR, возвраты, сверка с платформой.

- Маршрут: **Critical** (10 триггеров из 15, форс по `criticality` /
  `security_boundary`).
- Модель: **Claude Code без LLM у Spine** — архитектурный агент проектировал,
  все проверки исполнял `arch-be` без единого API-ключа (методология
  «Spine Core без своей LLM», см. `docs/experiments/`).
- Статус: комплект готов и зелёный по всем детерминированным гейтам;
  **выпуск заблокирован evidence-гейтом** — решение A3 по стратегии
  реализации (ADR-009, статус Proposed) и артефакты стадии реализации
  отсутствуют. Протокол ПЦР публично не раскрыт — протокольные детали
  помечены `[ТРЕБУЕТ ПРОВЕРКИ]`.

## Состав комплекта

| Артефакт | Что внутри |
|---|---|
| `ARCHITECTURE-SPINE.md` | 10 инвариантов AD-001…AD-010 (Binds/Prevents/Rule) + секция Deferred |
| `CONSTRAINTS.yaml` | 15 фитнес-правил C-001…C-015 с карточками (owner / expiry / effort_hours) |
| `model/` | 65 сущностей, 161 связь: SYS, CAP×5, CMP×10, INT×5, NFR×10, REQ×6, AD×10, ADR×9, QAS×3, RISK×4, OWNER×2 |
| `docs/adr/` | 9 решений, включая A3-развилку по стратегии реализации (ADR-009) |
| `docs/contracts/` | 5 контрактов: адаптер ПЦР, API каналов, АБС, антифрод, уведомления |
| `docs/spec/` | конечная машина операции (с обязательным `UNKNOWN`), лимиты и антифрод |
| `docs/` | solutioning, nfr, PROBLEM, SPEC, RISK, ACCEPTANCE, ROLLBACK, REVIEW |
| `.arch-handoff/` | handoff-пакет кодовому харнессу (TASK, ARCHITECTURE, CONSTRAINTS, SPEC, RUBRIC, ROLLBACK, MANIFEST, adr/) |
| `EVIDENCE.yaml` | evidence bundle маршрута Critical: 9 артефактов с хэшами |
| `reports/fitness.md` | отчёт фитнес-прогонов, сгенерированный реальными запусками гейтов |

Стержень решения — четыре связанных инварианта: `AD-001` (платформа ЦР —
единственный источник истины; в банке проекция с меткой свежести и признаком
`derived`), `AD-005` (обязательное состояние `UNKNOWN`: таймаут не трактуется
ни как успех, ни как отказ; повтор из неопределённого состояния запрещён),
`AD-002` (append-only журнал — единственный источник аудита и аргументов в
спорах), `AD-007` (сверка с платформой как постоянный контур с измеримым
лагом, без автоматической правки расхождений).

## Как прогнать гейты

Все команды исполняются без API-ключей — контур детерминированный:

```bash
cd кейсы/digital-ruble
arch-be control spine ARCHITECTURE-SPINE.md                    # нарушений нет
arch-be control check . --constraints CONSTRAINTS.yaml         # 15 правил, 0 нарушений → PASS
arch-be model validate model                                   # 65 сущностей, 0 находок → PASS
arch-be trace check .                                          # 6 звеньев, 100% покрытие → PASS
arch-be nfr budget . && arch-be nfr availability . \
  && arch-be nfr capacity . && arch-be nfr cost .              # 3 цели p99, SLA 99,4004%, TCO 46,86 млн ₽/год
arch-be control sensors docs/spec                              # обязательные секции и ссылки → PASS
arch-be control score --trigger new_component=true \
  --trigger security_boundary_change=true                      # → маршрут Critical
arch-be evidence verify .                      # ожидаемо FAIL: выпуск заблокирован
arch-be gate --repo . --constraints CONSTRAINTS.yaml           # составной гейт → PASS
```

> **Почему `arch-be gate --repo .` без `--constraints` красный.** Составной
> гейт по умолчанию читает `<repo>/.arch-handoff/CONSTRAINTS.yaml`, а в кейсе
> там сохранилась заготовка генератора `handoff` старой версии — синтаксически
> невалидный YAML (дефект A1 из отчётов эксперимента, в main исправлен).
> Настоящие правила кейса — корневой `CONSTRAINTS.yaml`; передавайте его
> явно, как в командах выше.

## Что показывает кейс

- **Гейт сказал «нет» — выпуск заблокирован.** `evidence verify` на маршруте
  Critical: из 13 обязательных артефактов собрано 9, отсутствуют 4
  (`decision_a3` — человеческий гейт не закрыт; `walking_skeleton`,
  `rollback_rehearsal`, `validation` — стадия реализации не наступала) →
  FAIL, exit 1. Это не сбой, а корректный отказ: доказательств следующей
  стадии физически нет, и гейт отказывается объявить пакет выпускаемым.
- **Целостность evidence проверяется хэшами, а не доверием.** `EVIDENCE.yaml`
  зафиксировал хэши артефактов на момент упаковки; спайн был отредактирован
  уже после сборки бандла (ссылка `NFR-008` → `NFR-009`) — `evidence verify`
  ловит это как `ИЗМЕНЁН: spine … изменён после упаковки` и валит выпуск.
  (В первой упаковке пойманы две подмены — спайн и `docs/adr`; см. второй
  отчёт в `docs/experiments/`.)
- **UNKNOWN-состояние как несущий элемент.** Таймаут платформы — не успех и
  не отказ, а отдельное состояние машины операции с выходом только по
  подтверждению платформы (AD-005, `docs/spec/operation-state-machine.md`).
- **Проекция платформы, а не второй баланс.** Кошелёк живёт на платформе
  Банка России; в банке — проекция с меткой свежести (AD-001), сверка —
  постоянный контур с измеримым лагом 5 мин (AD-007, NFR-009).
- **Append-only журнал как единственный источник аудита** (AD-002) и
  честные метки `[ТРЕБУЕТ ПРОВЕРКИ]` вместо выдуманных протокольных деталей.
- **Числа, которые пересчитываются:** доступность цепочки 99,4004% против
  SLA 98%; бюджет перевода C2C 2150/3000 мс; TCO 46,86 млн ₽/год, цена
  выхода 8,9 млн ₽ = 19% годового TCO; warning `budget-hop-uncovered:
  INT-005` — честное признание неполноты покрытия.
- **Гейты нашли дефекты в артефактах автора** (фраза в косвенном падеже
  под regex-правило, регистр заглавной буквы, отсутствие обязательных секций
  в спеках, правила без карточек owner/expiry) — механические расхождения
  между замыслом и записью, невидимые собственному ревью.

## Пять ценностей Spine — измерено на этом кейсе

По §8.2 первого отчёта (`docs/experiments/no-llm-2026-09-19.md`), сжато:

1. **Проверяющий, который не я.** Три дефекта в артефактах автора нашли
   гейты, а не автор; жёсткая форма — `evidence verify` вернул FAIL и
   заблокировал выпуск: харнесс-генератор физически не может произвести
   отказ от собственного результата, здесь — может.
2. **Схема, заставляющая полноту вместо дисциплины.** У инварианта обязано
   быть правило фитнеса или явное `unverifiable`; у интеграции — файл
   контракта; у ADR — затронутый компонент; у NFR — способ проверки. Пять
   контрактных файлов появились потому, что модель без существующего пути
   даёт error; итог — 161 связь и 100% по шести звеньям трассировки.
3. **Числа, которые проверяются, а не декларируются.** Доступность цепочки
   посчитана произведением по участкам с учётом реплик, латентность —
   суммой бюджетов hop'ов, TCO и цена выхода — из модели; плюс warning о
   непокрытом hop'е, который автор в собственный документ не вписал бы.
4. **Governance как ограничение автономии.** Цена сопровождения правил —
   26 ч/год по 15 правилам с владельцем и `expiry`; маршрут значимости
   (10/15 → Critical) форсирован неотключаемыми триггерами; человеческий
   гейт A3 нельзя закрыть за человека — и это же причина блокировки выпуска.
5. **Передача и сопоставимость.** Handoff-пакет собран в ~1500 токенов с
   машинным контрактом результата; якорная рубрика `solution_architecture`
   дала сопоставимое число 3,85/5 — измерение, воспроизводимое в другой
   сессии и на другом кейсе, а не мнение.

## Что осталось за границей (честно)

Детерминированный слой проверяет форму, числа и связи — **полноту решений он
не проверяет и не может**. Содержательные пробелы кейса (нет декомпозиции
REQ → работы, критерии приёмки не в EARS, нет ADR по репликации/DR под
заявленные RTO/RPO, неаутентифицированный стык канал→шлюз, нет аудита
действий оператора, backpressure не описан) нашли не инструменты, а
методики-скиллы (`readiness-gate` → CONCERNS, `adversarial-review` →
NOT-READY). Судейство по рубрикам остаётся за моделью — в режиме без LLM у
Spine судьёй был внешний агент, и split-judge (`rubric_prompt` →
`rubric_verify`) механически проверяет доказательность его оценок, но не
отменяет вердикт. Полный разбор границ — §8.4 первого отчёта и §6/§10
второго в `docs/experiments/`.

## Вердикты на 0.3.4

Маршрут `auto` (Fast на чистом дереве) — **PASS**, как и на 0.3.3: реестр
правил, спайн, трассировка и модель не изменились.

Маршрут `--route critical` — **FAIL** по `evidence_verify`: артефакты бандла
этого кейса — заглушки, а с 0.3.4 (Н1, ADR-041) семантика артефактов стала
частью вердикта: «файл на месте и хэш сходится» больше не означает «выпуск
разрешён». Это не регрессия кейса, а изменение того, что гейт обещает: на
0.3.3 тот же бандл давал зелёный.

Возврат к прежнему поведению — `[evidence] semantics = off` в конфиге.
Подробности — `docs/experiments/0.3.4-что-сделано.md`, раздел «Что может
покраснеть после обновления».
