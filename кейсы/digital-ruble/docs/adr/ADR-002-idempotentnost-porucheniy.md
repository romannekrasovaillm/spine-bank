# ADR-002. Идемпотентность поручений на каждой точке входа

- Date: 2026-09-19
- Status: Accepted

## Context

Поручение клиента проходит путь «канал → шлюз → оркестратор → адаптер →
платформа». Повторы возникают на каждом шаге: клиент нажал кнопку дважды,
канал повторил запрос по таймауту, очередь доставила сообщение дважды.
Финансовый эффект повтора — второй перевод или второе списание, поэтому
дедупликация не может быть «лучшим усилием» на одном из слоёв.

## Decision

Каждое изменяющее поручение несёт `Idempotency-Key` от канала. Дедупликация
выполняется в той же транзакции, что и бизнес-эффект: сначала фиксируется
намерение с ключом, затем выполняется эффект. Повтор с тем же ключом
возвращает результат первого исполнения и не создаёт новой операции. Срок
жизни ключей — не меньше окна ретраев канала плюс буфер. Идентификатор
поручения банка служит ключом операции и на стороне платформы, поэтому повтор
на стыке с ПЦР также не создаёт второй операции.

## Alternatives Considered

| Вариант | Почему отклонён |
|---|---|
| Дедупликация на уровне адаптера | повтор между каналом и адаптером создаёт дубль до попадания в адаптер |
| Дедупликация по совпадению суммы и получателя | запрещает легитимные повторные переводы и не ловит разницу во времени |
| Без дедупликации, «клиент сам виноват» | неприемлемо для финансовой операции |

## Consequences

### Positive

- Повтор любого участника пути не приводит к второму переводу.
- Таймаут на клиенте становится безопасным: повтор запроса не опасен.

### Negative

- Требуется хранилище ключей с регламентом очистки и метрикой аномалий.
- Канал обязан формировать ключ; для этого контракт явно требует заголовок.
