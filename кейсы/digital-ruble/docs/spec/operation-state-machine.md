# Конечная машина операции цифрового рубля

Состояния операции над кошельком и правила переходов. Машина — общая для
переводов C2C, оплаты C2B и возвратов; различается только набор допустимых
переходов на этапе подтверждения.

## Состояния

| Состояние | Смысл | Что видит клиент |
|---|---|---|
| `CREATED` | поручение принято, проверки пройдены, в ПЦР не отправлено | «обрабатывается» |
| `SENT` | поручение отправлено на платформу, ответа нет | «обрабатывается» |
| `CONFIRMED` | платформа подтвердила исполнение | «исполнено» |
| `REJECTED` | платформа отклонила с указанием причины | «не исполнено» + причина |
| `UNKNOWN` | ответ не получен или неопределён (таймаут, обрыв, неоднозначный ответ) | «в обработке, результат уточняется» |
| `RESOLVED_CONFIRMED` | исход `UNKNOWN` разрешён сверкой как исполнение | «исполнено» |
| `RESOLVED_REJECTED` | исход `UNKNOWN` разрешён сверкой как неисполнение | «не исполнено» |

## Правила переходов

- `CREATED → SENT`: поручение ушло в адаптер; фиксируется в журнале до вызова.
- `SENT → CONFIRMED | REJECTED`: получен однозначный ответ платформы.
- `SENT → UNKNOWN`: таймаут, обрыв соединения, ответ, не разбираемый
  однозначно. **Таймаут не трактуется ни как успех, ни как отказ.**
- `UNKNOWN → RESOLVED_CONFIRMED | RESOLVED_REJECTED`: только по результату
  запроса состояния или сверки. Переход в терминальное состояние без
  подтверждения платформы запрещён.
- Повторная отправка поручения из `UNKNOWN` без подтверждения неисполнения
  запрещена: повторное исполнение на платформе недопустимо.

## Что машина запрещает

- Возврат к `CREATED` после отправки (потеря следа операции).
- Любой переход из терминальных состояний, кроме компенсирующей записи
  журнала.
- Автоматическое «дорешение» исхода `UNKNOWN` по таймауту ожидания.

## Наблюдаемость

Счётчики по состояниям и время пребывания в `UNKNOWN` — обязательные метрики:
рост времени в `UNKNOWN` означает деградацию платформы раньше, чем её увидит
мониторинг платформы. Операции в `UNKNOWN` старше окна сверки попадают в
очередь разбора с владельцем.

## Проблема

Ответ платформы не всегда однозначен: таймаут не означает ни успеха, ни
отказа. Если сервис достраивает исход сам — он либо показывает клиенту
несуществующий результат, либо повторяет уже прошедшую операцию. Обе ошибки
финансовые, и обе необратимы для доверия клиента.

## Критерии приёмки

- В машине состояний присутствует `UNKNOWN`; переходы в терминальное
  состояние возможны только по подтверждению платформы.
- Повторная отправка поручения из `UNKNOWN` без подтверждения неисполнения
  невозможна.
- Канал получает для `UNKNOWN` формулировку «в обработке», отличимую от
  успеха и отказа.
- Время пребывания в `UNKNOWN` измеряется; застарелые случаи попадают в
  очередь разбора (`NFR-009`).
- Все переходы фиксируются в журнале (`AD-002`).

## Риски

Ключевой риск — соблазн «упростить» опыт клиента, достраивая исход по
таймауту: см. `RISK-002` (SLA платформы ниже заложенного) и `RISK-001`
(неизвестное поведение платформы при повторе). Оба риска снимаются только
подтверждённым поведением платформы, а не настройкой таймаутов.
