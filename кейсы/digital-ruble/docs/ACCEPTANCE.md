# Критерии приёмки

## Приёмка решения (текущая стадия)

Решение считается принятым, когда выполняются все условия:

1. `arch-be control spine ARCHITECTURE-SPINE.md` — без нарушений.
2. `arch-be control check . --constraints CONSTRAINTS.yaml` — PASS (нет
   находок severity error).
3. `arch-be model validate model` — PASS (нет битых ссылок, дублей, циклов).
4. `arch-be trace check .` — все шесть звеньев 100%, нет сирот.
5. `arch-be nfr budget|availability|capacity|cost .` — PASS.
6. `arch-be control sensors docs/spec` — все сенсоры PASS.
7. Открытые внешние входы помечены `[ТРЕБУЕТ ПРОВЕРКИ]`; ни один не выдан за
   установленный.
8. Решение A3 по стратегии реализации (`ADR-009`) зафиксировано человеком.

Пункты 1–7 проверяются механически, пункт 8 — человеком.

## Приёмка релиза (следующая стадия)

Выход в промышленную эксплуатацию дополнительно требует:

- walking skeleton: сквозной сценарий «поручение → платформа → журнал →
  уведомление» на подтверждённом протоколе платформы;
- проверка деградации: учения с отключением стыка — ни одной операции,
  показанной клиенту исполненной без подтверждения платформы;
- репетиция отката по плану `docs/ROLLBACK.md`;
- отчёт о валидации: нагрузочный прогон до 2400 rps, проверка лага сверки;
- прогон fitness-функций из `reports/fitness.md` без error-находок.

## Что не принимается как доказательство

- Скриншоты и ручные проверки без воспроизводимой команды.
- Утверждения о поведении платформы без ссылки на подтверждённый документ
  оператора платформы.
- «Тесты зелёные» без указания, какие именно гейты и с каким exit-кодом.
