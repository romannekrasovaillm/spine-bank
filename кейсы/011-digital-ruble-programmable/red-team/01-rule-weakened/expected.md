# Ожидание: 01-rule-weakened

- Что засеяно: в корневом `CONSTRAINTS.yaml` у правила `C-001` severity понижен `error` → `warn` без override.
- Команда-проба: `arch-be gate --repo .` (путь ограничений по умолчанию; в кейсе нет `.arch-handoff/CONSTRAINTS.yaml` — гейт берёт корневой файл по fallback'у путей).
- Ожидаемая реакция: секция `rule_weakened` — FAIL, exit 1 (анти-ослабление сравнивает по корневому пути; секция печатает использованный файл).
- Замечание: с явным `--constraints` путь ВНУТРИ репозитория сравнивается по относительному пути (fail-closed), путь ВНЕ репозитория — FAIL «анти-ослабление невозможно», а не молчаливый SKIP (см. отчёт волны DB-гейта).
