# ADR-010. Условное исполнение: escrow и DvP вместо доверия сторон

- Date: 2026-09-19
- Status: Accepted

## Context

Программируемый платёж связывает две стороны, которые не доверяют друг другу
по определению: иначе условие не нужно. Доверие нельзя «добавить» интерфейсом;
его заменяет механика: средства блокируются до подтверждения условия, обе
стороны работают с одной версией условия, а момент исполнения определяется
событием, а не договорённостью по телефону.

## Decision

Платёж по условию строится по модели escrow/DvP: до подтверждения условия
средства не двигаются; при подтверждении исполнение инициируется движком
условий ровно один раз; обе стороны видят одну и ту же версию условия и её
состояние. Любое исполнение проходит через существующие инварианты контура:
единственный адаптер (`AD-004`), журнал (`AD-002`), сверка (`AD-007`).

## Alternatives Considered

| Вариант | Почему отклонён |
|---|---|
| Доверительное исполнение по уведомлению стороны | нет механики, спор неразрешим |
| Мгновенное исполнение при первом подтверждении | нарушает escrow: платёж уходит до подтверждения второй стороны |
| Исполнение по таймауту условия | создаёт второй поток исполнений вне журнала и сверки |

## Consequences

### Positive

- Спор разрешается данными (версия условия, журнал), а не перепиской.
- Исполнение остаётся в общем контуре контроля: идемпотентность, UNKNOWN,
  сверка работают без исключений.

### Negative

- Клиентский путь длиннее: подтверждение обеих сторон добавляет шаг.
- Требуется поддержка блокировки средств на стороне платформы
  (`[ТРЕБУЕТ ПРОВЕРКИ]`).
