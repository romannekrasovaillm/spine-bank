# Программируемые платежи по условию (смарт-контракты для физлиц)

Условие как единственный источник правил исполнения: публикация версии,
подтверждение сторонами, escrow/DvP, частичное исполнение, спор.

## Проблема

Обычный перевод исполняется по факту поручения. Программируемый платёж
исполняется по **условию**, которое стороны согласовали заранее: оплата против
поставки, блокировка средств до подтверждения, частичная выплата по этапам.
Из этого следуют три угрозы, которых нет у обычного перевода:

- **расхождение версий условия** — стороны уверены, что согласовали разное;
- **дорешение неопределённости условием** — платформа не подтвердила
  исполнение, а движок условий считает условие выполненным по таймауту и
  инициирует повторное исполнение;
- **автоматический «арбитраж»** — расхождение сторон разрешается правилом
  системы, а не человеком, и решение нечем обосновать.

## Модель условия

| Понятие | Смысл |
|---|---|
| Версия условия | неизменяемый набор правил: стороны, сумма или доля, момент исполнения, подтверждающие события |
| Подтверждение стороны | отдельная операция каждой стороны над конкретной версией |
| Действующая версия | единственная версия, по которой может быть исполнен платёж |
| Состояние условия | `DRAFT` → `PUBLISHED` → `CONFIRMED` → `PARTIALLY_CONFIRMED` / `FULFILLED` / `DISPUTED` / `REVOKED` |
| Состояние операции | ортогонально состоянию условия: `CREATED`, `SENT`, `CONFIRMED`, `REJECTED`, `UNKNOWN` (см. `operation-state-machine.md`) |

**Ключевое различие**: состояние условия описывает договорённость, состояние
операции — деньги. `FULFILLED` по условию не означает `CONFIRMED` по операции.

## Поведение

1. Сторона публикует версию условия; вторая подтверждает её отдельным
   подтверждением (2FA).
2. До подтверждения обеими сторонами платёж по условию не исполняется.
3. При выполнении условия движок инициирует поручение в ПЦР через
   единственный адаптер (AD-004) и фиксирует намерение в журнале (AD-002).
4. Исход различается по трём значениям: подтверждено, отклонено, не
   определено. Неопределённый исход оставляет **операцию** в `UNKNOWN`
   (AD-014), даже если условие помечено исполненным.
5. Частичное подтверждение платформой переводит условие в
   `PARTIALLY_CONFIRMED`; остаток не исполняется до сверки.
6. Расхождение сторон переводит платёж в `DISPUTED`: движение средств
   приостанавливается, решение принимает человек (AD-013).

## Критерии приёмки

- **When** сторона публикует новую версию условия, **the** Сервис условий
  **shall** сделать действующей только эту версию, а предыдущую сохранить
  неизменной и доступной для разбора.
- **When** платформа подтверждает исполнение условия частично, **the** Движок
  исполнения условий **shall** отразить часть в состоянии условия и оставить
  операцию в `UNKNOWN` до результата сверки.
- **While** платёж находится в состоянии `DISPUTED`, **the** Движок исполнения
  условий **shall** не инициировать никаких движений средств по этому платежу.
- **If** платформа не подтвердила исполнение в течение окна ожидания, **then**
  **the** Движок исполнения условий **shall** оставить операцию в `UNKNOWN` и
  передать её в сверку, а не считать условие исполненным.
- **Where** задействовано частичное исполнение, **the** система **shall**
  запрещать исполнение остатка до подтверждения сверкой.

## Риски

- `RISK-005`: поддержка частичного исполнения на стороне платформы не
  подтверждена `[ТРЕБУЕТ ПРОВЕРКИ]`; при отсутствии поддержки сценарий
  частичного исполнения переводится в отдельное решение.
- `RISK-006`: флеш-нагрузка от одновременного срабатывания условий;
  смягчение — растепливание и порог остановки приёма (`ADR-013`).
- Спор с иностранной стороной: юрисдикция разрешения спора в условие не
  входит и остаётся договорной `[ТРЕБУЕТ ПРОВЕРКИ]`.
