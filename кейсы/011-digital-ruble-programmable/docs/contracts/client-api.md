# Контракт: API сервиса цифрового рубля для каналов

API, который потребляют мобильный банк и интернет-банк. Версия контракта
фиксируется в пути и не меняется без нового решения.

## Общие правила

- Каждое изменяющее поручение несёт заголовок `Idempotency-Key`,
  сформированный каналом. Повтор с тем же ключом возвращает результат первого
  вызова и не создаёт второй операции.
- Клиентские таймауты не являются отменой: при таймауте канал обязан
  запросить состояние, а не отправлять новое поручение.
- Ошибки — в едином формате (RFC 7807): `type`, `title`, `status`, `detail`,
  `instance`.

## Методы

| Метод | Назначение | Идемпотентность |
|---|---|---|
| `POST /v1/wallets` | открытие кошелька ЦР | `Idempotency-Key` |
| `POST /v1/wallets/{id}/deposits` | ввод средств в кошелёк | `Idempotency-Key` |
| `POST /v1/transfers` | перевод C2C по номеру телефона | `Idempotency-Key` |
| `POST /v1/payments/qr` | оплата C2B по QR | `Idempotency-Key` |
| `POST /v1/payments/{id}/refunds` | возврат по операции C2B | `Idempotency-Key` |
| `GET /v1/operations/{id}` | состояние операции | только чтение |
| `GET /v1/wallets/{id}/statement` | выписка по кошельку | только чтение |

## Состояния в ответе

Ответ отдаёт состояние операции как есть, включая неопределённое:
`CREATED`, `SENT`, `CONFIRMED`, `REJECTED`, `UNKNOWN`,
`RESOLVED_CONFIRMED`, `RESOLVED_REJECTED`. Состояние `UNKNOWN` канал обязан
показать как «в обработке, результат уточняется» и не имеет права трактовать
его как успех или отказ.

## Методы программируемых платежей

| Метод | Назначение | Идемпотентность |
|---|---|---|
| `POST /v1/conditions` | публикация версии условия | `Idempotency-Key` |
| `POST /v1/conditions/{id}/confirmations` | подтверждение версии стороной (2FA) | `Idempotency-Key` |
| `GET /v1/conditions/{id}` | состояние условия и действующая версия | только чтение |
| `POST /v1/conditions/{id}/disputes` | заявление о расхождении (перевод в спор) | `Idempotency-Key` |

Правило неизменности: опубликованная версия условия не редактируется. Попытка
изменения возвращает `409` со ссылкой на действующую версию — сторона обязана
опубликовать новую версию и подтвердить её заново.

## Чего контракт не обещает

- Мгновенной окончательности: окончательность даёт платформа ЦР, канал
  получает либо подтверждение, либо честное «в обработке».
- Доступности при недоступности платформы: в этом режиме изменяющие методы
  отвечают отказом недоступности (`503`), а чтение отдаёт несвежую проекцию с
  временем последней успешной сверки.
