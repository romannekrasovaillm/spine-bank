# Контракт: интеграция с АБС и учётным ядром

Назначение стыка — отражение операций цифрового рубля в учёте банка и
получение сведений, необходимых для идентификации клиента и связи
клиент ↔ кошелёк.

## Обмен

| Направление | Что передаётся | Режим |
|---|---|---|
| банк → АБС | факт операции: вид, сумма, состояние, время, идентификаторы | асинхронно, по журналу |
| банк → АБС | запрос сведений о клиенте для открытия кошелька | синхронно |
| АБС → банк | подтверждение отражения операции | асинхронно |

## Правила

- АБС **не** является источником истины о состоянии кошелька: учёт банка
  отражает операции, но остаток цифрового рубля живёт на платформе
  (`AD-001`). Расхождение учёта с платформой разрешается сверкой, а не
  правкой учёта.
- Передача в АБС идёт из журнала операций, а не из состояния оркестратора:
  источник учётных записей — неизменяемый журнал.
- Повторная доставка не создаёт вторую учётную запись: ключ — идентификатор
  операции.
- Канал защищён взаимной аутентификацией; обмен внутри периметра банка —
  по политике ИБ, без выхода в общие сети.
