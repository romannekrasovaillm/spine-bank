# Контракт: реестр условий платформы цифрового рубля

Внутренняя сторона стыка банка с реестром условий на стороне оператора
платформы. Внешний протокол платформы публично не раскрыт — `[ТРЕБУЕТ ПРОВЕРКИ]`;
здесь зафиксированы обязательства банка и граница допущения.

## Обязанности банка на стыке

| Обязанность | Требование |
|---|---|
| Единственная точка обмена | прямые вызовы реестра условий из компонентов, кроме движка условий, запрещены |
| Идемпотентность | идентификатор версии условия и идентификатор подтверждения — ключи операции; повтор не создаёт второй версии и второго подтверждения |
| Различение исходов | подтверждено / отклонено / не определено; частичное подтверждение — отдельное значение, не «успех» |
| Ограничение ожидания | таймаут 900 мс в бюджете `NFR-011`; таймаут переводит операцию в `UNKNOWN`, а не в отказ |
| Нормализация | ответ реестра переводится во внутреннюю модель состояния условия |
| Ключи | только через криптоконтур (`CMP-010`), взаимная аутентификация |

## Обмен (внутренняя сторона)

| Направление | Что передаётся | Режим |
|---|---|---|
| банк → реестр | публикация версии условия (стороны, доли, момент исполнения) | синхронно |
| банк → реестр | подтверждение стороны с 2FA-признаком | синхронно |
| реестр → банк | состояние версии и отметка о выполнении условия | синхронно |
| реестр → банк | выписка по исполненным условиям за период | пакетно, для сверки |

## Граница допущения

Пока состав методов и поведение реестра при частичном подтверждении не
подтверждены, движок условий проектируется изолированно: изменение протокола
не выходит за границы адаптера условий. Ни один компонент, кроме движка, не
знает имён полей и кодов отказов реестра.

## Открытые вопросы к оператору платформы

Поддержка частичного исполнения условия `[ТРЕБУЕТ ПРОВЕРКИ]`; глубина выписки
по условиям и её задержка `[ТРЕБУЕТ ПРОВЕРКИ]`; поведение при повторном
подтверждении стороны `[ТРЕБУЕТ ПРОВЕРКИ]`; классификация отказов реестра
`[ТРЕБУЕТ ПРОВЕРКИ]`.
