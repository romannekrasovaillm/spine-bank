# Контракт: информирование клиента

Стык с каналами уведомлений (пуш, SMS). Уведомление — следствие операции, а
не её часть: недоступность канала уведомлений не влияет на исполнение и не
меняет состояние операции.

## События

| Событие | Когда | Содержание |
|---|---|---|
| операция подтверждена | переход в `CONFIRMED` | сумма, получатель, время |
| операция отклонена | переход в `REJECTED` | причина в клиентской формулировке |
| исход уточняется | переход в `UNKNOWN` | «операция в обработке, сообщим о результате» |
| исход уточнён | переход в `RESOLVED_*` | результат после сверки |
| требуется подтверждение | решение `step_up` антифрода | запрос второго подтверждения |

## Правила

- Уведомления отправляются из журнала операций, а не из оркестратора: источник
  событий — неизменяемая запись, поэтому пропуск уведомления восстанавливается
  повторной обработкой журнала.
- Повторная доставка уведомления допустима, повторная операция — нет.
- В уведомлении нет полных реквизитов получателя и персональных данных сверх
  необходимого.
- Отсутствие доставленного уведомления не переводит операцию в другое
  состояние: расхождение между «клиент не знает» и «операция исполнена»
  разрешается выпиской, а не догадкой.
