# Разбор инцидента: массовые UNKNOWN при деградации платформы

Шаблон разбора, обязательный к заполнению после каждого инцидента класса
«массовые UNKNOWN». Заполняется владельцем разбора (OWNER-001), проверяется
архитектором изменения.

## Обязательные поля разбора

| Поле | Что указывается |
|---|---|
| Окно инцидента | начало и конец по времени журнала (не по времени обращения) |
| Владелец разбора | кто отвечает за выводы и сроки |
| Пик доли `UNKNOWN` | максимальная доля в окне 5 минут и время достижения порога остановки |
| Число операций в `UNKNOWN` | всего и сколько разрешено сверкой |
| Исполнения без подтверждения | должно быть **ноль**; любое иное значение останавливает разбор |
| Решение дежурного архитектора | остановка приёма: время, основание, кто принял |
| Возобновление | время, состояние очереди `UNKNOWN`, лаг сверки на момент решения |
| Расхождения после сверки | остались ли, кто владелец, срок закрытия |

## Порядок

1. Собрать окно по журналу операций (append-only) — не по логам приложения.
2. Посчитать долю `UNKNOWN` по минутам и найти время достижения порога.
3. Проверить, что ни одна операция по условию не исполнена без подтверждения
   платформы; при обнаружении — остановить разбор и эскалировать.
4. Сверить список операций `UNKNOWN` с выпиской платформы.
5. Зафиксировать выводы и изменения порогов/регламента, если они нужны.

## Что считается провалом разбора

- разбор по логам приложения без журнала операций;
- отсутствие решения дежурного архитектора с основанием;
- любой случай исполнения по условию без подтверждения платформы, оставленный
  без архитектурного решения.
