# Зарплатные и социальные выплаты в цифровых рублях (B2C/G2C)

Кейс собран **с нуля проводником** `arch-be bootstrap` и доведён до зелёного
на критическом маршруте. Его история — доказательство W3: каркас создаётся
одной командой, а дорожку до зелёного называет сам инструмент.

```bash
arch-be bootstrap "Зарплатные и социальные выплаты" --dir кейсы/salary-payments --domain выплат
arch-be bootstrap --status --dir кейсы/salary-payments   # спайн ✓ · правила ✓ · модель ✓ · бандл ✓
```

## Что это

Контур массовых выплат: приём реестра от работодателя (B2C) или оператора
социальных выплат (G2C), проверка получателя и лимитов окна, отправка
поручений в платформу цифрового рубля, построчная фиксация состояния, разбор
неопределённых исходов и сверка после окна.

| | |
|---|---|
| Маршрут | Critical (`.arch-handoff/ROUTE.lock`) |
| Модель | 43 сущности: SYS, CAP×3, REQ×5, NFR×5, CMP×6, INT×3, AD×7, ADR×5, RISK×4, QAS×3, OWNER |
| Правила | 15 (все `severity: error`) |
| Решения | 5 ADR с альтернативами и обратимостью, `docs/adr/` |
| Walking skeleton | `skeleton/payouts.py`, 9 тестов, `python3 -m pytest tests/ -q` |
| Бандл | 13 артефактов критического профиля, упакован `evidence pack` |

## Вердикт

```
$ arch-be gate --repo . --route critical
Итог: PASS
```

Одиннадцать составляющих, все PASS либо SKIP (по умолчанию выключена только
`decision_quality`). Паспорт вердикта — `arch-be gate --repo . --explain`.

## Измерение защищённости (`arch-be redteam`)

```bash
arch-be redteam . --no-decision-quality
```

**10 из 14 = 71 %** при пороге 78 % — кейс красный по этому измерению, и это
честный результат, а не дефект кейса:

- **D9 («картонный» ADR) не пойман** — требует включённой составляющей
  `decision_quality`, а она требует судью, отличного от автора. В этом
  окружении судья — та же модель, что писала документы; отчёт по ADR-001
  поэтому помечен `judge_is_author` (см. `reports/rubric/`).
- **D11 (код нарушает инвариант, правила на код нет) не пойман и не должен** —
  это работа ревьюера.
- Остальные 10 позиций пойманы: nfr (D1–D3), trace_check (D4), model_validate
  (D5, D12), rule_weakened (D7), fitness (D8, D11b), evidence_verify (D13, R).

Правило `C-015` (`no_card_data_in_tests`) добавлено именно после этого
измерения: без него D11b проходил мимо реестра.

## Решения и их качество

Пять ADR (ключ идемпотентности, очередь поручений, разбор по данным
платформы, построчная атомарность, сверка по снимку). Отчёт рубрики
`adr_quality` по ADR-001 получен через split-judge канал MCP:
`rubric_prompt` → ответы модели хоста → `rubric_verify --rw` → 4,80/5.
Отчёт честно помечен `judge_is_author`.

При включении составляющей (`[gate.required] critical += decision_quality`)
кейс краснеет: `rubric_report_missing` по четырём ADR — судья, отличный от
автора, в этом окружении недоступен.

## Чего зелёный не означает

Семантика выбора (ADR верен по существу, а не по форме), независимость
ревьюера и подлинность подписи A3 механикой не проверяются — они названы в
блоке 2 паспорта вердикта (`arch-be gate --explain`).
