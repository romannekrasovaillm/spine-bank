# Шаблон `unknown-outcome-no-resend`

Проверяемое свойство: **таймаут внешней системы оставляет операцию в
состоянии UNKNOWN, а не в SUCCESS и не в FAILED**; отправка во внешнюю
систему ровно одна — повторной отправки при неопределённом исходе нет;
после UNKNOWN разрешён только запрос статуса, и терминальный статус
закрывает операцию.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_unknown_outcome_no_resend.py` | свойства инварианта, читаются как спецификация |
| `fakes.py` | фейк внешней системы с раздельными счётчиками `sends` и `status_queries` |
| `reference_impl.py` | эталонная реализация: тесты зелёные из коробки |
| `java/` | та же проверка на JUnit 5 (`Subject.java` + `UnknownOutcomeNoResendTest.java`) |

Нарушающая реализация в кейс не кладётся: она остаётся в шаблоне и нужна
проверке зубов (`arch-be rules template verify --dir .`), которая подменяет
`reference_impl.py` нарушающей версией и убеждается, что тест **падает**.

## Как перенести проверку на настоящий код

1. **Оставить** фейк и тесты: свойство не зависит от того, кто его соблюдает.
2. **Заменить** `reference_impl.py` на импорт настоящей точки входа
   (`from app.payments import PaymentService`) — тогда тест проверяет ваш код.
3. **Переключить команду правила** в `CONSTRAINTS.yaml` со скелета на тест
   вашего кода (`python3 -m pytest -q tests/test_unknown_outcome_contract.py`).
   После этого проверка зубов помечается «адаптирован: проверьте вручную» —
   нарушающей реализации для вашего кода у харнесса нет.
4. **Оставить в реестре** `verified_by` у инварианта — правило остаётся
   звеном трассировки, но теперь оно проверяет поведение, а не текст.

## Чего шаблон не проверяет

- Что операция в состоянии UNKNOWN действительно доводится до терминального
  статуса сверкой — шаблон проверяет лишь то, что сверка закрывает исход,
  а не то, что она запускается по расписанию.
- Что запрос статуса идемпотентен на стороне внешней системы (это свойство
  протокола, а не фейка).
- Что при UNKNOWN не истекает срок резерва/блокировки — денежная сторона
  неопределённого исхода проверяется шаблоном `saga-reserve-compensation`.
