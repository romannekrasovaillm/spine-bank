# Критерии приёмки

Приёмка проводится на оконном сценарии: реестр на 500 000 строк, окно два
часа, платформа отвечает с задержкой и один раз отказывает.

## Критерии

1. **Приём.** Реестр принят целиком либо не принят вовсе; подтверждение приёма
   уложилось в p99 ≤ 2000 мс (NFR-001).
2. **Идемпотентность.** Повторная загрузка того же реестра не создаёт ни одной
   второй выплаты: число успешных строк не изменилось, число записей журнала не
   изменилось.
3. **Разбор.** Ни одна строка с неопределённым исходом не отправлена повторно;
   все такие строки разрешены данными платформы в течение одного рабочего дня.
4. **Частичный успех.** Отказ платформы по части строк не отменяет успешные:
   после окна успешные строки остались выплаченными, отклонённые перечислены
   поимённо.
5. **Полнота.** Число записей журнала по реестру равно числу строк реестра,
   включая строки в разборе (NFR-005).
6. **Сверка.** Отчёт сверки построен по снимку журнала, воспроизводим при
   повторном прогоне и перечисляет расхождения поимённо; расхождений нет либо
   каждое разобрано с указанием причины.
7. **Персональные данные.** В журнале и метках метрик нет персональных данных
   получателей: только идентификаторы реестра и строки, статусы и суммы.

## Что НЕ является критерием приёмки

- Отсутствие инцидентов: контур обязан разбирать расхождения, а не не иметь
  их.
- Скорость выплат сверх окна: окно задано регламентом, а не контуром.
