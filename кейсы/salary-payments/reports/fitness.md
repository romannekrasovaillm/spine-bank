# Прогон fitness-функций

Реестр правил: `CONSTRAINTS.yaml` (14 правил, все `severity: error`).
Команда: `arch-be control check .` (то же, что MCP `fitness_check`).

```
Правил: 14, нарушений: 0 (error: 0, warn: 0)
Итог: PASS
```

## Что именно проверяется

| Правило | Тип | Что держит |
|---|---|---|
| C-001 spine_present | file_exists | спайн есть и линтер его читает |
| C-002…C-007 | must_contain / must_not_contain | код скелета: ключ идемпотентности, отсутствие ПДн, сверка, append-only журнал, проверка лимитов, частичный успех |
| C-008 spine_binds | must_contain | инварианты не остались заголовками |
| C-009 adr_alternatives | each_file_must_contain | у каждого ADR есть раздел альтернатив |
| C-010…C-014 | file_exists | спецификация, регламент сверки, отчёт скелета, запись решения |

## Честная граница

Правила C-002…C-008 судят по **тексту файла**: они доказывают, что нужное слово
написано, а не что система так делает. Поведение проверяет walking skeleton,
а соответствие смысла — состязательное ревью. Доля правил на упоминание
печатается `arch-be control rules-report` и называется в паспорте вердикта.
