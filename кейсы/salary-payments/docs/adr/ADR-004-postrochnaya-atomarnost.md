# ADR-004. Построчная атомарность вместо отката реестра целиком

- **Статус**: Accepted
- **Дата**: 2026-09-19

## Context

Реестр падает на середине: платформа отклонила 300 строк из 500 тысяч.
Транзакционная семантика «реестр целиком» означала бы откат уже успешных
выплат, то есть возврат денег с личных счетов получателей.

## Decision

Атомарность **построчная**: успешная строка фиксируется журналом и больше не
повторяется; неуспешная уходит в разбор. Реестр как целое не имеет состояния
успеха или неудачи — состояние есть у строки.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Реестр целиком: упал — откатываем | привычная транзакционная модель | откат выплаченных строк невозможен без возврата денег получателям |
| Б. Построчная атомарность — **выбран** | успешные выплаты не теряются; переотправка безопасна | состояние реестра перестаёт быть одним флагом: нужен отчёт по строкам |
| В. Пакетами по 1000 строк | компромисс по объёму | откат пакета всё равно задевает уже выплаченные строки |
| Г. Продолжение с места падения без фиксации | быстро | журнал не знает, какие строки применены — сверка невозможна |

## Consequences

- Положительные: падение окна не приводит к возвратам; переотправка реестра
  безопасна благодаря ADR-001.
- Отрицательные: отчётность по реестру становится построчной; источник не
  получает простого «реестр принят/не принят» после начала выплат.
- **Обратимость**: низкая. Отказ от построчной фиксации требует пересборки
  журнала и согласования с источниками реестров. Цена пересмотра — отдельный
  проект, поэтому решение фиксируется ADR, а не настройкой.
