# ADR-001. Ключ идемпотентности — пара (реестр, строка)

- **Статус**: Accepted
- **Дата**: 2026-09-19
- **Контекст**: зарплатные и социальные выплаты в цифровых рублях, B2C/G2C

## Context

Реестр может быть доставлен повторно: работодатель перезаливает файл после
таймаута, оператор социальных выплат повторяет отправку при сбое канала.
Платформа цифрового рубля принимает поручения идемпотентно по ключу, который
мы обязаны сформировать сами. Ключ реестра целиком (идентификатор файла)
недостаточен: источники переиспользуют идентификатор при исправлении одной
строки, и тогда исправление выглядело бы как повтор.

## Decision

Ключ идемпотентности — пара **(идентификатор реестра, номер строки)**.
Дедупликация выполняется в одной транзакции с фиксацией эффекта: строка либо
применяется и записывается в журнал, либо распознаётся как уже применённая.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Ключ по реестру целиком (выбран и отклонён) | простой, один ключ на файл | исправление одной строки выглядит как повтор всего реестра |
| Б. Ключ по паре (реестр, строка) — **выбран** | точен при исправлениях, совпадает с построчной атомарностью (ADR-004) | ключ длиннее, нужен номер строки в реестре источника |
| В. Ключ по хэшу содержимого строки | не зависит от нумерации источника | изменение суммы при том же получателе создаёт новую выплату — неверно |
| Г. Без ключа, дедупликация по факту в журнале | нет поля в протоколе | гонка двух отправок одной строки приводит к двойной выплате |

## Consequences

- Положительные: повторная доставка реестра безопасна; исправление строки не
  дублирует выплаты по остальным строкам.
- Отрицательные: источник обязан нумеровать строки стабильно; нарушение
  нумерации на стороне источника даёт новую выплату.
- **Обратимость**: полная. Ключ можно сузить или расширить; уже применённые
  ключи остаются в журнале, история не теряется. Цена отката — согласование
  формата реестра с источником, без миграции данных.
