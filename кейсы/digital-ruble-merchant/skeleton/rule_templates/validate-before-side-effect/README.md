# Шаблон `validate-before-side-effect`

Проверяемое свойство: **провал проверки не оставляет за собой исполненного
действия** — при получателе из стоп-листа или сумме сверх лимита обращений
к внешней системе ноль и лимит не израсходован; при успешной проверке —
ровно одно обращение и списание ровно на сумму перевода.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_validate_before_side_effect.py` | свойства инварианта, читаются как спецификация |
| `fakes.py` | фейки внешней системы (счётчик обращений и применённые переводы), стоп-листа и лимита |
| `reference_impl.py` | эталонная реализация: тесты зелёные из коробки |
| `java/` | та же проверка на JUnit 5 (`Subject.java` + `ValidateBeforeSideEffectTest.java`) |

Нарушающая реализация в кейс не кладётся: она остаётся в шаблоне и нужна
проверке зубов (`arch-be rules template verify --dir .`), которая подменяет
`reference_impl.py` нарушающей версией и убеждается, что тест **падает**.
Засеянное нарушение ровно одно: перевод уходит во внешнюю систему **до**
проверки стоп-листа и лимита, поэтому провал проверки оставляет за собой
исполненное обращение.

## Как перенести проверку на настоящий код

1. **Оставить** фейки и тесты: свойство не зависит от того, кто его соблюдает.
2. **Заменить** `reference_impl.py` на импорт настоящей точки входа
   (`from app.payments import PaymentService`) — тогда тест проверяет ваш код.
3. **Переключить команду правила** в `CONSTRAINTS.yaml` со скелета на тест
   вашего кода (`python3 -m pytest -q tests/test_transfer_contract.py`).
   После этого проверка зубов помечается «адаптирован: проверьте вручную» —
   нарушающей реализации для вашего кода у харнесса нет.
4. **Оставить в реестре** `verified_by` у инварианта — правило остаётся
   звеном трассировки, но теперь оно проверяет поведение, а не текст.

## Чего шаблон не проверяет

- Что проверки действительно полны: фейк знает только стоп-лист и лимит,
  остальные предусловия вашей точки входа (KYC, статус счёта) вне шаблона.
- Что обращение к внешней системе идемпотентно при повторе после отказа
  сети — шаблон однопоточный и сети не касается.
- Что отказ возвращает вызывающему различимый код ошибки: шаблон проверяет
  только факт исключения, а не его тип в вашей иерархии.
