# ARCHITECTURE-SPINE — приём оплаты цифровым рублём для ТСП

Инварианты, действующие на все компоненты контура приёма. Нарушение любого — не «долг», а дефект выпуска.

## AD-1. Каждая операция приёма идемпотентна по ключу поручения

- **Binds**: Приём платежей ТСП, Оркестратор операций
- **Prevents**: двойное зачисление при повторной доставке уведомления от ПЦР
- **Rule**: ключ идемпотентности обязателен на каждой точке входа; дедупликация выполняется в одной транзакции с эффектом

## AD-2. Журнал операций append-only

- **Binds**: Журнал операций, Сверка с платформой ЦР
- **Prevents**: потерю следа операции и подмену истории при разборе расхождения
- **Rule**: журнал только дополняется; корректировка — компенсирующей записью со ссылкой на исходную

## AD-3. Неопределённый исход разрешается по данным платформы

- **Binds**: Оркестратор операций, Сверка с платформой ЦР
- **Prevents**: повторное списание при таймауте ответа платформы
- **Rule**: при неопределённом исходе операция переводится в состояние разбора и не повторяется до сверки

## AD-4. Персональные данные не попадают в журнал и телеметрию

- **Binds**: Журнал операций, Телеметрия
- **Prevents**: утечку ПДн через журналы приложения и метрики
- **Rule**: в журнал и метки метрик пишутся только идентификаторы и суммы; PAN и реквизиты не пишутся нигде

## AD-5. Одна операция — одна неизменяемая запись в журнале

- **Binds**: Журнал операций
- **Prevents**: расхождение между состоянием операции и историей её переходов
- **Rule**: переход состояния фиксируется ровно одной записью; повторный переход с тем же ключом игнорируется

## AD-6. Лимиты проверяются до списания

- **Binds**: Сервис лимитов, Оркестратор операций
- **Prevents**: списание сверх лимита при гонке параллельных операций клиента
- **Rule**: проверка и резервирование лимита выполняются атомарно до обращения к платформе

## AD-7. Интеграция с ПЦР — только через адаптер

- **Binds**: Адаптер платформы ЦР
- **Prevents**: расползание деталей протокола платформы по домену
- **Rule**: обращения к платформе идут только через адаптер; домен работает с его контрактом

## AD-8. Деградация не блокирует приём

- **Binds**: Оркестратор операций, Антифрод
- **Prevents**: полную остановку приёма при недоступности необязательного участника
- **Rule**: недоступность антифрода не блокирует приём: операция помечается для отложенной проверки

## AD-9. Сверка с платформой обязательна и воспроизводима

- **Binds**: Сверка с платформой ЦР
- **Prevents**: накопление необнаруженных расхождений
- **Rule**: сверка прогоняется по расписанию и по требованию; результат неизменяем и хранится рядом с журналом
