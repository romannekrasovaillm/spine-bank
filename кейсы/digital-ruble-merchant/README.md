# Кейс: приём оплаты цифровым рублём для ТСП

Маршрут **Critical**. Контур приёма платежей торгово-сервисных предприятий в
цифровом рубле: поручение ТСП, проверка лимитов, обращение к платформе
цифрового рубля, журнал операций, разбор неопределённых исходов, сверка.

Кейс — **red-team стенд**: на нём прогоняется `arch-be redteam`, который
засеивает по одному дефекту из каталога раздела 7 ТЗ 0.3.4 и печатает карту
обнаружения. Поэтому в кейсе намеренно есть и то, что механика обязана ловить
(правило `no_pan_in_tests` на `tests/**/*.py`), и то, что она ловить не должна
(семантические ссылки и смысл решений).

Состав: ARCHITECTURE-SPINE.md (9 инвариантов), CONSTRAINTS.yaml (13 правил),
model/ (сущности CAP, SYS, CMP, INT, NFR, REQ, AD, ADR, RISK, OWNER, QAS),
docs/adr/ (7 ADR), docs/spec/, docs/contracts/, tests/, evidence-бандл,
активная дельта `changes/merchant-tsp`.
