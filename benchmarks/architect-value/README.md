# architect-value — бенчмарк ценности архитектурного контроля Spine

Ответ на вопрос «что даёт архитектору 0.4.0 над 0.3.17». Бенчмарк измеряет восемь
вещей, которыми пользуется solution-архитектор, на четырёх чужих репозиториях
приложений (repo B), а не на самом Spine.

Механизмы волн R (recover), S (standards), K (контур) и D (arch-diff) на момент
закладки бенчмарка **не реализованы** — на 0.3.17 работают только предпосылки
(`survey`, `control check`, `arch-diff`, MCP). Поэтому `run_all.sh` гоняет то,
что живёт, и **явно печатает SKIP** для механик, которых ещё нет: «ложной
зелени» в отчёте не бывает. Пороги зафиксированы в `PREREGISTRATION.md` ДО
первого прогона новой механики и после результатов не меняются; отступления —
в `DEVIATIONS.md`.

## Состав

| Каталог | Что внутри | Смысл |
|---------|-----------|-------|
| `PREREGISTRATION.md` | протокол, дизайн, пороги, гипотезы | заморожен до прогона |
| `prereg_hashes.txt` | sha256 всех входов `ground_truth/ standard/ seeds/ labels/` | пломба заморозки |
| `repos.lock` | URL + SHA + локальный зеркало-клон 4 репо | неизменяемость входа |
| `ground_truth/<repo>.yaml` | эталон приложения B: компоненты, рёбра (`via`), хранилища, внешние системы | против чего меряем recall/precision |
| `standard/` | стандарт «Java-services» (12 требований S1–S12) + карта выразимости | что механизует control check |
| `seeds/` | C.2 (12 нарушений buckpal) + C.3 (6 обходов ArchUnit) | детекция засеянных дефектов |
| `labels/` | разметка значимых диффов B.3 (PetClinic, Boutique) + окна-шум | против чего меряем arch-diff-replay |
| `runners/` | только stdlib-Python: переиспользуемые прогонщики | воспроизводимость |
| `results/` | прогоны (коммитятся) | журнал «до → после» |
| `run_all.sh` | прогон всех сьютов на пиннутых SHA | одна команда |

## Сьюты и метрики

- **ArchRecover** (волна R) — метрики 2–6, 18, 19: восстановление компонентов,
  межсервисных рёбер, хранилищ, внешних систем; детерминизм и время recovery.
  На 0.3.17 нет `arch-be recover` → SKIP. Жива лишь предпосылка — метрика 1
  (`survey .` ≡ `survey <abs>`).
- **StdComply** (волна S) — метрики 7–10: выразимость стандарта, детекция
  семян C.2/C.3, отсутствие ложных FAIL от неприменимых корп-правил, форматы
  манифестов тех-радара. На 0.3.17 живы `control check` (семена C.2, корп-стандарт
  на клонах); C.3 (ArchUnit) — SKIP без JDK/jar.
- **Kontur** (волна K) — метрики 11, 12: доля обнаруживаемых мутантов на реальном
  коде и FP. На 0.3.17 мутаторы `--repo` не реализованы → SKIP; жива метрика 15
  (MCP schema↔impl).
- **arch-diff-replay** (волна D) — метрика 13: recall значимых диффов, precision
  состава, шум на окнах «нет изменений». На 0.3.17 жив сырой `arch-diff` (A.4),
  прогоняется через `runners/replay.py`.

## Как запускать

```bash
# всё (клоны берутся из --repos-dir, по умолчанию ~/bench-repos)
benchmarks/architect-value/run_all.sh

# отдельный сьют
benchmarks/architect-value/run_all.sh ArchRecover

# другой бинарь / каталог клонов / куда писать результаты
ARCH_BE=/path/to/arch-be benchmarks/architect-value/run_all.sh --repos-dir /mnt/clones
ARCH_VALUE_OUT=/tmp/out benchmarks/architect-value/run_all.sh
```

Прогонщики — только stdlib (никаких PyYAML/requests). Прогон без сети: сетевые
шаги (`archunit fetch`) выходят в SKIP, а не в «зелень».

## Контракт с задачей

Дизайн, пороги и правила — из `TASK-Spine-0.4.0-architect-value.md` §9–10 и
приложений A–C. Расхождения со спекой — в `DEVIATIONS.md` и в поле
`conflicts_with_prior_decisions` итогового ответа.
