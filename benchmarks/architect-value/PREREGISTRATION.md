## 3. Гипотезы

- **H1 (recover):** после волны R `arch-be recover` на деterминированном коде
  достигает порогов 2–5 и заменяет «1 компонент, 0 рёбер» из 0.3.17.
- **H2 (standards):** механизация стандарта (S1–S12) поднимает детекцию семян
  C.2 до ≥ 11/12 любой нотацией без роста ложных FAIL (метрика 9).
- **H3 (arch-diff):** разметка B.3 отделяет значимые диффы от окон-шума,
  давая recall ≥ 0.80 при шуме ≤ 10 %.

Гипотезы проверяются на пиннутых SHA; вердикт — по таблице §2, не по словам.

## 4. Как считается каждая метрика

- **Компоненты (2)** — precision/recall/F1 множеств имён компонентов против
  `ground_truth/*.yaml:components`, агрегация F1 по репо.
- **Рёбра (3)** — множества `(from,to)` с непустым пересечением `via`
  (`env`/`route`/`stub`/`topic`): recall = |совпало|/|эталон|,
  precision = |совпало|/|найдено|.
- **Хранилища (4)** и **внешние системы (5)** — множества имён против
  `stores`/`external`; precision для внешних (важен шум).
- **Шум (6)** — доля строк карты обследования без доказательства
  (`[confirmed]`/`[gap]`) от общего числа строк.
- **Выразимость (7)** — число требований S1–S12, для которых в стандарте есть
  исполняемая проверка (`type` ≠ `unverifiable`); карта в
  `standard/requirements.yaml:expressible`.
- **Семена C.2/C.3 (8, C.3)** — `runners/seed_buckpal.py`: копия чистого
  buckpal → одна правка → `control check --json` → поймано ли правилом-владельцем.
- **Корп-правила (9)** — `control check` корп-стандарта на PetClinic: правила с
  `glob`, не нашедшие ни одного файла, обязаны стать N/A, а не error.
- **Манифесты радара (10)** — правило `deny_dependency` должно видеть
  build.gradle, package.json, \*.csproj, pyproject.toml, а не только pom.xml/
  Cargo.toml/requirements.txt/go.mod.
- **Kontur-bench (11, 12)** — `runners/…` вызывает `arch-be redteam --repo`
  (после волны K); на 0.3.17 — SKIP.
- **arch-diff-replay (13)** — `runners/replay.py`: N первых родительских
  коммитов → `arch-diff --base <h>~1 --head <h> --format json`; значимость по
  `labels/arch-diff-replay.yaml`.
- **MCP schema↔impl (15)** — `runners/mcp_schema_probe.py`: `tools/list` →
  `tools/call` со schema-валидными аргументами; ловим «нужен параметр X», где X
  не объявлен в schema.
- **Детерминизм (18)** — повторный прогон даёт byte-for-byte тот же JSON.
- **Время (19)** — wall-clock `recover` на репо ≤ 5 тыс. файлов.

Метрики 14, 16, 17, 20 — вне Python-прогонщиков: `selftest` (в CI), наличие
MCP-инструментов (контракт-тест), golden judge и квалификация судьи (рубрики);
фиксируются как SKIP с указанием, где измеряются.

## 5. Правило остановки

Прогон сьюта завершён, когда по каждому его шагу есть RUN (с числами) или SKIP
(с причиной «волна X не реализована» / «клон отсутствует» / «нет прогонщика»).
SKIP не считается зелёным. Результаты пишутся в `results/<версия>-<дата>/` и
коммитятся; после коммита пороги §2 не редактируются — расхождение оформляется
записью в `DEVIATIONS.md`.
