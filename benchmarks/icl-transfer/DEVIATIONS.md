Пул, семена, holdout и пороги (`PREREGISTRATION.md`, `prereg_hashes.txt`,
`prereg/*`) НЕ изменены. Записи ниже — только про реализацию режима `--ci`

детерминированно, без живой LLM и без сети.

## 2026-10-15 — реализация `--ci`

1. **Гейт `--ci` — regex/строки, не AST.** `seed/gate/accept.py` разбирает
   Python через `ast`; обобщённый гейт `runners/iclbench.py` проверяет
   конвенции регулярными выражениями/проверкой файлов. Причина: гейт в `--ci`
   проверяет код, сгенерированный fake-исполнителем (детерминированные
   сниппеты), где AST-точность не меняет вердикт; живой прогон (`--live`,
   волна 3) остаётся на `accept.py`-семантике.
2. **`--ci` не гоняет pytest.** Видимое правило G7 проверяется наличием
   `tests/test_<module>.py`, сам pytest не запускается (детерминизм и скорость
   `< 2 мин` в `cargo test`). Живой гейт запускает pytest, как в стенде.
3. **Руки `--ci` — детерминированная симуляция.** `FakeLlm` (оркестратор с
   фиксированной политикой) + fake-исполнитель вместо реального `arch-be run`
   и `claude-code`. Рука `X` моделирует второго исполнителя параметром
   fake-исполнителя, `FLEET` — последовательной имитацией сдвига старта,
   `PROMO` — двумя фазами (обучение через гейт, затем pre-commit).
4. **CI-тест гоняет первый семя каждой руки** (`prereg/seeds.txt`), а не все
   n=6: цель `--ci` — детерминированная проверка механики, а не статистика
   (n≥6 — для `--live`).
5. **Анти-Goodhart греп** покрывает `src/` и `assets/` (как в TASK §9);
   `tests/icl_transfer_ci.rs` не упоминает конкретные конвенции пула.
