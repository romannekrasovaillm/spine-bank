# icl-transfer — бенчмарк обучающего контура (spine-bank 0.5.0)

Отвечает на вопрос: «обучение в контексте» стало **свойством архитектуры**,
а не удачей сессии? Пререгистрированный бенчмарк, в котором оркестратор
(Spine) сравнивается с сильнейшим кодовым агентом, а уроки переживают сессию,
модель и исполнителя.

Источник истины — `TASK-Spine-0.5.0-learning-loop.md` §6 и
`PREREGISTRATION.md` (заморожено до первого прогона). Исходный стенд живых
прогонов 0.4.10 — в `seed/` (из `icl-lab.tar.gz`, приложение A задачи).

## Состав

| Каталог/файл | Что внутри | Смысл |
|---|---|---|
| `PREREGISTRATION.md` | протокол, пул, семена, пороги, гипотезы | заморожен (хэши `prereg_hashes.txt`) |
| `prereg/pool.yaml` | 14 параметризованных скрытых конвенций (`id`, `subject_kind`, `params`, `marker`) | источник гейта и анти-Goodhart грепа |
| `prereg/holdout.txt` | 4 отложенные конвенции (только id) | читается ТОЛЬКО механизмом исключения |
| `prereg/seeds.txt` | по 6 семян на руку | фиксированы |
| `seed/` | оригинальный стенд icl-lab (run_arm.py, gate/accept.py, tasks.json, template/paylib, shim.py) | «до» — база 0.4.10 |
| `runners/iclbench.py` | генератор пула, обобщённый гейт, FakeLlm + fake-harness, руки, метрики | stdlib-only, детерминированно |
| `run_all.sh` | `--ci` (и `--live` → SKIP) | одна команда прогона |
| `results/` | сводки прогонов (детерминированные) | журнал «до → после» |

## Режим `--ci` (в объёме BENCH-1)

Детерминированная проверка **механики** обучающего контура без сети и без
живой LLM: FakeLlm (оркестратор с детерминированной политикой) + fake-harness
(исполнитель, генерирующий код по задачам). Входит в `cargo test`
(`tests/icl_transfer_ci.rs`).

Руки:

| Рука | Что меряет | Конфигурация |
|---|---|---|
| FI+L | E1: реестр уроков включён | свежая сессия, чистое репо, две серии |
| FI | контроль без памяти | реестр выключен |
| X | E2: перенос на второго исполнителя | две серии, реестр общий |
| GEN | E3: отложенное семейство «миграция» | обучение на модуль+CLI, проверка на миграции |
| PAIR | E4: две конвенции одного subject_kind | композиция |
| PROMO | E5: промоушен в pre-commit (L7) | 10 задач, фазы A/B |
| FLEET | E6: 5 задач со сдвигом | урок виден поздно стартовавшим |

Запуск:

```bash
# одна рука
python3 benchmarks/icl-transfer/runners/iclbench.py --ci-arm FI+L

# все руки + сводка
bash benchmarks/icl-transfer/run_all.sh --ci

# выбор конвенций по семени (детерминирован)
python3 benchmarks/icl-transfer/runners/iclbench.py --gen 141

# анти-Goodhart греп отдельно
python3 benchmarks/icl-transfer/runners/iclbench.py --check-antigoodhart
```

## Генератор пула

Из `prereg/pool.yaml` по семени выбираются 2–3 НЕ-holdout конвенции
(`n = 2 + seed % 2`), детерминированно (sha256 по `seed:id`, без `random`) —
результат не зависит от версии Python. `holdout.txt` читается только как
множество id для исключения; конкретный состав закрыт хэшем. Конвенция
применяется к задаче, только если `subject_kind` конвенции входит в
`subject_kinds` задачи (модуль/CLI → `new_module` + `new_public_symbol`;
миграция → `new_module`).

## Обобщённый гейт

`runners/iclbench.py` — обобщение `seed/gate/accept.py`: видимые правила
(Owner-докстринг, Decimal без float, округление только `round_money`,
регистрация в `registry.py`, наличие теста) + выбранные конвенции пула как
скрытые правила. Гейт пишет коды нарушений `G1..G7` и `HC-*`; FAIL с кодом
конвенции — источник урока.

## Анти-Goodhart

Маркерные строки пула (`marker:`) запрещены в `src/` и `assets/` (TASK §9).
Греп `--check-antigoodhart` проходится по `src/ assets/` и падает, если маркер
найден или пул пуст (греп не вакуумен). Входит в CI бенчмарка.

## Режим `--live`

Вне объёма BENCH-1 (волна 3). `run_all.sh --live` печатает честный SKIP с
причиной; нативный прогон с ключами `[models]` или шимом `seed/shim.py`
реализуется после L8–L10. В отчёте `--live` пишется результат `--live`, а не
`--ci` (TASK §7, риск 7).
