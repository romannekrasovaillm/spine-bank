# Шаблон `saga-reserve-compensation`

Проверяемое свойство: **резерв под операцию не остаётся подвешенным ни при
одном исходе** — отказ внешней системы снимает резерв и не даёт списания,
неопределённый исход резерв удерживает (не снят и не превращён в списание),
успех превращает резерв в списание ровно один раз.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_saga_reserve_compensation.py` | свойства инварианта, читаются как спецификация |
| `fakes.py` | фейки внешней системы и лимитного резерва со счётчиками удержаний, снятий и списаний |
| `reference_impl.py` | эталонная реализация: тесты зелёные из коробки |
| `java/` | та же проверка на JUnit 5 (`Subject.java` + `SagaReserveCompensationTest.java`) |

Нарушающая реализация в кейс не кладётся: она остаётся в шаблоне и нужна
проверке зубов (`arch-be rules template verify --dir .`), которая подменяет
`reference_impl.py` нарушающей версией и убеждается, что тест **падает**.

## Как перенести проверку на настоящий код

1. **Оставить** фейки и тесты: свойство не зависит от того, кто его соблюдает.
2. **Заменить** `reference_impl.py` на импорт настоящей саги
   (`from app.payments import PaymentSaga`) — тогда тест проверяет ваш код.
3. **Переключить команду правила** в `CONSTRAINTS.yaml` со скелета на тест
   вашего кода (`python3 -m pytest -q tests/test_saga_reserve_contract.py`).
   После этого проверка зубов помечается «адаптирован: проверьте вручную» —
   нарушающей реализации для вашего кода у харнесса нет.
4. **Оставить в реестре** `verified_by` у инварианта — правило остаётся
   звеном трассировки, но теперь оно проверяет поведение, а не текст.

## Чего шаблон не проверяет

- Что резерв удерживается атомарно относительно лимита — шаблон однопоточный,
  конкурентные операции в нём не разыгрываются.
- Что неопределённый исход доводится до конца сверкой (для этого рядом лежит
  шаблон `unknown-outcome-no-resend`).
- Что снятие резерва и списание идемпотентны при повторе команды саги —
  шаблон проверяет один прогон на операцию.
