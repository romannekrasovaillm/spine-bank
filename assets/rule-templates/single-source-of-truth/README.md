# Шаблон `single-source-of-truth`

Проверяемое свойство: **локальная проекция не «додумывает» состояние** —
показанное значение равно последнему ответу источника истины, у значения есть
версия, а устаревший (задержавшийся) ответ помечается устаревшим, а не
выдаётся молча за текущий.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_single_source_of_truth.py` | свойства инварианта, читаются как спецификация |
| `fakes.py` | фейк источника истины с версией, историей и управляемой задержкой ответа |
| `reference_impl.py` | эталонная реализация: тесты зелёные из коробки |
| `java/` | та же проверка на JUnit 5 (`Subject.java` + `SingleSourceOfTruthTest.java`) |

Нарушающая реализация в кейс не кладётся: она остаётся в шаблоне и нужна
проверке зубов (`arch-be rules template verify --dir .`), которая подменяет
`reference_impl.py` нарушающей версией и убеждается, что тест **падает**.

## Как перенести проверку на настоящий код

1. **Оставить** фейк и тесты: свойство не зависит от того, кто его соблюдает.
2. **Заменить** `reference_impl.py` на импорт настоящей проекции
   (`from app.read_model import Projection`) — тогда тест проверяет ваш код.
3. **Переключить команду правила** в `CONSTRAINTS.yaml` со скелета на тест
   вашего кода (`python3 -m pytest -q tests/test_read_model_contract.py`).
   После этого проверка зубов помечается «адаптирован: проверьте вручную» —
   нарушающей реализации для вашего кода у харнесса нет.
4. **Оставить в реестре** `verified_by` у инварианта — правило остаётся
   звеном трассировки, но теперь оно проверяет поведение, а не текст.

## Чего шаблон не проверяет

- Что источник истины действительно один: шаблон проверяет поведение
  проекции, а не топологию хранилищ (это свойство вашей модели данных).
- Что запись в источник и обновление проекции атомарны — шаблон однопоточный,
  а задержка имитируется тиками, а не реальным временем.
