# Шаблон `generic-property-test` (заготовка)

Проверяемое свойство: **не сформулировано** — это заготовка. Тест пропускается
(`skip`, exit code 0), пока автор не опишет свойство и не заменит заглушку.
Шаблон помечен `executable: false`: у него нет ни эталонной, ни нарушающей
реализации, поэтому проверка зубов к нему неприменима.

Заготовка нужна, когда инвариант уже признан важным, но ещё не выражен
исполняемой формой: она даёт готовое место в скелете, куда его положить.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_invariant.py` | заглушка свойства: пропускается, пока свойство не сформулировано |
| `fakes.py` | каркас фейка со счётчиком эффектов |

## Как превратить заготовку в правило

1. **Сформулировать свойство** одной фразой в docstring теста — так, чтобы оно
   читалось как спецификация, а не как описание кода.
2. **Построить фейк** в `fakes.py`: счётчик должен считать ровно то, что
   свойство запрещает или требует (обращения к внешней системе, созданные
   действия, списанный лимит).
3. **Заменить заглушку** проверками с русскими assert-сообщениями, называющими
   нарушенное свойство; `pytest.skip(...)` при этом убирается.
4. **Добавить нарушающую реализацию** и убедиться, что тест на ней падает:
   правило, которое никогда не краснеет, не проверяет ничего. После этого
   шаблон перестаёт быть заготовкой — с него можно снять `executable: false`
   и заполнить `match.ru`/`match.en` ключевыми словами.
5. **Включить правило** в `CONSTRAINTS.yaml` и оставить `verified_by`
   у инварианта — правило станет звеном трассировки.

## Чего шаблон не проверяет

- Ничего: заглушка по построению не проверяет ни одного свойства.
- Что выбранное свойство вообще выразимо тестом — это решение автора,
  заготовка лишь напоминает о шагах.
