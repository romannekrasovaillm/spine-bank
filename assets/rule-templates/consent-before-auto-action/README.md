# Шаблон `consent-before-auto-action`

Проверяемое свойство: **автодействие по событию клиента выполняется только
при действующей записи о согласии** — без записи действие не создаётся,
отзыв согласия останавливает следующее срабатывание, незавершённая операция
клиента блокирует старт нового автодействия.

## Что положил `arch-be rules template apply`

| Файл | Роль |
|---|---|
| `test_consent_before_auto_action.py` | свойства инварианта, читаются как спецификация |
| `fakes.py` | фейки реестра согласий, незавершённых операций и счётчика автодействий |
| `reference_impl.py` | эталонная реализация: тесты зелёные из коробки |
| `java/` | та же проверка на JUnit 5 (`Subject.java` + `ConsentBeforeAutoActionTest.java`) |

Нарушающая реализация в кейс не кладётся: она остаётся в шаблоне и нужна
проверке зубов (`arch-be rules template verify --dir .`), которая подменяет
`reference_impl.py` нарушающей версией и убеждается, что тест **падает**.

## Что именно засеяно в нарушающей реализации

Одно нарушение: автодействие создаётся **без обращения к реестру согласий**
(проверка незавершённой операции при этом сохранена). Падают свойства
«без записи о согласии автодействие не создаётся» и «отзыв согласия
останавливает следующее срабатывание».

## Как перенести проверку на настоящий код

1. **Оставить** фейки и тесты: свойство не зависит от того, кто его соблюдает.
2. **Заменить** `reference_impl.py` на импорт настоящего сервиса автодействий
   (`from app.autopayments import AutoActionService`) — тогда тест проверяет
   ваш код, а реестр согласий и счётчик остаются фейками.
3. **Переключить команду правила** в `CONSTRAINTS.yaml` со скелета на тест
   вашего кода (`python3 -m pytest -q tests/test_consent_gate.py`).
   После этого проверка зубов помечается «адаптирован: проверьте вручную» —
   нарушающей реализации для вашего кода у харнесса нет.
4. **Оставить в реестре** `verified_by` у инварианта — правило остаётся
   звеном трассировки, но теперь оно проверяет поведение, а не текст.

## Чего шаблон не проверяет

- Что согласие действительно получено от клиента: реестр — фейк, запись
  в него кладёт тест. Достоверность источника согласия — свойство вашего
  процесса, а не шаблона.
- Что объём согласия (`scope`) соответствует операции: тест подаёт один
  объём, разграничение объёмов — свойство вашей модели данных.
- Что блокировка по незавершённой операции атомарна при конкурентных
  событиях — шаблон однопоточный.
