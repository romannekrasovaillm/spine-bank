# Меры защиты: угроза → контрмеры

| Угроза | Контрмеры |
|---|---|
| Indirect prompt injection | изоляция недоверенного контента (чёткая разметка «данные, не инструкции»); не давать привилегированные инструменты агенту, читающему внешнее; детерминированная проверка/подтверждение перед действиями; классификатор инъекций на входе; ограничение того, что можно сделать по данным из внешнего источника |
| Excessive agency | минимальный набор инструментов и прав; узкие scope токенов; подтверждение необратимых действий; лимиты (суммы, объёмы, частота) на стороне инструмента, а не в промпте |
| Утечка данных | egress-allowlist и подтверждение сетевых действий; разделение агентов (доступ к данным XOR доступ к сети); запрет данных в URL; маскирование в логах; DLP на каналах |
| Confused deputy | явная проверка полномочий на стороне инструмента для КАЖДОГО действия (не доверять тому, что «агент решил»); отдельные идентичности агента и пользователя |
| Небезопасный вывод | не исполнять вывод модели напрямую; параметризованные запросы, валидация схемой, песочница для кода |
| Tool/description poisoning | ревью описаний MCP-инструментов; доверенные издатели; закрепление версий; аудит (`agent-config-audit`) |
| Rug pull / supply chain | закреплённые версии и хэши, собственное зеркало, мониторинг изменений, изоляция серверов |
| Отравление памяти | валидация и ограничение того, что попадает в долговременную память; не хранить инструкции из недоверенных источников; отдельная память на пользователя/сессию |
| Отравление RAG | контроль источников индексации, права доступа к документам, проверка контента |
| Перерасход/DoS | лимиты шагов, бюджета токенов и частоты вызовов; таймауты; обнаружение зацикливаний (набор agent-eval) |
| Мультиагентные | относиться к выводу суб-агента как к недоверенному; не повышать права при делегировании; изоляция контекстов |

## Архитектурные паттерны
- **Планирование до данных**: план действий строится из доверенной задачи ДО
  чтения недоверенного контента; недоверенные данные не меняют план/права
  (подход в духе «CaMeL»: разделение управляющего и информационного потоков).
- **Два агента**: «привилегированный» (имеет инструменты, не видит сырой
  недоверенный контент) + «карантинный» (обрабатывает недоверенное, без прав).
- **Детерминированная обёртка**: критичные действия проходят через код с
  проверками/лимитами, а не напрямую вызываются моделью.
- **Человек в контуре** для необратимого и дорогого; понятное подтверждение с сутью действия.
- **Egress-контроль** как последний барьер: даже при успешной инъекции данные
  некуда отправить.
