# Политика уровней риска изменений — шаблон

```markdown
# Политика уровней риска: <команда / продукт / организация>
Версия: 1.0 | Владелец: <архитектор> | Пересмотр: <дата>

## Уровни и маршруты
| Уровень | Определение | Обязательные проверки | Ревью | Кто одобряет | SLA ревью |
|---|---|---|---|---|---|
| T0 | ... | все автоматические зелёные | нет | автоприёмка | — |
| T1 | ... | + AI-ревью | выборочно | член команды | 1 день |
| T2 | ... | + архитектурные проверки | асинхронно, design/delta | архитектор | 2 дня |
| T3 | ... | + эвалы домена, проверка plan ↔ diff | синхронно | именованный владелец + архитектор | по договорённости |

## Правила классификации (по путям и признакам)
Ссылка на машиночитаемый конфиг: `<путь>/risk-config.json`

## Правила повышения уровня
- Любое изменение проверок, их исключений и базовых линий → не ниже T2.
- Регулируемые данные → T3.
- Сомнение → на уровень выше.

## Расширение автоприёмки
Граница T0 расширяется, если за последние <N> недель: откатов агентных изменений < <x>%, архитектурных дефектов в проде — 0. Решение о расширении фиксируется в этом документе.

## Метрики
Доля T0, минуты ревью на изменение по уровням, откаты, ускользнувшие дефекты.
```
