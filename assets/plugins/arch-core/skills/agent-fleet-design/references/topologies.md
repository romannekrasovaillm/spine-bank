# Топологии флотов агентов

## Содержание
1. Один агент + человек
2. Оркестратор → исполнители
3. Параллельные сессии в worktree
4. Map-reduce для миграций
5. Исполнитель–критик
6. Конвейер ролей
7. Фоновые событийные агенты
8. Комбинирование

---

## 1. Один агент + человек
**Когда:** высокая неопределённость, исследование, дизайн.
**Как:** интерактивная сессия, план до правок (plan mode, brainstorming в superpowers, explore/propose в OpenSpec).
**Сильные стороны:** максимальное качество суждения, человек видит рассуждения.
**Отказы:** не масштабируется; человек становится исполнителем, а не проверяющим.
**Человеческое внимание:** высокое на единицу работы.

## 2. Оркестратор → исполнители
**Когда:** функция, разбитая на независимые задачи с понятными критериями.
**Как:** оркестратор держит план, на каждую задачу запускает исполнителя со свежим контекстом, между задачами — ревью (в superpowers: сначала соответствие спецификации, затем качество кода). Для больших объёмов — динамические workflows с сотнями сабагентов в одной сессии, где это поддерживается.
**Сильные стороны:** изоляция контекста, параллелизм, локализация ошибок.
**Отказы:** плохая декомпозиция → задачи зависят друг от друга; оркестратор теряет картину при длинных планах.
**Смягчение:** план мелкими шагами с явными критериями приёмки; сжатые отчёты исполнителей.

## 3. Параллельные сессии в worktree
**Когда:** несколько независимых функций одновременно.
**Как:** каждая сессия в своём git worktree и ветке; человек как техлид переключается между ними. Плейбук Anthropic советует начинать с 2–3 параллельных сессий на инженера.
**Сильные стороны:** простота, естественная изоляция.
**Отказы:** человек перегружен переключениями; конфликты при слиянии; дублирование общих компонентов.
**Смягчение:** нарезка по модулям, реестр общих компонентов, частые слияния.

## 4. Map-reduce для миграций
**Когда:** много однотипных единиц (эндпоинты, модули, файлы конфигурации).
**Как:**
1. Характеризационные тесты фиксируют текущее поведение до миграции.
2. Пилотная волна: 3–5 единиц разной сложности мигрирует агент под пристальным контролем человека.
3. Из пилота — шаблон: инструкция, примеры до/после, список ловушек, проверки.
4. Волны по модулям (map): исполнители применяют шаблон, каждый в своей зоне.
5. Сведение (reduce): агрегированный отчёт, выборочное человеческое ревью, исправление шаблона при повторяющихся ошибках.
**Сильные стороны:** огромная пропускная способность при контролируемом риске.
**Отказы:** ошибка в шаблоне размножается; агенты «чинят» тесты.
**Смягчение:** ревью шаблона как главный человеческий контроль; запрет изменения тестов; остановка волны при доле ошибок выше порога.

## 5. Исполнитель–критик
**Когда:** высокая цена ошибки: безопасность, деньги, данные, регуляторика.
**Как:** независимый агент-проверяющий получает спецификацию и результат, но не рассуждения исполнителя (иначе он склонен соглашаться). Разные инструкции, при возможности — разная конфигурация или модель.
**Сильные стороны:** ловит ошибки, которые исполнитель рационализировал.
**Отказы:** критик придирается к стилю и пропускает суть; бесконечные циклы.
**Смягчение:** чек-лист критика по рискам; лимит итераций; эскалация человеку при разногласии.

## 6. Конвейер ролей
**Когда:** сквозной процесс от идеи до кода с несколькими видами экспертизы.
**Как:** фазы с ролями (в BMAD: Analyst → PM → Architect → SM → Dev → QA), каждая фаза производит версионируемый артефакт, который становится проверенным контекстом следующей.
**Сильные стороны:** полнота планирования, прослеживаемость.
**Отказы:** избыточность для малых задач; ошибка ранней фазы протекает дальше.
**Смягчение:** масштабирование глубины по сложности (треки BMAD); человеческие контрольные точки на артефактах ранних фаз.

## 7. Фоновые событийные агенты
**Когда:** эксплуатация, CI-сбои, триаж ошибок, обновление зависимостей.
**Как:** событие (алерт, упавший пайплайн, новая уязвимость) запускает агента, который анализирует и предлагает действие — исправление, PR или новый intent, возвращающий работу в петлю планирования.
**Сильные стороны:** скорость реакции, разгрузка людей от рутины.
**Отказы:** шквал PR; действия по недоверенному вводу (логи и тикеты могут содержать инъекции).
**Смягчение:** лимиты частоты, только предложения без права мержа, минимальные права на запись.

## 8. Комбинирование
Реальные флоты комбинируют топологии: конвейер ролей для планирования, оркестратор → исполнители для реализации, исполнитель–критик для рискованных частей, фоновые агенты в эксплуатации. Проектируйте комбинацию явно и указывайте в карточке, где проходит граница и какой артефакт её пересекает.
