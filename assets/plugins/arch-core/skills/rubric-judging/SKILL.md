# Рубричная оценка

Рубрика превращает «нравится/не нравится» в измеримую оценку: критерии с весами и якорями уровней. Два класса:

- **Якорные** — стабильные корпоративные шкалы (`arch-be rubric list`): `solution_architecture` (15 взвешенных критериев), `architecture_gates` (A0–A5), `macedo_dimensions`, `adr_quality`, `handoff_quality`.
- **Динамические** — генерируются судьёй под предмет оценки от якорной основы (`rubric_generate` / `--dynamic-subject`): предметно-специфичные критерии там, где якоря нет.

## Как работает судья (инструмент `rubric_evaluate`)

1. Судья — независимая установка: «ты не проектировал — оценивай доказательно».
2. Каждый балл ОБЯЗАН иметь цитату-свидетельство из текста. Нет свидетельства → балл 1.
3. Взвешенный итог: Σ(score·weight)/Σweight по шкале 1–5; критерии без оценки → 1 с пометкой.
4. Отчёт — markdown с таблицей и вердиктом, пишется в `reports/`.

## Когда какую рубрику

- Документ solution-архитектуры → `solution_architecture` (порог 3.5).
- ADR → `adr_quality`. Handoff/итог кодового агента → `handoff_quality`.
- Зрелость процесса команды → `macedo_dimensions`, `architecture_gates`.
- Нестандартный предмет (план миграции ЦОД, каталог API) → динамическая от `solution_architecture`.

## Смысловые рубрики: судить по досье, а не по документу

Четыре встроенные рубрики оценивают не качество документа, а **смысл**:
`adr_spine_consistency` (решение против инварианта, класс `D10`),
`model_link_semantics` (ссылка не на ту сущность, `D6`),
`nfr_mechanism_fit` (обещание показателя без механизма),
`code_invariant_conformance` (код против инварианта, `D11`). Механика эти
классы не ловит по построению — их видит только суждение.

У каждой в YAML объявлен вид досье (`pack:`) и главный критерий
(`blocking: true`). Досье — вход судьи, собранный из репозитория:

```bash
arch-be rubric pack adr_vs_spine docs/adr/ADR-042-x.md        # посмотреть вход
```

В MCP — аргументы `pack`+`subject` у `rubric_prompt`/`rubric_verify`
(взаимоисключающи с `target`/`target_text`); рубрика с досье, запущенная по
обычному документу, отказывает. Что меняется для судьи:

- **низкий балл — это обвинение**, и он обязан опираться на цитаты ОБЕИХ
  сторон (`Цитата subject: "…". Цитата reference: "…".`). Цитата из ADR не
  засчитывается как цитата из спайна;
- **высокий балл** («противоречий нет») цитатой не доказуем: вместо неё судья
  перечисляет в `checked` идентификаторы всех проверенных ссылочных
  источников, иначе критерий исключается как непокрытый;
- обвинение без подтверждённых цитат — флаг `accusation_unconfirmed`:
  критерий исключается из итога, но гейт этим не краснеет (выдуманное
  обвинение наказывает судью, а не документ).

Находки составляющей гейта `semantic_quality` (ADR-052) ссылаются на этот
раздел и на скилл `semantic-review`.

## Калибровка судьи

- Один эталонный разобранный пример на рубрику (калибровочный корпус).
- Прогон двух судей (deepseek + glm) на одном тексте: расхождение итога >0.5 — повод пересмотреть якоря.
- Баллы судьи — вход для решения, не автоматический вердикт; A3 — за человеком.

## Антипаттерны

- Судья = автор документа (та же сессия/контекст).
- Средний балл без чтения находок (диагностика важнее числа).
- Динамическая рубрика без якорной основы — дрейф шкалы.
