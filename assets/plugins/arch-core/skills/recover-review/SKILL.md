# Recover review

`recover` строит граф «как построено» детерминированно: узлы/рёбра ревизии, черновик `model/` со `status: inferred`. Детерминизм — достоинство и граница: сканер видит только то, что выражено в коде. Назначение компонента, неявный контракт, связь «через общую таблицу» — это интерпретация, и её место строго отделено от фактов (ADR-069, слой `[inferred]`).

Навык описывает, как LLM-хост дополняет граф **предположениями**, не размывая доказанную часть.

## Разделение слоёв (жёсткое)

- `survey.md` + узлы/рёбра `recover --format json` — **`[confirmed]`**: доказано сканером, у каждого факта ссылка `файл:строка`. Пишет только `arch-be`, человек их не редактирует.
- `survey-notes.md` + `model/*` — **`[inferred]`**: догадки модели о назначении, границах, пропущенных связях. Пишет **только** LLM-хост.

Модель **никогда** не создаёт `[confirmed]` и не пишет сущность модели со `status`, отличным от `inferred`. Факт — привилегия сканера с разрешимым evidence.

## Метки

- `[inferred]` — вывод модели: назначение компонента, вероятная связь, граница домена. Всегда проверять перед опорой.
- `[gap]` — пробел: данных нет, нужен владелец домена (не догадка).

`[confirmed]` в слое модели — **нарушение** R6 (см. ниже).

## Процедура

1. Построить граф: `arch-be recover <repo> --format json` (схема `arch-be/recover/v1`) и, при необходимости, черновик `arch-be recover <repo> --model-out model/`.
2. Прочитать граф: компоненты (`cmp:`), внешние системы (`sys:`), хранилища (`store:`), контракты, топики, рёбра и `gaps`.
3. Для компонента/связи, назначение которой из кода неочевидно, **дописать** `[inferred]`-предположение в `docs/reverse/survey-notes.md`; альтернативно — уточнить `model/<ID>.md`, сохранив `status: inferred`.
4. Каждое предположение формулировать как проверяемое («вероятно, владелец записи в таблицу `orders` — `cmp:orders-api`»), а не как утверждение.
5. Пропущенную связь между двумя компонентами — оформить как `[inferred]`-ребро с обоснованием из кода; если связи нет вовсе — `[gap]`.
6. Прогнать механику: `arch-be survey <repo> --audit` (`--model-out` при нестандартном каталоге модели). Ноль нарушений — слой чист.

## Механика проверки (R6)

`arch-be survey <repo> --audit` сканирует слой модели (`survey-notes.md` + `model/**/*.md`) и падает с exit 1, если:

- встретил `[confirmed]` без evidence вида `путь:строка`;
- evidence `[confirmed]` не разрешается в существующую строку существующего файла;
- сущность модели имеет `status ≠ inferred`.

Вывод: список находок `артефакт:строка: проблема — утверждение` либо `OK`. Механика отказывает модели, выдавшей догадку за факт.

## Антипаттерны

- Модель пишет `[confirmed]` «потому что уверена» — факт без evidence, размывает доверие ко всему графу.
- Правка `status: inferred → confirmed` в `model/*` руками модели — обход слоя, ловится аудитом.
- Предположение без ссылки на код — не проверяемо, неотличимо от галлюцинации.
- «Дописал survey.md» — этот файл пересобирается сканером, правки исчезнут.
