# Нативные вызовы прежде bash

Самоаудит SA-Bench (`docs/experiments/self-audit-native-tools.md`): в собственном
харнессе Spine-агент сделал ~80 bash-вызовов и **ни одного** нативного вызова
MCP-инструментов Spine. Сильный агент по умолчанию уходит в bash/grep/web —
это не лечится уговором, лечится **контуром**: хук напоминает, скилл называет
точное соответствие «событие → инструмент».

## Таблица: событие → нативный инструмент

| Событие | Нативный инструмент | Почему не bash |
|---|---|---|
| Новая тема, «как в банке принято…» | `kb_search` (до `web`) | локальная база архитектора точнее и без сети |
| Оценка значимости изменения | `significance_score` | 15 триггеров и маршрут Fast/Standard/Critical |
| Правка ADR (`docs/adr/`) | `adr_registry` (расхождения) + `rubric_evaluate` (`adr_quality`) | реестр знает статусы и противоречия связей |
| Правка инварианта (`ARCHITECTURE-SPINE`) | `spine_lint` | линтер спайна, а не глазами |
| Ссылки модели «не на ту» сущность | `model_query` / `rubric_run` (`model_link_semantics`) | форма ссылку не проверит |
| Граф «как построено» | `recover` + `model_query` | детерминированный сканер, не догадка |
| Контракты | `contract_diff` / `openapi_lint` / `asyncapi_lint` | семантический диф, не diff текста |
| Проверка правил репозитория | `fitness_check` | см. оговорку по no-exec ниже |
| После релиза / смена правил | `agentsmd_lint` | синхронность AGENTS.md с репозиторием |

## Когда bash законен

Нативные инструменты не вытесняют CLI полностью — есть узкие случаи, где bash
**правильный** путь (из того же самоаудита):

- **Живой релизный прогон** — сборка, `cargo test`, запуск бинаря, `git`
  операций: это не архитектурный вопрос, а исполнение.
- **Пайплайны сравнения** — когда нужно склеить несколько команд, где нативный
  инструмент даёт лишь часть (например, сравнить вывод двух инструментов).
- **Разведка файлов** — `read_file`/`glob`/`grep` это тоже нативные инструменты
  харнесса; bash-варианты (`cat`, `find`, `rg`) не нужны, но и не запрещены.

## Оговорка: native fitness_check исполняет команды

Важно из самоаудита: **нативный `fitness_check` через MCP исполняет команды
правил** и на большом репозитории упёрся в таймаут 300 с, тогда как CLI с
`ARCH_NO_EXEC=1` отработал за 0.7 с. Правило:

- быстрая проверка правил в цикле правок → `ARCH_NO_EXEC=1 ./target/debug/arch-be control check . --constraints CONSTRAINTS.yaml`;
- полное исполнение правил → нативно `fitness_check`, но осознавая стоимость.

## Процедура

1. Перед действием спросить: «есть ли нативный инструмент на это событие?» — сверить по таблице.
2. Если да — вызвать его **первым**; bash оставить для исполнения/сборки.
3. После правок ADR/spine — нативная проверка **до** коммита, не после.
4. Хук `[arch-core]` в выводе инструмента — это напоминание контура, не шум: он
   называет инструмент именно для текущего файла.

## Антипаттерны

- **bash-инерция** — «привычнее через grep/curl», а нативный инструмент рядом.
- **web прежде kb** — сеть вместо локальной базы архитектора.
- **Правка ADR без `adr_registry`** — противоречие связей уедет в коммит.
- **Коммит без контроля правил** — `fitness_check`/`control check` пропущен.
