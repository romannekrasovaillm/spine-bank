# Шаблон архитектурного раздела CLAUDE.md / AGENTS.md

Цель — 30–60 строк. Всё, что длиннее, выносится в скиллы, правила каталогов или ADR со ссылкой.

```markdown
## Архитектура

**Назначение системы.** Одно-два предложения: что делает, для кого, какие данные критичны.

**Границы модулей.**
- `billing/` — расчёт и выставление счетов; владеет таблицами `invoice_*`.
- `payments/` — проведение платежей; владеет `payment_*`.
- Модули общаются только через публичные интерфейсы в `<module>/api/` и доменные события. Импорт из `<module>/internal/` чужого модуля запрещён.

**Обязательные решения (не нарушать без запроса на решение).**
- ADR-0007 PostgreSQL — единственное хранилище транзакционных данных.
- ADR-0012 События только через outbox.
- ADR-0019 Внешние вызовы — только через `integrations/` с таймаутом и circuit breaker.
Полный реестр: `docs/adr/`.

**Если задача требует нарушить решение или границу:** остановись, опиши конфликт в плане/design и предложи запрос на решение. Не обходи молча.

**Перед изменениями, затрагивающими данные, границы модулей, внешние интеграции или безопасность**, сверься с соответствующим ADR и отметь в плане, какие решения затронуты.

**Проверки архитектуры.** `make arch-test` — должна проходить перед завершением задачи. Сообщения об ошибках содержат, как исправить нарушение.

**Глоссарий домена.** `docs/glossary.md` — используй эти термины в именах и спецификациях.
```
