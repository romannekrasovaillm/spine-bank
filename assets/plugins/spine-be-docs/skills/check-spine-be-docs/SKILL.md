# Справка по документации Spine-BE (check-spine-be-docs)

Отвечай на вопросы о **самом продукте Spine-BE** из документации репозитория,
а не из памяти. Скилл — про использование и устройство харнесса
(«как настроить провайдера», «что делает control check», «какой ADR про SDK»);
это НЕ про разработку кода по задаче пользователя.

## Единственный источник истины

Документация в корне репозитория Spine-BE. Точка входа — карта
`docs/README.md`: в ней таблицы «Я… → мой путь» и полный перечень гайдов.
Все пути ниже — относительно корня репозитория.

Если текущий рабочий каталог — не репозиторий Spine-BE, сначала найди
документацию (рабочая копия рядом с проектом пользователя). Если документы
недоступны — скажи об этом прямо, ответь из того, что знаешь, и помечай,
что именно не удалось сверить с документацией.

## Как отвечать

1. Выбери файл из таблицы выше.
2. **Прочти файл до ответа** — отвечай строго из прочитанного, никогда по памяти.
   Имена команд, флагов, полей конфига, инструментов и инвариантов сверяй
   с текстом документа; не выдумывай их.
3. Ссылайся на источник путём к файлу (`docs/control.md`, `docs/adr/ADR-028.md`),
   чтобы пользователь мог проверить.
4. Если вопрос про «почему так сделано» — ищи соответствующий ADR в `docs/adr/`
   (имена файлов `ADR-NNN-<тема>.md` говорят тему; Grep по заголовкам ускоряет).
5. Если документация вопрос не покрывает или файл не читается — скажи об этом
   прямо: ответь из того, что уже знаешь, и явно пометь, какие части не сверены
   с документацией. Никогда не выдумывай поведение продукта.
6. Документация на русском; ответы пользователю — на русском.

## Границы

- Не подменяй документацию содержимым чата: если память и файл расходятся,
  прав файл (и стоит сказать об этом расхождении).
- Заметил, что документ устарел относительно кода, — назови это отдельно,
  не «чиня» документацию молча в ответе.
