# Смысловая оценка: порядок, а не отдельный вызов

Смысловой слой Spine — это **суждение с доказательствами**: сервер собирает
досье и сверяет цитаты, модель хоста судит. Порядок важен: каждый шаг
отвечает за одно, и пропуск шага не ускоряет, а обесценивает результат.

## Шаг 1. Список субъектов

Смысловые рубрики работают не по документу, а по досье. У каждой в YAML
объявлен вид досье (`pack:`):

| Рубрика | Досье | Субъект |
|---|---|---|
| `adr_spine_consistency` | `adr_vs_spine` | принятые ADR (`docs/adr/ADR-*.md`) |
| `model_link_semantics` | `entity_links` | сущности модели со связями |
| `nfr_mechanism_fit` | `nfr_mechanism` | `NFR-…` |
| `code_invariant_conformance` | `code_vs_spine` | файлы под `code_roots` компонент |

Область выбирает человек: `changed` (затронутые диффом от базы — включая
случай, когда изменился спайн, а субъект нет) или `all` (весь пакет, для
периодического прогона). Список субъектов — половина работы: оценивать «весь
пакет вообще» бессмысленно и дорого.

## Шаг 2. Досье

Для каждого субъекта:

```
rubric_prompt {"rubric": "adr_spine_consistency", "pack": "adr_vs_spine",
               "subject": "docs/adr/ADR-042-x.md", "root": "."}
```

Ответ несёт системный и пользовательский промпт, JSON-схему ответа, число
сэмплов k и описание досье (`pack`) с хэшем и поимёнными хэшами источников.
Файл кода, не влезающий в лимит, приходит нарезанным: инструмент назовёт
субъектов-фрагментов (`src/gate.rs#12-88`) — вызывай по каждому.

**Посмотри досье глазами.** Если второй стороны противоречия в нём нет
(инвариант не привязан трассировкой, карточка цели отсутствует, контракт не
найден) — сначала чинится досье, а не судится субъект.

## Шаг 3. k независимых ответов

Исполни промпт **своей** моделью k раз — независимо: не копируй себя, меняй
порядок разбора критериев, перечитывай досье. Отвечай строго по схеме:

- низкий балл смыслового критерия — это **найденное противоречие**, и он
  обязан опираться на цитаты ОБЕИХ сторон (`Цитата subject: "…". Цитата
  reference: "…".`) — отсутствие не цитируется, поэтому «нет свидетельства»
  здесь неверный ответ, а неверный балл;
- высокий балл — перечисли в `checked` идентификаторы **всех** ссылочных
  источников досье, иначе критерий исключат как непокрытый.

## Шаг 4. Verify

```
rubric_verify {"rubric": "adr_spine_consistency", "pack": "adr_vs_spine",
               "subject": "docs/adr/ADR-042-x.md", "root": ".",
               "answers": [<k сырых ответов>], "judge_model": "<фактическая модель>"}
```

Сервер соберёт отчёт тем же кодом, что встроенный судья: медиана, σ →
`unstable`, цитаты → `evidence_not_found` / `accusation_unconfirmed`, покрытие
→ `coverage_incomplete`. Отчёт ложится в `reports/rubric/<субъект>--<вид>.json`
под `--rw` — именно его читает гейт.

**Судья обязан отличаться от автора документа.** Пишешь ADR ты — судит другая
модель; одна модель на обе роли — это `judge_is_author`, и отчёт помечается.

## Шаг 5. Гейт

Составляющая `semantic_quality` (ADR-052) читает отчёты: сверяет хэш досье,
порог и подтверждённость цитат. Включается явно — строкой `semantic_quality` в
`[gate.required]` маршрута. Зелёный гейт с этой составляющей означает
«суждение есть и оно привязано к этой редакции досье», а не «решение верное».

## Шаг 6. Красный red-team (проверка самого контура)

```bash
arch-be redteam <кейс> --keep-semantic /tmp/semantic
# в каждом /tmp/semantic/D* — SEMANTIC-TODO.json с рубрикой, досье и субъектом
arch-be redteam semantic-score /tmp/semantic
```

Строка «смысловой слой: поймано k из n» (n — число клонов, по которым есть
отчёт судьи) отвечает на вопрос «работает ли
суждение там, где механика бессильна». В долю обнаружения (11 из 14) и в
порог 78 % она **не входит** — это измерение другого слоя.

## Антипаттерны

- Судить без досье (по одному документу) и называть это смысловой оценкой.
- Править субъект «под рубрику» вместо исправления смысла: критерий зеленеет,
  противоречие остаётся.
- Выдавать свой прогон за независимый и не указывать фактического судью.
- Засчитывать «поимку» по низкому баллу без подтверждённых цитат: механику не
  обманешь — критерий исключён из итога, и это `accusation_unconfirmed`, а не
  находка.
- Приписывать смысловой строке влияние на долю обнаружения.
