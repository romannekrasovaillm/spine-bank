# Fitness-гейт: FAIL → починка → PASS

Контракт: `.arch-handoff/CONSTRAINTS.yaml` (или в корне) — правила
`must_contain` / `must_not_contain` / `command_succeeds` с severity
critical/error/warn. Гейт: `fitness_check {"repo": "."}` (MCP) или
`arch-be control check .` (CLI, то же самое). PASS = exit 0.

## Протокол при FAIL

1. Прочитай КАЖДУЮ находку: `file`, `line`, `rule`, текст паттерна.
2. Пойми намерение правила из его `name` (например `no_float_for_money` =
   «деньги не в float») — чини по смыслу, не по букве (не закомментируй
   правило и не «спрячь» паттерн — это дрейф, ловится `delta guard` и
   аудитом).
3. Почини код минимальным дифом.
4. Обязательно перепроверь `fitness_check` — только `passed=true` считается.

## Типовые правила и чинки

| Находка | Чинка |
|---|---|
| `no_float_for_money` (`\bf64\b`) | Целые минорные единицы (i64 копейки), форматирование целочисленное |
| `tests_present` (`#\[test\]`) | `#[cfg(test)] mod tests` с реальной проверкой главного пути |
| `must_contain` по глобу «не найден ни одного файла» | Создай ожидаемый файл/каталог ИЛИ спроси архитектора, актуально ли правило |

## Хук-гейт

Если Stop-хук харнесса блокирует завершение с «Итог: FAIL» — это не ошибка
харнесса, а гейт: исправь находки и завершай спокойно. НЕ проси пользователя
«отключить хук» — предложи исправить или обоснованно скорректировать правило
(через ADR + дельту, см. `spine-content-bootstrap`).
