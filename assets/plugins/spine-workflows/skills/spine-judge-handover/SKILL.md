# Передача судейства и приёмка

Ты — основной агент. Оценивать решения самому нельзя: судья обязан быть
отдельной установкой, а метки «судья» и «автор» — не совпадать (анти-биас).
Порядок ниже — это протокол, а не пожелание: он закрывает находки гейта и
оставляет след в отчёте.

## 1. Инвентарь

```
rubric_handover {path: "<кейс>"}      # или: arch-be rubric handover --dir <кейс>
```

Ответ: принятые ADR без свежего отчёта или с устаревшим, модель-автор из шапки
каждого документа, доступные судьи CLI с семейством и **два готовых текста
передачи**. Ничего не пишет — можно звать сколько нужно.

## 2. Выбор способа

| Способ | Как | Уровень независимости в отчёте |
|---|---|---|
| Spine запускает судью сам | `rubric_run {rubric, target, model: "<судья-кли>"}` или `arch-be rubric run <рубрика> --all-accepted --model <судья>` | **обеспечена запуском** — Spine знает, что каждый сэмпл отдельный процесс |
| Судит второй харнесс | отдай второму агенту текст «Способ 2» из handover: `rubric_prompt` → k ответов → `rubric_verify` | **заявлена** — метки передал хост, механика их не проверяет |

Предпочитай первый способ: он короче и уровень выше. Второй — когда нужен
судья другого семейства, которого у Spine нет (Claude судит то, что писал
GLM, — и наоборот).

**Подключение второго харнесса — с узкой записью:** `arch-be connect <хост>
--rw=reports` (запись только в `reports/rubric/`). В read-only отчёт не
сохранится, и гейт скажет `rubric_report_missing`; если хост уже подключён
read-only — сохрани `artifact_json` из ответа `rubric_verify` сам, по
`artifact_path` из того же ответа.

## 3. Ожидание

Ждать придётся: судья — это k независимых ответов на документ. Пока ждёшь, не
суди «пока архитектор переключается» — это и есть тот самый судья-автор,
которого контур ловит находкой `judge_is_author`.

## 4. Приёмка

```
rubric_accept {path: "<кейс>"}        # или: arch-be rubric accept --dir <кейс>
```

Ответ: по каждому ADR — свежий ли отчёт, кто судил, какой уровень
независимости, сходятся ли ответы. Ненулевой код — гейт по `decision_quality`
всё ещё красный (проверяется той же составляющей, что у `arch-be gate`).

## 5. Гейт

`arch-be gate --repo <кейс>` (составляющая `decision_quality` должна быть
включена в `[gate.required]`). Если проект поднял планку — `min_independence
= "launched"` — приёмка `declared` отчётов не пройдёт: это ожидаемо и лечится
первым способом.

## Антипаттерны

- **Судить самому.** Метки совпадут с автором → `judge_is_author`, а оценка
  не независима.
- **Подставлять метку другого судьи.** `judge_model` — та модель, что реально
  ответила; подмена — прямая ложь в происхождении, и `rubric_raw_tampered` /
  `rubric_report_inconsistent` её поймают, если править ещё и отчёт.
- **Править ADR между передачей и приёмкой.** Отчёт привязан к редакции
  документа: правка делает его устаревшим (`rubric_report_stale`), и оценивать
  придётся заново.
- **Править балл в отчёте руками.** Отчёт пересобирается из сырых ответов —
  расхождение станет находкой `rubric_report_inconsistent` (error).
