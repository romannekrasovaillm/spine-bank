# Архитектурный разбор через Spine (всё read-only)

Стандартная связка (все вызовы MCP, LLM у Spine нет — выводы формулируешь ты):

1. **Маршрут**: `significance_score` с `triggers` (например
   `{"new_component": true}`, `{"security_boundary": true}`,
   `{"irreversible_migration": true}`) → route Fast/Standard/Critical.
   Всегда помечай, что маршрут — функция ЗАЯВЛЕННЫХ триггеров, а не
   истина о решении: если что-то не спросили — скажи это.
2. **Модель**: `model_query {"dir": "model"}` (список) и
   `model_query {"dir": "model", "id": "CMP-001"}` (карточка). Следи за
   сиротами (сущности без связей) — это находки.
3. **Трассировка**: `trace_check {"case": "."}` → цепочка
   REQ → NFR → AD/ADR → CMP → правило CONSTRAINTS. AD без правила и без
   `unverifiable` — error: предложи правило или явное обоснование.
4. **Спайн**: `spine_lint {"path": "ARCHITECTURE-SPINE.md"}` — формат
   инвариантов.
5. **AGENTS.md**: `agentsmd_lint {"repo": "."}` — свежесть канала инструкций.

## Выдача архитектору

Сводка таблицей: маршрут (+оговорки), состав модели (сироты!), покрытие
трассы, вердикт гейта. Находки — с конкретным файлом/ID и предлагаемой
чинкой. Никогда не выдумывай сущности, которых не вернул `model_query`.
