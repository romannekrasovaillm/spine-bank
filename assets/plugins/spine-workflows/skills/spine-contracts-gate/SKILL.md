# Контрактный гейт: линт + diff

Инструменты (read-only): `openapi_lint {"path": "contracts/api.yaml"}`,
`asyncapi_lint {"path": "contracts/events.yaml"}`,
`contract_diff {"old": "v1.yaml", "new": "v2.yaml"}` (все с опц. `cwd`).

## Протокол

1. Линт ОБЕИХ версий отдельно (warn-находки — стиль, error — блокеры).
2. `contract_diff` v1→v2: breaking changes (удалённые пути/поля, сужение
   типов, новые обязательные поля в запросах) — это FAIL для минорной
   версии. Небreaking (добавление опциональных полей, новые пути) — ок.
3. Вердикт архитектору: список breaking с конкретными путями/полями +
   рекомендация (версия API v2, расширение вместо замены, deprecation-окно).

## Дисциплина

- Не сглаживай breaking-находки («ну клиенты обновятся») — называй их
  ломающими и требуй явного решения архитектора.
- Нет файла контракта — предложи его создать (это находка само по себе для
  зрелого контура), не выдумывай линт «на глаз».
