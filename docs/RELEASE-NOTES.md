# Что нового — архив релизных заметок README

Релизные заметки, раньше открывавшие README (0.3.4 — 0.4.0). Полная история — в [CHANGELOG.md](../CHANGELOG.md).

## Что нового в 0.4.0 — ценность для архитектора, доказанная на чужом коде

Три функции, ради которых архитектор берёт Spine, теперь работают на чужом
коде и доказаны бенчмарками с пререгистрацией (`benchmarks/architect-value/`,
результаты живых прогонов в `results/`).

- **`arch-be recover` — восстановление архитектуры по коду.** Полный граф
  ревизии (компоненты, рёбра, хранилища, внешние системы) с `via`/
  `evidence` (файл:строка)/`confidence`, детерминизм байт-в-байт, 0.2–1.0 с
  на репозиторий. Живой пример на публичном репо
  [spring-petclinic-microservices](https://github.com/spring-petclinic/spring-petclinic-microservices):

```
$ arch-be recover ~/spring-petclinic-microservices
# Граф ревизии (recover)
Ревизия: 1d76b00d
Узлов: 10 (компонент 8, внешних систем 2)   Рёбер: 10
- api-gateway --calls · route--> genai-service   (…/application.yml:40)
- genai-service --calls · stub--> vets-service   (…/VectorStoreController.java:66)
- genai-service --connect--> sys:openai          (…/application.yml:24 +5)
```

  Межсервисные рёбра на Online Boutique: **17/17** эталонных (0 из 17 на
  0.3.16); PetClinic: **6/6**; компоненты многомодульных сборок и пакетный
  уровень монолитов (buckpal — зоны гексагона, F1 0.89). MCP-инструменты
  `recover` и `arch_diff` — из агента. Черновик `model/` со `status:
  inferred` не затирает правки архитектора (ADR-069).
- **Проверка корпоративных стандартов.** `applies_to`: неприменимое
  корп-правило — статус **N/A**, а не ложный FAIL (PetClinic: 2 → 0).
  Радар — Gradle/npm/csproj/pyproject/go.mod, диапазоны версий
  (`below: "2.17.1"`), скоупы test/runtime. Новые типы правил
  `conditional`, `outbound_allowlist`, `multiline`. Стандарт из 12
  требований: **7/12 → 11/12** механизировано (ADR-070).
- **Контур, ловящий дефекты.** `redteam --repo <репо> --standard
  <CONSTRAINTS.yaml>` засевает нарушения стандарта в реальный код —
  карта обнаружения по слоям (текст/ArchUnit/радар); измеримость кейсов
  1/14 → **6/14** с причинами по остальным (ADR-071). Архитектурный
  дифф доказан на размеченной истории: recall значимых 1.00,
  composition-F1 0.90, шум 6/6 → 0/6 (ADR-072).
- **`arch-be constraints-harvest`** — детерминированный сборщик
  фактов-ограничений для ADR (производительность, владение, лицензии/EOL,
  env-поверхность, feature-флаги) — закрыт главный пробел задачи DECIDE
  (ADR-073).
- **Волна B (0.3.17):** девять дефектов живых прогонов — `survey .`,
  MCP-схема, selftest из коробки, нотация `dependency_direction`,
  wildcard-импорт, corp-spine-образец, `redteam --hermetic`, денилист
  шума, ошибки без стектрейса.

Полный разбор — в [CHANGELOG.md](../CHANGELOG.md), там же обязательный раздел
«Что может покраснеть после обновления».

## Что нового в 0.3.15

«Не красный за отсутствие железа»: правило реестра объявляет ресурсы среды,
без которых его проверка невозможна, и гейт честно пропускает такое правило
(SKIP с причиной) вместо ложного FAIL на чужой машине; `arch_drift` перестал
спотыкаться о большие кейсы. Полный разбор — в [CHANGELOG.md](../CHANGELOG.md),
там же обязательный раздел «Что может покраснеть после обновления».

- **`requires:` у правила реестра** (ADR-068 «Stand-bound правила гейта»;
  перенесено из ML-редакции, где это ADR-046) —
  правило называет ресурс (`cuda`, `stand` или свой): ресурса нет — **SKIP с
  причиной** (не PASS и не FAIL) плюс обязательная строка «требуется прогон
  на GB10»; ресурс есть — обычная семантика PASS/FAIL. SKIP не лазейка:
  стендовый прогон остаётся условием приёмки.
- **Реестр зондов `[gate.requires.<имя>]` настраивается — ядро не знает
  предметной области.** `kind` ∈ `file | binary | env | hostname | device |
  command` + параметры вида (`path`/`name`/`var`/`pattern`/`cmd`) + `note`.
  Банковский кейс объявляет `requires: [oracle-client]` с зондом
  `kind = "binary", name = "sqlplus"` без правок кода; встроенные `cuda` и
  `stand` переопределяются конфигом.
- **Пропуск виден в машинных отчётах.** В SARIF/JUnit/GitLab правило,
  пропущенное из-за недоступного ресурса, — отдельный **SKIP-статус**, а не
  зелёный: «проверка не прогонялась» нельзя прочитать как успех.
- **`[gate.arch_drift] max_files` и `ignore`** — потолок читаемых в снимок
  файлов (дефолт 2000) и подстрочные исключения путей, применяемые к обоим
  снимкам: кейс с тысячами файлов окружений (`env/`) больше не срывает дифф
  «как построено» против модели.
- **Что может покраснеть.** Правило с `requires`, которому не отвечает ни
  встроенный зонд, ни секция конфига, — **ошибка реестра** (fail-closed:
  опечатка не превращается в вечный SKIP). На машине без ресурса исполняемые
  правила переходят из FAIL в SKIP, и если так пропущены обязательные
  составляющие, гейт даёт **INCOMPLETE (exit 3)** вместо PASS.

## Что нового в 0.3.14

«Зелёный, который нельзя написать рукой, OpenSpec без двойного учёта и
архитектурный дифф каждого PR» — волны A–F и K задания v2. Полный разбор —
в [CHANGELOG.md](../CHANGELOG.md), там же обязательный раздел «Что может
покраснеть после обновления»; замеры — в `docs/experiments/` (церемония
Critical, реплей маршрута значимости по истории).

- **Архитектурный дифф каждого PR (волна K, ADR-063/064)** — новая точка
  входа в продукт: `arch-be arch-diff --base main` в любом репозитории
  показывает, что PR изменил в системе (рёбра вне модели, контракты, NFR,
  инварианты), и предлагает правку модели одним `accept`. См. «Шаг 1» ниже.
- **Отчёт о прогоне пишет машина (A1, ADR-066).** `arch-be evidence record
  fitness|tests|skeleton` — запись с командой, exit-кодом, HEAD и хэшем
  входов; рукописная строка «Итог: PASS» больше не удостоверяет прогон
  (`evidence_report_unbound`; в каркасе `bootstrap` — error).
- **Церемония Critical короче (A2).** `risk_level` выводится из записи
  значимости, заглушки машинных артефактов больше не создаются: автор пишет
  7 файлов вместо 11 (замер — `docs/experiments/ceremony-0.3.14.md`).
- **OpenSpec без двойного учёта (F1–F6, ADR-062/067).** Change OpenSpec —
  равноправный источник покрытия `delta_guard`; `openspec_coverage` —
  составляющая единого гейта; `openspec gate --change`; `handoff
  --openspec-change`; находка `covers_orphan`.
- **«Поведенческое» означает «с зубьями» (волна B, ADR-065).** `arch-be
  rules teeth` измеряет каждое правило мутацией (три группы в
  `rules-report`); ступень 3 `trust` — по несущим инвариантам с
  подтверждёнными зубьями (`[trust] require_teeth`).
- **Модель привязана к коду (волна C).** Составляющие гейта `model_drift` и
  `arch_drift` (по `[gate.required]`), находки `declared-edge-unused` и
  `nfr-metric-missing` (за флагом).
- **Маршрут значимости измерен (волна D, ADR-061).** Паспорт называет
  недетектируемые триггеры; глобы кейса для слепых зон; `new_vendor` —
  только новые имена пакетов; `control score --replay` по истории.
- **Redteam против реальных ошибок агентов (волна E).** Мутаторы D18–D24 из
  корпуса `openspec-vs-spine` (180 генераций); две доли обнаружения —
  документы+модель и код раздельно.
- **Что может покраснеть.** Рукописные отчёты в строгом режиме записей;
  покрытие, созданное исполнителем в своём диапазоне (`delta_guard`, теперь
  и в пост-гейте); требования OpenSpec без решения (при `openspec_coverage`
  в `[gate.required]`).

## Что нового в 0.3.13

Устойчивость к сетевым окнам и диагностика: ход пережидает DPI-окна вместо
падения, doctor отличает «модель умерла» от «сеть/DPI режет», маршрут
значимости видит NFR и цели RTO/RPO, а хуки-гейты версионируются вместе с
бинарём. Полный разбор — в [CHANGELOG.md](../CHANGELOG.md), там же
обязательный раздел «Что может покраснеть после обновления».

- **«Длинное терпение» на транспортные сбои модели.** Окна DPI/VPN рвут
  связь пачками по минутам, а быстрые ретраи провайдера (≤ ~40 с) их не
  переживают — ход падал. Теперь сетевая ошибка пережидается: вызов модели
  повторяется в пределах стенного бюджета
  `[agent] network_retry_budget_secs` (по умолчанию 180 с; 0 — прежнее
  поведение), в чат идут заметки с остатком бюджета, прерывание — Esc.
  В статус-баре TUI — индикатор «⚠ сеть: повтор…» / «сбой Nм назад».
- **doctor прозванивает endpoint'ы моделей (`models-net`).**
  `GET <base_url>/models` без ключа, параллельно, таймаут 5 с: любой
  HTTP-ответ (включая 401) — «живо» с латентностью; транспортный отказ —
  короткая причина («таймаут», «отказ в соединении», «сброшено —
  сеть/DPI?»). Недоступная модель по умолчанию — Fail. Учитываются
  `proxy`/CA/mTLS; core-редакция отвечает честным SKIP.
- **NFR-детекторы маршрута значимости (ROADMAP 1.7 п.3).** Появление или
  правка `model/NFR-*` и изменение целей RTO/RPO (`rto_minutes:`,
  `rpo_seconds:`, инлайн «RTO ≤ 15») теперь поднимают маршрут штатно:
  ужесточение RTO 240 → 15 больше не уйдёт по Fast-треку.
- **Хуки-гейты — подкоманды бинаря (ROADMAP 1.7 п.2).**
  `arch-be hook stop|post-tool-use|pre-commit|pre-push`: логика хуков
  переехала из shell-шаблонов в бинарь и версионируется вместе с ядром —
  исправление хука приезжает с обновлением, без повторного `connect` на
  каждой машине. `connect` сам заменяет прежние шаблоны на тонкие shim'ы,
  `doctor --host` проверяет форму хука.
- **TUI: версия под лого с первого кадра и без «призраков».** Заставка
  показывает «Spine-BE vX.Y.Z» сразу (раньше — последние кадры фазы);
  хвосты строк после рефлоу терминала убраны сверкой размера каждый кадр.
- **Что может покраснеть.** `doctor` на машине без связи с endpoint'ами
  (Fail по модели по умолчанию); диффы с NFR/RTO/RPO (маршрут выше,
  evidence полнее); автоматика, ждавшая быстрый отказ хода при мёртвой
  сети (теперь — до 3 минут ожидания, откат
  `network_retry_budget_secs = 0`).

## Что нового в 0.3.12

Эшелонированная защита (волны A–D): проверяемый больше не управляет
проверкой, поставке можно верить, входы рантайма и исходники на замке — и
рядом новые режимы вызова агента по протоколу ACP. Полный разбор — в
[CHANGELOG.md](../CHANGELOG.md), там же обязательный раздел «Что может
покраснеть после обновления».

- **Гейт, который нельзя тихо ослабить (волна A).** Правка тела правила без
  активного override — находка `BodyChanged`; override узаконивает только
  настоящий принятый ADR в пределах горизонта (`override_adr_missing`,
  `override_adr_not_accepted`, `override_horizon_exceeded`); подмена
  контрольной плоскости (Stop-хук, пороги рубрик, манифест пакета) —
  `control_plane_tampered` / `manifest_tampered`; одобрение, возникшее
  внутри прогона исполнителя, — `self_approved` (ADR-055). `harness_run`
  перепроверяет результат пост-гейтом вне окружения исполнителя.
- **Поставка, которой можно верить (волна B).** Релиз по тегу собирается
  только с зелёного CI коммита (fail-closed); SBOM каждой редакции — той же
  сборкой и в том же `SHA256SUMS`, что и бинари; сами бинари — с SLSA build
  provenance, манифест хэшей подписан keyless `cosign` (проверка —
  `docs/supply-chain.md`); все actions — по полному SHA, `CODEOWNERS` на
  механику допуска, `cargo deny` в CI.
- **Рантайм и исходники на замке (волна C).** `plugins.lock`: плагин с
  расходящимся содержимым больше не загружается (`plugin_tampered`). На
  маршруте Critical процесс кодового агента получает чистое окружение по
  умолчанию (`PATH, HOME, LANG, TERM, TMPDIR` + явно выданное; возврат к
  наследованию — `env_inherit = true` с предупреждением). Составляющая
  `secrets` ловит литералы ключей в изменённых файлах (`secret_literal`).
- **Режимы вызова агента — ACP рядом с headless (ADR-057).** Собственный
  ACP-клиент (JSON-RPC 2.0 поверх stdio, без новых зависимостей), конфиг
  `mode = "acp" | "auto"`: `auto` сам откатывается на headless при провале
  рукопожатия (итог помечается `fallback` с причиной). Ход различает
  `stopReason`: отмена — мягкий `Cancelled`, обрыв по лимиту — `TurnLimit`
  (частичный ответ сохраняется и разбирается на контракт), `refusal` —
  ошибка прогона. Фикстура-агент конформна официальному TCK ACP (33/33).
- **Слои после гейта (волна D, за флагами — вердикт и exit-коды не
  меняются).** `gate --shadow-constraints` — канарейка реестра правил (что
  покраснеет при переходе — отдельным блоком); `policy export kyverno|rego`
  — инварианты развёртывания из секции `deployment:` в политики кластера;
  `gate --format bitbucket-insights` и `connect ci --provider bitbucket`;
  `nfr verify --metrics` — сверка фактических метрик с бюджетами модели.
- **Что может покраснеть.** Репозитории, где ослабление правил узаконено
  выдуманным или непринятым ADR, собственной дельтой или одобрением «в ходе
  прогона»; Critical-прогоны, молча полагавшиеся на унаследованное окружение
  (прокси, ключи); библиотеки плагинов под `plugins.lock` после правок без
  перегенерации замка. Конфиги без `mode`/`acp` работают как раньше.

## Что нового в 0.3.11

Патч по итогам ночного мутационного прогона: закрыты пробелы в тестах, которые
он вскрыл, и две поломки самой джобы `mutants`. Одно изменение видно снаружи —
и оно меняет вердикты (полный разбор — в [CHANGELOG.md](../CHANGELOG.md), раздел
«Что может покраснеть после обновления»).

- **`ALTER TABLE … ALTER COLUMN … SET DATA TYPE` снова работает.** Каноническая
  форма Postgres разбиралась неверно: имя колонки читалось вторым словом, то
  есть «COLUMN», а такой колонки в таблице нет — оператор молча не применялся,
  и смена типа через него проходила зелёной. Теперь имя берётся после префикса
  формы, остаток — за ним; короткие формы (`ADD <колонка>`, `DROP <колонка>`,
  `ALTER <колонка> …`) и MySQL-форма `MODIFY` работают. Несовместимая смена
  типа в диффе контракта — находка `CD-S03` (error, exit 1): кейс, зелёный
  благодаря слепоте парсера, станет красным — это и есть цель правки.
- **Джоба `mutants` больше не краснеет из-за номера шарда.** `cargo-mutants` 27
  нумерует шарды с нуля, поэтому `--shard 12/12` — невалидное значение («shard
  k must be less than n»): шард 12 падал за 0,05 с, не прогнав ни одного
  мутанта, и держал Nightly красным независимо от покрытия тестами. Матрица
  переведена в 0…11.
- **Тесты против выживших мутантов.** Закрыты ветки, которые не проверялись
  вовсе: детектор формата контракта (расширения, маркеры содержимого, отказ),
  глубина обхода `OpenAPI` и JSON Schema, диапазоны `reserved` в proto, разбор
  `ALTER TABLE` в DDL, границы паспорта вердикта (потолки находок и имён,
  счётчики `nfr`), отбор субъектов смысловой рубрики, границы порогов
  `decision_quality` и `semantic_quality`. Тесты составляющих гейта вынесены в
  подмодуль `src/gate/components/` — продовый модуль вернулся в границу C-33
  (3000 строк) без смены публичных путей `crate::gate::components::…`.

Патч по итогам **расширенных живых тестов 0.3.9** (весь CLI, обе редакции,
MCP-орган, TUI): контур перестал терять свидетельства на путях, которые руками

  общий `judge_rules::write_archive`, а в ответе инструмента есть поле
  `archive`.
- **`rules template apply` снова видит инварианты.** `--ad AD-n` (CLI и MCP
  `rule_template_apply`) требовал форму заголовка `## AD-N. …`, тогда как спайны
  репозитория, кейсов и каркаса `bootstrap` пишут `## AD-N: …`: агент получал
  «нет объявленных инвариантов» на любом реальном спайне. Разбор делегирован
  каноническому парсеру контура контроля — один канон на крейт.
- **`cron` работает сразу после `arch-be init`.** Три отказа подряд: пути в
  образце расписания начинались с `~`, которую планировщик не раскрывал;
  штатный дайджест базы знаний не укладывался в жёсткие 16 итераций (теперь
  `max_turns` у задачи в `cron.toml`, образец — 40); статус отчёта читался
  строго из последней строки, а шаблон задачи оборачивает JSON-контракт в
  ```` ```json ```` — валидный `{"status": "complete"}` давал `unknown`.
  Ограждения и пустые строки пропускаются, а в сообщении об исчерпании лимита
  есть подсказка про настройку.
- **`doctor` проверяет задачи cron**: называет задачи, файлов которых нет
  (`cron tick` упал бы на чтении), а не ограничивается наличием `cron.toml`.

- **Второй судья (E5.1)**: `rubric run --pack … --second-model <имя>` — две

## Что нового в 0.3.5

Релиз про **контур, который нельзя выключить случайно**: убраны стыки, на
которых архитектурный контроль отключался молча — а вердикт продолжал
выглядеть зелёным.

- **Реестр правил — один, и его расхождение видно.** `bootstrap` клал реестр в
  корень кейса, генератор пакета подкладывал в пакет заготовку из одного
  правила, а резолвер читал пакетную копию — команда получала «Правил: 1,
  PASS». Теперь пакетный реестр — копия корневого, а расхождение копий —

- **Хук не молчит о пропуске.** Гарда «реестр лежит в `.arch-handoff/`»
  удалена: Stop-хук, pre-commit и pre-push ищут реестр так же, как гейт, а без
  реестра говорят об этом и выходят с exit 2 — вместо прежнего тихого нуля
  (T-01).
- **Значимость не выключается опечаткой.** Незнакомое имя триггера — ошибка
  вызова с ближайшим каноническим (раньше `new_components` молча занижал
  маршрут), маршрут из диффа опознаёт контракт по содержимому и каталогу, а не
  по слову в имени файла, и видит новые сущности модели (T-04, T-05).
- **Одна форма базы диффа.** `A`, `A..B`, `A...B` разбираются в одном месте:
  документированный `origin/main...HEAD` больше не превращается в
  `...HEAD...HEAD` и не уводит гейт в fail-safe Critical (T-03).
- **Контракты: тело ответа и обязательность тела запроса.** `CD-009` — поле
  исчезло из тела ответа, `CD-010` — `requestBody.required: false → true`;
  параметры за `#/components/parameters/…` резолвятся. Раньше удаление поля из
  ответа давало «breaking: 0 … PASS» (Д5).
- **Инвариант → исполняемая проверка.** `arch-be rules template list` —
  библиотека шаблонов `command_succeeds` (идемпотентность, неопределённый
  исход, сага с резервом, единственный источник истины, журнал append-only,
  ПДн в журналах, согласие до автодействия, проверка до побочного эффекта) на
  python и Java: `apply` кладёт тест свойства и эталонную реализацию в кейс,
  `verify` доказывает, что тест падает на нарушающей. `rules_suggest` называет
  **каждый** инвариант без проверки поведения, паспорт вердикта печатает их
  поимённо. Подробности — ADR-050,
  `docs/experiments/executable-invariants-2026-09-20.md`.
- **Заготовка больше не выглядит пройденной проверкой.** Отчёт репетиции отката
  из `bootstrap` объявляет себя заготовкой (`passed: false`), а
  `evidence verify` ловит `rehearsal_empty` и якорь, не резолвящийся в коммит
  (Д8, ADR-049). Цитата-свидетельство судьи рубрики сверяется в **каждом**
  сэмпле, а не только у выбранного под медиану (Д10).

Релиз про **честную границу зелёного** — три вещи, которые раньше приходилось
объяснять словами, теперь печатает сам контур:
