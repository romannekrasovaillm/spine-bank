# Рубрики и бенчмарки

Движок рубрик архитектурного контроля (`src/rubric.rs`) и специализированные
бенчмарки solution architecture (`src/bench.rs`). Идеи — корпоративная
матрица оценки из `docs/SOURCE_BRIEF.md` §C и таксономия Macedo §D.

## Якорные рубрики

Десять готовых YAML в `assets/rubrics/` (после `arch-be init` —
`~/.arch-harness/assets/rubrics/`). Шесть оценивают **качество документа**,
четыре — **смысл связей и утверждений** и работают по досье (см. ниже):

| Файл | Критериев | Назначение |
|---|---|---|
| `solution_architecture.yaml` | 15 | Комплексная оценка документа solution-архитектуры банка: корпоративный охват, качество решения, NFR, проверяемость, стоимость внедрения (сумма весов 100). |
| `architecture_gates.yaml` | 6 | Полнота контрольных точек A0–A5 в пакете изменения: fit → impact → trigger → human decision → evidence → drift. |
| `adr_quality.yaml` | 5 | Качество ADR: контекст и силы, альтернативы, отрицательные последствия, обратимость, статус-дисциплина (AWS AI-DLC). |
| `handoff_quality.yaml` | 5 | Качество handoff-пакета кодовому харнессу: epic-context, инварианты, критерии приёмки, headless-контракт, план отката. |
| `macedo_dimensions.yaml` | 6 | Шесть измерений таксономии Macedo (arXiv:2606.04967): спецификация, контекст, роли, исполнение, валидация, портируемость; шкала 0–2 отображена на 1–5. |
| `agents_md_quality.yaml` | 5 | AGENTS.md как канал архитектурного контроля: команды проверяемы, инварианты названы, стоп-условия эскалации есть, зоны не перепутаны, заглушек нет. |
| `adr_spine_consistency.yaml` | 4 | **Смысловая** (досье `adr_vs_spine`): решение не разрешает того, что запрещает инвариант спайна. Класс `D10`. |
| `model_link_semantics.yaml` | 4 | **Смысловая** (досье `entity_links`): роль сущности-цели в ссылке соответствует её ответственности. Класс `D6`. |
| `nfr_mechanism_fit.yaml` | 4 | **Смысловая** (досье `nfr_mechanism`): привязанный решением механизм способен дать обещанный показатель. |
| `code_invariant_conformance.yaml` | 3 | **Смысловая** (досье `code_vs_spine`): в коде нет конструкции, нарушающей инвариант, и нет обхода защиты. Класс `D11`. |

`arch-be rubric list` — список с числом критериев. У смысловой рубрики в YAML
объявлен вид досье (`pack:`), у главного критерия — `blocking: true`: по нему
составляющая гейта `semantic_quality` строит блокирующую находку. Рубрика с
досье, запущенная по обычному документу, — ошибка вызова, а не оценка не по
тому входу: второй стороны противоречия судья не увидит.

### Схема YAML рубрики

```yaml
name: adr_quality                 # имя (snake_case)
description: "Что измеряет рубрика"
scale_max: 5                      # максимум шкалы
origin: anchor                    # anchor | dynamic (проставляется движком)
criteria:
  - id: alternatives              # snake_case
    name: Альтернативы
    description: "Что оценивается"
    weight: 3                     # вес; сумма произвольна, нормируется при подсчёте
    anchors:                      # якоря уровней (опционально): «1» → отсутствует, «5» → образцово
      1: "Альтернатив нет"
      3: "Перечислены, но картонны"
      5: "Реальные, с честными причинами отказа"
    evidence_on: low              # когда цитата обязательна (ADR-051); дефолт high — поведение 0.3.4
    evidence_roles: [subject, reference]   # из каких источников досье нужны цитаты (ADR-051)
```

Загрузка — `rubric::load`; битые файлы в каталоге пропускаются при листинге.

**Направление доказательства (`evidence_on`, ADR-051).** В обычной рубрике
цитата обязательна при балле ≥ 2 — это цитата за похвалу. В смысловой рубрике
обвинение устроено наоборот: противоречие — это **низкий** балл, и цитата нужна
именно там. `low` требует цитату при балле ≤ 2 («1» в таком критерии означает
найденное противоречие, а не отсутствие свидетельства — промпт судьи это
называет), `both` — на обоих концах шкалы, `high` (дефолт) сохраняет поведение
0.3.4.

**Роли источников (`evidence_roles`, ADR-051).** `[subject, reference]` требует
**две** цитаты, и каждая сверяется только со своим источником досье: цитата из
ADR не засчитывается как цитата из спайна. Формат — `Цитата subject: "…". Цитата
reference: "…".` Неподтверждённое обвинение даёт метку `accusation_unconfirmed`:
критерий исключается из взвешенного итога, но блокирующей находкой не
становится — выдуманное обвинение наказывает судью, а не документ. Доля сэмплов
с неподтверждённой цитатой пишется в `evidence_unconfirmed_ratio` (сверка идёт в
каждом сэмпле, а не только в обосновании под медиану).

**Покрытие вместо цитаты (`coverage`, ADR-051).** Отсутствие противоречия цитатой
не докажешь — отсутствие не цитируется. Критерий с `coverage: reference_ids`
требует от судьи при балле ≥ 4 перечислить в ответе (`checked`) идентификаторы
**всех** проверенных ссылочных источников досье; механика сверяет перечень с
составом досье, и пропуск хотя бы одного даёт метку `coverage_incomplete` с
исключением критерия из итога. Это не доказывает, что судья думал, но не даёт
поставить «5» не глядя. Критерий с покрытием, оценённый по документу **без**
досье, — явная ошибка `coverage_without_dossier`: сверять перечень не с чем.

Все три секции аддитивны: рубрики без них читаются и оцениваются как раньше, и
промпт судьи для них побайтно прежний.

## LLM-судья (`rubric::evaluate_with_options`)

Калибровка и верификация — ADR-004 (`docs/adr/ADR-004-rubric-judge-calibration.md`),
настройки — секция `[judge]` конфига (`config.example.toml`).

- Системный промпт: судья — **независимый рецензент** («ты не проектировал
  эту систему — твоя работа найти, что сломается»). Каждая оценка ≥ 2 обязана
  начинаться с **дословной цитаты** из текста (`Цитата: "…"` в `rationale`);
  свидетельства нет — балл 1 с пометкой «свидетельство отсутствует» (цитата
  не требуется). Это и есть evidence-подход: оценка без опоры на текст
  запрещена — и теперь проверяется механически.
- **k-сэмплов** (`judge.samples`, по умолчанию 3): критерий оценивается k
  независимыми прогонами, итоговый балл — округлённая медиана; population-σ
  сэмплов выше `judge.unstable_stdev` (1.0) → метка **`unstable`** у критерия.
- **Верификация цитаты**: извлеченная из `rationale` цитата сопоставляется с
  оцениваемым текстом (нормализация регистра/пробелов → точный substring,
  иначе fuzzy по словам крейтом `similar`, порог `judge.evidence_min_similarity`
  = 0.8). Не подтверждена → метка **`evidence_not_found`**, критерий
  **исключается из взвешенного итога** (балл виден в отчёте); если засчитанных
  критериев не осталось — ошибка. Кросс-строчные цитаты поддерживаются:
  литеральные `\n`/`\r`/`\t` (два символа — судьи часто присылают перевод
  строки в escape-форме) в **цитате** приводятся к пробелу перед
  нормализацией (волна E); сам документ при сверке не изменяется, порог
  0.8 прежний.
- **Лимит длины**: текст длиннее 24 000 символов (`MAX_TARGET_CHARS`) —
  **явная ошибка** с лимитом и фактической длиной (в инструменте —
  `ToolOutput::err`), а не тихое усечение, как раньше.
- **Изоляция от prompt injection**: оцениваемый текст оборачивается маркерами
  `=== НАЧАЛО/КОНЕЦ ОЦЕНИВАЕМОГО ТЕКСТА ===`; промпт предписывает судье
  игнорировать любые инструкции внутри маркеров.
- **JSON-контракт ответа** (строго один объект, без markdown-обёрток):

```json
{"scores": [{"criterion_id": "<id>", "score": 1, "rationale": "Цитата: \"<фрагмент>\". <пояснение>"}],
 "verdict": "<1–2 предложения: главный риск и готовность>"}
```

- Разбор терпим к обёрткам (извлечение от первой `{` до последней `}`),
  балл принимается числом или строкой с числом. При неудаче — **один retry**
  с инструкцией «только JSON»; повторная неудача — ошибка `HarnessError::Rubric`
  с фрагментом ответа.
- **Транспортная устойчивость**: вызов судьи повторяется один раз при
  сетевой/декод-ошибке самого `complete` (наблюдение симуляции: «судья дал
  ошибку декодирования, ручной повтор прошёл» — теперь повтор встроен).
  Методологически рубрика не может быть единственным гейтом приёмки:
  LLM-оценка недетерминирована — сочетайте с fitness-правилами и контрактом
  результата (он машиночитаемый).
- Постобработка: баллы сэмплов клэмпятся в `1..=scale_max`; критерии,
  пропущенные судьёй в сэмпле, получают в нём 1; обоснование — из сэмпла с
  медианным баллом (иначе первое непустое, иначе «судья не оценил»);
  порядок — как в рубрике.
- **Взвешенный итог**: `weighted_total = Σ(score·weight) / Σweight` по
  засчитанным критериям (без `evidence_not_found`). Сумма весов ≤ 0 — ошибка.

### Запуск

```bash
arch-be rubric run adr_quality docs/adr/ADR-001-kafka.md
arch-be rubric run solution_architecture docs/solution.md --model deepseek-pro
```

Отчёт — markdown: таблица «критерий | вес | балл | метки | обоснование»
(метки: `unstable (σ=…)`, `evidence_not_found`), взвешенный итог со списком
незасчитанных критериев, вердикт, имя судьи с числом сэмплов, дата. Пишется
в `reports/rubric-<name>-<timestamp>.md`. В TUI: `/rubric list`,
`/rubric run <name> <file>` (отчёт — в чат и на вкладку «Рубрика»).

### Происхождение оценки (ADR-048)

Вместе с машиночитаемым отчётом (`reports/rubric/<slug>.json`) сохраняются
**сырые ответы судьи** — `reports/rubric/raw/<slug>/sample-<n>.json` — и их
хэши в поле `provenance.samples`. Отчёт дополнительно несёт `provenance`
(режим `declared` — метки передал хост, `launched` — судью запустил Spine) и
`scores` (баллы по критериям). Из этих двух свидетельств отчёт пересобирается
тем же кодом, без LLM:

```bash
arch-be rubric reverify reports/rubric/ADR-001-kafka.json   # или каталог
```

Расхождение (`критерий 'x': в отчёте 5, из сырых ответов 3`) — код 1. В гейте
то же делает составляющая `decision_quality`: `rubric_report_inconsistent`
(балл правили руками) и `rubric_raw_tampered` (правили сохранённый ответ).
Отчёт без сырых ответов честно называется невоспроизводимым — это не находка.

**Отчёт по досье (E1.3):** изменение источника после оценки — не расхождение
балла, а устаревание входа: `✗ … досье устарело — src/control.rs — изменён
после оценки` и код 1. Сверка сравнивает записанные `pack_sha256` и поимённые
хэши `inputs` с досье, пересобранным из репозитория; отчёт без отпечатка досье
(записанный до 0.3.8) не штрафуется — сверять не с чем.

**Гейт (E1.4):** отчёты по досье судятся той же составляющей `decision_quality`
наравне с ADR: `rubric_report_stale` (досье изменилось после оценки),
`rubric_raw_tampered`, `rubric_report_inconsistent`; отчёт по досье без сырых
ответов — warn `rubric_report_unreproducible` (read-only контур MCP файлов не
пишет, провалом это краснило бы настройку, а не решение).

**Решение рубрики (E4.1).** У отчёта есть одно слово для CI и человека:
`pass` — механика не нашла ничего, чего она не подтверждает; `fail` —
подтверждённое нарушение (блокирующий критерий низкий, цитаты на месте);
`human` — решает человек (инъекция во входе, невалидные сэмплы,
неподтверждённое обвинение, неполное покрытие, `evidence_partial`). Решение
лежит в отчёте (`decision`, `decision_reasons`), в markdown-шапке и в ответах
MCP; `arch-be rubric run` возвращает его код выхода: 0 / 1 / 2. Порог
взвешенного итога в решение не входит — это политика маршрута.

**Политика маршрута (E4.2).** Что делать с решением `human`, решает проект:
`[gate.decision_policy] fast|standard|critical = "warn" | "human"` (дефолт
warn / warn / human). По умолчанию блокирует только Critical: там
неподтверждённое обвинение, неполное покрытие и частично не подтвердившиеся
свидетельства дают error-находку и SKIP составляющей → вердикт INCOMPLETE, а
решение принимает человек. На Fast/Standard то же состояние — предупреждение.
Инъекция во входе и невалидные сэмплы политике не подчиняются: они блокируют
на любом маршруте. Находки судьи видны и в машинном формате: `arch-be gate
--format sarif` несёт идентификатор правила, файл-субъект и цитаты обеих ролей
(E4.3).

**Квалификация судьи (E6.1–E6.3).** Механика проверяет честность цитат и
полноту, но не правильность суждения; поэтому судья измеряется на эталонном
наборе. `arch-be rubric qualify <рубрика> --set assets/qualification/code_vs_spine`
прогоняет модель по 30 случаям с известной истиной (пять классов дефектов плюс
чистые) и пишет `reports/qualification/<рубрика>--<модель>.json` с полнотой,
точностью и долей `human` по классам, версией модели и хэшем набора. Пороги
допуска — полнота ≥ 0.8, точность ≥ 0.8, `human` ≤ 0.5. Требование допуска
включается проектом: `require_qualified_judge = true` в
`[gate.decision_quality]`/`[gate.semantic_quality]` — тогда на блокирующем
маршруте судья без пройденной квалификации получает `judge_unqualified` →
INCOMPLETE; по умолчанию флаг выключен (поведение 0.3.8). Проверка действует
для отчётов по досье (там, где есть эталонный набор). Формат набора открыт: новый случай — файл в
`code/` и строка в `cases.yaml`.

**Регрессия квалификации (E6.4/E6.5).** Шкала `trust` называет смысловую долю
обнаружения по классам дефектов из отчёта квалификации (модель, вердикт допуска;
нет отчёта — «не измерена»). Повторная квалификация: `arch-be rubric qualify …
--check` сверяет записанный отчёт с текущим набором и порогами, не вызывая
судью, — код 1 и причина, если набор изменился или пороги не пройдены. Смена
`judge_model` видна сразу: у новой модели отчёта нет, и допуск (если включён)
не пройден до квалификации.

**Детекторы в досье (E7.1/E7.2).** Результаты механического контура входят в
досье ролью `detector`: `reports/detectors/<имя>.json` c
`{"name": "...", "status": "pass"|"fail", ...}` (пишет проект или CI). Их хэши
входят в `pack_sha256`, поэтому отчёт привязан к срезу измерений. Если детектор
красный, а судья ставит «чисто» (балл ≥ 4 у блокирующего критерия), критерий
получает метку `detector_contradiction` и решение уходит человеку — «судья не
согласовал вердикт с измерением». Согласие и зелёные детекторы метки не дают;
промпт судьи прямо говорит, что роль `detector` — измерение, а не мнение.

**Стоимость ревью (E8.3).** Отчёт рубрики хранит время судьи
(`judge_duration_ms`) и токены (`judge_prompt_tokens` / `judge_completion_tokens`),
JSON-близнец несёт то же в историю, а `arch-be metrics` печатает строку
«Смысловые ревью (E8.3)»: прогонов со стоимостью, решения по типам, суммарное и
среднее время, токены и токенов на решение. Токены приходят из `usage` ответа
провайдера (`LlmProvider::complete_with_usage`); если провайдер их не отдаёт,
прогон в стоимость не попадает — неизвестная цена не читается как нулевая.
Два прогона в одну секунду получают разные имена файлов (`…-120000-2`), поэтому
история и стоимость не теряют ревью.

**Кэш вердикта (E8.2).** `[judge] cache = true` — вердикт повторно не
покупается: запись лежит в `$ARCH_HOME/state/judge-cache.json` под ключом из
хэшей рубрики, модели, оцениваемого текста и настроек судьи. Неизменённое досье
отдаёт вердикт без вызова модели; правка кода, смена модели или порогов
промахиваются. Попадание видно в отчёте (`provenance.cache`) и в stderr
(«Вердикт из кэша: снят …, предъявлен N раз(а)»), обход — `--no-cache`.
Сырые ответы судьи едут вместе с записью, поэтому `rubric reverify` работает и
для вердикта из кэша. По умолчанию кэш выключен; маршрут `declared`
(split-judge через MCP) не кэшируется — там модель вызывает хост.

**Адаптивные сэмплы (E8.1).** `[judge] adaptive_samples = true` экономит
вызовы судьи на однозначных ответах: первый ответ, где все критерии получили
балл на краю шкалы (`1` или `scale_max`), принимается без добора сэмплов; балл в
зоне сомнения (`2..scale_max-1`), балл вне шкалы или неоценённый критерий
добирают выборку до `samples`. По умолчанию режим выключен: одиночный ответ —
это один голос из трёх, и расхождение сэмплов режим не ловит, поэтому экономия
проверяется квалификацией на эталонном наборе (E6), а число сэмплов видно в
отчёте.

**Повторяющиеся находки → кандидаты в правила (E7.3).** История отчётов рубрик
живёт в архиве (`$ARCH_HOME/reports`): `rubric run` пишет markdown для человека и
JSON-близнеца для механики. `arch-be rules suggest --from-judge [--history <каталог>]
[--min-runs N]` читает архив (порог по умолчанию 3 прогона) и предлагает
детерминированные правила там, где судья повторяется: обвинение с подтверждённой
цитатой, встретившееся на двух и более разных целях, даёт готовый фрагмент
`must_not_contain` (цитата → запрещённый паттерн, regex-экранированный); повтор
метки механики (`evidence_not_found`, `unstable`, `accusation_unconfirmed`, …) —
advisory без механики. Обвинения с неподтверждённой цитатой в правила не попадают:
закреплять ошибку модели нельзя, но повод для пересмотра рубрики виден. Кандидаты
только предлагаются — реестр правил меняет человек.

**Второй судья (E5.1).** На маршруте Critical одной модели мало: уверенная
ошибка с настоящей цитатой механике не видна (цитата есть, перечень полон).
`arch-be rubric run <рубрика> --pack <вид> --subject <субъект> --second-model
<имя из [models]>` судит вход дважды независимо: у каждого судьи свой отчёт
(`<slug>.json` и `<slug>--second.json`), свои сырые ответы и своё происхождение.
Решения и итоги сравниваются с допуском `0.75`; расхождение — решение `human`
(код выхода 2), причина в `decision_reasons`, сводка — в поле `second_judge`
основного отчёта, находка гейта — `judge_disagreement` (блокирует по политике
маршрута, `[gate.decision_policy]`). Пока парный прогон поддержан для досье
(`--pack`); парный прогон по документу — следующий шаг.

**Инъекции на входе (E2).** У собранного досье нет шапки,
поэтому автор кода берётся из **контракта передачи**: `MANIFEST.json`
handoff-пакета называет модель-исполнителя. Приоритет источников — шапка
документа → `--author-model` → контракт → «неизвестен» (`author_source`:
`header` / `argument` / `contract` / `none`). С известным автором уровень
`independence` вычисляется по составу судьи и автора (`declared`,
`declared_cross_family`, `launched`, `launched_cross_family`) вместо `none`, а
совпадение судьи с автором кода даёт `independence: none` и находку
`judge_is_author`: судья, проверяющий собственный код, независимым не считается.

**Решение архитектора (E4.5).** Ответ человека на решение `human` — запись в
репозитории, а не галочка: `arch-be rubric decide reports/rubric/<slug>.json
--accept --by "Иван Петров <ivan@bank>" --reason "риск принят"` пишет
`reports/human/<slug>.decision.json` (кто, когда, что, почему и SHA-256 файла
отчёта) и печатает готовую строку подписанного коммита. Гейт читает запись:
`accept` снимает эскалацию оговорок судьи — находка остаётся видимой как
`human_decision_accepted` с именем и датой, а вердикт не блокируется; `reject`
оставляет эскалацию. Правка отчёта после решения решение обесценивает (хэш не
сходится) — решение относится к конкретной ревизии отчёта. Инъекция во входе и
невалидные сэмплы решением не снимаются: там вопрос не в политике, а в доверии
к суждению.

**Пакет архитектору (E4.4).** На каждое решение `human` `rubric run` кладёт
`<repo>/reports/human/<slug>.md`: субъект, решение, судья, итог, причины,
таблица баллов с обоснованиями судьи, путь отчёта и каталог сырых ответов и
три шага для человека (подтвердить/отклонить, записать подписанное решение,
приложить контрдовод в эталонный набор). Пакет коммитится вместе с отчётом.

**Качество ответа судьи (E3).** Балл вне шкалы (`9` при `scale_max: 5`) —
невалидный сэмпл, а не пятёрка после обрезки: ответ перезапрашивается, а
выживший невалидный сэмпл не голосует за балл, получает метку `invalid_samples`
и виден в доле `invalid_samples_ratio`. Отчёт при этом собирается — иначе
аудировать нечего, — но гейт при доле выше порога
(`[gate.decision_quality]/[gate.semantic_quality] max_invalid_samples_ratio`,
дефолт `0.5`) уходит в SKIP: вердикт INCOMPLETE, решение за человеком; ниже
порога — предупреждение. Оговорка `evidence_partial` (часть свидетельств не
подтвердилась) на маршруте Critical тоже уходит человеку, на Fast/Standard
остаётся предупреждением.

**Инъекции на входе (E2).** Тот же детектор, что предупреждает о выводе
инструментов чтения (ADR-038), прогоняется по входу судьи; кроме английских
формул он ловит **директиву вердикта** на обоих языках («отметить как чистую»,
`mark as compliant`, `do not flag`) — именно такую инъекцию подсовывает стенд
`spine-judge-bench`, и прежний англоязычный набор её пропускал — по документу и по
тексту досье. Помеченные строки (номер + паттерн) попадают в отчёт
(`input_injections`), в машиночитаемый отчёт (`input_injection_lines`) и в ответ
`rubric_prompt` хосту; в промпте судьи стоит предупреждение с их перечнем.
Цитата из помеченной строки свидетельством не засчитывается: сверка идёт
повторно по тексту без таких строк, критерий получает метку `injection_quote` и
остаётся без подтверждённых цитат. Если инъекция была единственным источником
свидетельств, отчёт собирается (число — «что поставил судья»), но решение по
нему механика не принимает: `semantic_quality`/`decision_quality` дают находку
`semantic_input_injection`/`rubric_input_injection`, составляющая уходит в SKIP,
а вердикт гейта — **INCOMPLETE** (exit 3). Это и есть решение `human` из
архитектурного ревью: спорное уходит человеку, а не тонет в PASS.

Что происхождение **не** удостоверяет: какая модель отвечала, механика не
знает ни в одном режиме; `operator` — запись из git-конфига, а не подпись.
Подробности и границы — `docs/adr/ADR-048-…md`.

### Досье судьи: вход для смысловых рубрик (ADR-051)

Рубрика качества судит **один** документ на качество. Смысловая ошибка —
противоречие между двумя артефактами (решение против инварианта спайна,
ссылка не на ту сущность, код против инварианта), и судье нужен не документ,
а набор источников. Этот набор собирает **досье**:

```bash
arch-be rubric pack adr_vs_spine docs/adr/ADR-051-x.md
arch-be rubric pack entity_links INT-001 --root кейсы/salary-payments
arch-be rubric pack code_vs_spine src/gate.rs        # большой файл делится на фрагменты
arch-be rubric pack code_vs_spine src/gate.rs#3422-3561   # фрагмент адресуется поимённо
```

| Вид досье | Субъект | Состав |
|---|---|---|
| `adr_vs_spine` | путь к ADR | ADR целиком + инварианты спайна (`AD-n`) и отложенные решения (`DEF-n`) |
| `entity_links` | идентификатор сущности | карточка субъекта + карточки всех целей его связей; для `INT` — очерк файла контракта |
| `nfr_mechanism` | идентификатор `NFR-…` | карточка NFR + ADR и компоненты, привязанные трассировкой в обе стороны |
| `code_vs_spine` | путь к файлу кода | файл (или фрагмент) + инварианты спайна |

Каждый источник обрамлён маркером `=== ИСТОЧНИК <роль>: <путь> === … ===
КОНЕЦ ИСТОЧНИКА ===`; роли — `subject` и `reference`. Печатаются хэш досье
(SHA-256 собранного текста) и поимённые хэши источников: правка **любого** из
них — в том числе спайна, а не субъекта, — обесценивает отчёт. Свойства
сборки: тот же репозиторий даёт побайтно тот же текст; маркер внутри источника
— ошибка сборки, а не экранирование; лимит 24 000 символов без тихого
усечения; источник с секретом — досье не выдаётся вовсе (`pack_contains_secret`).

В MCP досье запрашивается у `rubric_prompt`/`rubric_verify` аргументами
`pack`+`subject` (взаимоисключающи с `target`/`target_text`); отчёт по досье
ложится в `reports/rubric/` под именем `<субъект>--<вид>.json` с полями
`pack_kind`, `subject`, `pack_sha256`, `inputs`.

Отчёт по досье пишет **сырые ответы судьи и происхождение** так же, как отчёт
по документу (ADR-048): `reports/rubric/raw/<субъект>--<вид>/sample-<n>.json`,
поля `provenance` (режим `launched` у `rubric run --pack`, `declared` у
split-judge) и `judge_config`. `arch-be rubric reverify` воспроизводит такой
отчёт, пересобирая досье из репозитория тем же кодом сборки; отчёт по досье
без сохранённых ответов (записанный ранними версиями) честно называется
невоспроизводимым — как и у документа, это граница проверки, а не находка.

## Динамические рубрики

Под предмет оценки, которого нет в якорных, рубрика генерируется моделью

### Golden-set: калибровка судьи (ADR-004)

`assets/benchmarks/golden/` — 7 маленьких синтетических ADR (`<имя>.md`) с
эталонными оценками (`<имя>.expected.yaml`: рубрика + баллы по критериям
`adr_quality`). Прогон судьи по набору и согласие с эталоном:

```bash
arch-be bench run --golden                     # судья — модель по умолчанию
arch-be bench run --golden --model glm-flash   # дешёвый регрессионный прогон
```

- Метрика — **MAE** (среднее |судья − эталон| по всем парам
  «документ × критерий»); печатается по каждому документу и итогом.
- Отчёт дополнительно печатает **MAE по критериям** (критерий → MAE по всем
  документам) и **length bias** — корреляцию Спирмена взвешенного балла
  с длиной документа в символах отдельно для судьи и эталона
  (`length bias: судья ρ=…, эталон ρ=…`); ρ судьи заметно выше ρ эталона —
  признак смещения судьи к длинным текстам. При менее чем двух документах
  строка не печатается (корреляция не определена).
- Итоговый MAE выше порога `judge.golden_max_mae` (по умолчанию 1.0 балла)
  → **exit code 1**: регрессионный гейт качества судьи для CI (ловит правки
  промпта/рубрики, уронившие согласие).
- Битый эталон (нет документа, балл вне шкалы, критерий вне рубрики) —
  ошибка данных, а не расхождение судьи.
- Live-режим: нужен API-ключ; юнит-тесты покрывают вычисления без сети,
  live-смоук — `cargo test -- --ignored golden_live`.
- **MAE-трекер (M-2)**: `arch-be bench run --golden --record <PATH>` дописывает
  результат строкой JSON в evidence-журнал (дата, модель, MAE, MAE по
  критериям, ρ судьи/эталона, число документов); история —
  `arch-be bench golden-history <PATH>` (markdown-таблица, битые строки
  журнала пропускаются с warn-строкой).
- **Согласие с живыми архитекторами (J-3)**: `arch-be bench human-agreement
  --golden-dir <DIR> --humans <DIR>` сравнивает golden-эталоны с медианой
  человеческих анкет (`<документ>.<участник>.expected.yaml` той же схемы):
  MAE эталона с людьми против межчеловеческого разброса + вердикт.
  Протокол сбора анкет и пересмотра эталонов — `docs/judge-human-agreement.md`.

### Golden-набор смысловых рубрик (ADR-051)

Смысловые рубрики калибруются поимённо: у каждой свой набор из шести
**досье** в `assets/benchmarks/golden/semantic/<рубрика>/`. Досье — не документ,
а замороженный вход судьи: тот же текст с маркерами источников, какой собирает
`arch-be rubric pack`.

```bash
arch-be bench run --golden --rubric adr_spine_consistency
```

Эталон — **диапазон**, а не точка (`no_contradiction: {min: 1, max: 2}`):
«противоречие найдено» это 1..2, и требовать ровно 1 значило бы мерить не то,
что рубрика обещает. Старый формат со скалярами читается как прежде.

Отчёт печатает три числа, а не одно: **попадание в диапазон** (доля пар
«критерий × досье», где балл судьи внутри), **ложные обвинения** на чистых
кейсах и **пропуски** на дефектных. В среднем MAE эти две ошибки взаимно
гасятся — поэтому каждая пара «досье + эталон» несёт метку `kind: clean |
defective`, и провалы считаются раздельно.

Пойманным считается главный критерий рубрики (`blocking: true`) ≤ 2 **с
подтверждёнными цитатами**: обвинение без цитат механика сама исключает из
итога, и записывать это судье в заслугу нельзя. Распределённый дефект вправе
жить во втором критерии (механизм достаточен, а проверка измеряет не то) —
набор это допускает, а строка «пропуск» тогда честно называет, что блокирующий
критерий его не увидел.

### Поставляемые сценарии (`assets/benchmarks/`)

Все шесть — банковский контур, порог `3.5`, рубрика `solution_architecture`;
первые три — про банк «Северный», следующие три — из реальных архитектурных сессий.

- **`payment_integration`** `[integration, adr, nfr, c4, payments]` —
  приём онлайн-платежей на маркетплейсе через внешний PSP: C4-диаграмма
  контейнеров (mermaid) с границей PCI/КИИ, два ADR (оркестрация платежа:
  новый сервис vs модуль ядра; токенизация картовых операций), NFR с
  измеримыми целями (p99 ≤ 1.5 с при 400 rps, RTO/RPO с обоснованием RPO=0,
  идемпотентность списаний и возвратов).
- **`legacy_decomposition`** `[brownfield, decomposition, reverse-discovery,
  delta-spec, legacy]` — декомпозиция монолита ядра 22 лет (PL/SQL + Java):
  честное reverse discovery (каждое утверждение с confidence high/medium/low,
  пробелы — явно в gaps, ничего не додумывать), выделение первого контура
  отсечения, дельта-спецификация brownfield-изменения.
- **`event_driven_design`** `[event-driven, integration, consistency,
  idempotency, kafka]` — событийная интеграция доменов «Кредиты» и
  «Клиентские коммуникации»: контракты событий, модель согласованности,
  идемпотентность консьюмеров, поведение при деградации; событийные
  решения фиксируются как ADR.
- **`pangolin_replication`** `[data, resilience, adr, nfr, replication]` —
  доставка данных боевого кластера Pangolin (Platform V, СберТех — сборка
  PostgreSQL, не MPP) на второй ЦОД для отчётности и DR при запрете потоковой
  репликации и Patroni-standby политикой ИБ: ADR с RTO/RPO-классами по каждой
  альтернативе (CDC wal2json → брокер → апплаер; снапшоты pgcopydb/pgloader;
  FDW; COPY-файлы), 2–3 spine-инварианта (Binds/Prevents/Rule), NFR (лаг CDC,
  рост WAL, ПДн в потоке), открытые вопросы с владельцами.
- **`gigachat_sla_resilience`** `[integration, resilience, adr, nfr, llm]` —
  устойчивый интеграционный слой AIGena → GigaChat API при отсутствии SLA
  (429/5xx под нагрузкой, 10 потоков юрлица, токен 30 мин, нет идемпотентности):
  ADR многослойной защиты (rate limiter под лимитами вендора, retry backoff+jitter
  с бюджетом, circuit breaker half-open, queue-leveller, cache-aside, fallback,
  RED-метрики и алерт по burn-rate 429), альтернативы с отказом, NFR (P99,
  допустимая деградация), риски.
- **`meta_agent_realtime`** `[data, ai, adr, nfr, c4, retrieval]` — агент ответов
  архитектору над репозиторием МЕТА (системы, ТчВ, ИВ, протоколы, владельцы —
  5+ таблиц с JOIN'ами) строго ≤10 секунд на техстеке банка (Pangolin, GigaChat
  без SLA): ADR (read-model витрина, двухканальный retrieval, LLM-слой с анти-429
  и кэшем, тайм-бюджет по этапам, retrieval-only fallback ≤2 с, freshness-NFR),
  C4-контейнеры (mermaid), альтернативы (text-to-SQL, function calling, локальная
  модель) с вердиктами.
