# Метрики обучения контура (learning-metrics/v1)

Команда `arch-be metrics --learning` сводит обучение контура в один отчёт из
двух источников: **журналы сессий** (`session-*.jsonl` в `paths.sessions_dir`)
и **реестр уроков** (`.arch/lessons/ledger.jsonl`, ADR-085). Это волна 1
задачи 0.5.0 «контур, который учится» (пункт L11): метрики показывают, учится
ли контур между задачами и во что это обходится, не полагаясь на свободный
текст LLM.

Все счётчики детерминированы: один и тот же журнал + реестр дают один и тот
же отчёт (байт-в-байт). Пустые значения выводятся как `null` (JSON) или
«данных нет» (markdown) — это честное «не измеряли», а не «ноль».

## Формат вывода

- `arch-be metrics --learning` — Markdown;
- `arch-be metrics --learning --json` — JSON со схемой `learning-metrics/v1`
  (поле `schema`). Версия схемы поднимается только при ломающем изменении
  полей; добавление полей совместимо внутри `v1`.
- `arch-be metrics --learning --repo <PATH>` — реестр уроков из `<PATH>` вместо
  текущего каталога.

## Поля отчёта

| Поле JSON | Тип | Смысл | Источник |
|---|---|---|---|
| `schema` | string | `"learning-metrics/v1"` — версия контракта | — |
| `repeat_failure_rate` | number \| null | Доля повторных FAIL: FAIL по сигнатуре, уже бывшей в реестре. `null` — FAIL не было | реестр |
| `repeat_failures` | integer | Число повторных FAIL (все FAIL минус первый на каждую сигнатуру) | реестр |
| `total_failures` | integer | Всего FAIL по всем сигнатурам | реестр |
| `prevented` | integer | Предотвращённых провалов: урок был в задании, сигнатура прошла гейт без FAIL (событие `hit`) | реестр |
| `dispatches_per_task` | number \| null | Прогонов исполнителя (`harness_run`) на задачу. `null` — задач не было | журнал |
| `total_dispatches` | integer | Всего прогонов `harness_run` | журнал |
| `total_tasks` | integer | Разных задач (ключ — явный `task` прогона, иначе `path`) | журнал |
| `lesson_statuses` | object | Распределение уроков по статусам (`observed`/`candidate`/`confirmed`/`promoted`/`retired`) | реестр |
| `lessons_total` | integer | Всего уроков в реестре | реестр |
| `promoted_rules` | integer | Промоутированных правил (уроков с заполненным `promoted_rule`, L7) | реестр |
| `lessons_block_prompt_share` | number \| null | Доля блока уроков в промпте (0..1). `null` — нет данных | реестр + журнал |
| `lessons_block_tokens` | integer | Оценка размера блока уроков в токенах (сумма рендеров уроков без `retired`, символы / 4) | реестр |
| `tokens_per_task` | number \| null | Токены на задачу (prompt + completion из записей `usage`). `null` — нет задач или usage | журнал |
| `total_tokens` | integer | Всего токенов (prompt + completion) из записей `usage` | журнал |
| `sessions_with_usage` | integer | Сессий, давших записи `usage` | журнал |
| `sessions` | integer | Сессий (журналов) всего | журнал |

## Семантика метрик

- **`repeat_failure_rate`** — прямой индикатор обучения (база в TASK §6):
  первый FAIL сигнатуры рождает урок, а повторный FAIL по той же сигнатуре
  означает, что урок не сработал. Низкая доля повторов = контур не наступает
  на одни и те же грабли. `repeat_failures = Σ max(fails − 1, 0)` по урокам.
- **`prevented`** — обратная сторона: сколько раз урок, будучи в задании,
  завершился PASS без FAIL по своей сигнатуре (счётчик `hits` реестра).
  Основа критериев E1–E3.
- **`dispatches_per_task`** — «прогонов исполнителя на задачу» (TASK §9):
  чем ближе к 1, тем меньше лишних прогонов после усвоения урока.
- **`lesson_statuses` / `promoted_rules`** — здоровье реестра: сколько уроков
  дошло до `confirmed`/`promoted` (E5 — самоужесточение контура).
- **`lessons_block_prompt_share`** — доля бюджета промпта, которую занимает
  блок уроков (L3): оценка размера блока — сумма детерминированных рендеров
  уроков без `retired` (символы / 4), делённая на сумму `prompt_tokens`
  usage-записей. Поле дополняет метрику состава промпта L9 (первый запрос
  ≤ 25 000 символов).
- **`tokens_per_task`** — стоимость обучения в токенах на одну задачу; при
  заданных тарифах моделей денежная стоимость видна в `metrics --cost-report`.

## Связь с остальными метриками

- Токены здесь — из записей `usage` журнала. Их пишет агент из
  `stream_options.include_usage` (стрим) и из `complete_with_usage`
  (нестриминг, закрывает B7): `arch-be metrics` без `--learning` показывает
  те же счётчики в «сводке» и «смете» (`--cost-report`).
- Отчёт о повторах FAIL→PASS по правилам гейта — в `arch-be digest`
  (`docs/outcome-metrics.md`), а не здесь: `digest` считает по журналу MCP,
  `--learning` — по реестру уроков и журналам сессий.
