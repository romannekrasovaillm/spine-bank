# 0.3.5: репродукции дефектов

Срез, на котором ищутся дефекты, — `0539223` (0.3.4, тег `v0.3.4`). Все
команды ниже проверены на **релизном** бинаре 0.3.4, скачанном из GitHub
Releases (`arch-be-linux-x86_64`, sha256 начинается на `9653f460`), — не на
отладочной сборке: дефект контура обязан воспроизводиться на том, что у
пользователя.

Каждая запись: команда → вывод → вердикт «воспроизведено / не
воспроизведено». Невоспроизведённое не чинится.

## T-01. Stop-хук молчит на красном кейсе от `bootstrap` — воспроизведено

```bash
cd /tmp && rm -rf t01 && mkdir t01 && cd t01
/…/arch-be-0.3.4-release bootstrap "Хук тест" --dir case
cd case && /…/arch-be-0.3.4-release connect claude
# кейс заведомо красный: каркас содержит заглушки
/…/arch-be-0.3.4-release gate --repo .
```

```
Итог: FAIL — провалено составляющих: 1 (exit 1)
Гейт поймал 13 нарушений до ревью — исправьте и перепроверьте
```

Команда Stop-хука из `.claude/settings.json`:

```sh
if command -v arch-be >/dev/null 2>&1 && [ -f .arch-handoff/CONSTRAINTS.yaml ]; then …
```

```bash
echo '{"hook_event_name":"Stop"}' | bash -c "$(python3 -c "import json;print(json.load(open('.claude/settings.json'))['hooks']['Stop'][0]['hooks'][0]['command'])")"
echo $?
```

```
0
```

**Причина в коде найдена:** гард `[ -f .arch-handoff/CONSTRAINTS.yaml ]`
(`src/connect.rs`, шаблоны `stop_hook_command` / `post_tool_use_hook_command` /
`pre_commit_hook_block`). `bootstrap` кладёт реестр в КОРЕНЬ кейса
(`src/bootstrap.rs`, `push("CONSTRAINTS.yaml", …)`), поэтому условие ложно и
хук завершается раньше гейта. Тот же гард стоит в шаблоне pre-commit
(`connect git-hooks`) — на кейсе с корневым реестром он так же мертв.

## T-02. `handoff_create` подменяет реестр правил — воспроизведено

```bash
cd /tmp/t01/case            # реестр в корне: 3 правила
/…/arch-be-0.3.4-release handoff --repo . --task "тестовая задача" claude-code
grep -c 'id: C-' CONSTRAINTS.yaml                 # 3
grep -c 'name:' .arch-handoff/CONSTRAINTS.yaml    # 1
/…/arch-be-0.3.4-release gate --repo .
```

```
[PASS] fitness * — Правил: 1, нарушений: 0 (error: 0, warn: 0); реестр: 1
правил (error: 0), отпечаток 5667359d — файл: .arch-handoff/CONSTRAINTS.yaml;
копии реестра различаются: используется ./.arch-handoff/CONSTRAINTS.yaml;
./CONSTRAINTS.yaml отличается (drift)
```

Гейт молча переключился на заготовку пакета (1 правило вместо 3), причём
расхождение двух копий — **пометка в тексте**, а не находка: вердикт
составляющей `fitness` остаётся PASS. Следствие из задания — `redteam` D7
(ослабление реестра) не ловится: он мутирует корневой файл, а гейт читает
пакетную копию.

## T-03. Двойной `...HEAD` — воспроизведено

```bash
/…/arch-be-0.3.4-release gate --repo . --route auto --base 0539223
/…/arch-be-0.3.4-release gate --repo . --route auto --base "0539223...HEAD"
```

```
Маршрут: Fast (auto: score 0 (триггеров нет))
Маршрут: Critical (auto: дифф недоступен (control: anti-bypass: . — база диффа
недоступна: неоднозначный аргумент «0539223...HEAD...HEAD»: неизвестная
редакция или не путь в рабочем каталоге. …) — fail-safe маршрут Critical)
```

**Причина в коде найдена:** `control::detect_diff_triggers` (`src/control.rs`)
формирует диапазон как `format!("{r}...HEAD")`, а шаблоны `connect`
(Stop-хук, pre-push, CI GitLab/GitHub) передают базу уже с `...HEAD`
(`src/connect.rs`). Документированная в `--help` форма `origin/main...HEAD`
ломает детектор — гейт всегда уходит в fail-safe Critical.
