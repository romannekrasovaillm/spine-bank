# Самоаудит: «агент в своём харнессе не использует свои инструменты» (SA-Bench)

Дата: 2026-10-12 · повод: критика Claude из SA-Bench (`Spine Harness — 0
вызовов инструментов Spine за 16 прогонов; ведёт себя как агент с bash`) ·
метод: самоаудит сессии 0.3.17→0.4.3 + немедленная живая демонстрация
забытых нативных инструментов.

## 1. Критика подтверждена самоаудитом

Распределение вызовов за кампанию (примерно):
- оркестрация (мой слой): harness_run ×12, handoff_create ×8,
  subagent_* ×8, rubric_* ×12, significance_score ×1;
- базовые: bash ~80+, файловые ~25;
- **архитектурные MCP-инструменты Спайна нативно: 0** (fitness_check,
  spine_lint, adr_registry, trace_check, model_query, change_impact,
  contract_diff, landscape_report, kb_search — не вызывались; всё
  эквивалентное делалось CLI через bash).

## 2. Что оправдано, а что — упущение

**Оправдано (специфика задачи):** продукт этой сессии — сам бинарь;
приёмка требует живых прогонов релизной сборки (`ARCH_BE=target/release`),
MCP-инструменты гоняют ту же механику в другом фронтене. Тестировать
deliverable = вызывать deliverable. Конвейеры (cmp/wc/grep/python) в bash
для сравнения прогонов также вне возможностей MCP-инструментов.

**Упущение (реальное):** инструменты, дающие находки по СОСТОЯНИЮ репо, а
не по бинарю, — adr_registry после добавления 11 ADR, spine_lint,
kb_search перед новыми задачами, landscape_report — не вызывались ни разу.

## 3. Немедленная проверка забытых инструментов — находки

| Инструмент (нативно) | Результат |
|---|---|
| `adr_registry` | **13 находок**; 1 — из моей кампании: ADR-070 «объявляет исключение без обоснования» — маркер `override` в строке провенанса (упоминание, не объявление). **Исправлено** переформулировкой провенанса («узаконенные переопределения правил»). Остальные 12 — исторический долг (ADR-005…067, до кампании) |
| `spine_lint` | нарушений нет |
| `model_query` (кейс) | работает: 51 сущность digital-ruble-merchant, 7 ADR |
| `trace_check` | у spine-bank нет `model/` (архитектура — spine+CONSTRAINTS) — честный отказ, не сбой |
| `fitness_check` | **таймаут 300 с** против 0.7 с CLI-дог-фуда с ARCH_NO_EXEC=1: нативный вызов исполняет `command_succeeds` (включая `cargo test`) — различие окружений, невидимое из bash-привычки |
| `landscape_report` (кейсы) | 24 системы набора, дедупликация, 1 находка id-divergence («Core Banking (АБС)» в двух проектах с разными INT) |

Вывод: один запуск нативных инструментов дал **1 исправление + 1
продуктовую находку + 1 различие окружений** — упущение было не косметикой.

## 4. Продуктовые выводы (в дополнение к SA-Bench)

1. **Подтверждаем рекомендацию SA-Bench «пилот на Spine Core, не Harness»**:
   мой собственный случай — прямая иллюстрация; сильный агент по умолчанию
   выбирает привычный bash даже внутри своего харнесса. Лечится не
   убеждением, а контуром: гейт/CI требует arch-be явно (реестр правил —
   задача архитектора, не агента).
2. **Бэклог-находка из детектора:** `declares_exception` (E10.2) матчит
   маркеры в любой строке ADR — включая провенанс/упоминания (ADR-070).
   Кандидат на уточнение: скопировать матчинг на секцию Decision (или
   исключать строку провенанса). Детектор честен (правило E10.2 требует
   отчёт обоснования), но генерирует ложный шум на упоминаниях.
3. **Правило для себя (зафиксировано здесь):** после правок ADR/спайна —
   `adr_registry` + `spine_lint` нативно до коммита; перед новой темой —
   `kb_search` до веба (моё же правило из системного промпта, которое я
   нарушал); нативный `fitness_check` — осознанно с учётом исполнения
   команд (на больших репо — ограничивать).
