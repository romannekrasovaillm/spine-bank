# Эквивалентные мутанты: исключения ночной джобы `mutants`

Ночная джоба `mutants` (`.github/workflows/nightly.yml`) краснеет на выживших
мутантах. Норма реакции — **тест**: если мутанта можно различить на входе,
который контур обязан разбирать, значит поведение не покрыто, и место ему в
тестах, а не в списке исключений.

Исключение (`exclude_re` в `.cargo/mutants.toml`) допустимо ровно в одном
случае: **мутант неразличим на корректном входе** — обе ветки дают один
вердикт, одну находку и одно сообщение. Такое исключение не ослабляет
контур: оно фиксирует, что сигнал относился к невалидному входу, который
контур не обязан разбирать, а не к пробелу в тестах.

Каждая строка исключения обязана иметь здесь обоснование: что именно
подменяется, почему на корректном входе разницы нет и каким тестом эта
граница удержана.

## Список

### `src/contract_diff/ddl.rs`: `replace && with || in parse_column_def`

```rust
if !type_tokens.is_empty() && SQL_CONSTRAINT_WORDS.contains(&stripped) {
    break; // тип кончился: первое слово-ограничитель
}
type_tokens.push(tok);
```

Мутация `&&` → `||` меняет поведение только когда **первое** слово после имени
колонки само является словом-ограничителем (`NOT`, `DEFAULT`, …): оригинал
берёт его как тип, мутант обрывает тип сразу и получает пустую строку.

В корректном DDL тип идёт первым (`c bigint not null`), поэтому ветки
совпадают: тип непуст, ограничитель встречается позже. Разница достижима
только на определении колонки без типа (`c not null`), то есть на DDL,
который контур не обязан разбирать. Граница удержана тестами
`ddl_type_change_incompatible_breaking_widening_warn`,
`alter_column_set_data_type_is_applied` и
`parameterized_type_widening_requires_same_name_and_params`: они проверяют
разбор типов на корректных определениях и падают, если разбор типов сломан
по-настоящему.

## Чего в списке быть не должно

- Мутанты, различимые на валидном входе (например, короткие формы
  `ALTER TABLE t ADD c int` — они закрыты тестом
  `short_alter_actions_without_column_keyword_are_applied`).
- Мутанты «не падает, а молчит»: если подмена убирает находку или вердикт,
  которые контур обязан выдавать, это пробел в тестах, а не эквивалентность.
