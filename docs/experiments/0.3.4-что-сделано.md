## 4. Что не сделано

Волны C и W ТЗ не начаты. Это не «перенесено осознанно» — работа в сессии
закончилась на волне B, и ниже честный список.

- **Волна C (P2)** — ни один пункт: Н8 (имена аргументов MCP и `serde(alias)`
  для `path`), Н9 (`adr registry` и формы прозы `Статус`/`Status`), Н10
  (эвристика `executable-invariants` в `rules-suggest`, абзацы в скиллы,
  метрика «доля правил, проверяющих поведение» в `rules-report`), Н11 (число
  скиллов в `doctor` и `plugin_list`), `connect ci --releases-url`, `fix_hint`
  у предупреждения `handoff`. В `ROADMAP.md` не переносились — не оформлено.
- **Волна W (вау-эффект)** — ни один пункт: W1 (`gate --explain` и
  `verdict_explain`), W2 (`arch-be redteam`), W3 (`arch-be bootstrap`),
  W4 (`arch-be trust`).
- **Кейс `кейсы/digital-ruble-merchant` и каталог `red-team/`** — не созданы.
  Следовательно, **критерий приёмки релиза «red-team ловит ≥ 11 из 14» не
  измерен**: у таблицы раздела 7 нет исполняемой формы. Поимённо закрыты
  правками только D5 (Н2), D7 (Н5), D9 (Н7), D12 (Н2), D13 и R (Н1), D14 (Н3)
  — это 7 позиций из 14, и заявка на «≥ 11» требует прогона, которого не было.
- **Новый кейс «Зарплатные и социальные выплаты в цифровых рублях»
  (B2C/G2C, Critical) через `arch-be bootstrap`** — не построен:
  `arch-be bootstrap` (W3) не реализован, поэтому «с нуля через bootstrap»
  физически нечем выполнить. Кейс не создавался и вручную — это следующий шаг
  после W3.
- **Сравнение с релизным бинарём 0.3.3 из GitHub Releases** — не делалось:
  стенд собирал 0.3.3 из коммита `9486d79` (`cargo build --release`). Это тот
  же коммит, что помечен тегом `v0.3.3`, но сравнение шло с локальной сборкой,
  а не со скачанным релизным ассетом.
- **Пять сценариев на новом кейсе** (пакет, дельта, бандл до зелёного,
  качество решений, контур контроля) и **каналы MCP / скиллы / хуки /
  плейбуки / headless** — не прогонялись на новом кейсе; MCP-плейбук
  `spine-bundle` (часть W3) не создан.
- **DoD-пункты, требующие волн C и W**: обновление `docs/mcp_for_architects.md`
  под Н8, скиллы `spine-*`, `CHANGELOG`/release notes с разделом «Что может
  покраснеть», `ROADMAP.md` с переносом незакрытого, подъём `Cargo.toml` до
  `0.3.4` и сборка релизных ассетов. Версия в `Cargo.toml` **оставлена
  `0.3.3`** — поднимать её до готовности DoD значило бы выдать неполное за
  релиз.
- **ADR-041/042/043** написаны с альтернативами, отрицательными последствиями
  и оценкой обратимости, но **не прогонялись рубрикой `adr_quality` с судьёй,
  отличным от автора**: LLM-судья в этом сеансе не вызывался (нет ключа и
  сети для провайдера), поэтому пункт DoD «≥ 3,5 судьёй, отличным от автора,
  либо помечены `judge_is_author`» не выполнен. Пометки `judge_is_author` у них
  тоже нет.

## 5. Стоп-условия раздела 1.9

Ни одно не сработало:

- контракт `gate-verdict/v1` не ломался — поля аддитивны (`inputs` шире,
  `components[].findings_digest` добавлено); `v2` не понадобилась;
- смысл exit-кодов `0 / 1 / 3` не менялся;
- ни один из существующих тестов не удалён и не ослаблен;
- находок «не воспроизводится, но очевидно есть» не заявлялось: единственная
  невоспроизведённая часть (стектрейс в Н6) записана в `0.3.4-repro.md` как
  не-дефект, а не «исправлена на всякий случай».

Решение человека, запрошенное по Н1 (severity новых находок на Standard/Fast):
принято предложение ТЗ по умолчанию — **Critical `error`, Standard/Fast `warn`
в 0.3.4**, перекрытие ключом `[evidence] semantics = off|warn|error`, оформлено
в ADR-041.

Решение A3 за человека не подписывалось: `decided_by` оставлен пустым, и это
ловится — тест `verify_flags_unsigned_a3` подтверждает находку `a3_not_signed`
на пустом поле и на прочерке.

## 6. Что может покраснеть после обновления

- **Все аттестации меняются** (Н3): состав входов шире, поэтому сравнение
  `attestation` с сохранённым ранее значением даст расхождение. Сравнивать
  корректно только внутри одной версии.
- **Critical**: бандл, где `DECISION.md`/`WALKING-SKELETON.md`/`REVIEW`/
  репетиция отката/отчёты валидации были заглушками, перестаёт быть зелёным
  (exit 1). Возврат к поведению 0.3.3 — `[evidence] semantics = off`.
- **Standard/Fast**: те же случаи дают предупреждения без смены exit-кода.
- **Любой маршрут**: битая ссылка модели (Н2) теперь краснит `gate` — раньше
  её видели только `model validate` и `review`.
- **Незакоммиченные новые файлы под защищёнными путями** (Н4а) теперь видны
  `delta guard` и до `git add`. Это сужает окно «правку спайна нечем покрыть»,
  но может покраснить рабочие процессы, полагавшиеся на прежнее поведение.
- **`decision_quality`** по умолчанию выключена — покраснеть не может, пока её
  не добавят в `[gate.required]`.
