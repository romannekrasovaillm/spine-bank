## 5. Что не сделано

- **Релизные ассеты и `SHA256SUMS` не собирались** (`release.yml` не
  запускался — релиз не публикуется по условию задания). Версия в `Cargo.toml`
  поднята до `0.3.4`, `CHANGELOG.md` написан с разделом «Что может покраснеть
  после обновления».
- **ADR-041/042/043 не прогнаны рубрикой с судьёй, отличным от автора.** В
  окружении нет второй модели: судья — та же модель, что писала документ.
  ADR помечены строкой `Judge: judge_is_author`; механически помеченный отчёт
  (`judge_is_author` в `reports/rubric/`) есть у ADR-001 нового кейса, где
  split-judge канал прогнан целиком.
- **`ROADMAP.md` не обновлён** переносом незакрытого.
- **Сравнение с релизным ассетом 0.3.3 из GitHub Releases не делалось.** Стенд
  собирал 0.3.3 из коммита `9486d79` (`cargo build --release`). Это тот же
  коммит, что помечен тегом `v0.3.3`, но сравнение шло с локальной сборкой.
- **Внешние кодовые харнессы не участвовали**: пять сценариев раздела 9
  пройдены каналами Spine (CLI, MCP, плейбуки, скиллы, хуки) на новом кейсе,
  но не живой сессией Claude Code / Qwen Code / omp — как и в исходном
  исследовании (оговорка приложения к ТЗ).
- **Хуки проверены командой, а не установкой в чужой харнесс**: сценарий
  «ослабление правила после коммита» прогнан `gate --base HEAD~1...HEAD` — той
  же командой, которую вызывает pre-push. Интеграционный тест с bare-remote
  (Н5) проходит в `tests/cli.rs`.
- **Кейс `salary-payments` красный по мутационному измерению** (10/14): причина
  названа в его `README.md`; порог не понижался, чтобы «пройти».

## 6. Стоп-условия раздела 1.9

Ни одно не сработало:

- контракт `gate-verdict/v1` не ломался: поля аддитивны (`inputs` шире,
  `components[].findings_digest`, `passport` у `--explain`, `trust` отдельным
  конвертом `arch-be/trust/v1`); `v2` не понадобилась;
- смысл exit-кодов `0 / 1 / 3` не менялся;
- ни один из существующих тестов не удалён и не ослаблен;
- находок «не воспроизводится, но очевидно есть» не заявлялось: единственная
  невоспроизведённая часть (стектрейс в Н6) записана в `0.3.4-repro.md` как
  не-дефект, а не «исправлена на всякий случай».

Решение человека, запрошенное по Н1 (severity новых находок на Standard/Fast):
принято предложение ТЗ по умолчанию — **Critical `error`, Standard/Fast `warn`**,
перекрытие ключом `[evidence] semantics = off|warn|error`, оформлено в ADR-041.

Решение A3 за человека не подписывалось: у кейса `salary-payments` поле
`decided_by` заполнено владельцем контура в тексте, но подлинность подписи
механикой не подтверждается и названа в блоке 2 паспорта; тест
`verify_flags_unsigned_a3` подтверждает, что пустое поле и прочерк ловятся.

## 7. Что может покраснеть после обновления

- **Все аттестации меняются** (Н3): состав входов шире, поэтому сравнение
  `attestation` с сохранённым ранее значением даст расхождение. Сравнивать
  корректно только внутри одной версии.
- **Critical**: бандл, где `DECISION.md`/`WALKING-SKELETON.md`/`REVIEW`/
  репетиция отката/отчёты валидации были заглушками, перестаёт быть зелёным
  (exit 1). Возврат к поведению 0.3.3 — `[evidence] semantics = off`.
- **Standard/Fast**: те же случаи дают предупреждения без смены exit-кода.
- **Любой маршрут**: битая ссылка модели (Н2) теперь краснит `gate`.
- **Незакоммиченные новые файлы под защищёнными путями** (Н4а) видны
  `delta guard` до `git add`. В том числе — каркас `bootstrap`, созданный
  внутри чужого репозитория: проводник об этом предупреждает строкой `notes`.
- **`control check <подкаталог>`** (Н12) больше не сравнивает реестр кейса с
  корневым: если кто-то полагался на прежний ложный `rule_weakened` как на
  сигнал, сигнала не будет.
- **`evidence verify`** печатает дополнительную строку со ссылкой на паспорт —
  парсеры, читающие вывод построчно, увидят новую строку.
- **`decision_quality`** по умолчанию выключена — покраснеть не может, пока её
  не добавят в `[gate.required]`.
