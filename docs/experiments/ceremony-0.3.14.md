# Замер церемонии «от bootstrap до зелёного» — до/после волны A (0.3.14)

Пункт A2 задания TASK-v2: профиль Critical бандла Evidence Bundle частично
выводится машиной (`risk_level` — из записи значимости в `EVIDENCE.yaml`,
отчёты прогонов — из записей `arch-be evidence record`, ADR-066;
`rollback_rehearsal` — из REHEARSAL.json гейта A4, ADR-049), и проводник
не создаёт заглушки для выводимых артефактов. Здесь — замер, сколько файлов
человек правит руками и сколько длится путь до зелёного, до и после.

## Методика и честные границы

- **До**: бинарь `arch-be 0.3.13` (коммит `e3ee160`), каталог `/tmp/hp1`.
  Числа из задания (34 файла, 11 рукописных файлов) **перепроверены живым
  прогоном** этим бинарём в рамках этого замера — подтвердились.
- **После**: debug-бинарь worktree 0.3.14 (HEAD `41eb96f`), каталог
  `/tmp/hp2`. Сценарий доигран до `Итог: PASS` гейта.
- Время — **машинное время шагов** (стена, debug-сборка, одна машина).
  Работа человека не тайминговалась, а посчитана в файлах: писать прозу —
  минуты на файл, прогнать команду — секунды; смешивать их в одну колонку
  «время» было бы нечестно.
- Оба прогона — по одному разу, без усреднения: разброс debug-бинарей на
  таких длительностях делает второй знак бессмысленным; порядок величин —
  то, что нужно таблице.

Машинное время сопоставимо (разница — шум debug-сборки): экономия не в
секундах, а в составе работы. Из церемонии убраны четыре рукописных файла,
три из которых были чистой имитацией (отчёт о прогоне без прогона); взамен
появились три настоящих прогона по 1–2 секунды каждый.

Шаг, который НЕ изменился и остался ручным: `baseline_commit` в
`.arch-handoff/ROLLBACK.yaml` bootstrap в обеих версиях пишет заглушкой
(`<slug>-1`, не резолвится) — перед `handoff` его заменяют на HEAD
(пакет пиннит контрольную плоскость, правка после `handoff` ловится как
`control_plane_tampered`). Кандидат на выводимость машиной в следующей волне.

## Протокол прогона «после» (воспроизводимо)

```bash
AB=./target/debug/arch-be   # сборка worktree 0.3.14
$AB bootstrap "Зарплатные выплаты ЦР" --dir /tmp/hp2 --domain платежей
# → «Каркас создан: /tmp/hp2 (29 файлов)…»
# → «спайн ✓ · правила ✓ · модель ✓ · бандл пишет автор 8/8 · выведет машина 1/5 (13 находок)»
cd /tmp/hp2
# 1. автор пишет 6 файлов + заполняет место <оценка> в docs/adr/ADR-001-*.md
# 2. baseline: git rev-parse HEAD → .arch-handoff/ROLLBACK.yaml
$AB handoff claude-code --repo . --task "…" --route critical --spec …  # пакет + MANIFEST.json
$AB control gate A4 . --rehearse        # → Итог: PASS (REHEARSAL.json)
$AB evidence record fitness             # дефолт: arch-be control check .
$AB evidence record tests    --cmd "python3 -m pytest skeleton -q"
$AB evidence record skeleton --cmd "python3 -m pytest skeleton -q"
git add -A && git commit -m "…"          # записи привязаны к HEAD: коммит ДО записей
$AB evidence pack . --route critical    # → «Бандл: пишет автор 8/8 · выведет машина 5/5»
$AB gate --repo . --route critical      # → Итог: PASS
```

Порядок имеет значение и проверен обеими сторонами: коммит после записей
инвалидирует их (`evidence_record_stale` — «HEAD сместился»), а запись до
handoff остаётся свежей (пакет живёт в `.arch-handoff/`, исключённом из
хэша входов).

## Протокол прогона «до» (0.3.13, контрольный)

Тот же сценарий на бинаре `e3ee160`: 11 рукописных файлов (включая три
отчёта из двух строк прозы со «Итог: PASS (8 из 8)», без единого прогона),
починка заглушки baseline, handoff, репетиция, pack, gate → **PASS** —
репродукция «рукописного PASS» (раздел 3 TASK-v2, секция A1
`docs/experiments/fork-repro-0.3.14.md`) на контрольном бинаре
подтверждена в этом замере.

## Связь с приёмкой A2

- «На Critical автор пишет не больше 8 артефактов» — выполнено: 7 (6 файлов
  + место в шаблоне ADR). Тот же предел держит тест
  `bootstrap_walks_to_green_when_artifacts_are_written`.
- «Выведенное нельзя подменить прозой» — выполнено: рукописный отчёт без
  записи даёт `evidence_report_unbound`; в каркасе с `require_records = true`
  это error (проверено на этом же сценарии в `fork-repro-0.3.14.md` §A1).
- Раздельный счёт «пишет автор X/8 · выведет машина Y/5» печатают и
  `bootstrap --status`, и `evidence pack` — пара чисел, по которой снят этот
  замер, доступна в каждом прогоне.
