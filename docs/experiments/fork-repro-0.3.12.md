Первая попытка (точно по скрипту задания): `rules: []` + override на

## RA-3. Невалидная severity — парсер ловит раньше логики — не воспроизведено (и не должно)

нет: невалидный реестр и должен краснеть. В протоколе — для полноты.

## B-1. Пакетная копия реестра разошлась с корневой (registry_diverged) — ожидает решения архитектора

Волна B требует добавить фитнес-правила C-35…C-43 в **корневой**
`CONSTRAINTS.yaml` (B4/B5). Пакетная копия `.arch-handoff/CONSTRAINTS.yaml`
выдана при сборке пакета (50 правил) и по жёсткому ограничению задания
исполнителем не изменяется. После правки корневого реестра (59 правил)
единый гейт (`arch-be gate`) — пакет-first резолвер — выдаёт находку
`registry_diverged` (T-02, ADR-045):

```
[error] .arch-handoff/CONSTRAINTS.yaml:0 registry_diverged — копии реестра
различаются: гейт прочитал .arch-handoff/CONSTRAINTS.yaml (50 правил),
CONSTRAINTS.yaml (59 правил) — правила второй копии в вердикте не участвуют.
```

Приёмочный dogfood задания (`arch-be control check . --constraints
CONSTRAINTS.yaml`, явный корневой реестр) при этом **зелёный**: находка
возникает только на пакет-first резолвере (`arch-be gate` без `--constraints`).

**Почему не «исправлено» синхронизацией.** `cp CONSTRAINTS.yaml
.arch-handoff/CONSTRAINTS.yaml` или `arch-be handoff … --refresh-constraints`
изменяют файл из пинов контрольной плоскости (`MANIFEST.json.control_plane`):
задание прямо запрещает исполнителю правки в `.arch-handoff/**`, а ADR-045
отводит обновление пакетной копии явному акту архитектора. Правка реестра,
**по которому судит гейт**, ради его позеленения — ровно тот антипаттерн,
который закрывает волна A (A3/A5): исполнитель меняет контрольную плоскость,
чтобы гейт стал зелёным.

**Решение архитектора (любое из):**
1. `arch-be handoff --repo . --task … --refresh-constraints` — перегенерировать
   пакетную копию из корня (перепишет `.arch-handoff/CONSTRAINTS.yaml` и пин
   `MANIFEST.json`);
2. явно снять пин `.arch-handoff/CONSTRAINTS.yaml` и разрешить исполнителю
   синхронизировать копии.

До решения пакет-first гейт (`arch-be gate`) остаётся красным по
`registry_diverged`; правила C-35…C-43 действуют на явном корневом реестре
(как и в CI-джобе dogfood).
