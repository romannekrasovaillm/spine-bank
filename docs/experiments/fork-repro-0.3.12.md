`PASS`: добавлен минимальный `ARCHITECTURE-SPINE.md`, чтобы составляющая
`spine_lint` имела вход (без неё итог — INCOMPLETE из-за отсутствия спайна,
что маскирует суть).


Вердикт: **воспроизведено**. Три линии защиты одновременно зелёные при
вопиющем нарушении (`PAN=4111...` в коде, поймано 0 нарушений):

- `rule_weakened` не считает ослаблением понижение severity
  critical→medium при активном override — `active_override_keys`

- `fitness` не исполняет правило под override (0 нарушений при

  прогона целиком.

## RA-2. Полное удаление правила + override — воспроизведено, с оговоркой

Первая попытка (точно по скрипту задания): `rules: []` + override на
удалённый X-1. `rule_weakened` PASS, `delta_guard` PASS, но `fitness` FAIL
по посторонней причине — «файл не содержит правил — ожидается непустой
корень `rules:`». Вердикт: **воспроизведено частично**: путь
самоузаконивания через удаление правил существует (ослабление не поймано),
однако пустой реестр ловится валидацией — закрывать A1/A2 достаточно для
содержательных ослаблений; валидацию пустого `rules:` при активных
overrides стоит проверить отдельно при имплементации A1.

## RA-3. Невалидная severity — парсер ловит раньше логики — не воспроизведено (и не должно)

`severity: low` вне enum — `rule_weakened` падает со сбоем сравнения
(«severity должно быть error|warn|block|critical|high|medium»). Ошибки
нет: невалидный реестр и должен краснеть. В протоколе — для полноты.
