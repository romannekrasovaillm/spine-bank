# ADR-083. Периметр доверия Harness (SEAF-испытание v3): песочница путей fs-инструментов, fail-closed конфигурация, reverse-профиль и MCP-мост report

- Date: 2026-10-12
- Status: Accepted [ADOPTED] — решение человека (A3): владелец выбрал
  полный объём («всё сразу»: песочница путей, fail-closed конфиг,
  reverse-профиль, MCP-мост report, kind=cli tool-calls) единым пакетом
  0.4.10/0.4.11 параллельно flow-v1 — 2026-10-12, выбор зафиксирован в
  диалоге витка (propose_options); митигации Negative (fs_allow-дефолт
  ~/.arch-harness в init, CHANGELOG) обязательны к реализации
- Модель-автор: spine-arch (claude)
- Маршрут: Critical (score 2: security_boundary_change + trust_zone_change —
  форсируют Critical по правилам значимости; это правильная строгость:
  правки меняют модель доверия fs-инструментов и загрузки конфигурации)
- Пересмотр: при появлении необходимости писать вне песочницы по легити-
  мной причине (например, экспорт в ~/.arch-harness) — расширять через
  ЯВНЫЙ allowlist-механизм, не через снятие песочницы; при живом пилоте
  в периметре банка — пересмотреть дефолты reverse-профиля по факту.
- Провенанс: «Spine-SEAF-испытание-v3» (12.10.2026, Spine 0.4.6):
  раздел «Найдены дефекты Harness, важные для банковского контура» и
  предложения 5.2 P0/P1; модель угроз ADR-038 (T-контур); ADR-080
  (report, этап 2 — MCP-мост был запланирован, испытание подтвердило
  его приоритет: «MCP-сервер не отдаёт report» — причина нерентабель-
  ности Spine Core в задаче).

## Context

**1. Испытание SEAF дало измеримый отрицательный результат.** Spine не дал
прироста против агента без Spine (рубрики 4.89/4.67 против 4.56/4.56 —
разница в шуме одного прогона; полнота интеграций Core+агент НИЖЕ базовой
линии: 0.92/0.83 против 1.00). Причина названа прямо: инструменты Spine
почти не вызывались (1 из 134 у Core; 0 архитектурных у Harness), потому
что (а) MCP не отдаёт `report` — главный артефакт ADR-080; (б) recover
возвращает граф ревизии, «бесполезный для модели v3» — нет ни валидатора
модели v3, ни фактов-подсказок; (в) Harness без `init` теряет скиллы
молча.

**2. Четыре дефекта периметра доверия — блокер банковского контура.**
Подтверждено чтением кода (0.4.9): `ToolContext::resolve` (tool.rs:130)
пропускает абсолютные пути без ограничения — read_file/write_file/edit_file
читают и пишут ЛЮБОЙ путь файловой системы; `Config::load(cli_path)`
(config.rs:2025) при нечитаемом явном `--config` молча берёт `Config::
default()` с провайдером DeepSeek — unexpected-network-call класс; `[web]
enabled` по умолчанию true; провайдер `kind=cli` не умеет tool-calls —
Harness без OpenAI-ключа неработоспособен в агентном цикле.

**3. Это уже не гипотеза, а измерение.** Испытание зафиксировало факти-
ческие чтения/записи вне рабочего каталога. Для периметра банка sandbox
bash (ADR-038) есть, а fs-инструменты — дыра рядом с ним: модель может
обойти песочницу bash простым write_file по абсолютному пути.

## Decision

1. **Песочница путей fs-инструментов (P0, безопасность).** `resolve()`
   становится зоной: путь обязан разрешаться ВНУТРИ рабочего каталога
   (после canonicalize обеих сторон; symlink-петли — существующий
   SKIP_DIRS-механизм не касается fs-инструментов, канонизация обязательна).
   Выход за границу → отказ (is_error) с текстом «вне рабочего каталога:
   <путь>; доступные операции — только внутри <cwd>» + запись в журнал
   политики (модель угроз ADR-031/038, строка в audit-журнале сессии).
   Опциональный allowlist в конфиге (`[tools] fs_allow = ["/abs/path", …]`)
   для легитимных исключений — расширение зоны, не снятие. Относится к
   read_file/write_file/edit_file/glob/grep (bash — свой sandbox ADR-038).

2. **Fail-closed конфигурация (P0).** Явный `--config <path>` (cli_path),
   который не читается/не парсится, — ОШИБКА запуска (exit ≠ 0), не
   fallback на дефолты. Fallback на дефолты остаётся только когда путь
   НЕ задан явно (candidates не найдены → default, как сегодня). Провайдер
   по умолчанию не выбирается молча: если агентный цикл стартует без явно
   настроенного провайдера — отказ с перечнем вариантов конфигурации
   (частично есть: «нет API-ключа» UX-6 0.4.9; усиливаем до уровня запуска).

3. **Профиль `reverse` (P0).** Новый пресет запуска (config-профиль или
   флаг `arch-be run --profile reverse`): веб-инструменты выключены,
   исходники только для чтения (read-only зона: cwd читается, запись —
   только в `<out>` подкаталог вывода), скиллы восстановления доступны
   БЕЗ init (встроенный минимальный набор reverse-discovery/recover-review
   из ассетов, если библиотека пользователя пуста — с warn в журнале, не
   молчанием). Отвечает сценарию испытания: два этапа, воспроизводимость.

4. **MCP-мост `report` (P0, из ADR-080 этап 2).** `report` в BRIDGE_READ_
   ONLY: тот же строитель src/report/ (AD-11), параметры path/format/rev,
   read-only. Снимает главный барьер использования Core-агентами по
   измерению испытания.

5. **`kind=cli` tool-calls (P1).** CLI-провайдер умеет цикл tool-calls
   (протокол ACP-адаптера уже умеет — переиспользовать): Harness работает
   на CLI-подписке без OpenAI-ключей. До реализации — честный отказ при
   попытке агентного цикла с kind=cli (сейчас — поломка на полпути).

6. **Валидатор модели v3 + факты интеграций (P1, из 5.1).** `report_
   validate` как MCP-инструмент и `report_facts` (HTTP-клиенты Ktor/
   RestClient/WebClient с base-url из конфига, маршруты Spring Cloud
   Gateway, @Scheduled/outbox с признаком async) — отдельная волна после
   R+ (ADR-082: детекторы пересекаются, делать после).

7. **Чего не делаем:** не меняем модель угроз (docs/threat-model.md
   дополняется строками песочницы fs — новой угрозы нет, закрывается
   существующая T-строка обхода); не трогаем recover/v1 (его «бесполез-
   ность для v3» лечится пунктом 6, не ломкой контракта).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Только задокументировать границы (без кода) | Ноль кода | Испытание показало ФАКТИЧЕСКИЕ выходы за периметр; банковский контур не примет документированную дыру; отказ |
| Песочница только через bwrap для всего процесса | Один механизм (ADR-038) | fs-инструменты — внутри процесса, bwrap их не ограничивает точечно; ядро Core-сборки не должно тянуть bwrap-зависимость среды; отказ от единого механизма, оставляем точечный |
| Allowlist без границы по умолчанию (инверсия: разрешено всё вне списка) | Обратная совместимость 100% | Дыра по умолчанию сохраняется — прямо противоречит цели; отказ |
| MCP-мост report + валидатор v3 без периметра (только ценность) | Быстро закрывает «Spine не нужен» | Доверие теряется быстрее ценности: инструмент, читающий вне периметра, не берут в банк; порядок обратный — сначала периметр |

## Consequences

### Positive

- Периметр доверия замыкается: fs-инструменты перестают быть обходом
  bash-песочницы; fail-closed конфиг убирает класс «неожиданный внешний
  вызов»; reverse-профиль делает прогоны испытаний воспроизводимыми.
- Главная причина нерентабельности Core (нет report в MCP) устраняется
  мостом — измеримое ожидание на следующем испытании.
- Harness становится пригодным к работе без OpenAI-ключей (kind=cli).

### Negative

- **Обратная совместимость ломается у легитимных сценариев записи вне
  cwd** (экспорт в ~/.arch-harness и т.п.): миграция — через fs_allow
  (в init-дефолт конфига сразу прописать ~/.arch-harness, чтобы
  существующие потоки не сломались) + CHANGELOG «Что может покраснеть».
- **Песочница — новый слой отказа**: ложные блокировки (symlink на
  рабочий каталог и т.п.) потребуют диагностики; текст ошибки обязан
  называть оба пути (запрошенный и границу).
- **Профиль reverse — новая поверхность конфигурации**: пересечение с
  autonomy-уровнями (R1–R4) требует аккуратности в справке.
- **kind=cli tool-calls — сложный адаптер**: риск поломки на нестандарт-
  ных выводах CLI; принимаем поэтапно (сначала честный отказ).

## Reversibility

**Costly** (песочница путей и fail-closed конфиг меняют поведение по
умолчанию — откат через конфиг-флаги `[tools] fs_sandbox = false` /
кандидатную цепочку, но после принятия в периметре банка откат — тоже
событие безопасности). Остальное (мост, профиль, cli-tool-calls) —
reversible. Отдельная дельта changes/perimeter-trust.
