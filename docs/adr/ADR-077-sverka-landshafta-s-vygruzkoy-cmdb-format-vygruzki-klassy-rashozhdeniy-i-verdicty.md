# ADR-077. Сверка ландшафта с выгрузкой CMDB: формат выгрузки, три класса расхождений и вердикты записей

- Date: 2026-10-11
- Status: Accepted [ADOPTED] — контракт `arch-be/landscape-diff/v1` и правила
  сверки фиксируются в волне LANDSCAPE (TASK 0.4.0, бенчмарк AB-02)
- Модель-автор: spine-arch (claude)
- Провенанс: линия `recover` (ADR-069, граф «как построено») × линия
  агрегации ландшафта (ADR-036/ADR-037) — сверка сшивает оба источника
  (модель и граф кода) с внешним инвентарём (CMDB)
- Пересмотр: при появлении второго потребителя схемы `landscape-diff/v1`
  либо при переходе от файловой выгрузки CMDB к живому API инвентаря —
  пересмотреть состав полей и набор классов расхождений

## Context

**1. Агрегация ландшафта замкнута на себя — внешнего инвентаря в контуре
нет.** `build_landscape` (ADR-037) сводит `model/` проектов в один ландшафт,
но не сверяет его ни с чем вне репозитория. В корпоративном контуре истина
о «что реально заведено» живёт в CMDB (инвентарь систем), и расхождение
дизайна с инвентарём — самостоятельный класс дефектов: система спроектирована
и работает, но не заведена; система числится, но кода/модели нет; владелец
данных в инвентаре и в архитектуре разный. Бенчмарк AB-02 кладёт это в
**0,25 счёта** (F1 сверки CMDB — главная новая метрика) плюс **0,15**
(F1 конфликтов владения); до 0.4.0 контура не существует вовсе.

**2. Владельца в модели нет как поля — только как текст.** Модель (ADR-003)
не имеет первоклассного `owner` у сущности; владелец пишется в теле `SYS`/`INT`
строкой `Владелец: «…»`. Конфликт владения (AB-02, задача 3: два мастера,
общая схема, запись в чужую БД) обнаруживается только сопоставлением этого
текста с полем `owner` записи CMDB — и требует нормализации (регистр, пробелы).

**3. Граф кода и модель — два разных источника «что есть».** Компонент может
быть в коде, но не в модели (as-built опережает дизайн), и наоборот. Сверка
обязана смотреть оба: класс «не заведено в CMDB» ловится по объединению
модель ⊕ граф кода, иначе система, живущая только в коде, молча выпадет.

**4. Ложные срабатывания штрафуются.** AB-02 штрафует за галлюцинации:
объявить запись CMDB «лишней», когда сверять было не с чем (пустой ландшафт,
не передан код), — это ложный orphan. Нужен честный третий вердикт
(«не проверяема»), а не бинарность «подтверждена/ошибочна».

**5. Файловая выгрузка, не сервис.** ADR-033 фиксирует: реестры — файловая
агрегация, не сервис. Живой API CMDB (ServiceNow и пр.) противоречит границе
продукта (single-user, файлы) и добавил бы сетевую зависимость и секреты.

## Decision

1. **Команда `arch-be landscape diff`.** `arch-be landscape diff --cmdb
   <файл> [--root <dir>] [--aliases <файл>] [--repo <dir>] [--rev <rev>]
   [--format md|json] [--model-out <dir>]` сверяет ландшафт с выгрузкой CMDB.
   `--root` по умолчанию `.`; без `--repo` сверка идёт только по модели, с
   `--repo` — по объединению модель ⊕ граф кода
   (`arch_diff::as_built_with`, компоненты `NodeKind::Component`).

2. **Формат выгрузки CMDB — минимальный YAML** (единообразие с моделью;
   `serde_yaml_ng` разбирает и JSON, тот же файл можно подать в JSON-форме).
   Поля записи: `id?`, `name` (обязателен), `owner?`, `status`
   (`active|deprecated|retired`, по умолчанию `active`), `replaces?`. Два
   допустимых корня — обёртка `systems:` либо «голый» список. Пустой
   файл/список и запись без `name` — ошибка; записи сортируются
   `(canonical_name(name), id)` для детерминизма.

3. **Три класса расхождений, каждый с доказательством.**
   - `cmdb-missing` **[error]** — система из модели/графа кода не заведена в
     CMDB (evidence — `проект:ID` либо `код:узел`);
   - `cmdb-orphan` **[warn]** — запись CMDB без модели/кода (evidence —
     `CMDB:<id>`);
   - `owner-conflict` **[error]** — владелец CMDB ≠ владелец модели
     (evidence — `CMDB:<id> ↔ проект:ID`, в сообщении оба значения).

4. **`retired` гасит шум.** Запись CMDB со статусом `retired`/
   `decommissioned`/`eol`, которой нет в модели/коде, не попадает в находки:
   для снятой с эксплуатации системы отсутствие реализации ожидаемо. Вердикт
   записи — «подтверждена». Систематические ошибки CMDB AB-02 (устаревшие
   системы) при этом не маскируют реальных расхождений по живым системам.

5. **Вердикт по каждой записи CMDB (AB-02, задача 5): `подтверждена |
   ошибочна | не проверяема`.** «Подтверждена» — сопоставлена и владелец
   согласован (или `retired`); «ошибочна» — висит без модели/кода либо
   владелец конфликтует; «не проверяема» — в ландшафте нет ни одного
   источника (ни модели, ни графа кода), сверять не с чем. В последнем случае
   orphan-предупреждения не выдаются (`has_sources`), чтобы не штрафовать за
   отсутствие данных.

6. **Черновик модели `--model-out` — неразрушающий, `status: inferred`.**
   Пишутся `SYS-NNN.md` со `status: inferred`, `source: cmdb@<файл>` и строкой
   `Владелец: «…»`. По образцу `recover --model-out` (ADR-069): сущность со
   `status ≠ inferred` (правка архитектора) не перезаписывается и попадает в
   список «пропущено».

7. **JSON-контракт `arch-be/landscape-diff/v1`.** Конверт как у
   `arch-diff`/`recover`: `schema`, `arch_be` (версия), `root`, `cmdb`,
   `counts` (errors/warnings/design_systems/code_systems/cmdb_records/
   verdicts), `findings[]`, `verdicts[]`, `model_out?`, `passed`.
   `passed = true` при нуле ошибок (warn не роняет сверку). Вывод
   детерминирован (сортировки выше).

**Поправки:** нет (первая редакция).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Файловая YAML-выгрузка CMDB + три класса расхождений + вердикты + `retired`-гашение + `model-out`** (принято) | Единый формат с моделью; offline, без секретов; честный третий вердикт; использует существующий граф `as_built` | Выгрузка стареет (freshness не гарантирован — ответственность владельца инвентаря) |
| B. Оставить только агрегацию `model/` (status quo) | Ноль кода | AB-02 метрики сверки CMDB и конфликтов владения не закрыты (0,40 счёта) |
| C. Живой API CMDB (ServiceNow и пр.) | Всегда актуально, двусторонняя синхронизация | Противоречит ADR-033 (реестры — файлы, не сервис); сеть, секреты, RBAC; вне границы single-user-продукта |
| D. CSV-выгрузка (как в постановке AB-02: «CSV 60–90 записей») | Ближе к реальной выгрузке CMDB | Второй формат рядом с YAML-моделью; CSV не выражает вложенность `replaces` без соглашения о колонках; JSON/YAML читаются тем же `serde_yaml_ng` без нового парсера |
| E. Бинарность «подтверждена/ошибочна» без «не проверяема» | Проще | Ложные orphan на пустом ландшафте → штраф за галлюцинации (AB-02); нет честного «данных нет» |
| F. Отдельное поле `owner` в сущности модели | Владелец — первоклассная сущность (чище сверка) | Инвазивно к ADR-003 и всей модели; ломает существующие `SYS`; отложено (owner-from-body уже работает) |

## Consequences

### Positive

- Пробел LANDSCAPE закрыт: F1 сверки CMDB (0,25) и F1 конфликтов владения
  (0,15) получают механический контур с доказательствами (AB-02, задача 5).
- Сверка смотрит на **оба** источника (модель ⊕ граф кода) — система,
  живущая только в коде, не выпадает из класса «не заведено в CMDB».
- Честный вердикт «не проверяема» и `has_sources` снимают ложные orphan при
  отсутствии данных — прямой ответ на штраф за галлюцинации.
- `retired`-гашение отделяет систематический шум устаревших записей CMDB от
  реальных расхождений по живым системам.
- Идемпотентность `--model-out` (не затирает `status ≠ inferred`) делает
  черновик безопасным при повторных прогонах на живом клоне.
- Детерминизм (`landscape-diff/v1` байт-в-байт) и offline-работа пригодны для
  CI и бенчмарков.

### Negative

- **Выгрузка стареет.** Сверка честна на дату снимка CMDB; freshness не
  гарантируется механизмом (митигация — выгрузку обновляет владелец
  инвентаря; в отчёте фиксируется путь и содержимое файла).
- **Свободный текст владельца.** CMDB-владелец — строка, модельный — строка в
  теле; нормализация `norm_owner` (регистр, пробелы) груба: `«Team A»` и
  `«Team-A»` разойдутся. Остаточный риск ложного конфликта признаётся;
  типизованное поле `owner` отложено (вариант F).
- **Владелец только из тела `SYS`/`INT`:** системы, где владелец не записан,
  из сверки владения выпадают (нет обеих сторон сравнения) — конфликт не
  ловится, но и ложного срабатывания нет.
- **Расширилась поверхность CLI:** новая подкоманда `landscape diff` и новая
  схема `landscape-diff/v1` (потребители схемы должны читать `schema`).
- **CSV из постановки AB-02 не читается напрямую** — реальную CSV-выгрузку
  нужно сконвертировать в YAML/JSON (цена единого формата; митигация —
  тривиальная конвертация, поля плоские).

## Reversibility

**Обратимо, цена низкая.** Подкоманда снимается удалением ветки
`LandscapeCmd::Diff` и записи в `Cmd::Landscape`; схема `landscape-diff/v1` —
версией контракта (потребители, читающие `schema`, отсекут неизвестную
версию). Правило `retired`-гашения и вердикт «не проверяема» — чистые функции
над выгрузкой, отключаются без следа в данных. Черновик `model/` — файлы на
диске, удаляются; правило «не затирать `status ≠ inferred`» защищает от
необратимых потерь правок. Необратим ровно один аспект — номер ADR-077
(номера не переиспользуются): цена фиксации, не риск отката.
