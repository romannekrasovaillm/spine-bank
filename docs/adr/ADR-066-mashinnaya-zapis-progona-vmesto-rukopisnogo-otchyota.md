# ADR-066. Отчёт о прогоне — машинная запись, привязанная к входам (A1)

- Date: 2026-10-07
- Status: Proposed
- Reversibility: обратимо. `[evidence] require_records = false` (дефолт)
  возвращает поведение 0.3.13: markdown-отчёт достаточен, находка
  `evidence_report_unbound` остаётся предупреждением. Данных не касается:
  записи `.arch-handoff/evidence/*.json` только читаются верификатором
- Нумерация: ADR-060…ADR-064 заняты срезами 0.3.14 (A3, D3, F1, K3, K5)

## Context

До 0.3.14 артефакты бандла `validation`, `fitness_report` и
`walking_skeleton` проверялись как проза: достаточно было строки
«Итог: PASS (8 из 8)», написанной рукой, без единого прогона
(репродукция — `docs/experiments/fork-repro-0.3.14.md`, секция A1:
бандл Critical с рукописными отчётами давал `arch-be gate --route critical`
→ PASS, exit 0). Отягчающее: подсказка находки звучала «добавьте итоговую
строку прогона» — она учила обходу, а не работе.

Репетиция отката так уже устроена (`REHEARSAL.json`, ADR-049): факт прогона
фиксирует машина, а не автор. A1 распространяет этот образец на все отчёты
о прогонах бандла.

## Decision

1. **Команда `arch-be evidence record fitness|tests|skeleton [--cmd …]`**
   выполняет прогон и пишет `.arch-handoff/evidence/<kind>.json`
   (схема `arch-be/evidence-record/v1`): команда, exit-код, время, длительность,
   HEAD, хэш входов, итог, хвост вывода. Для `fitness` — дополнительно
   отпечаток реестра (SHA-256 файла CONSTRAINTS.yaml) и аттестация вердикта
   (свёртка `вид\0команда\0exit\0входы\0реестр`). Команда по умолчанию есть
   только у `fitness` (`arch-be control check .`); для `tests`/`skeleton`
   `--cmd` обязателен — универсальной команды тестов нет. Провал прогона —
   тоже запись (`passed: false`): FAIL-запись честнее отсутствия записи.
2. **Хэш входов.** `fitness`: всё дерево кейса (правила читают и документы)
   плюс отпечаток реестра; `tests`/`skeleton`: дерево без markdown-прозы
   (правка отчёта не инвалидирует прогон тестов). Из свёртки исключены
   `.git`, `.arch-handoff`, `target`, `node_modules`, `__pycache__`,
   `.pytest_cache` и `EVIDENCE.yaml` — иначе прогон и упаковка инвалидировали
   бы свою же запись.
3. **Свежесть записи — совпадение HEAD И хэша входов.** Текст задания
   формулирует «HEAD или хэш входов»; «или» оставляло бы незакоммиченную
   правку кода незамеченной (HEAD тот же, входы другие) — а это прямая
   приёмка A1. Поэтому: запись свежая, пока совпадают оба; вне git
   (`head: "absent"`) судят только входы. Устаревшая запись — находка
   `evidence_record_stale` (severity маршрута).
4. **`evidence_report_unbound`** — markdown-отчёт есть, машинной записи нет:
   по умолчанию `warn` (поведение прежних версий не меняется), по флагу
   `[evidence] require_records = true` — `error` (правило 4, warn → error по
   флагу). Каркас `arch-be bootstrap` (bank-профиль, ROUTE.lock = critical)
   генерирует `arch-harness.toml` с включённым флагом: новые кейсы сразу
   живут в режиме «отчёт пишет машина».
5. **Подсказки не учат обходу.** Все находки по артефактам прогонов ведут к
   `arch-be evidence record <kind>`; требование «добавьте строку итога»
   снято — строка в прозе больше не удостоверяет прогон. Тест
   `report_findings_never_teach_prose_bypass` держит эту границу.
6. **Markdown остаётся** человеко-читаемым сопровождением: проверка
   `evidence_reports_fail` (FAIL в тексте против записи PASS) сохранена.
   Когда запись есть, артефактом бандла становится файл записи (хэш в
   манифесте) — подмена записи ловится целостностью бандла.

## Consequences

- Бандл Critical с рукописными отчётами после фикса: находки
  `evidence_report_unbound`; в кейсе с `require_records = true` — exit 1.
  Правка кода после записи — `evidence_record_stale`.
- Зелёный маршрут Critical теперь требует реальных прогонов
  (`evidence record …`) до `evidence pack`; запись старше правок кода
  не принимается — церемония становится «прогон → запись → упаковка».
- Чего механика НЕ делает: запись удостоверяет факт и свежесть команды,
  а не достаточность прогона (что прогонять — решает автор `--cmd`; это
  печатается в `not_verified`). Тривиальная команда (`--cmd true`) возможна,
  но она видна ревьюеру в самой записи; оценка осмысленности команд —
  работа ревьюера и redteam, не этого ADR.
- Ограничение: хэш входов `tests`/`skeleton` не видит правки `*.md`; у
  `fitness` правка документов инвалидирует запись (правила читают документы)
  — осознанная асимметрия, описанная в п.2.
