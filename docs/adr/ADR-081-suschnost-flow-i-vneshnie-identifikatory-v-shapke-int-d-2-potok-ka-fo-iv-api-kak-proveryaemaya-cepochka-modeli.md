# ADR-081. Сущность FLOW и внешние идентификаторы в шапке INT (Д-2): поток КА ФО → ИВ → API как проверяемая цепочка модели

- Date: 2026-10-12
- Status: Proposed
- Модель-автор: spine-arch (claude)
- Маршрут: Standard (score 2: new_component + api_contract_change)
- Пересмотр: при появлении живого источника МЕТА/API-реестра (снимки, Д-5) —
  расширить проверку registry_api с форматной до сверки с реестром;
  при появлении второго потребителя FLOW (кроме model_validate/impact) —
  пересмотреть состав полей.
- Провенанс: Д-2 «Сценариев v7» (С1-Ш2: участники/ИВ/контракты потока);
  SA-Bench (карточки с `flow`/`meta_id` «не загружаются вовсе», 1 из 7
  эталонных грузится); подсказка-интерим 0.4.8 (П5: «держите в теле»);
  решение аудита: «новые форматы — через явно версионированную схему».

## Context

**1. Поток КА ФО — центральный объект работы SA — не выражается в модели.**
Сценарий С1 требует показать ИВ и API, через которые идёт поток, и убедиться,
что каждый ИВ потока учтён (бюджет, контракт, договорённость). Сегодня INT
несёт бюджет/контракт, но: принадлежность ИВ потоку живёт в тексте карточки,
внешние идентификаторы (ИВ из МЕТЫ, имя+версия API из реестра, ссылка на
договорённость AGR) — тоже. Механика это не видит.

**2. Схема закрыта — и это правильно, но боль зафиксирована измерением.**
`deny_unknown_fields` (ADR-003) ловит опечатки — ценно. Но SA-Bench показал
цену: карточки с полями формата v7 «не загружаются вовсе», эталон примера
приложения З.2.3 грузится 1 из 7. Пользователь вынужден выносить служебные
связи в тело — теряется проверяемость (ссылки в теле не валидируются).

**3. Д-5 (сверка с внешним реестром) пока невозможна.** Живых снимков
МЕТА/API-реестра нет; проверять `registry_api` не с чем. Значит, первая
стадия Д-2 — референциальная целостность ВНУТРИ модели, без внешней сверки.

## Decision

1. **Новая сущность `FLOW`** (12-й префикс): id `FLOW-nn`, type `flow`,
   поля — name-набор как у сущностей (id/type/title/status/date) плюс
   `integrations: [INT-…]` (упорядоченный список ИВ потока). FLOW — объект
   каталога потоков; не участует в depends_on-графе компонентов (у него нет
   реализаций), но входит в модель/реестры/пейзаж как сущность.

2. **Опциональные поля шапки INT** (аддитивно, все опциональны):
   - `meta_id: String` — внешний идентификатор ИВ (формат `ИВ-<цифры>`
     или локальный вариант `<PREFIX>-<цифры>`; проверка формата + уникальность
     в рамках модели — дубль meta_id у двух INT = error);
   - `registry_api: String` — имя и версия API внешнего реестра (свободная
     строка `Имя vMAJOR.MINOR`; проверка формата версии; сверка с реестром —
     Д-5, НЕ в этой волне);
   - `agreement: String` — путь к документу договорённости (AGR); проверка
     существования файла — по образцу `contract` (ADR-035).

3. **Проверки (model_validate, новые коды):**
   - `flow-int-missing`: FLOW.integrations ссылается на несуществующий INT
     (error — тот же механизм, что depends_on);
   - `int-meta-id-duplicate`: один meta_id у двух INT (error);
   - `int-meta-id-format` / `int-registry-api-format` (error);
   - `agreement-missing`: путь не существует (error, по образцу
     int-contract-missing);
   - `flow-empty` (warn): FLOW без integrations — «поток без ИВ» (сильно
     пахнет незакрытым скетчем, но не блокирует).

4. **Полнота потока — производная проверка в `nfr budget` и `trace`:**
   INT с бюджетом/контрактом, не входящий ни в один FLOW — warn
   `int-without-flow` (зеркало `budget-hop-uncovered`). Не error: модель
   малых кейсов без потоков легальна.

5. **Подсказка 0.4.8 (П5) обновляется:** после релиза текст «держите в теле
   карточки» меняется на «поля flow/meta_id/registry_api/agreement доступны
   в шапке с 0.4.10; в теле — только свободный текст» (аккуратная миграция
   подсказки, без ломки сообщений парсеров — текст расширяется).

6. **Чего НЕ делаем в этой волне:** сверка registry_api с внешним реестром
   (Д-5 — нужны снимки), автосоздание Q из дыр FLOW (Д-8), AGR как тип
   сущности (С4 — отдельное решение; здесь AGR — только файл по ссылке).
   Сущность Q — не вводим (вопросы — не архитектурные объекты модели).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Статус-кво: всё в теле карточки (конвенция) | Ноль кода | SA-Bench: 6/7 карточек не грузятся; связи непроверяемы; «пилот требует либо Д-2, либо договорённость» — договорённость уже есть и болит |
| Sidecar-файл external-ids.yaml (карта INT→МЕТА→API) | Схема модели не трогается | Второй источник правды; рассинхрон карточек и карты неизбежен (тот же дефект, за который критиковали двух копий CONSTRAINTS — T-02) |
| Полная схема v2 с schema_version в frontmatter | Явная версия схемы | Миграция всех карточек ради опциональных полей; трение без выгоды: поля аддитивны, старые модели валидны без изменений |
| AGR как тип сущности (вместо поля agreement) | Симметрия с INT | Раздувает волну: подтверждение сторон, версии, статусы — это С4/Д-5; здесь нужна только проверяемая ссылка |

## Consequences

### Positive

- Цепочка Д-2 «поток → ИВ → API → договорённость» становится машинно
  проверяемой внутри модели: референциальная целостность, форматы внешних
  ID, существование AGR, покрытие FLOW бюджетами/контрактами.
- Карточки формата v7 (приложение З.2.3) загружаются без правок — снимается
  главный боль пилота С1 по SA-Bench.
- FLOW входит в существующие реестры (landscape, impact: «что заденет
  изменение потока») почти бесплатно — сущностный механизм единый.
- Поля опциональны: существующие кейсы (salary-payments, digital-ruble…)
  валидны байт-в-байт.

### Negative

- **12-й префикс разъезжается по всем перечислениям kinds** (landscape,
  impact, graph, recover draft, MCP-справка, ID_PATTERN): точек касания
  ~10–15, нужен полный прогон grep по `EntityKind::ALL`/префиксам — волна
  не «одно поле», это шов через ядро модели.
- **Подсказка 0.4.8 живёт один релиз** (П5 → новый текст): парсеры сообщений
  заметят смену текста — задекларировать в CHANGELOG.
- **meta_id/registry_api без внешней сверы — полупустые обещания**: формат
  и уникальность проверяются, актуальность в МЕТЕ — нет (честно пишем в
  доках: «свёрка — Д-5»); риск, что поле заполнют «на глазок» и оно
  протухнет — принимаем, это лучше, чем текст в теле.
- **FLOW без инструмента авторинга**: карточки пишут руками/агентом;
  `bootstrap`-генератор FLOW — не в этой волне.

## Reversibility

**Reversible.** Поля опциональны, сущность FLOW — новая (удаление не ломает
существующие модели); откат — убрать префикс и поля, модели с FLOW после
отката дадут unknown-prefix error (явный, не тихий). Проверки — аддитивные
коды model_validate.
