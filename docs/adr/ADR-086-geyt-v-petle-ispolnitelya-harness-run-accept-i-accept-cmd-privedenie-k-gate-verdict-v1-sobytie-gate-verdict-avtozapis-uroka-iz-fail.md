# ADR-086. Гейт в петле исполнителя: harness_run.accept и accept_cmd, приведение к gate-verdict/v1, событие gate_verdict, автозапись урока из FAIL

- Date: 2026-10-14
- Status: Proposed
- Модель-автор: spine-arch (оркестратор), по TASK-Spine-0.5.0-learning-loop.md
- Дельта: `changes/learning-loop-050/DELTA.md` (пункт L2)

## Context

Вердикт приёмки исполнителя в 0.4.10/0.4.11 нештатен (B3): пост-гейт работает только при наличии handoff-манифеста (иначе «пропускается молча»), произвольную команду приёмки не принимает, в историю сессии как событие не пишется. Spine узнаёт вердикт только потому, что промпт велел вызвать bash — хрупкий канал, на котором держится всё обучение. Без машинного вердикта нет ни `evidence` для уроков (ADR-085), ни метрики `prevented`.

## Decision

1. `harness_run` получает аддитивный параметр `accept` (строка-команда); адаптер — поле `[harnesses.x].accept_cmd`. По умолчанию: `arch-be gate .`, если в репозитории есть `CONSTRAINTS.yaml`, иначе пусто.
2. Команда запускается после `finalize_run` **вне песочницы исполнителя** (семантика пост-гейта A4).
3. Результат приводится к `gate-verdict/v1`: JSON-вывод команды берётся как есть; иначе коды вида `[A-Z]+\d+` / rule-id разбираются построчно, exit-код задаёт статус. Сам контракт `*/v1` не меняется.
4. Вердикт идёт **первой строкой** результата `harness_run` и пишется событием `gate_verdict` в журнал сессии.
5. Каждый FAIL с кодом автоматически вызывает `lessons_record` (источник `gate`) — канал «вердикт → урок» становится детерминированным, а не подсказкой в промпте.
6. `post_gate` без манифеста больше не «пропускается молча», если задан `accept` (закрывает B3).
7. Core: `arch-be hook stop` и `post-tool-use` после прогона гейта пишут FAIL-коды в реестр уроков — хост-агент без своей памяти копит уроки, проверенные гейтом.

Совместимость: без `accept` вывод `harness_run` байт-в-байт как в 0.4.10 (тест).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. accept-команда + вердикт первой строкой (выбран)** | Штатный канал, не зависящий от промпта; совместимость за флагом; verdict_excerpt подпитывает реестр | Новый шаг в петле исполнителя — латентность на каждый прогон |
| B. Только расширить пост-гейт манифеста | Нет новых параметров | Не работает без `.arch-handoff/` — а handoff_create вызывается в 3% прогонов (B4); основной путь остаётся слепым |
| C. Парсить stdout исполнителя LLM-ом на предмет вердикта | Гибко | Недоверенные данные как источник истины; прямой путь к отравлению памяти (риск 1 TASK) |
| D. Статус-кво (промпт велит звать bash) | Ноль кода | Измерено как хрупкое: Spine «узнаёт» вердикт случайно (TASK §0, B3) |

## Consequences

### Positive

- Вердикт гейта — событие журнала и первая строка результата: оркестратор и человек видят его всегда.
- FAIL → урок автоматически: обучение не зависит от дисциплины промпта (основа E1).
- Исполнитель получает требование прогнать `accept_cmd` перед коммитом (через L5) — гейт есть даже там, где у кодера его нет; здесь создаётся разрыв с C+M.

### Negative

- Лишний прогон гейта на каждый harness_run — время и стоимость; митигация: accept по умолчанию только при наличии CONSTRAINTS.yaml, таймауты как у пост-гейта.
- Разбор свободного вывода гейта (не-JSON) эвристичен: ложные коды возможны; митигация: приоритет JSON-вывода, коды — по строгому regex.
- Меняется формат результата harness_run при заданном accept — потребители, парсящие первую строку, обязаны учитывать вердикт (документируется; без accept — байт-в-байт).

## Reversibility

reversible. Параметр аддитивен; без `accept` поведение идентично 0.4.10 (контрольный тест байт-в-байт). Откат — revert коммита L2.
