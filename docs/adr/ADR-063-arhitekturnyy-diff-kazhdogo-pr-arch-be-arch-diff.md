# ADR-063. Архитектурный дифф каждого PR (`arch-be arch-diff`): граф as-built, дифф в трёх измерениях, контракт `arch-be/arch-diff/v1`

- Дата: 2026-10-07
- Статус: Proposed
- Модель-автор: kimi-k2 (волна K, TASK-v2 §9)

## Context

Архитектор не может прочитать сотни PR в неделю, а код-ревью показывает
строки, а не систему: новое ребро между компонентами, прямое подключение к
чужой БД, правка контракта тонут среди переименований. Модель (`model/`)
отстаёт от кода, потому что её поддержка — отдельная работа. У Spine все
детерминированные детали для ответа «что этот PR изменил в архитектуре» уже
есть и разбросаны по механикам: извлечение импортов (`control/exec.rs`,
ADR-029/030), интеграции `host:port` и манифесты (`survey.rs`), классификация
контрактов (`contract_diff`, ADR-046), NFR-формулы (`nfr.rs`, ADR-007),
маршрут значимости (`diff_triggers.rs`, ADR-034), Mermaid (`model/graph.rs`).

Ограничения: core (без сети, TUI и LLM — AD-2, граница C-34); детерминизм
(правило 10 TASK-v2: повторный прогон на тех же коммитах — байт-в-байт тот
же результат); обратная совместимость exit-кодов 0/1/2/3 и форматов
(правило 4); рабочее дерево репозитория не изменяется.

## Decision

### 1. Граф «как построено» (`arch_diff::as_built`, K1)

Снимок ревизии читается из git (`ls-tree --long -z` + `git show` на файл,
потолки: 2000 сканируемых файлов, 1 МБ на файл) — рабочее дерево не
трогается. Узлы:

- компоненты: CMP модели с `code_roots`; каталоги с манифестом сборки вне
  `code_roots` — тоже узлы с пометкой `inferred` (набор манифестов —
  как у `survey`/дрейфа модели); без модели граф строится по манифестам;
- внешние системы: `host:port` из конфигов (regex интеграций `survey`,
  userinfo срезается, петлевые пропускаются, редактор секретов применяется);
- хранилища: строки подключения (та же семантика, что у детектора
  `new_datastore`; схемы postgres/mysql/mongodb/redis/kafka → узел
  `store:`, `bootstrap.servers` → Kafka);
- контракты: файлы OpenAPI/AsyncAPI/protobuf (эвристики детектора
  `api_contract_change`: имя, глоб `[significance]`, ключ верхнего уровня
  в заголовке).

Рёбра: импорт между компонентами (общее извлечение `src/imports.rs`,
вынесенное из `control/exec.rs`; для Go/монорепо — суффиксное совпадение
пакета с корнем цели), обращение к внешней системе/хранилищу, публикация
контракта (файл контракта внутри корня компонента). У каждого ребра
основания `файл:строка` (потолок 10, дальше — счётчик). Узлы и рёбра
отсортированы; id стабильны (`CMP-001`, `dir:<каталог>`, `sys:<host:port>`,
`store:<scheme>://<host>`, `contract:<путь>`).

### 2. Дифф в трёх измерениях (`arch_diff::arch_diff`, K2)

1. **Реальность PR:** добавленные/удалённые узлы и рёбра между `as_built(base)`
   и `as_built(head)`. Переименование/перенос файлов внутри одного компонента
   изменением архитектуры не считается (граф строится на уровне компонентов;
   детектор триггеров работает по `git diff` с rename detection).
2. **Расхождение с моделью:** каждое ребро head помечается `в модели /
   нет в модели`: импорт — по `depends_on` CMP; обращение — по упоминанию
   хоста в INT/SYS; контракт — по полю `contract` INT (ADR-035). Объявленные
   рёбра `depends_on` без единого импорта в коде head — отдельный список
   (та же семантика, что находка `declared-edge-unused` волны C2).
3. **Смысл:** задетые инварианты AD (по `affects` AD и `implements` CMP) с
   правилами-охранниками (`verified_by: C-NNN` → реестр CONSTRAINTS.yaml на
   head) и классом зубов; затронутые ADR (по `affects`); классификация
   контрактов (`contract_diff`: ломающее/аддитивное/добавлен/удалён);
   сдвиг NFR (`nfr budget`/`nfr capacity` «было → стало» при изменении
   сущностей модели); маршрут значимости и триггеры с источником
   (`declared`/`diff`/`declared+diff`, fail-safe объединение ADR-034).

### 3. Вывод (`arch-be arch-diff`, K3)

`arch-be arch-diff --repo . --base <ref> [--head <ref>] [--format
md|mermaid|json|sarif] [--trigger имя=true …] [--fail-on …]`:

- **md**: сводка ≤ одного экрана (маршрут, новые/удалённые связи и узлы,
  контракты, NFR, инварианты, предложения модели); детали (основания,
  триггеры) — сворачиваемыми `<details>`-блоками. Пустой дифф — одна строка
  «Архитектурных изменений нет».
- **mermaid**: `flowchart LR` (стиль `graph_mermaid`): неизменённые рёбра —
  `-->`, добавленные — `==>`, удалённые и рёбра вне модели — `-.->` с
  меткой; новые/удалённые узлы — классами `added`/`removed`.
- **json**: машинный контракт `arch-be/arch-diff/v1` (поле `schema`, как у
  `gate-verdict/v1`). Версия схемы фиксируется тестом стабильности полей;
  добавление поля — минорно, переименование/удаление — новая версия схемы.
- **sarif**: SARIF 2.1.0 (общий рендер `report_fmt`): рёбра вне модели,
  задетые инварианты и ломающие контракты — warnings с адресами
  `файл:строка`, чтобы площадки показали их в интерфейсе PR без доработок.

Exit-коды не переизобретаются: команда информационная, `exit 0` всегда,
кроме `--fail-on undeclared-edge|breaking-contract|invariant-touched`
(перечисляемые) — тогда `exit 1` при наличии соответствующего факта.
Подключение составляющей `arch_drift` к гейту — отдельный пункт (K6), здесь
не делается.

### 4. Класс зубов правила — интерфейс к волне B

Дифф читает `.arch-handoff/teeth.json` рабочего дерева (толерантно:
`{"rules": {"<имя>": {"teeth": "confirmed"|"text"|"unknown"}}}` или плоская
карта). Без файла или без правила в нём — честное «зубы не измерены»
(`unknown`). Само измерение зубьев (мутации) волна K **не реализует** — это
команда `arch-be rules teeth` волны B; здесь только чтение результата.

### 5. Предложения правки модели — только формирование

Для каждого ребра «нет в модели» и нового компонента дифф формирует
пронумерованное предложение (`depends_on += …`, новая сущность SYS/INT/CMP
с `code_roots`/контрактом); предложение, противоречащее задетому инварианту,
помечено его id (⚠). Принятие/отклонение предложений (`arch-diff accept/
reject`) — волна K5, здесь не реализуется.

## Alternatives Considered

- **Временный `git worktree` вместо `git show` в память** — отвергнуто:
  worktree пишет в `.git` репозитория (мутация состояния на чтении), падает
  на bare-репозиториях и требует уборки; снимок в память read-only.
- **LLM-анализ диффа** — отвергнуто AD-2: детерминированный слой без LLM;
  эвристики документированно приблизительны, но воспроизводимы.
- **Отдельный язык запросов к графу** — избыточно для экрана PR; JSON-
  контракт + SARIF покрывают площадки, mermaid — ревью человеком.
- **Помечать «в модели» по полному соответствию INT хосту** — отвергнуто:
  в модели хост пишется прозой; выбрано детерминированное совпадение подстроки
  (хост без порта в id/заголовке/теле INT/SYS), честно задокументированное
  как эвристика.

## Consequences

### Positive

- Один экран на PR: что изменилось в системе, с основаниями `файл:строка`,
  без LLM и без настройки — работает в любом репозитории (`inferred`-узлы),
  модель только обогащает.
- Пустой дифф = «архитектуре ревью не нужно» — снимает с архитектора поток
  рефакторингов.
- Обновление модели становится побочным эффектом ревью (предложения),
  а не отдельной обязанностью.

### Negative

- Разрешение импортов эвристическое: Kotlin без `;`, динамические импорты,
  Go-алиасы вне суффиксного совпадения — документированные пропуски
  (ложное отсутствие ребра возможно; ложное ребро — нет).
- Снимок до 2000 файлов/1 МБ — bounded-работа; больше — честная ошибка.
- `teeth.json` — интерфейс надежды на волну B: до её файла класс зубов
  всегда «не измерены» (честно, но бедно).

## Reversibility

**Reversible.** Команда и форматы аддитивны; без `--fail-on` exit-код всегда
0; существующие составляющие гейта и `gate-verdict/v1` не затронуты. Откат —
git revert.
