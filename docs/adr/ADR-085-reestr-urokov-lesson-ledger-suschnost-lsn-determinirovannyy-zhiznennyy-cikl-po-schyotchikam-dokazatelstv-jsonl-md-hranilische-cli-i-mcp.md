# ADR-085. Реестр уроков Lesson Ledger: сущность LSN, детерминированный жизненный цикл по счётчикам доказательств, JSONL+MD хранилище, CLI и MCP

- Date: 2026-10-14
- Status: Accepted
- Модель-автор: spine-arch (оркестратор), по TASK-Spine-0.5.0-learning-loop.md
- Дельта: `changes/learning-loop-050/DELTA.md` (пункт L1)

## Context

Живые прогоны 0.4.10 (36 сессий, 108 запусков исполнителя, отчёт «Spine Harness: две гипотезы против данных») показали обучение в контексте на уровне оркестратора (0/17 повторов скрытой конвенции с контекстом против 8/8 без), но эффект держится на свободном тексте LLM, умирает с сессией и L3-компактификацией; штатная `failure_memory` ловит только сбои инструментов по сигнатуре `tool:class` (B1), а `failure_lessons.md` никто не читает (B2). Нужна долговечная сущность «урок», переживающая сессию, смену модели и исполнителя, с жизненным циклом, который нельзя «уболтать» — AD-2 (жизненный цикл решается детерминированно, LLM только формулирует текст).

## Decision

Вводим модуль `src/lessons/` (`mod.rs`, `ledger.rs`, `render.rs`, `scope.rs`) — реестр уроков Lesson Ledger:

- Сущность `Lesson`: `id` (LSN-<sha8 сигнатуры>, стабильный, без перенумерации), `signature` {source: gate|fitness|tool|review, code, subject_kind}, `statement` (текст, может быть `[inferred]` от LLM — статус от него не зависит), `scope` {level: file|module|package|repo|user|org, globs}, `evidence[]` {run_id, harness, verdict_excerpt, file:line, ts, outcome: fail|pass_after_apply}, счётчики `hits`/`misses`, `status`, `provenance` (кто записал, sha256 вердикта, версия arch-be).
- Хранилище: `.arch/lessons/ledger.jsonl` (append-only события; уровень repo), `$ARCH_HOME/lessons/` (уровень user), org — через экспорт/импорт (ADR-091). Рендер `.arch/lessons/LESSONS.md` детерминирован, отсортирован по id.
- Переходы статусов — только по счётчикам, пороги в `[lessons]` конфига: `observed` (первый FAIL с сигнатурой) → `candidate` (FAIL повторился или урок применён и дал PASS) → `confirmed` (hits ≥ 2, misses = 0, ≥ 2 разных задачи) → `promoted` (только через L7/ADR-089) → `retired` (misses ≥ 2 подряд, правило удалено из CONSTRAINTS, истёк expiry). LLM никогда не меняет статус.
- CLI: `arch-be lessons list|show|record|retire|export|import`. MCP: `lessons_query`, `lessons_record` — доступно в `--features core` (хост-агент без своей LLM получает память, проверенную гейтом). Уточнение по итогам реализации (коммит de621cc, конфликт №1 контракта): `lessons_record` пишет в рабочий каталог клиента и потому отдаётся только под `arch-be mcp serve --rw` (read-only инвариант MCP-сервера, ADR-083, сохраняется); `lessons_query` доступен всегда. CLI-путь записи не ограничен.
- Поиск — существующий BM25 из `src/kb.rs`. Новых зависимостей в `[dependencies]` нет. Всё поведение — за `[lessons] enabled` (по умолчанию `false` до волны 3).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Lesson Ledger (выбран)** | append-only JSONL: аудит, конкурентная дозапись, детерминированный рендер; статусы по счётчикам — защита от LLM-произвола (AD-2) | Своя сущность и свой жизненный цикл — код и тесты |
| B. Расширить `failure_memory` до полноценного реестра | Меньше кода, механика сигнатур уже есть | failure_memory заточена под `tool:class`, без scope/evidence/статусов; смешение «сбоя инструмента» и «вердикта гейта» размыло бы семантику; B1/B2 показали, что точка роста неверна |
| C. Хранить уроки только в md-файлах (как MEMORY.md) | Простота, человекочитаемость | Нет детерминированных переходов и счётчиков; md-рендер — производная, а не источник истины; конкурентная запись ломает формат |
| D. Статус-кво: уроки в свободном тексте задания кодеру | Ноль кода | Именно это измерено как хрупкое: умирает с сессией/компактификацией, не обобщается, не превращается в правило (TASK §0) |

## Consequences

### Positive

- Урок переживает сессию, компактификацию, смену модели и исполнителя (основа E1, E2).
- Каждый статус подкреплён счётчиком доказательств с `run_id` — воспроизводимость и аудит.
- Core-сборка получает межсессионную память через MCP без своей LLM.
- `failure_lessons.md` мигрирует в реестр (закрываются B1, B2 на уровне хранилища).

### Negative

- Новый суб-ресурс состояния (`.arch/lessons/`) — миграция, права, gitignore-политика репозиториев.
- Конкурентная дозапись JSONL требует блокировок/атомарности (тест двух процессов).
- Риск раздувания реестра шумом — митигация: retired по misses/expiry, лимиты L3-инъекции (ADR-087).
- Пороги переходов — эмпирика, зафиксированная в пререгистрации; смена порогов — отдельная дельта.

## Reversibility

reversible. Вся механика за флагом `[lessons] enabled=false`; реестр — новые файлы, удаление не трогает существующие данные и контракты. gate-verdict/v1, exit-коды и смысл CONSTRAINTS.yaml не меняются.
