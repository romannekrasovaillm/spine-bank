# ADR-090. Ленивая загрузка инструментов и профили: ядро + tool_search, профили orchestrate/architect/reverse/full, бюджет первого запроса ≤ 25000 символов

- Date: 2026-10-14
- Status: Proposed
- Модель-автор: spine-arch (оркестратор), по TASK-Spine-0.5.0-learning-loop.md
- Дельта: `changes/learning-loop-050/DELTA.md` (пункт L9) · закрывает B6

## Context

Все 67 схем инструментов отправляются в каждом ходе: 52 054 символа, 84% первого запроса (B6, замер `capture.py` стенда). По факту поведения Spine работает 4 базовыми инструментами; из 51 доменного за 36 сессий вызваны 12. Места под накопленный опыт (блок уроков ADR-087) в контексте не остаётся: бюджет съеден схемами.

## Decision

1. **Ядро в каждом запросе:** `bash`, `read_file`, `write_file`, `edit_file`, `glob`, `grep`, `harness_run`, `propose_options`, `lessons_query`, новый `tool_search(query) -> [spec]`.
2. Доменные схемы подгружаются в запрос после `tool_search`/`skill_load` и живут до конца сессии (кэш). Вызов незагруженного доменного инструмента подгружает его, а не падает (тест).
3. **Профили:** `orchestrate` (ядро + `significance_score`), `architect` (ядро + контрольный контур), `reverse` (существующий), `full` (как сейчас — по умолчанию до волны 3; с волны 3 дефолт для `arch-be run` — `orchestrate`).
4. **Цель:** первый запрос ≤ 25 000 символов вместе с системным промптом (база 62 021). Высвобожденный бюджет — под блок уроков.
5. **Регрессионная граница:** `benchmarks/architect-value` не хуже 0.4.10 по каждой строке; архитектурные задачи стенда A1–A6 используют ≥ 10 разных доменных инструментов (база 12).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Ядро + tool_search + профили (выбран)** | −60% первого запроса; бюджет под уроки; детерминированный поиск схем | Лишний ход на подгрузку схемы; риск, что модель не найдёт инструмент |
| B. Статический профиль на задачу (без tool_search) | Предсказуемость | Профиль угадывается до задачи; ошибка профиля = нет инструмента вовсе |
| C. Сжатие схем (короткие описания, тот же набор) | Без смены модели доступа | Экономия ограничена; 67 схем всё равно в каждом запросе |
| D. Статус-кво | Ноль кода | 84% первого запроса — схемы; обучению негде жить (TASK §0) |

## Consequences

### Positive

- Контекстный бюджет под опыт без роста окна; стоимость первого запроса падает кратно.
- `tool_search` делает рост библиотеки инструментов безболезненным (новый инструмент не раздувает каждый запрос).

### Negative

- Риск «инструмент существует, но модель его не нашла» — деградация архитектурных задач; митигация: регрессионная граница architect-value и ≥10 доменных инструментов на A1–A6, профиль `full` как аварийный выход.
- Кэш загруженных схем усложняет управление контекстом (схемы живут до конца сессии).
- Смена дефолтного профиля в волне 3 меняет поведение `arch-be run` — миграция задокументирована в CHANGELOG.

## Reversibility

reversible. Профиль `full` воспроизводит поведение 0.4.10; дефолт переключается конфигом. Откат — revert коммита L9.
