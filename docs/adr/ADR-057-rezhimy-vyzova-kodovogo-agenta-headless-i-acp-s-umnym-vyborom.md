# ADR-057. Режимы вызова кодового агента: headless и ACP с умным выбором

- Дата: 2026-10-03
- Статус: Accepted (стратегия умного выбора — вариант (а) «конфиг + auto + fallback», выбрана владельцем 2026-10-03)
- Модель-автор: deepseek (подготовка), решение — человек

## Context

`run_harness` (MCP `harness_run`, `arch-be agent`) вызывает кодовых агентов
единственным способом — headless: процесс с флагами, промпт позиционным
аргументом / флагом / stdin (`PromptMode`), вывод — сырой текст. Контракт
адаптера `[harnesses.<имя>]` в `~/.config/arch-harness/config.toml` описывает
`binary`/`args`/`prompt_mode`/`env`/`env_allow`/таймауты.

Обследование хоста (2026-10-03, `--help` каждого бинаря):

| Агент | Headless-режим | ACP-режим | Команда ACP |
|---|---|---|---|
| claude (Claude Code 2.1.278) | `-p --dangerously-skip-permissions`, stdin | да, через адаптер | `claude-code-acp` (@zed-industries/claude-code-acp@0.16.2, установлен) |
| qwen (Qwen Code) | `-p {prompt}` | да, нативно | `qwen --acp` (+ `--channel ACP`) |
| kimi (Kimi Code) | `-p {prompt}` | да, нативно | `kimi acp` (подкоманда «ACP server over stdio») |
| openclaw | `agent --message {prompt}` | да | `openclaw acp` (bridge поверх Gateway) |
| hermes | `-z {prompt}` | да | `hermes acp` |
| theseus | `-p {prompt}` | **нет** | — |
| codewhale | `exec --auto {prompt}` | **нет** | — |

ACP (Agent Client Protocol, agentclientprotocol.com; спецификация сверена
2026-10-03) — JSON-RPC 2.0 поверх stdio: `initialize` (версия протокола,
capabilities), `session/new` (cwd, MCP-серверы), `session/prompt` (задача;
ответ — стрим нотификаций `session/update`: `agent_message_chunk`,
`tool_call`, `tool_call_update`, `plan`), запросы `session/request_permission`
(агент спрашивает клиента о допуске инструмента), `session/cancel` (мягкая
отмена), клиентские методы `fs/read_text_file`/`fs/write_text_file`/
`terminal/*`/`elicitation/*` (управляются capabilities в `initialize`).

Силы:

- **Наблюдаемость.** Idle-детект сейчас опирается на stdout/stderr и активность
  файлов; долгий молчащий tool-вызов внутри агента неотличим от зависания. В
  ACP активность — события протокола (`tool_call`, чанки): таймаут тишины
  становится честным. Журнал прогона получает структурированные tool-вызовы.
- **Отмена.** `session/cancel` корректнее SIGKILL процессной группы (агент
  успевает завершить вложенные активности).
- **Единый контракт.** Зоопарк флагов (`-p`/`exec --auto`/`--message`/`-z`)
  заменяется одним протоколом; новые агенты подключаются одной секцией.
- **Политика допуска.** `session/request_permission` — точка, где контроль
  допуска инструмента может стать явным (сейчас везде skip-permissions/yolo).
- **Против:** второй путь кода; сторонние ACP-адаптеры (claude-code-acp —
  слой Zed поверх Anthropic SDK) со своим жизненным циклом версий; theseus и
  codewhale ACP не умеют — нужен fallback; JSON-контракт результата
  (status/open_questions) живёт в финальном тексте ответа и должен
  извлекаться из стрима.

## Decision

**Принципиальная схема (финализируется выбором стратегии ниже):**

1. **Два режима вызова** в `CodingHarnessConfig`:
   - `prompt` — существующий headless (позиционный/флаг/stdin), без изменений;
   - `acp` — клиент протокола: spawn ACP-процесса (бинарь/арги из новой
     секции `[harnesses.<имя>.acp]`), `initialize` (capabilities: fs=false,
     terminal=false, elicitation=false — агент не должен их звать; на вызов —
     error -32601), `session/new` (cwd = каталог прогона: worktree изоляции
     или репозиторий), `session/prompt` с задачей, чтение стрима
     `session/update`; финальный ответ агента (агрегат `agent_message_chunk`
     после последнего `tool_call`) — как «stdout» для разбора JSON-контракта;
     `session/cancel` при таймаутах; `session/request_permission` —
     авто-выбор первой `allow`-опции с журналированием запроса
     (эквивалент текущего skip-permissions; политика допуска — отдельная
     волна, честная граница ниже).
2. **Умный выбор режима — вариант (а), принят владельцем 2026-10-03:**
   `mode = "auto"` (дефолт): ACP-секция `[harnesses.<имя>.acp]` задекларирована
   → ACP; не задекларирована → headless; провал инициализации ACP (таймаут
   `initialize`, ошибка протокола, ранний exit) при `auto` → откат на
   headless с предупреждением в итоге прогона; `mode = "acp"` — без отката
   (провал = ошибка прогона); `mode = "prompt"` — принудительный headless.
3. **Развёртка на агентов хоста**: acp-секции для claude-code
   (`claude-code-acp`), qwen-code (`qwen --acp`), kimi-code (`kimi acp`),
   openclaw (`openclaw acp`), hermes (`hermes acp`); theseus/codewhale —
   без acp-секции (headless), с пометкой «ACP не поддержан» в конфиге.
4. Изоляция прогона (worktree, env_clear/env_allow, пост-гейт, авто-коммит)
   — общие для обоих режимов; ACP-процесс запускается в том же cwd/окружении.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **(а) Декларация в конфиге + `mode=auto` с fallback — ✅ выбран:** ACP-команда фиксируется в `[harnesses.X.acp]`; auto: есть секция → ACP, нет → headless; провал init → headless + предупреждение. | Детерминизм (конфиг — SSOT, как весь arch-harness); нулевая цена для theseus/codewhale; провал ACP не блокирует работу; поведение по умолчанию «умное» без сюрпризов. | Fallback может маскировать деградацию ACP (митигация: предупреждение в итоге + журнал); конфиг надо пополнять при смене мажоров агентов. |
| **(б) Автодетект на хосте:** зондировать `--acp`/`acp` подкоманды при первом вызове, кэшировать в state. | Ноль конфигурации; «само находится». | Недетерминизм (поведение зависит от версии агента в PATH — прямо против философии конфига-SSOT); зонд по help-выводу хрупок; первый прогон платит латентность зонда; сюрпризы после обновлений агентов. |
| **(в) Только явный режим (`mode=acp\|prompt`, дефолт prompt):** | Максимальная предсказуемость; простейший код. | «Умного выбора» нет — каждый адаптер настраивается руками; выгода ACP не включается по умолчанию; против формулировки задачи. |

Статус-кво (только headless) — не вариант по постановке задачи; фиксирует
наблюдаемость idle-детекта на stderr/файлах и зоопарк флагов.

## Consequences

### Positive

- Честный idle-детект (события протокола вместо эвристики stderr+файлы);
  структурированный журнал tool-вызовов прогона.
- Мягкая отмена (`session/cancel`) вместо только SIGKILL.
- Единый контракт подключения агентов; подключение нового ACP-агента —
  одна секция конфига.
- Точка входа будущей политики допуска инструментов
  (`session/request_permission`) — сейчас заглушена авто-allow, но с
  журналом: аудит допуска возможен уже с этой версией.

### Negative

- Второй путь кода вызова (JSON-RPC клиент) — площадь тестирования растёт;
  мутационное покрытие и eval-сьют должны охватить оба режима.
- Сторонний слой: `claude-code-acp` (Zed) — отдельная версия, отдельные
  релизы, не контролируются репозиторием (mitигация: пин версии в
  установке окружения, версия пишется в журнал прогона).
- Авто-allow `request_permission` = сегодняшние yolo/skip-permissions —
  security boundary не улучшен, только журналируется; врать об этом нельзя.
- Fallback (auto) может скрыть хронический сбой ACP: прогон молча уходит в
  headless (митигация: предупреждение в `HarnessRun`-итоге + счётчик в
  журнале; `mode="acp"` для прогонов, где ACP обязателен).
- Стрим `agent_message_chunk` агрегируется в память: сверхдлинные ответы
  агента держатся целиком (ограничение снять нельзя — JSON-контракт в хвосте).

## Reversibility

**Reversible.** Поля конфига аддитивны; дефолт `auto` без acp-секций
эквивалентен сегодняшнему поведению. Выключение: удалить acp-секции (или
`mode = "prompt"` глобально) — код ACP остаётся мёртвым путём, удаляется
`git revert` без миграций.
