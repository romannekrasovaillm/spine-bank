# ADR-087. Инъекция уроков в контекст и защита от компактификации: закреплённый блок из реестра, карантин инъекций, хуки session-start/user-prompt-submit, блок уроков субагентам

- Date: 2026-10-14
- Status: Accepted
- Модель-автор: spine-arch (оркестратор), по TASK-Spine-0.5.0-learning-loop.md
- Дельта: `changes/learning-loop-050/DELTA.md` (пункт L3)

## Context

Даже записанный урок сегодня не доходит до адресата: L1/L3-компактификация не различает «урок» и «шум» и пересказывает их вместе (B5); `failure_lessons.md` не читается никем (B2); субагенты и ralph-раунды стартуют со свежим контекстом, урок родителя до них не доходит (B8); у Spine Core нет событий хуков SessionStart/UserPromptSubmit, чтобы отдать уроки хост-агенту (B9). При этом уроки — недоверенные данные (текст может родиться из stdout исполнителя): прямой риск prompt-injection в системный промпт (риск 1 TASK).

## Decision

1. **[Harness] Закреплённый блок.** При старте сессии и перед каждым `harness_run` в контекст подмешивается блок `## Уроки контура (выучено, проверено гейтом)`: top-K уроков, отобранных по scope к cwd и путям задачи (K и лимит токенов — в `[lessons]` конфига).
2. **Переживание компактификации.** L1-маскирование и L3-саммари блок не трогают: после компактификации блок **пересобирается из реестра**, а не пересказывается из истории (закрывает B5). Тест: блок присутствует после `compact_now` при L1 и L3.
3. **Миграция failure_memory.** `failure_lessons.md` мигрирует в реестр (B1, B2); `failure_memory` получает сигнатуры источников `gate` и `fitness`.
4. **[Core] Новые события хуков.** `arch-be hook session-start` (уроки области репозитория в контекст хоста) и `arch-be hook user-prompt-submit` (уроки, релевантные упомянутым путям; BM25 из `src/kb.rs`). `connect` устанавливает их для Claude Code и Kimi Code с fail-soft гардом (пустой вывод без реестра), как у существующих хуков (закрывает B9).
5. **Гигиена.** Уроки — данные, не инструкции: блок оборачивается маркером данных и проходит `src/injection.rs`; урок с признаками prompt-injection не попадает в блок и помечается `quarantine`. Тест: текст «ignore previous instructions» → карантин.
6. **Субагенты и ralph (B8).** В свежий контекст субагента передаётся только блок уроков — контролируемая утечка опыта при сохранении свежести контекста.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Закреплённый блок, пересборка из реестра (выбран)** | Урок не может быть «забыт» компактификацией по построению; лимит токенов явный | Постоянная доля контекста; нужна дисциплина лимита (K, токены) |
| B. Просить L3-саммари «сохранять правила» | Ноль кода | LLM пересказывает, а не переносит: измерено как хрупкое (B5); нет гарантии |
| C. Уроки только через инструмент lessons_query по запросу | Нулевой расход контекста по умолчанию | Модель должна вспомнить, что надо спросить, — тот же дефект, что B2 (файл никто не читает) |
| D. Полный контекст субагентам вместо блока уроков | Больше информации | Ломает замысел свежего контекста (B8 — by design), раздувает стоимость |

## Consequences

### Positive

- Урок становится свойством контура, а не окна диалога (основа E1); переживает смену модели.
- Хост-агенты Core (Claude Code, Kimi Code) получают проверенную гейтом память без своей LLM.
- Карантин инъекций закрывает канал отравления памяти через stdout исполнителя (порог: 0 случаев).

### Negative

- Постоянный расход контекста на блок (митигация: жёсткий лимит токенов, отбор L4, L9 высвобождает бюджет схем).
- Устаревший урок в блоке может вредить (митигация: retired по misses, автоматический вывод из блока).
- Новые хуки расширяют поверхность connect — fail-soft обязателен, регрессия существующих 4 хуков недопустима.

## Reversibility

reversible. Блок и хуки — за `[lessons] enabled=false` по умолчанию до волны 3; хуки fail-soft (без реестра — пустой вывод, exit 0). Откат — revert коммита L3; установленные хуки снимаются `connect` повторной установкой.
