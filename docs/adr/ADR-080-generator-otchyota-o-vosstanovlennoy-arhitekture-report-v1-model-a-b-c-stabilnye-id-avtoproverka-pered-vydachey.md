# ADR-080. Генератор отчёта о восстановленной архитектуре (report/v1): модель A/B/C, стабильные ID, автопроверка перед выдачей

- Date: 2026-10-12
- Status: Proposed
- Модель-автор: spine-arch (claude)
- Маршрут: Standard (significance score 2: new_component + api_contract_change)
- Пересмотр: при появлении второго потребителя схемы `report/v1` (кроме CLI, MCP и
  бенчмарков) либо при требовании PDF-сборки внутри бинаря (сейчас — внешний
  конвейер) — пересмотреть состав полей и место рендера.
- Провенанс: внешний формат-стандарт
  `spine-architecture-report-format.md` (Бенчи, 2026-10-12) поверх линии
  recover (ADR-069) и survey (reverse discovery, ADR-037-линия)

## Context

**1. Формат отчёта задан извне и шире графа.** Бенчмарк предъявляет к Spine
формат «отчёт о восстановленной архитектуре» (14 разделов + приложения A–G +
лист экспертной оценки): трассируемость `[src: файл:строки]`, уровни
уверенности A/B/C на каждом элементе, стабильные ID семейств
CTX/CNT/CMP/INT/ADR/RISK, диаграмма+таблица, разделение фактов и
интерпретаций, отдельный раздел неопределённостей, автопроверка перед
выдачей, сборка Markdown → PDF. Текущие артефакты дают только фрагменты:
`recover` — граф ревизии (узлы/рёбра/evidence/gaps), `survey` — карту
обследования (9 секций, `[confirmed]`/`[gap]`/`[inferred]`). Единого
артефакта «отчёт» не существует; метрика — «инструмента нет».

**2. Уверенность сегодня двухуровневая, формат требует трёхуровневую.**
`ArchNode.inferred: bool` и `Confidence::{Confirmed, Inferred}` на calls-рёбрах
не различают «прямо из кода/конфига» (A), «выведено по косвенным признакам» (B)
и «гипотеза» (C). Слияние A и B в один флаг — прямое несоответствие формату
и потеря информации для эксперта.

**3. LLM-слой без контракта на отчёт.** Формат предписывает: интерпретации
генерируются с привязкой к ID элементов, а автопроверка гарантирует, что
ни один элемент не остался без источника и уверенности. ADR-069 (R6) уже
дал дисциплину «LLM пишет только [inferred]» для графа — отчёт нуждается в
её продолжении: LLM не создаёт элементы и уверенность, только наполняет
заранее выделенные интерпретационные блоки.

**4. Два производителя разойдутся.** Отчёт понадобен как минимум из CLI
(`arch-be report`), из MCP (инструмент для кодовых агентов) и из
бенчмарков. Если каждый будет собирать секции сам, таблицы, ID и
confidence-разметка разойдутся — тот же класс дефекта, что T-02/B2 для
параметров схем.

## Decision

1. **Команда `arch-be report <repo>` и схема `arch-be/report/v1`.** Отчёт —
   отдельный артефакт поверх `recover/v1`: строитель один раз собирает
   модель отчёта (элементы с report-ID, уверенностью A/B/C, evidence;
   секционные данные), из модели детерминированно рендерятся все форматы.
   Порядок формата соблюден буквально: модель (JSON) → таблицы и
   диаграммы (md/mermaid) → интерпретационные блоки → автопроверка.

2. **Уверенность A/B/C — производная детерминированных правил, не LLM.**
   Отображение фиксировано: элемент с `model_id` (принятая модель) или
   edge `confidence=confirmed` → **A**; узел `inferred=true` (манифест
   сборки без модели), edge `inferred` → **B**; элементы из `gaps`
   (имя без компонента) и всё, что наполняет LLM-слой → **C**. LLM не
   может назначить A или B — только C в своих блоках (продолжение R6
   ADR-069).

3. **Стабильные report-ID назначаются сортировкой, bijective-маппинг к
   графу.** Семейства формата: `CTX-nn` (акторы/внешние системы),
   `CNT-nn` (контейнеры), `CMP-nn` (компоненты), `INT-nn` (интерфейсы),
   `RISK-nn` (риски), `ADR-nn` (восстановленные решения, скоп`ы отчёта).
   Назначение детерминировано (sort по kind+graph_id) и стабильно между
   прогонами одной ревизии — как `recover/v1`.

4. **Автопроверка перед выдачей — fail-closed, три инварианта формата:**
   (и1) у каждого элемента есть непустой evidence и уровень уверенности;
   (и2) каждый ID на диаграмме присутствует в таблицах (и наоборот);
   (и3) каждый evidence `файл:строка` разрешается в файл ревизии
   (по графу `recover`, SHA в метаданных). Нарушение — отказ выдачи с
   находками, exit ≠ 0; флага «выдать всё равно» нет.

5. **Разделение слоёв по разделам формата.** Детерминированные (данные из
   графа+скана): метаданные, §2 легенда, §3 обзор, §4 контекст, §5
   контейнеры, §6 компоненты (матрица зависимостей, циклы — DFS по
   import-рёбрам), §8 интерфейсы, §11 развёртывание, §13 качество
   (циклы/god-модули/подсказки мёртвого кода), §14 неопределённости,
   приложения A–D, G, лист экспертной оценки. Интерпретационные
   (LLM-блоки с C-уверенностью, помечены плашкой): §1 резюме (сводки —
   детерминированы, находки — LLM), §6 паттерны, §9 сценарии (скелеты
   путей по графу — детерминированы), §10 сквозные аспекты (зонды
   присутствия — детерминированы, оценка — LLM), §12 ADR-записи, §7
   доменная модель (факты из survey — детерминированы), приложение E
   (сравнение с README/docs), F (глоссарий).

6. **SSOT: один строитель — `src/report/`.** CLI, MCP-мост и бенчмарки
   вызывают один сборщик; инвариант AD-11 спайна (Binds/Prevents/Rule —
   ниже). Схема версионируется `arch-be/report/v1`, изменения — аддитивно.

7. **PDF — внешний конвейер, не бинарь.** Сборка Markdown → PDF
   (Typst/Pandoc/WeasyPrint по наличию бинаря) документируется в
   `docs/REPORT.md` и подсказкой команды; новые `[dependencies]`
   запрещены (политика 0.3.12, deny.toml) — PDF-рендер в бинарь не
   тянем. Команда проверяет доступность конвертера и даёт точную
   команду сборки с параметрами запуска (приложение G).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Расширить `recover --format report` вместо новой команды | Нет новой команды; граф уже строится | Смешивает контракт графа (recover/v1, ADR-069) с контрактом отчёта; два формата в одной схеме; survey-факты не в графе — всё равно второй источник; отказ |
| Полностью LLM-генерация отчёта агентом из recover/survey-выводов | Быстрее всего; нет нового кода | Нарушает AD-2 и R6 ADR-069: LLM без контракта назначает уверенность и выдумывает элементы; автопроверку формата нечем исполнять; недетерминированность между прогонами |
| PDF-рендер внутри бинаря (typst-library/weasyprint через FFI) | Одна команда до PDF | Ломает политику «без новых deps» (deny.toml, задача 0.3.12) и AD-6-линию; бинарник растёт на десятки МБ; отказ — внешний конвейер |
| Статус-кво: recover + survey отдельно, отчёт собирает человек/агент вручную | Нулевые доработки | Формат бенчмарка не выполняется вовсе; метрика «инструмента нет»; каждое ручное сведение — новый источник расхождений |

## Consequences

### Positive

- Формат бенчмарка `spine-architecture-report-format` закрывается
  детерминированным ядром: трассируемость, A/B/C, стабильные ID,
  автопроверка fail-closed, лист экспертной оценки (ложится на
  рубричный контур Spine — оценивается `rubric_evaluate`).
- `recover/v1` получает второго потребителя схемы — граф перестаёт быть
  «диффовым» артефактом (условие пересмотра ADR-069 выполнено осознанно).
- A/B/C-уверенность отчёта — механическая производная evidence-модели:
  эксперт проверяет любой тезис за минуту (принцип 1 формата).
- MCP-инструмент `report` даёт отчёт кодовым агентам чужих харнессов —
  ровно сценарий бенчмарков SA-Bench/ArchBenchmarks.

### Negative

- **Объём:** новый модуль ~1.5–3 KLOC + тесты + фикстуры; два
  харнесс-прогона с моими ревью между ними — стоимость принятия.
- **Дублирование данных между graph-ID и report-ID:** маппинг нужно
  поддерживать (bijective-таблица в модели); рассинхрон ловится
  автопроверкой (и2), но это новый класс находок.
- **LLM-блоки первого релиза — скелеты:** §1-находки, §9-сценарии,
  §12-ADR-записи и глоссарий требуют LLM-слоя; без него разделы
  выходят с `[gap]`-промптами. Это честно (раздел 14 собирает их),
  но «идеальное» решение формата — итерация 0.5.x.
- **Автопроверка (и3) честна только в глубину графа:** evidence
  файлов вне детекторов recover (например, README-цитаты приложения E)
  проверяются на существование файла, но не на номер строки —
  документируемое ограничение метода (§14.4).
- **Отказ от PDF в бинаре** — пользователь без Typst/Pandoc получает
  Markdown + инструкцию; конвейер PDF — его ответственность.

## Reversibility

**Reversible.** Новый модуль `src/report/`, команда, MCP-инструмент и схема
`report/v1` не трогают существующие контракты (`recover/v1` неизменен,
survey не переписывается); откат — удаление модуля и команды, AD-11
снимается следующей дельтой. Маппинг A/B/C локализован в одном месте.
