# ADR-088. Обобщение и композиция уроков: детерминированное расширение scope по счётчикам, составные чек-листы LSN-C, классификатор subject_kind по диффу

- Date: 2026-10-14
- Status: Proposed
- Модель-автор: spine-arch (оркестратор), по TASK-Spine-0.5.0-learning-loop.md
- Дельта: `changes/learning-loop-050/DELTA.md` (пункт L6) · критерии E3, E4

## Context

Урок, полученный в одном модуле, должен работать за пределами задачи, где его получили (E3), а два урока из разных провалов должны складываться в правило, которого не было ни в одном вердикте (E4). При этом AD-2 запрещает LLM менять жизненный цикл: обобщение обязано быть детерминированным, иначе «обобщение» превращается в галлюцинацию, распространённую на весь репозиторий.

## Decision

1. **Расширение области (детерминированно).** Урок с одной сигнатурой, подтверждённый в ≥ 2 разных модулях одного пакета, поднимается до `package`; в ≥ 2 пакетах — до `repo`. Контрпример (miss в новой области) откатывает область назад. Счётчики — в `evidence`, переходы — только по ним.
2. **Композиция.** Уроки, которые ≥ 2 раз проваливались в одной задаче или по одному `subject_kind` («новый публичный символ», «новая миграция», «новый эндпоинт»), сворачиваются в составной чек-лист `LSN-C-*` со ссылками на исходные. Статус составного — не выше минимального из исходных; урок с `misses > 0` в композицию не входит.
3. **Классификатор subject_kind** — детерминированный, по диффу исполнителя (новый файл в пакете, новый публичный символ, новый маршрут, новый SQL); переиспользует `recover`/`arch_diff`.
4. **LLM — только формулировка.** `statement` составного урока может быть `[inferred]` от LLM; применимость решает счётчик.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Счётчики + детерминированный классификатор (выбран)** | Обобщение воспроизводимо и аудируемо; откат области по контрпримеру | Консервативность: обобщение медленнее, чем «на глаз» |
| B. LLM обобщает уроки сама | Быстро, гибко | Прямое нарушение AD-2; ошибка обобщения расползается по всем задачам |
| C. Без обобщения, урок привязан к модулю навсегда | Простота | Нет E3: на новом семействе задач всё начинается с нуля |
| D. Статус-кво (урок в тексте задания) | Ноль кода | Не переживает сессию, не складывается (TASK §0) |

## Consequences

### Positive

- E3/E4 получают машинное основание: перенос на отложенное семейство и составные чек-листы — не промпт-эвристика, а следствие счётчиков.
- Откат области по контрпримеру защищает от ложного обобщения (анти-переобучение, риск 2 TASK).

### Negative

- Сложность реестра растёт (составные сущности, откаты scope) — больше тестов.
- Классификатор subject_kind по диффу эвристичен на границах (переименования, сгенерированный код); ошибка классификации → уроки не складываются (ложный отрицательный, не ложный положительный — приемлемо).

## Reversibility

reversible. Всё за `[lessons] enabled=false`; составные уроки — производные сущности со ссылками, удаление не трогает исходные.
