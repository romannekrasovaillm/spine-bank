# ADR-075. Условия активации рёбер, аннотация висячих компонентов и deployment-вид (волна REC)

- Date: 2026-10-11
- Status: Accepted [ADOPTED] — поле `condition` на ребре (аддитивно к
  `arch-be/recover/v1` и `arch-be/arch-diff/v1`), аннотация висячих
  компонентов и правило D3 (inferred ≤ standard в review inbox)
  фиксируются волной REC (TASK 0.4.1, закрытие пробела «условия активации
  рёбер» + deployment-вид)
- Модель-автор: spine-arch (claude)
- Пересмотр: при появлении второго носителя условности (декларативные
  feature-флаги времени исполнения, политика service mesh, аннотации
  `@ConditionalOnProperty` в исходниках) — расширить `ConditionKind`
  третьим-четвёртым значением; при смене конвенции overlay-разметки —
  пересмотреть эвристику `EnvOverlay` (закрытый список env-токенов)
- Провенанс: продолжает `recover` (ADR-069) и `arch-diff` (ADR-063/064);
  правило D3 предвозвещено ADR-072 (метрика 13: «при добавлении D3 —
  расширить метрику „шум“ весом inferred-рёбер»)

## Context

**1. Граф не отличал безусловную связь от условной.** `recover`/`arch-diff`
показывали связь с внешней системой/хранилищем как постоянно
существующую. Но реальные рёбра живут под условием: petclinic — ребро к
`openai` активно, только пока задан `spring.ai.openai.api-key`; boutique —
ребро `productcatalog → alloydb` активно, только пока задан
`ALLOYDB_CLUSTER_NAME`. Без условия граф утверждает связь, которой в
окружении может не быть, — отсюда низкая точность рёбер у конкурентов
(edge precision ≈ 0.45 измерялась именно как доля «связей без условий»).
Приёмочная под-оценка условий «до»: 0.15.

**2. Deployment×env не выражался вовсе.** Одно и то же дерево даёт разные
связи в разных окружениях: helm overlay `values-<env>.yaml` (или
kustomize `overlays/<env>/…`) включает параметр только в конкретном
окружении. Граф схлопывал окружения в один безусловный — терялся
deployment-вид (что включено в prod, что в dev).

**3. Висячие компоненты молчали.** Компонент без входящих и исходящих
рёбер — либо мёртвый код, либо недоинструментирован (связи есть, но не
видны детекторам). И то, и другое архитектору важно, но вывод графа об
этом молчал: «нет ребра» неотличимо от «ребро не найдено».

**4. Review inbox (K7) не учитывал достоверность рёбер.** Рёбра `calls`
несут `confidence` (R2): `confirmed` (имя из основания совпало со
службой) и `inferred` (имя распознано кандидатом косвенно). Ящик
сортировал по маршруту, не глядя на достоверность, — выведенная связь
поднимала запись к срочному ревью наравне с подтверждённой. ADR-072
(строка «D3 … следующая итерация») уже назвал это следующим шагом.

## Decision

1. **Поле `condition` на ребре — аддитивно.** `ArchEdge` получает
   `condition: Option<Condition>`, где `Condition { kind: ConditionKind,
   text: String }`, `ConditionKind` = `config-key` | `env-flag` |
   `env-overlay` (метки отдаёт существующий `label()`). Поле сериализуется
   только при наличии (`skip_serializing_if = "Option::is_none"`): контракты
   `arch-be/recover/v1` и `arch-be/arch-diff/v1` остаются аддитивными —
   граф без условий сериализуется байт-в-байт как прежде. `condition`
   входит в ключ свёртки рёбер (`EdgeKey`) и в сортировку — детерминизм
   (правило 10) сохраняется: два ребра одного направления под разными
   условиями — два ребра (это и есть deployment×env).

2. **Источники условия (детерминированно, без LLM):**
   - `config-key` — совпавший по префиксу ключ каталога провайдеров
     (`spring.ai.openai` покрывает `spring.ai.openai.api-key`); текст —
     dotted-ключ каталога (`Providers::match_key`);
   - `env-flag` — совпавший needle каталога (`ALLOYDB_CLUSTER_NAME`,
     `OPENAI_API_KEY`); текст — имя переменной (`Providers::match_needle`);
   - `env-overlay` — путь overlay-файла: сегмент-маркер
     (`overlays`|`envs`|`environments`) + env-токен из закрытого списка
     (`prod`, `staging`, `dev`, …, `demo`) либо имя файла
     `values-<env>.yaml` / `application-<env>.yaml`. Текст — env. Overlay
     **перекрывает** построчное условие: в overlay-файле связь помечена
     окружением, а не ключом (это deployment-вид).
   - **Владелец конфига вне `code_roots`** (k8s-манифесты в `kustomize/`,
     helm) разрешается не префиксом пути (его нет), а документом: `kind` ∈
     {`Deployment`, `StatefulSet`}, `metadata.name` нормализуется и
     сопоставляется с заголовком компонента. Kustomize-компонент
     (`kind: Component`) несёт условие внутри встроенного блока `patch: |` —
     он разбирается тем же путём (снятие отступа + разбор YAML). Так
     `productcatalog → alloydb` виден: условие живёт в патче
     `productcatalogservice` внутри `components/alloydb/kustomization.yaml`.

3. **Висячий компонент — аннотация, не находка.** Компонент без входящих
   и исходящих рёбер печатается подсказкой «нет связей: кандидат в dead
   code или недоинструментирован»: в JSON — аддитивный массив `hints`
   (только при непустом списке), в md — раздел «## Подсказки». Это
   **аннотация вывода**, а не fitness-находка: `fitness_check` не падает.
   Порядок — по id графа (детерминизм). Не-компоненты (хранилища,
   внешние системы, контракты, топики) не помечаются: висячее хранилище —
   не мёртвый код, а неиспользуемый ресурс (иная семантика).

4. **D3: inferred-ребро не поднимает маршрут выше standard.** Review inbox
   считает `inferred_edges` среди добавленных рёбер; эффективный ранг
   сортировки = `min(route_rank, standard)` при `inferred_edges > 0`
   (иначе — сырой ранг). Сырой `route` артефакта **не подменяется** (это
   данные CI); понижается лишь вес записи, а в строке появляется флаг
   «inferred-рёбра: N — требуется подтверждение (маршрут не выше
   standard)». JSON-отчёт несёт счётчик аддитивно.

5. **Рендер.** md-строка ребра дополняется « · условие: `<text>`
   (`<kind>`)». JSON-контракты несут поле автоматически через serde.

**Поправки:** нет (первая редакция).

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. `condition` — поле ребра (аддитивно); overlay перекрывает ключ; висячий компонент — аннотация; D3 в inbox** (принято) | Контракты v1 аддитивны (потребители без условия не ломаются); deployment×env выражается двумя рёбрами под разными условиями; детерминизм сохраняется; правка локальна волне REC | Расширяется поверхность схемы; эвристика overlay/needle принципиально неполна |
| B. Условие — отдельный узел/ребро (`cond:<…>`), связь указывает на него | Явная модель «условие как сущность» | Взрыв узлов и рёбер; потребитель обязан джойнить; `recover` перестаёт быть графом «как построено» — это уже другой граф; нарушает «новых детекторов не вводим» (ADR-069, п.1) |
| C. Висячий компонент — fitness-находка (падает гейт) | Заметно, не проигнорируешь | Ложные срабатывания: корневые компоненты (frontend, loadgen) и недоинструментированные легитимны; гейт падал бы на чужом коде — прямое противоречие «fitness не должен гореть на норме» |
| D. Капать маршрут в самом диффе (не в inbox) | Правило живёт рядом с `route` | Смешивает «значимость изменения» (что изменилось) с «достоверностью вывода» (насколько уверены) — разные оси; `route` диффа читают другие потребители, для которых inferred не понижение. D3 — правило приоритизации ревью, его место в inbox |

## Consequences

### Positive

- Точность рёбер: связь перестаёт утверждаться безусловно — petclinic
  (`spring.ai.openai`), boutique (`ALLOYDB_CLUSTER_NAME`) видны как
  условные; под-оценка условий закрывается аддитивно, без ломки v1.
- Deployment×env выражен: overlay-файл даёт ребро с условием-окружением;
  два ребра одного направления под разными условиями — видны оба.
- Висячий компонент назван, а не замолчан — архитектор видит кандидатов в
  мёртвый код; аннотация не превращается в ложный отказ гейта.
- Ревью-очередь честнее: выведенная связь не отодвигает подтверждённую и
  не поднимается к срочному ревью без подтверждения (D3).

### Negative

- **Условие из строки конфигурации — эвристика.** Needle-совпадение
  (`ALLOYDB_CLUSTER_NAME` в любой строке) даёт условие даже там, где
  переменная декоративна; overlay-детектор опирается на закрытый список
  env-токенов и не узнает кастомные имена окружений. Ложные условия
  возможны — цена честно признаётся; митигация — расширяемый каталог
  (`providers.yaml`) и консервативный список токенов.
- **Однострочная связь может дать два условия** (config-key из
  `flatten_keys` и env-flag из `match_needle` для одной строки): при
  совпадении текста ребро сворачивается в одно (evidence-множество), но
  при разных основаниях — два ребра. Остаточный шум признаётся;
  overlay перекрывает оба.
- **Схема расширилась:** контракты `recover/v1` и `arch-diff/v1`
  пополнились опциональным `condition` и (recover) массивом `hints`;
  приёмка `mcp_schema_probe`/схема-тесты должны покрыть аддитивность
  (чистый граф — байт-в-байт прежний).
- **D3-правило — приоритизация, не истина:** inferred-ребро может быть
  верным; понижение до standard замедляет его ревью. Митигация — флаг
  прямо называет причину и требует подтверждения, а не скрывает запись.

## Reversibility

**Обратимо, цена низкая.** Поле `condition` и массив `hints` —
аддитивные: откат — удаление ветки разбора overlay/needle и атрибуции
документов вне `code_roots` в `as_built.rs` и `dead_hints` в `recover.rs`;
потребители, читающие схему, отсекут поле или проигнорируют его. Каталог провайдеров расширяется
пользовательским файлом без правок кода (`$ARCH_HOME/assets/recover/
providers.yaml`) — расширение условий обратимо данными. Правило D3
(D3-кап) снимается удалением `effective_rank`/флага в `review_inbox.rs`
без следа в артефактах CI (сырой `route` не подменялся). Необратим ровно
один аспект — номер ADR-075 (номера не переиспользуются): цена фиксации,
а не риск отката.
