# ADR-055. Одобрение ослаблений извне агентского диапазона (self_approved)

- Дата: 2026-10-03
- Статус: Accepted (вариант выбран владельцем 2026-10-03 из трёх предложенных; волна A релиза 0.3.12, пункт A5 задания TASK-Spine-Core-0.3.12.md)
- Модель-автор: deepseek (подготовка), решение — человек

## Context

Волна A закрыла цепочку самоузаконивания: выдуманный ADR (A2), правка тела
правила (A1), подмена контрольной плоскости (A3), непроверенный результат
прогона (A4) и переписывание MANIFEST (A4.1b). Осталась последняя дверь:
агент в режиме rw может создать **настоящий** ADR со статусом accepted
(`adr_new`), собственную дельту (`delta_propose`) и override — формально все
проверки A2/A3 пройдут: ADR существует и принят, дельта покрывает правку,
пины не тронуты. Проверяемый сам выдал себе одобрение.

Ключевое наблюдение: прогоны `harness_run` идут в изолированном worktree
(`[fleet] require_worktree`), созданном от baseline-коммита. **Всё, что
появилось в диапазоне `base..HEAD` этого worktree, по построению является
работой исполнителя** — идентичность коммиттера не важна и не проверяема
(git user.name/email подделываются тривиально), но происхождение по
диапазону — факт архитектуры контура, а не обещание агента.

## Decision

Принять вариант **(а) — диапазон прогона**:

1. Пост-гейт `harness_run` (A4, вне окружения исполнителя) определяет
   агентский диапазон: `baseline_commit..HEAD` изолированного worktree.
2. ADR, override и дельта, **впервые появившиеся** в этом диапазоне, не
   узаконивают ослабление правил реестра: вместо подавления находки
   `rule_weakened` пост-гейт выдаёт `[error] self_approved — одобрение
   возникло в диапазоне прогона исполнителя (base..HEAD) → перенесите
   одобрение в основной репозиторий решением владельца`.
3. `self_approved` видна в паспорте вердикта (gate-passport).
4. Легитимный путь одобрения: владелец принимает решение **после** merge
   работы (в основном дереве, своим коммитом/через PR) — ADR и дельта
   вне агентского диапазона узаконивают ослабление штатно.

## Alternatives

- **(б) Список владельцев** (`approved_by` в ADR/дельте против `owners`
  из конфига) — отвергнуто: конфиг репозитория локален и редактируем
  агентом в той же песочнице, защита круговая; требует ведения owners
  в каждом кейсе.
- **(в) Криптографическая подпись** (одобряющий коммит/тег подписан
  ключом владельца, ssh-signing) — отвергнуто для 0.3.12: настройка
  ключей и процесс для человека тяжелее, не успеть без риска; зафиксировано
  как усиление дорожной карты для банковского контура (см. Reversibility).
- **Статус-кво** (A2 как есть) — отвергнуто: оставляет последнюю дверь
  самоузаконивания открытой, что противоречит цели волны A
  («проверяемый не управляет проверкой»).

## Consequences

- Положительные: закрыта последняя композиция самоузаконивания; признак
  работает без новой инфраструктуры и без доверия git-идентичности;
  детерминирован (диапазон — факт контура изоляции).
- Отрицательные: одобрение «в ходе прогона» (владелец вручную коммитит
  ADR в песочницу исполнителя) перестаёт узаконивать — процесс требует
  переноса решения в основное дерево после merge; в обычных (не-worktree)
  репозиториях вариант (а) не применяется вовсе — там остаётся A2 без
  защиты от self-approval (честная граница, см. паспорт);
  ложное срабатывание возможно, если ослабление легализовано ADR,
  созданным исполнителем по явной инструкции задачи, — митигируется
  формулировкой задачи (одобрения выдаёт владелец, не исполнитель).
- Для CI: новая error-находка `self_approved` появляется только в
  пост-гейте `harness_run` — чужие пайплайны не красятся.

## Reversibility

Высокая: проверка аддитивна к пост-гейту A4, отключается вместе с ним
(`post_gate = false`), откат — `git revert`. Усиление до (в) (подписи)
не исключается: `self_approved` по диапазону остаётся первым слоем,
подпись — вторым для контуров с ключевыми владельцами.
