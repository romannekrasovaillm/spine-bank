# ADR-093. Связка критерия рубрики с fitness-правилом: детекторы в досье, детерминированное первенство, judged_by, промоушен по калибровке

- Date: 2026-10-18
- Status: Accepted
- Модель-автор: Claude Opus 5.5 (сессия переноса принципов agentic-fitness-functions)

## Context

В Spine две половины архитектурного контроля жили раздельно. Детерминированная —
правила `CONSTRAINTS.yaml`, исполняемые гейтом; смысловая — рубрики с LLM-судьёй
по досье (ADR-051/052). Связь между ними была текстовой: в комментарии рубрики
`nfr_mechanism_fit` сказано, что она закрывает дыру правила
`rto_rpo_backed_by_adr`, но ни механика, ни гейт этого не знали.

Разбор репозитория agentic-fitness-functions (Google ADK, «судья над
детерминированными проверками») дал принципы, которых у Spine не было как
механики: одна характеристика — пара «детерминированное свидетельство +
суждение»; сначала свидетельство, потом суждение; детерминированное первенство;
низкая уверенность — эскалация, а не pass; «советующий, пока не откалиброван».
В самом AFF связь держится на промпте; у Spine она должна быть механикой (AD-2:
вердикт контроля не генерируется моделью).

Разбор Spine нашёл и прямые дыры:

1. `semantic_quality` не читал собственное решение рубрики: отчёт с меткой
   `detector_contradiction` (решение `human`) проходил PASS — метка не исключает
   критерий из итога, а гейт её не смотрел. `unstable` до гейта не доходил.
2. Слот детекторов досье (`reports/detectors/`, E7.1) никто не наполнял, и он
   был подключён только к `code_vs_spine`.
3. Ни поле критерия, ни поле правила не называли вторую половину связки.

## Decision

Пять волн, каждая аддитивна и выключена по умолчанию там, где меняла бы вердикт
чужих пайплайнов.

**Волна 0 — гейт не мягче решения рубрики.** `semantic_quality` эскалирует
`detector_contradiction` на любом маршруте (измерение первично), `unstable` — по
политике маршрута, решение рубрики `human` без известной гейту метки — по
политике маршрута, `fail` без признаков противоречия — блокирует.

**Волна 1 — экспорт исходов правил.** `control::detectors` пишет детектор на
правило в `reports/detectors/rules/<id>.json`: исход (`pass/fail/warn/skip/na/
overridden`), инвариант, файлы и первые находки, статус зубьев той же редакции
правила. Файл детерминирован (без меток времени): повторный экспорт того же
исхода не обесценивает отчёт судьи, смена исхода — обесценивает. Экспорт —
`control check --export-detectors` или `[gate.semantic_quality]
export_detectors = true`. Детекторы правил входят во **все** виды досье, но по
относимости: явная привязка, файл субъекта, инвариант из ссылок, карточка
правила; потолок 12. Хост, гейт, сверка, квалификация и red-team собирают досье
одной функцией (`rubric_pack::build_for`/`build_with`).

**Волна 2 — связка и детерминированное первенство.** Критерий рубрики получает
`bound_rules: [{rule, role: necessary|evidence}]` и `binding_mode:
advisory|blocking` (дефолт `advisory`). Гейт применяет таблицу сочетаний к
исходам правил ЭТОГО прогона (`gate::binding`):

| Исход правила для субъекта | Роль | Механика |
|---|---|---|
| `fail` | `necessary` | критерий провален без судьи — отчёт не нужен (короткое замыкание) |
| `fail`, судья ≥ 3 | любая | `binding_contradiction` — эскалация |
| `pass`, зубья не подтверждены | `necessary` | `binding_rule_toothless` |
| `skip` / нет прогона | любая | `binding_not_measured` — эскалация при политике `human` |
| `na` / `overridden` | любая | предупреждение |
| правила нет в реестре | любая | `binding_rule_unknown` — error в любом режиме |

Правило — на весь репозиторий, субъект — один артефакт: красное правило
относится к субъекту, только если его находки в файле субъекта или правило
глобальное (находки на уровне реестра).

**Волна 3 — трассировка.** У AD появляется `judged_by: [<рубрика>#<критерий>]`,
сверяемый с каталогом рубрик (`ad-judged-by-broken`). Звено «AD unverifiable →
рубрика» и матрица «AD × {правило, рубрика}» — в отчёте трассировки, CLI и MCP.
Находка `ad-unguarded` (unverifiable без рубрики) — по `[trace] judged_required`
(дефолт `off`). `judged_by` не заменяет механическое звено AD-9: отказ от
правила по-прежнему объявляется `unverifiable` с обоснованием.

**Волна 4 — калибровка и промоушен.** Блокирующая связка решает вердикт, только
когда (а) прожит теневой режим — гейт пишет в `.arch-handoff/binding-shadow.jsonl`,
что было бы при `blocking`; (б) зубья необходимых правил подтверждены, судья
прошёл **строгую** квалификацию (метрики пересчитываются по текущим порогам —
ручная правка `passed: true` не даёт допуска); (в) человек подписал связку
(`arch-be rubric promote`), подпись привязана к SHA-256 файла рубрики и составу
правил. Без подписи блокирующая связка работает как советующая (`binding_unsigned`).
Неквалифицированный судья понижает зависящие от балла нарушения; провал
необходимого правила — чистое измерение и от допуска судьи не зависит.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| **A. Связка на стороне критерия рубрики (выбран)** | Один источник истины; правило не знает о рубриках; анти-ослабление рубрики — CODEOWNERS и подпись | Связка видна от правила только вычислением |
| B. Поле `rubric:` у правила `CONSTRAINTS.yaml` | Рядом с правилом | Две стороны одной связи разойдутся; правило в чужом пакете (`extends`) не знает рубрик проекта |
| C. Все детекторы во все досье | Просто | Досье раздувается реестром, отчёт устаревает от смены исхода любого правила |
| D. Гейт читает экспортированные файлы детекторов | Один источник для судьи и гейта | Файл мог остаться от прошлого прогона; исходы того же прогона надёжнее |
| E. Связки в поставляемых рубриках | Работает «из коробки» | `binding_rule_unknown` у каждого проекта без этого правила — связка задаётся в проектной копии |

## Consequences

### Positive

- Принцип fitness-функции стал механикой: пара «правило + критерий» объявлена,
  исход правила входит в досье и в вердикт, расхождение с судьёй видно.
- Гейт больше не зеленеет на «чисто» судьи при красном детекторе.
- Инвариант `unverifiable` получает измеримую смысловую охрану или видимую дыру.

### Negative

- Ещё одна поверхность конфигурации; ошибка привязки (`binding_rule_unknown`)
  краснит гейт даже в советующем режиме — сознательно: связка на пустоту хуже
  отсутствия связки.
- Связка не доказывает, что правило измеряет смысл критерия — это решение автора
  рубрики; паспорт вердикта говорит это прямо (блок 2).
- `decision_quality` (качество ADR по порогу) решение рубрики `human` не читает:
  у документных рубрик метки вроде `evidence_not_found` штатно частые, и
  эскалация покраснила бы честные ADR. Пересмотр — после калибровки
  документных рубрик.

## Reversibility

reversible: все поля аддитивны и по умолчанию выключены (`export_detectors`,
`judged_required`, связки в рубриках). Удаление связок из рубрик возвращает
поведение 0.4.16, кроме волны 0 — её откат вернёт дыру «PASS при красном
детекторе».
