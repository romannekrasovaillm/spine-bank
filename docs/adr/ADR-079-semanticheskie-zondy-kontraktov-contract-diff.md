# ADR-079. Семантические зонды контрактов (`contract-diff --semantic`): смысловые сдвиги, невидимые структурному диффу

- Date: 2026-10-12
- Status: Accepted — четыре семантических зонда (`--semantic`, AB-12) и
  раннер `semantic_diff.py` фиксируются по итогам живого прогона (волна 0.4.2,
  TASK §CONTRACT)
- Модель-автор: spine-arch (claude) — исполнено флот-агентом волны 0.4.2
  (`feat(CT)`, `bench(CT)`), ADR оформлен интегратором
- Пересмотр: семантические зонды для proto/avro/json-schema/ddl —
  отдельной волной; при первом прецеденте FP на не-денежных суффиксах —
  пересмотреть таблицу семейств единиц
- Провенанс: продолжает ADR-015 (контрактный контур, OpenAPI-lint),
  ADR-035 (связка `INT.contract` — impact по модели), ADR-020 (headless
  JSON-контракт, `contract-diff/v1`)

## Context

AB-12 — семейство «эволюция контракта» с весом семантики **0.40** (главная
недооценённая метрика). `contract-diff` ловит **структурные** ломающие
изменения: CD-001..CD-010 для OpenAPI (удаление операции, смена типа
свойства, удаление ответа, сужение схемы), CD-P/A/J/S — для
proto/avro/json-schema/ddl. Но **смысловые** сдвиги структурному диффу
невидимы: удаление значения из `enum`, смена единицы измерения в имени поля,
смена `default`, переименование ключа партиционирования. Потребитель,
парсящий `amount_cents` как копейки, не покраснеет от диффа, в котором
структура совпала байт-в-байт по типам.

Смена **обязательности** поля уже покрыта механикой CD (CD-003/CD-008/
CD-010) — дублировать её семантическим зондом нельзя (двойной счёт в
знаменателе AB-12).

## Decision

1. **Четыре семантических зонда** в отдельном списке `semantic_changes`
   (аддитивно к `contract-diff/v1`; структурный `findings` не трогается):
   - **enum:** значение **удалено** из `enum` → `semantic_enum_narrowed`
     (**error**): потребитель со старым значением ломается; значение
     **добавлено** → `semantic_enum_widened` (**warn**) — расширение;
   - **unit:** поле с маркером единицы в имени переименовано **со сменой
     семейства** (`amount_cents` → `amount_rubles`) или потеряло маркер
     (`amount_cents` → `amount`) → `semantic_unit_changed` (**error**);
     смена внутри одного семейства (`cents` ↔ `kopecks`, оба `money_minor`)
     допустима и находки не даёт;
   - **default:** `default` существующего поля изменён или снят →
     `semantic_default_shift` (**warn**);
   - **partitioning:** параметр `…partitionKey`/`…partitionId`
     переименован/удалён → `semantic_partition_key_changed` (**warn**).
2. **Только по флагу:** CLI `contract-diff --semantic`, MCP
   `semantic=true`. Без флага JSON `contract-diff/v1` **байт-в-байт**
   прежний — ключа `semantic_changes` нет (обратная совместимость).
3. **Только OpenAPI** — основной формат AB-12; остальные форматы пока без
   семантических зондов (граница волны).
4. **Impact-hint:** зонды возвращают имена затронутых полей; при заданном
   `--model` потребители ищутся **сканом файлов** корня кейса (метка
   `[inferred]`, без гарантий — модель/граф точнее) с потолками (глубина 6,
   2000 файлов, 512 KiB, ≤15 потребителей); связка `INT.contract`
   (ADR-035, механика `impact`) при заданной модели сохраняется.
5. **Вердикт:** семантическая ошибка (severity **error**) делает отчёт
   `breaking` (`passed=false`), warn — нет.

## Alternatives

- **Готовые библиотеки диффа JSON-Schema/OpenAPI** (oasdiff, openapi-diff,
  jschon). Отвергнуто: (а) новая зависимость запрещена в задаче; (б) они
  **структурные** — единица измерения в имени поля вообще не выражается в
  OpenAPI-схеме, зонд неизбежно сверх библиотеки.
- **Судья-LLM для смысловой сверки.** Отвергнуто: AD-2 (детерминированный
  контур без сети) — семантика контракта проверяема **механически**
  (enum/единица/default/партиционирование — синтаксически наблюдаемые
  факты); LLM внесла бы невоспроизводимость и стоимость без выигрыша.
- **Зонды по всем форматам сразу.** Отвергнуто: OpenAPI — основной формат
  AB-12; расширение эталонной механики на proto/avro/ddl размыло бы
  знаменатель — отдельной волной.
- **Дублировать `required` в `semantic_changes`.** Отвергнуто: CD-003/
  CD-008/CD-010 уже ловят; дубль даёт двойной счёт и раздувает знаменатель
  AB-12 (проверяется тестом «смена required → `semantic_changes` пуст»).

## Consequences

- **Положительные:** AB-12 semantics (вес 0.40) закрыт механически; FP-
  защита подтверждена benign-фикстурой (приватное переименование с
  сохранением смысла → `semantic_changes` пуст); обратная совместимость
  `contract-diff/v1` сохранена (без флага вывод не изменён); раннер
  `semantic_diff.py` (4 сигнала + 1 чистый) даёт самопроверку бенчмарка.
- **Отрицательные:** эвристика единиц **по имени поля** — FP на не-денежных
  суффиксах (`_ms`/`_s` у не-временного поля); потребители **по grep** —
  низкая точность на больших репо (метка `[inferred]` честно сигнализирует
  о статусе догадки); таблица семейств единиц фиксирована (расширение
  курируемое); новый JSON-блок `semantic_changes`/`semantic_consumers` —
  потребители `contract-diff/v1` должны его игнорировать.
- **Риски:** короткий суффикс `_s`/`_sec` — ложное семейство на редких
  именах (смягчено: длинные суффиксы проверяются раньше коротких); при
  первом прецеденте FP — пересмотр таблицы (см. Пересмотр).

## Reversibility

Высокая: зонды **аддитивны** и **за флагом** — код семантики изолирован в
`semantic.rs`, структурный дифф и `contract-diff/v1` не изменены. Откат —
удаление коммитов; без `--semantic` поведение `contract-diff` возвращается
к до-ADR состоянию точно (байт-в-байт).
