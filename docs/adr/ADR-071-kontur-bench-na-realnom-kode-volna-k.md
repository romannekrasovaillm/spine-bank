# ADR-071. Контур-бенч на реальном коде: `redteam --repo/--standard`, маршруты CASE.yaml (волна K)

- Date: 2026-10-11
- Status: Accepted [ADOPTED] — режим «репозиторий + стандарт» у `redteam`,
  объявление маршрута кейса в `CASE.yaml` и сводка измеримости — волна K
  (TASK 0.4.0, §7), по итогам живых прогонов метрик 11–12
- Модель-автор: spine-arch (claude) — волна K исполнена флот-агентом
  (`feat(K1)`, `feat(K2)`), ADR оформлен интегратором
- Пересмотр: при появлении второго стандарта-потребителя режима
  `--repo/--standard` (не Java-сервисы) — пересмотреть набор мутаторов
  по умолчанию; K3/K4 (внешний корпус, реплей чистой истории) добираются
  следующей итерацией
- Провенанс: продолжает линию контур-бенча (`src/redteam/`, B7 волны B —
  недостающие раннеры и `--hermetic`) и корп-стандарта (ADR-070)

## Context

**1. Контур-бенч измерял пакеты Spine, а не защиту реального кода.**
Живой прогон (TASK §2.5): 0/14 кейсов измеримы без pytest (эталон краснел
«обязательная fitness без входа»), 1/14 с pytest. Кейсы, по построению не
являющиеся пакетом Critical (`jvm-archunit-gate`, `legacy-survey`),
не имели способа объявить свой маршрут — мерились чужой линейкой.
**2. Засев нарушений стандарта в реальный код не существовал.** Мутаторы
`redteam` работали только по корпусу кейса; пара «чужой репозиторий +
корп-стандарт» — главный сценарий архитектора (COMPLY/GOVERN) — не
покрывалась.

## Decision

1. **`arch-be redteam --repo <repo> --standard <CONSTRAINTS.yaml>
   [--mutators …]`**: засевает нарушения стандарта в копию реального
   кода (мутаторы C.2 + обходы §2.4: wildcard, FQN, static import,
   Gradle, scope) и строит карту обнаружения раздельно по слоям —
   текстовые правила / ArchUnit / радар. Слой, не способный поймать
   засев, помечает его честно («ловится только мостом»), а не молчит.
2. **`CASE.yaml` у кейса** объявляет маршрут прогона; `redteam --all`
   печатает сводку «измерен / не измерен: причина» — включая
   отсутствующие раннеры (B7) и «не пакет Spine» для кейсов-инструментов.
3. **Отчёт:** обнаружение по каждому мутатору с владельцем-правилом и
   файлом:строкой засева; FP-контроль — чистые вставки (закомментированный
   import, пароль в комментарии).

## Alternatives

- **Расширение корпуса кейсов вместо режима --repo.** Отвергнуто:
  корпус синтетический, под него писались regex (главная находка TASK
  §2.2 — «на чужом коде ценность почти не видна»); реальный код —
  единственный честный полигон.
- **Отдельная команда `stdcomply-bench`.** Отвергнуто: дублирование
  механики мутаторов и отчёта; режим существующего `redteam` сохраняет
  единый контур и exit-коды.
- **Только текстовый слой.** Отвергнуто: карта по слоям — суть
  честности (текст слеп к FQN — B5); сокрытие пропусков = ложное
  «зелёное» правило.

## Consequences

- **Положительные:** метрика 11 = 6/14 измеримы (живой прогон, порог
  ≥6) с причинами по остальным; K2 даёт карту обнаружения на реальном
  buckpal (текст ловит импорты/пароли, радар — Gradle h2/hsqldb,
  ArchUnit-засевы помечены «ловится только мостом»); FP-контроль чист.
- **Отрицательные:** K2-засевы под pom.xml не применяются на
  Gradle-репозиториях («цель не найдена») — мутатор привязан к формату
  манифеста, матрица «репо × формат» требует курируемого набора;
  `--repo/--standard` не заменяет корпус кейсов (K3/K4 — внешний
  корпус дефектов и реплей чистой истории — следующая итерация).
- **Риски:** карта по слоям может читаться как «провал», если слой
  помечен «ловится только мостом» без ArchUnit-jar на стенде —
  отчёт обязан называть причину SKIP (как B7).

## Reversibility

Высокая: режим аддитивен (флаги `--repo/--standard` у существующей
команды), `CASE.yaml` опционален (нет файла — прежнее поведение
Critical). Откат — удаление режима; кейсы возвращаются к прежней
семантике удалением CASE.yaml.
