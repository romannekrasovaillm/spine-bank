# ADR-082. Косвенная проводка в recover (волна R+): ConfigMap-ref, Helm-values и build-args как источники рёбер — поле indirect в recover/v1

- Date: 2026-10-12
- Status: Proposed
- Модель-автор: spine-arch (claude)
- Маршрут: Standard (score 2: new_component + api_contract_change)
- Пересмотр: при появлении живого корпуса с service mesh (Istio VirtualService/
  DestinationRule) или SEAF-метамодели в периметре — расширить слои indirect
  и пересмотреть способ резолюции имён; при F1(observed) ≥ 0.85 на корпусе —
  рассмотреть подтверждение части inferred-рёбер в confirmed.
- Провенанс: ArchBenchmarks v2 S3h (разбор Spine 0.4.0: dochub-recover
  F1(observed) 0.48 против 0.70 у брифа; «17/17 рёбер» получены на прямой
  проводке и не переносятся на непрямую; рекомендация №4 — «дополнить разбор
  Helm-оверлеев и feature-флагов»); линия recover/v1 (ADR-069), условия
  активации рёбер (ADR-075).

## Context

**1. Прямая проводка исчерпала корпус.** Детекторы `calls` (ADR-069/R2)
читают имя цели прямо из артефакта потребителя: env-переменная, gateway-
маршрут, gRPC-стаб, топик. Реальные ландшафты (DocHub в корпусе ArchBench)
проводят связи иначе: имя службы живёт в **ConfigMap**, на который ссылается
pod-spec через `configMapRef`; в **Helm values/overlay**, где шаблон подстав-
ляет его в манифест; в **build-args** (Dockerfile ARG + compose `build.args`),
где адрес вшивается в образ. Потребитель не называет цель — её называет
слой развёртывания. Результат: F1(observed) 0.48 против 0.70 у сильного
LLM-брифа — recover хуже чтения агентом, а «17/17» маркетингового прогона
на прямой проводке создают ложное ожидание.

**2. Косвенность уже наполовину в коде — но не как ребро.** ADR-075 ввёл
`Condition { kind: ConfigKey|EnvFlag|EnvOverlay }`: recover уже читает
helm values-<env> и config-ключи, но только как **условие жизни** ребра,
найденного прямым детектором. Самого ребра косвенный источник не строит.
Механизм `overlay_env` (as_built.rs:387) распознаёт overlays/envs/values-<env> —
фундамент есть, надстройки нет.

**3. Enum Via расширять нельзя — контракт v1 заморожен аддитивно.**
`Via {Env, Route, Stub, Topic}` сериализуется snake_case; добавление вариан-
тов сломает десериализацию у бинарей < этой версии на графах с новыми
значениями. Нужен аддитивный носитель, не трогающий enum.

**4. Confidence-дисциплина.** Косвенное ребро — всегда `inferred` в терминах
R2: имя из слоя развёртывания совпало с компонентом репозитория по конвен-
ции/селектору, а не продиктовано потребителем. Повышение до confirmed —
только при явной ассоциации (label selector, имя Deployment = имени компо-
нента) — и то оставляем inferred: конвенция может врать.

## Decision

1. **Три детектора косвенной проводки (волна R+), один строитель рёбер.**
   - **configmap-ref**: k8s-манифест (Deployment/Pod/Job) → `envFrom.
     configMapRef`/`valueFrom.configMapKeyRef` → ConfigMap `data.<ключ>` →
     строка URL/host/endpoint → цель; ребро от компонента-владельца манифеста
     (по selector/имени, DeployTopology) к цели.
   - **helm-values**: `values[-<env>].yaml` ключи вида `<svc>.host|url|
     endpoint|addr|base_url` (+ вложенные `<svc>: {host: …}`) → цель;
     потребитель — chart/templates, ссылающиеся на значение (`.Values.<svc>`);
     без резолвции шаблонов — потребитель по каталогу chart.
   - **build-args**: Dockerfile `ARG *_ADDR|*_URL|*_HOST|*_ENDPOINT` +
     compose `build.args`/CI-env, передающий имя службы → цель; потребитель —
     каталог Dockerfile.
   Каждый детектор = функция «артефакты → сырые попадания (имя цели,
   обе стороны evidence)», затем общий резолвер имён (существующие канди-
   даты R2: компоненты репо, DeployTopology) строит ребро.

2. **Носитель в контракте — `indirect: Option<Indirect>` у ArchEdge**,
   не расширение Via: `Indirect { layer: IndirectLayer (configmap |
   helm_values | build_arg — свой enum в новом поле, аддитивно), key:
   String (dotted-путь: configmap/<имя>/<ключ>, values/<svc>.<ключ>,
   buildarg/<ARG>) }`. Сериализация skip-if-none: старые бинари и чистые
   графы байт-в-байт прежние. Рендеры (md/mermaid) помечают ребро
   «· configmap», `draft_model` — INT с source-примечанием.

3. **Evidence — обе стороны, потолок как у рёбер.** Для configmap-ref:
   `манифест:строка` + `configmap:строка`; для helm-values — values-файл и
   (если найден) template; build-args — Dockerfile и передатчик. Односто-
   роннее попадание (ConfigMap есть, рефов нет) — не ребро, а `gaps`-строка
   (существующий механизм).

4. **Условность (ADR-075) применяется и к косвенным.** values-<env>.yaml
   даёт `condition { kind: EnvOverlay }` как сегодня; ConfigMap из overlay-
   каталога — тоже. Косвенность и условность — ортогональны.

5. **Приёмка по F1(observed) на фикстуре непрямой проводки** (мини-«Кварц
   Indirect»: 2 сервиса, связь только через ConfigMap + values-<env> +
   build-arg, 6–8 целевых рёбер): до волны — 0, после — ≥ 6/8 с evidence
   обеих сторон; recall условных рёбер не ниже прямой проводки. Раннер
   (benchmark-контур K, ADR-071/072) — отдельной задачей, эта волна —
   детекторы + контракт + фикстура-тест.

6. **Чего не делаем:** резолвция Helm-шаблонов ({{ .Values }} подстановка)
   полным парсером — только ключевой индекс; service mesh (Istio CRD) —
   вне; SEAF jsonata/$rels — отдельный слой (метамодель, не k8s); повыше-
   ние косвенных рёбер до confirmed — никогда автоматически.

## Alternatives Considered

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Расширить enum Via (configmap/helm/…) | Одно поле, единая семантика «откуда прочитано» | Breaking для recover/v1 у старых бинарей (enum-десериализация); контракт v1 заморожен аддитивно — отказ |
| Отдельный «deployment-graph» параллельно ArchGraph | Не трогает recover/v1 | Второй источник правды о связях; merge в голове потребителя; противоречит SSOT-уроку survey↔as_built (ADR-069 п.2) |
| LLM-слой достраивает косвенные рёбра по подсказке recover | Быстро, без кода | Нарушает R6/ADR-069 (LLM пишет только inferred и не создаёт confirmed) в худшей форме: невозмоность отличить выдумку; недетерминизм; отказ |
| Только документировать ограничение (§14.4 отчёта report) | Ноль кода | F1 0.48 у брифа остаётся; слабейшее семейство бенча не лечится; рекомендация №4 ArchBench не выполняется |

## Consequences

### Positive

- Слабейшее семейство бенча получает механику: DocHub-класс ландшафтов
  (ConfigMap/Helm/build-args) восстанавливается детерминированно, с evidence
  обеих сторон и честным inferred.
- recover/v1 остаётся аддитивным: `indirect` — новое опциональное поле,
  старые графы и бинари не затронуты; render/draft_model получают источник
  для INT-черновиков.
- Механизм условий (ADR-075) переиспользуется без изменений — косвенные
  рёбра из per-env файлов автоматически несут condition.

### Negative

- **Волна ~2–3 KLOC + фикстура**: три детектора, резолвер ассоциаций
  «манифест → компонент» (selectors/имена — эвристика, ложные срабатывания
  возможны; каждая ассоциация обязана попасть в evidence, чтобы эксперт
  проверил).
- **Именование по конвенции — источник ложных рёбер**: `<svc>.host` в
  values может не быть службой репо (внешний API); митигация — резолвер
  только по существующим кандидатам (как R2), неразрешённые — в gaps.
- **Полнота шаблонов недостижима**: без рендера Helm часть рёбер останется
  невидимой (упомянута в §14.4 отчёта report как ограничение метода).
- **Фикстура непрямой проводки — новая забота корпуса**: её надо держать
  актуальной (golden) и не путать с прямой «Кварц».

## Reversibility

**Reversible.** Поле `indirect` опционально (skip-if-none), детекторы —
аддитивные источники рёбер; откат — убрать детекторы и поле, графы без
косвенных рёбер байт-в-байт прежние. Отдельная дельта changes/recover-indirect.
