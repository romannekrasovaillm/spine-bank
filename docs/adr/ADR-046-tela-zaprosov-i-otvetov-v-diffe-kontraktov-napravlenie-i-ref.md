# ADR-046. Тела запросов и ответов в диффе контрактов: направление, `$ref` и CD-009/CD-010

- Date: 2026-09-20
- Status: Accepted
- Reversibility: обратимо. CD-009/CD-010 — две независимые находки в
  `contract_diff` (`diff_response_body`, блок `requestBody.required`); их можно
  снять по отдельности, вернувшись к «тело ответа не сравнивается» и «флаг
  обязательности тела не сравнивается». Данных не касается: инструмент только
  читает два файла контракта
- Judge: judge_is_author — рубрикой `adr_quality` документ оценивала та же
  модель, что его писала (независимый судья в этом окружении недоступен)

## Context

`contract_diff` отвечает на вопрос «сломает ли это изменение потребителя».
До 0.3.5 он смотрел на `paths` → операции → параметры → коды ответов →
`components.schemas.*.properties.*` (только смена `type`, CD-006). Тело
запроса не читалось вовсе (T-06 закрыл часть: CD-008 — поле, ставшее
обязательным), тело ответа — тем более, а параметр, объявленный через
`#/components/parameters/…`, пропускался целиком («Deferred» — так и было
записано в комментарии).

Наблюдение 2026-09-19 (кейс кошелька цифрового рубля) показало цену пробела:
удаление поля `fee` из схемы ответа, перевод `requestBody.required` из `false`
в `true` и удаление обязательного параметра за `$ref` давали «breaking: 0 …
Итог: PASS». PASS здесь означает не «проверено, всё хорошо», а «не смотрели» —
худший вид зелёного в контуре, который сам же объявляет ложный зелёный
дефектом (Д1, ADR-045).

Отдельный вопрос — **направление**. Для тела запроса ломающим является то, что
заставляет потребителя прислать больше (новое обязательное поле, CD-008). Для
тела ответа всё наоборот: потребитель читает ответ, поэтому ломает его
**исчезновение** поля, а появление нового обязательного поля ответа безопасно —
потребитель его просто не читал. Одно правило на оба направления давало бы
ложные находки на безопасной правке.

## Decision

1. **Тело ответа сравнивается по множеству полей (CD-009, error).** Из схемы
   каждого общего кода ответа по каждому media type собираются все пути полей
   (`all_field_paths`, режим `PathsMode::All`) — включая необязательные;
   поле, которое было и исчезло, называется находкой. Добавленные поля ответа
   находок не дают: они совместимы по построению, и это записано в коде, а не
   подразумевается.
2. **Тело запроса стало обязательным — ломающее (CD-010, error).** Сравниваются
   сами флаги `requestBody.required` (`false → true`), а не схемы: проверка не
   зависит от того, читается ли содержимое тела, и работает для тела без схемы.
   Обратный переход (`true → false`) — ослабление, не ломающее.
3. **Параметры за `$ref` резолвятся** тем же `resolve_schema`, что и схемы тел
   (JSON Pointer внутрь документа, `allOf`, потолок `SCHEMA_MAX_DEPTH`).
   Нерезолвящаяся или внешняя ссылка по-прежнему пропускается: выдумывать
   параметр по имени файла нельзя.
4. **Рекурсия одна на два вопроса.** Обход полей схемы — общая функция
   (`collect_paths` с режимом `Required`/`All`), тела запроса и ответа
   различаются только вопросом к результату обхода. Дублировать обход ради
   второго направления значило бы завести два места, расходящихся при первой
   же правке.
5. **Все три правила подчиняются CD-007**: ломающий дифф без смены major
   `info.version` — отдельная находка (error). Новые коды не заводят
   собственного версионирования.

## Alternatives

- **`warn` вместо `error` для CD-009/CD-010** — мягче для чужих пайплайнов, но
  инструмент до сих пор называл ломающее изменение совместимым; оставить это
  предупреждением значит продолжать выдавать PASS там, где потребитель
  ломается. Выбран `error` сразу, как и предложено формулировкой задачи;
  вернуть прежнее поведение можно снятием правил (см. Reversibility).
- **Сравнивать тела ответов «как запросы»** (одно правило на оба направления) —
  даёт ложные находки на добавлении поля в ответ и тем самым учит игнорировать
  `contract_diff`. Отвергнуто.
- **Полный JSON-Schema-дифф (CD-J01…CD-J05) внутри тел запроса** — заманчиво
  «переиспользовать всё», но меняет коды находок в OpenAPI-документе на
  `CD-J*` (чужие для этого формата) и добавляет находки, которых задача не
  просила: удаление необязательного поля запроса, сужение типа. Оставлено
  возможным продолжением: механика обхода теперь общая, добавить правило — это
  один вопрос к тому же обходу.
- **Резолвить внешние `$ref` (`other.yaml#/…`)** — требует чтения чужих файлов и
  превращает инструмент в сборщик схем; внешняя ссылка остаётся честной
  пометкой gap.

## Consequences

- **Контракты, у которых поля ответа исчезали или тело запроса становилось
  обязательным, впервые показывают FAIL.** Это и есть цель изменения: находки
  настоящие, ложных среди них нет — сравниваются раскрытые схемы. Откат —
  снятие правил, а не ключ конфига: правила не имеют «мягкого» режима (как
  CD-001…CD-007).
- **`$ref`-параметры теперь видны**: контракт, где обязательный параметр удалён
  вместе с компонентом, краснеет по CD-003. Это может покраснить пайплайн,
  который раньше проходил молча; пропуск здесь не был поведением, которое стоит
  сохранять.
- Контракт `gate-verdict/v1` не затронут: `contract_diff` — отдельный
  инструмент, его вывод аддитивен (новые коды в тех же полях `rule`/`location`).
- Оценка стоимости сопровождения: одна общая рекурсия, три правила, ноль новых
  зависимостей, ноль сетевых вызовов; поведение детерминировано.
