# ADR-064. Модель обновляется принятием диффа: `arch-diff accept`/`reject`, журнал решений `arch-be/arch-diff-decisions/v1`

- Дата: 2026-10-08
- Статус: Proposed
- Модель-автор: kimi-k2 (волна K, TASK-v2 §9, пункт K5)

## Context

Волна K (ADR-063) показывает на каждый PR архитектурный дифф и формирует
пронумерованные предложения правки модели (`depends_on += …`, новые сущности
SYS/INT/CMP). Без механики принятия предложения остаются текстом: модель
отстаёт, а те же рёбра предлагаются снова и снова — шум, который учит
архитектора игнорировать дифф.

Ограничения и действующие решения:

- **Модель меняется только через дельту** (модель 5.2, `delta guard`): любая
  правка `model/` обязана упоминаться в активной дельте `changes/<name>/DELTA.md`
  или change OpenSpec (F1, ADR-062); при `[delta] sources = ["openspec"]`
  markdown OpenSpec Spine не пишет (правило 9).
- Предложение может противоречить инварианту AD (пометка ⚠): такое решение —
  прерогатива архитектора, и оно обязано остаться зафиксированным.
- Агент не должен «принимать» сам себе ребро, нарушающее инвариант: источник
  решения (человек/агент) фиксируется; механика принуждения и связывание с
  подписью A3 — ADR-060 (вне этой волны).
- Детерминизм (правило 10) и обратная совместимость `arch-be/arch-diff/v1`
  (ADR-063: добавление поля — минорно, удаление/переименование — новая версия).

## Decision

### 1. `arch-be arch-diff accept <n…>` — принятые предложения оформляются дельтой

`accept` пересчитывает дифф (та же `--base` → те же номера), выбирает
пронумерованные предложения и создаёт `changes/<name>/DELTA.md`
(`delta::new_with_body`): секции `delta validate` заполнены без заглушек,
пути файлов `model/` — дословно (по ним `delta guard` засчитывает покрытие
последующей правки), основания `файл:строка` — в тексте правок. Сама команда
файлы `model/` НЕ правит: модель меняется через дельту, `delta guard`
действует как обычно.

- Предложение с ⚠ (противоречит AD) принимается, но дельта фиксирует
  конфликт явно — секция «Конфликты с инвариантами» с номером предложения и
  id инварианта.
- При `[delta] sources = ["openspec"]` дельта НЕ пишется: команда отказывает
  с подсказкой оформить change OpenSpec (`delta::openspec_only_hint`), журнал
  не пополняется — решение не состоялось.
- Имя дельты: `--name` или `arch-diff-<head8>`; занято — суффикс `-2`, `-3`, …
  (потолок 99, дальше — просьба задать имя явно).

### 2. Журнал решений `.arch-handoff/arch-diff-decisions.json`

Схема `arch-be/arch-diff-decisions/v1` (поле `schema`, как у
`gate-verdict/v1`): `entries[] = {edge_id, decision: accept|reject, reason,
grounds_hash, decided_at, source: human|agent|unknown}`, плюс аддитивное
`delta` (имя дельты) у accept-записей.

- `edge_id` — стабильный ключ объекта решения: `<kind>:<from>-><to>` для
  рёбер (`import:CMP-001->CMP-004`), `node:<id>` для новых компонентов.
- `grounds_hash` — sha256 списка оснований `файл:строка` ребра (для узла —
  его id). Решение действует, пока основания не изменились: изменились —
  ребро предлагается снова, решение повторяется уже на новых основаниях.
- Журнал append-only: новое решение по ребру дописывается, действует
  последняя запись (last-wins). История решений не перезаписывается (AD-5).
- Битый журнал — ошибка диффа, а не молчаливый сброс: потерянные отказы
  хуже упавшего прогона.
- Журнал — артефакт рабочего дерева (как `teeth.json` волны B): `arch-diff`
  читает его при каждом прогоне и не показывает решённые предложения.

### 3. `arch-be arch-diff reject <n> --reason "…"`

Записывает отказ в журнал; `--reason` обязателен и непуст (журнал без
причины бессмыслен). Повторно это ребро не предлагается, пока `grounds_hash`
не изменился. Отклонённое ребро, оставшееся в коде, — находка для гейта
(K6, отдельный пункт, здесь не делается).

### 4. Номера предложений стабильны в сеансе

Решённые предложения исчезают из списка, номера оставшихся СОХРАНЯЮТСЯ
(перенумерации нет): `accept 1` не сдвигает номер соседнего предложения, и
`reject 2` по только что показанному выводу остаётся корректным. Дырки в
нумерации — честный след принятых решений.

### 5. Источник решения — честно, без принуждения

Поле `source` заполняется из переменной окружения `ARCH_BE_ACTOR`
(`human`/`agent`, регистр не важен); без неё или при ином значении —
`unknown`. Бинарь не угадывает агента по косвенным признакам и не принуждает:
связывание с A3-подписью и механика «агент не может принять ⚠-ребро» —
ADR-060.

### 6. Эволюция `arch-be/arch-diff/v1`

У предложений (`proposals[]`) — два аддитивных поля: `edge_id`,
`grounds_hash`. Набор ключей верхнего уровня не меняется; тест стабильности
контракта (K3) не тронут; новые поля запинены отдельным тестом.

## Alternatives Considered

- **Применять правку `model/` прямо из `accept`** — отвергнуто: модель
  меняется только через дельту (модель 5.2); автоправка обходила бы
  дисциплину, которую призвана поддерживать, и смешивала бы решение с
  исполнением (правку пишет исполнитель под дельтой — её видно в диффе PR).
- **Журнал в git notes / отдельной ветке** — отвергнуто: требует сети и push
  (граница C-34, офлайн-контур), а решения — состояние рабочего дерева,
  как `teeth.json` и `redteam.json`.
- **Upsert вместо append-only журнала** — отвергнуто: AD-5 (журнал —
  источник аудита); last-wins при чтении даёт ту же семантику без потери
  истории.
- **Идентификаторы предложений вместо номеров в CLI** — отвергнуто: экран
  диффа оперирует номерами (K3); `edge_id` остаётся машинным ключом журнала,
  номер — человеческим.
- **Перенумерация после фильтрации решённых** — отвергнута по живому прогону:
  `accept 1` сдвигал номера остальных, и `reject 2` из того же вывода
  ломался.

## Consequences

### Positive

- Модель перестаёт отставать: поддержка — одно решение на изменение
  (`accept`), а не отдельная работа.
- Дифф перестаёт шуметь повторными предложениями (`reject` с причиной),
  но «забытое» отклонение оживает при смене оснований (`grounds_hash`).
- Решения аудируемы: кто (source), когда (decided_at), на каких основаниях
  (grounds_hash), какой дельтой оформлено принятие (delta).

### Negative

- Номера предложений позиционны: после влития дельты (ребро ушло в модель)
  номера сдвигаются — `accept`/`reject` обязаны ссылаться на свежий вывод
  (ошибка «нет предложения №N» называет это прямо).
- Журнал — рабочее дерево, не git-история: при сбросе `.arch-handoff/`
  решения теряются (так же, как `teeth.json`); коммитить журнал — решение
  команды, механика не навязывает.

## Reversibility

**Reversible.** Команды аддитивны (`arch-diff` без подкоманд работает как
прежде); `arch-diff/v1` меняется аддитивно; журнал — отдельный новый файл,
его удаление возвращает поведение K3 (все предложения видны). Откат —
git revert.
