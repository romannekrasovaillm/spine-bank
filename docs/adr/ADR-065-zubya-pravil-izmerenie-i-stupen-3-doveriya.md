# ADR-065. Зубья правил: измерение на копии кейса, файл `teeth.json` и опора ступени 3 доверия на измерение

- Date: 2026-10-07
- Status: Proposed
- Reversibility: полностью обратимо: `arch-be rules teeth` только читает кейс
  (мутации — на временных копиях), `teeth.json` — аддитивный артефакт,
  `[trust] require_teeth` по умолчанию `false` (поведение ступени 3 побитово
  прежнее); откат — удалить файл и снять флаг, миграций нет

## Context

Волна B задания 0.3.14 («зелёный, который нельзя написать рукой») ставит
проблему: «поведенческое» правило определялось ТИПОМ
(`BEHAVIOUR_RULE_KINDS`), поэтому `command_succeeds` с `command: 'true'`
считался проверкой поведения, а эталонные кейсы имеют 0–2 поведенческих
правила из 13–34 — зелёный контура ничего не говорит о том, ловит ли реестр
нарушения.

Факты до решения:

- `trust` (ступень 3) и `control rules-report` считали долю «проверяют
  поведение» по типу правила, без всякого измерения;
- проверка зубьев существовала только для правил из шаблонов
  (`rule-templates.lock`, ADR-050): у пользовательских `command_succeeds` и
  любых `must_contain` её не было;
- ступень 3 доверия требовала `behaviour > 0` по типу — пустая команда
  `true` его удовлетворяла.

Требования решения: обратная совместимость (схема «warn → error по флагу»,
правило 4 задания), read-only к проверяемому кейсу, без сети и LLM (ядро,
AD-2), честные статусы («не измерено» ≠ «с зубьями»), порог доли и включение
строгого режима — конфигурацией, а не константой ([РЕШЕНИЕ ЧЕЛОВЕКА]).

## Decision

1. **Измерение зубьев (`arch-be rules teeth [--rule <id>] [--save]`)** —
   новый модуль `src/control/teeth.rs`: на копии кейса во временном каталоге
   (подход `redteam`) каждое правило получает мутацию, которую обязано
   поймать, и мутация исполняется полным движком `control check` на
   одноправильном реестре (YAML-узел правила извлекается из текста реестра
   без переписывания):
   - `must_not_contain` — вставка строки, совпадающей с `pattern`; образец
     синтезируется из regex (`regex_specimen`: литералы, классы, повторы,
     первая ветка альтернативы) и проверяется скомпилированным шаблоном до
     записи; нет файлов по glob — `rule_glob_empty`;
   - `must_contain` / `each_file_must_contain` — удаление совпадений из всех
     файлов набора; совпадений нет — честный `unknown` («удалять нечего»);
   - `file_exists` / `dir_must_have_file` — удаление обязательного файла;
   - `command_succeeds` — тривиальная команда (`true`, `:`, `exit 0`, только
     `echo`) — находка `executable_rule_trivial`; нетривиальная без
     применённого шаблона с нарушающей реализацией — `unknown`; с шаблоном —
     подмена нарушающей реализацией из библиотеки (как `rules template
     verify`, ADR-050);
   - прочие типы (`dependency_direction`, `context_boundary`, `archunit`,
     `max_age`, `deny_dependency`) — `unknown`: мутатор не поддержан.
   Статусы-находки (`toothless`, `trivial`, `glob_empty`) дают exit 1;
   `unknown` — не находка.
2. **Хранение** — `.arch-handoff/teeth.json` (схема `arch-be/rules-teeth/v1`)
   пишется только по `--save`; у записи — отпечаток проверяемых полей правила
   (тип, наборы, шаблон, команда): правка тела правила после измерения
   обнуляет доверие к записи (потребитель считает зубья неизмеренными).
   Без файла все потребители говорят «не измерено».
3. **Потребители без пересчёта**: `control rules-report` делит реестр на три
   группы («проверяют поведение (зубья подтверждены)», «текст», «зубья не
   измерены») и заявляет долю поведенческих только по измерению; `trust`
   (ступень 3) — см. п. 4.
4. **Ступень 3 доверия (warn → error)**: по умолчанию условие ступени
   прежнее (`behaviour > 0` по типу), а измерение показывается
   предупреждением якоря (`warnings` — новое аддитивное поле отчёта
   `arch-be/trust/v1`; причина недостижения называет непокрытые инварианты
   поимённо). По флагу `[trust] require_teeth = true` условие измеренное:
   при несущих инвариантах (`load_bearing: true` в `model/`) каждый обязан
   быть покрыт правилом с подтверждёнными зубьями; без несущих — доля таких
   правил ≥ `[trust] behaviour_share_min` (дефолт 0.2).
5. **Кодовая доля redteam (волна E)**: `[redteam] min_code_detection`
   (`Option<f64>`, дефолт «выключено») — порог доли обнаружения кодовых
   дефектов; порог суммарной доли (0.78) не меняется.

## Consequences

- Зелёный контура, построенный на текстовых правилах и `command: 'true'`,
  перестаёт выглядеть защищённым: измерение показывает зубья поимённо.
- Кейсы без `teeth.json` не меняют вердикт `trust` (warn-фаза), но
  `rules-report` перестаёт заявлять долю поведенческих по типам — текст
  отчёта меняется, exit-коды и вердикты — нет.
- Цена измерения — копия кейса на правило (контентные правила — разреженная
  копия набора файлов) и один прогон движка на правило; команды реестра
  исполняются в копии (та же модель, что у `rules template verify`).
- Пороги `behaviour_share_min` и `min_code_detection` — дефолты на
  ратификации архитектора; включение `require_teeth` — решение проекта.
