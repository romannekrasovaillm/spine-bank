# Вердикт Spine Core: три состояния, вход, храповик маршрута, самотест

Начиная с 0.3.3 вердикт гейта — это **документ с аттестацией**, а не строка в
терминале. Изменение введено по отчётам прогона 0.3.2 «усиление вердиктов ДКА»
(19.09.2026), где ось «можно ли опереться на вердикт» получила 2.3/5 при оси
«что Spine ловит» 4.5/5. Решение зафиксировано в
[ADR-040](adr/ADR-040-trehznachnyy-verdict-geyta-incomplete-eksit-3-matrica-obyazatelnosti.md).

## Три состояния вместо зелёного/красного

| Итог | Когда | Exit |
|---|---|---|
| `PASS` | все обязательные для маршрута составляющие пройдены, FAIL нет | 0 |
| `FAIL` | есть проваленная составляющая | 1 |
| `INCOMPLETE` | FAIL нет, но обязательная составляющая без входа (`SKIP`) | 3 |

Раньше итог был бинарным («нет ни одного FAIL»), и `SKIP` поглощался зелёным:
на кейсе «цифровой рубль» `evidence verify .` давал exit 1, а
`gate --route critical` — exit 0, потому что бандл в корне кейса был невидим
гейту. Теперь `gate` находит `EVIDENCE.yaml` и в корне, и в `changes/<имя>/`, а
`SKIP` обязательной составляющей даёт `INCOMPLETE`.

```bash
arch-be gate --repo . --route critical          # итог + аттестация
arch-be gate --repo . --format json             # конверт вердикта (П7)
```

Конверт (`arch-be/gate-verdict/v1`): `verdict`, `exit_code`, `route`, `inputs`,
`components[].required`, `components[].findings_digest`, `not_checked`,
`attestation`. Поле `not_checked` честно называет, на что зелёный цвет **не**
распространяется. Аттестация — SHA-256 канонического конверта: тот же вход даёт
ту же аттестацию в CLI, MCP, хуке и CI.

### Из чего состоит аттестация (0.3.4, ADR-043)

До 0.3.4 входом был только хэш реестра правил, поэтому три разных мутанта
давали одну аттестацию, а безвредная правка текста сущности — аттестацию
эталона. Теперь `inputs` — это состояние репозитория, а вердикт различается не
только по имени и статусу составляющей:

| Вход | Что хэшируется | Отсутствует |
|---|---|---|
| `constraints` | файл `CONSTRAINTS.yaml`, которым прогоняли | `absent` |
| `spine` | `ARCHITECTURE-SPINE.md` (или `docs/ARCHITECTURE-SPINE.md`) | `absent` |
| `model` | рекурсивный канонический SHA-256 каталога `model/` (относительные пути, порядок по возрастанию, без `.git`) | `absent` |
| `evidence:<rel>` | каждый найденный `EVIDENCE.yaml` (корень и активные change-dir) | `absent` |
| `evidence_bundles` | число проверенных бандлов | — |
| `route_lock` | `.arch-handoff/ROUTE.lock` | `absent` |
| `base` | SHA коммита базы диффа (не строка `HEAD~1`) | `absent` |

Плюс `components[].findings_digest` — SHA-256 отсортированного списка
`(код находки, путь)`: **два разных FAIL одной составляющей различимы**, а не
сливаются в «`nfr` = FAIL». Текст сообщений в свёртку не входит: формулировки —
часть представления и меняются без смены смысла вердикта.

Пути — только относительные, времени в свёртке нет: тот же коммит,
склонированный в другой каталог, обязан дать ту же аттестацию.

### Воспроизводимость по конверту

```bash
arch-be gate --repo . --format json > verdict.json
arch-be gate --repo . --verify-envelope verdict.json
# → «Вердикт относится к этому состоянию: verdict.json»
# → либо «Состояние изменилось с момента вердикта: spine: sha256:… → sha256:…»,
#    exit 1
```

Проверяются входы (реестр правил, спайн, модель, бандлы, `ROUTE.lock`, коммит
базы). Состав находок не пересчитывается — для этого нужен полный прогон
`arch-be gate` с теми же флагами.

## Матрица обязательности по маршруту

`config.toml`:

```toml
[gate.required]
fast     = ["fitness", "spine_lint"]
standard = ["fitness", "spine_lint", "trace_check", "rule_weakened", "nfr",
            "model_validate"]
critical = ["fitness", "spine_lint", "trace_check", "rule_weakened",
            "delta_guard", "sensors", "nfr", "evidence_verify",
            "model_validate"]
```

`SKIP` необязательной составляющей остаётся допустимым (fail-soft на
инфраструктуру первого подключения), но печатается; `SKIP` обязательной — нет.

## Храповик маршрута: `.arch-handoff/ROUTE.lock`

```yaml
route: critical            # минимум для этого репозитория
reason: "обработка ЦФА/ЦР, 10/15 триггеров"
decided_by: ADR-012
review_after: 2027-03-01
```

Эффективный маршрут = `max(вычисленный из диффа, заявленный в ROUTE.lock)`.
Критический проект проверяется как Critical даже на чистом дереве и на
маленьком merge request; шаблоны CI могут остаться с `--route auto` без потери
строгости. Понижение заявленного маршрута относительно git-базы без
`decided_by: ADR-…` — находка `route_lowered`.

## Инвариантность вердикта

- **Путь.** Хэш каталога-артефакта считается по относительным путям внутри
  артефакта, рекурсивно, SHA-256 (`src/hash.rs`): `evidence verify .` и
  `evidence verify "$PWD"` дают один ответ, правка во вложенном подкаталоге
  видна. Бандлы старого формата (FNV-1a) проверяются с предупреждением о
  переупаковке.
- **Установка.** `connect` пишет `.arch-handoff/connect-manifest.json` (пути,
  версия, хэши); детекторы значимости исключают установленное Spine, поэтому
  подключение инструмента не меняет маршрут проекта (Д3). Ручные исключения —
  `.spineignore`.
- **Реестр правил.** `control check` и MCP `fitness_check` сверяют состав правил
  с git-базой и печатают отпечаток реестра (`правил`, `error`, SHA-256 состава):
  строка «14 правил» при вчерашних 15 — самостоятельный сигнал, а не молчаливый
  зелёный.

## Паспорт вердикта: чего зелёный НЕ означает

```bash
arch-be gate --explain                 # страница markdown вместо обычного отчёта
arch-be gate --format json --explain   # конверт вердикта + ключ `passport`
```

Паспорт — представление, а не новая проверка: он ничего не решает и не меняет
вердикт, аттестация от него не зависит. Одна страница, три блока:

1. **Проверено** — составляющие прогона со своими числами (сущностей, правил,
   NFR-целей), с пометкой обязательности для маршрута и счётом находок.
2. **Заявлено, но механикой не проверяется** — подпись A3 (заявлена, но
   подлинность не подтверждена), семантика ссылок модели (ссылка разрешается в
   *существующую* сущность, но не в *нужную*), независимость судьи рубрики и
   ревьюера, адекватность решения, доля правил, судящих по тексту файла, а не по
   поведению системы. Список собирается по фактам репозитория: нет `docs/adr` —
   нет утверждения о решениях; нет бандла — нет утверждения о ревьюере.
3. **Не проверено** — составляющие, ушедшие в SKIP, с причиной («нет каталога
   `model/`», «составляющая не включена в `[gate.required]`»); обязательные для
   маршрута помечены — это и есть INCOMPLETE (exit 3).

Внизу — аттестация и команда сверки конверта. Вступление страницы зависит от
итога: на красном вердикте она говорит о красном («механика нашла
перечисленное; блоки 2 и 3 — то, чего не поймала и она»), а не повторяет
формулу про зелёный. `evidence verify` печатает ссылку на паспорт: вердикт
бандла — часть вердикта гейта, и читатель бандла до гейта может не дойти.

## Самотест вердикта

```bash
arch-be selftest          # 10 инвариантов на изолированной песочнице
arch-be selftest --json   # машинный отчёт
```

Проверяются свойства ответов, а не ответы: монотонность по маршруту
(`INCOMPLETE` вместо ложного зелёного), достижимость зелёного, чувствительность
к засеянному дефекту, храповик `ROUTE.lock`, идемпотентность аттестации,
инвариантность к написанию пути, чувствительность аттестации к состоянию
`model/` (Н3, ADR-043). Ненулевой exit — свойство нарушено; команда
пригодна для CI и для прогона заказчиком на своей машине.

Три инварианта проверяют свойства самого контура — те, что в 0.3.4 нашёл
внешний прогон, а не самотест (волна W):

- `hook_does_not_guess_registry_location` (T-01) — сгенерированный
  `connect claude` хук вызывает гейт и НЕ содержит гарды по расположению
  реестра (`[ -f .arch-handoff/CONSTRAINTS.yaml ]`): каркас `bootstrap` кладёт
  реестр в корень, и такая гарда делала хук мёртвым;
- `divergent_registries_are_a_finding` (T-02) — расхождение двух копий реестра
  правил краснит гейт находкой `registry_diverged`, а не остаётся пометкой в
  PASS-строке;
- `base_range_is_normalized_once` (T-03) — база диффа нормализуется один раз:
  `origin/main` и `origin/main...HEAD` дают один диапазон, `...HEAD` не
  удваивается.

## Границы (честно)

- Spine проверяет **наличие, форму, связи и числа**, не адекватность решения.
- Landscшaft-связи считаются между **системами**: если в моделях кейсов нет
  ссылок между системами, честный ответ — 0 связей (это свойство данных, а не
  дефект детектора).
- Семантика ссылок («не на ту» сущность) и качество судьи остаются за
  человеком и внешней моделью.
