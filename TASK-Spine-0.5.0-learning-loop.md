# Задание: spine-bank 0.5.0 — «контур, который учится»

> Положи файл в корень форка рядом с `AGENTS.md` и начни сессию словами:
> «Прочитай `TASK.md` и действуй по нему. Сначала план, потом код».
> Основа: **живые прогоны** `romannekrasovaillm/spine-bank` на коммите `641b46a` (v0.4.10, 2026-10-14):
> 36 сессий Spine Harness с агентным циклом, 108 запусков Claude Code как исполнителя, 113 проверок
> приёмочного гейта. Отчёт: «Spine Harness: две гипотезы против данных» (PDF ДКА).
> Стенд и скрипты — архив `icl-lab.tar.gz` (приложение A), его содержимое кладётся в
> `benchmarks/icl-transfer/seed/`.

## 0. Суть в одном абзаце

Живые прогоны подтвердили: у Spine есть **обучение в контексте на уровне оркестратора**, которого нет у
отдельного запуска кодового агента. Spine стоит на петле обратной связи *между* задачами, видит
вердикт гейта, превращает его в правило и вписывает правило в следующие задания кодеру. Абляция
дала 0/17 повторов скрытой ошибки с контекстом против 8/8 без памяти (p ≈ 9·10⁻⁷) и −53% повторных
прогонов исполнителя. Но эффект **случайный, хрупкий и неглубокий**:
- он держится на свободном тексте LLM;
- он умирает с сессией и при L3-компактификации;
- штатная `failure_memory` его не ловит: 5 уроков на 36 сессий, все про битые вызовы инструментов,
  и ни один не возвращается в промпт;
- упаковщик `handoff_create` используется в 3% прогонов, так что урок не попадает в пакет;
- вердикт гейта Spine узнаёт только потому, что промпт велел вызвать bash;
- по поведению Spine работает 4 базовыми инструментами, но в каждый запрос уходят схемы 67
  инструментов, это 84% первого промпта, а места под накопленный опыт не остаётся.

Цель 0.5.0 — сделать обучение **свойством архитектуры, а не удачей сессии**:
1. урок, полученный один раз, переживает сессию, компактификацию, смену модели и смену исполнителя;
2. урок обобщается за пределы задачи, где его получили;
3. подтверждённый урок превращается в детерминированное fitness-правило, то есть контур ужесточается
   сам;
4. всё это измеряется бенчмарком с пререгистрацией, в котором Spine сравнивается с **сильнейшим**
   кодовым агентом с собственной памятью, а не с голым.

**Критерий успеха (одной строкой):** таблица «до → после» из раздела 9 заполнена живым прогоном
`benchmarks/icl-transfer/run_all.sh`. Каждая строка «после» не хуже порога, и хотя бы три из
шести критериев системной эмерджентности (раздел 3) выполнены.

## 1. Правила работы

1. **Сначала воспроизведи.** Каждая находка раздела 2 воспроизводится стендом из приложения A или
   командой из раздела 2. На каждую — падающий тест (unit или `tests/*.rs`) **до** фикса. Если находка
   не воспроизводится, запиши это в `docs/experiments/live-0.5.0-repro.md` и не чини.
2. **Соглашения репозитория:** `AGENTS.md`, `docs/RUST_CONVENTIONS.md`. Находки — по-русски,
   в формате `[error] <код> — <что> → <fix_hint>`.
3. **AD-2 сохраняется.** Жизненный цикл урока (статус, область действия, промоушен в правило) решается
   **детерминированно, по счётчикам доказательств**. LLM может только *сформулировать* текст урока
   (слой `[inferred]`) и никогда не меняет статус сама. Ни один урок не становится fitness-правилом
   без детерминированного доказательства (≥ N подтверждений гейтом) и, на маршруте Critical, без
   подписи человека.
4. **Без новых зависимостей** в `[dependencies]`. Хранилище уроков — JSONL плюс рендер в md, поиск —
   уже имеющийся BM25 из `src/kb.rs`.
5. **Обратная совместимость.** Сохраняются `harness_run` без новых параметров, `gate-verdict/v1`,
   exit-коды `0/1/2/3`, смысл `CONSTRAINTS.yaml` и `failure_memory = off|propose|write`. Новые поля
   добавляются аддитивно, новое поведение — за флагом конфига со значением по умолчанию «как было»
   до волны 3 (раздел 8).
6. **Один пункт — один коммит** (`feat(L1): …`, `fix(B3): …`), тесты в том же коммите. Перед коммитом:
   `cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test && cargo test --no-default-features --features core`
   и дог-фуд `./target/debug/arch-be control check . --constraints CONSTRAINTS.yaml`.
7. **Ешь свою еду.** Решения оформляются ADR начиная с **ADR-084**; правки спайна и реестра — через
   дельту. Первый урок, который Spine запишет в собственный реестр уроков, должен прийти из работы над
   этим заданием (раздел 6, критерий «дог-фуд»).
8. **Пререгистрация до прогона.** Пул скрытых конвенций, семена, отложенная выборка (holdout) и пороги
   замораживаются хэшами (`PREREGISTRATION.md` + `prereg_hashes.txt`) **до** первого прогона новой
   механики. Подкручивать после результатов нельзя, отклонения пишутся в `DEVIATIONS.md`.
9. **Анти-Goodhart.** Запрещено знать о конкретных конвенциях стенда (`__all__`, `CATALOG.md` и любых
   из пула) в коде Spine, промптах, скиллах и тестах вне `benchmarks/icl-transfer/`. Проверка: grep по
   `src/ assets/` на строки из пула входит в CI бенчмарка.
10. **Стоп-условия:**
    - нужно сломать `*/v1`-контракт;
    - нужно ослабить порог, чтобы пункт «прошёл»;
    - урок становится правилом без детерминированного доказательства;
    - пункт помечен **[РЕШЕНИЕ ЧЕЛОВЕКА]**.

## 3. Целевое свойство: операционное определение «системной эмерджентности»

Слово «эмерджентный» в этом проекте используется **только** в операционном смысле. Поведение считается
эмерджентным, если система достигает результата, которого нет ни у одной её части в отдельности, и
который не запрограммирован явно для данного случая. Шесть проверяемых критериев:

| ID | Критерий | Что доказывает | Как меряем (раздел 6) |
|---|---|---|---|
| **E1** | **Перенос между сессиями.** Урок из сессии 1 соблюдается в сессии 2 без общего контекста | память стала свойством системы, а не окна | рука FI+L: доля повторов скрытых конвенций на T2–T5 |
| **E2** | **Перенос между исполнителями.** Урок, полученный на claude-code, соблюдает другой исполнитель | знание живёт в контуре, а не в кодере | рука X: обучение на исполнителе A, проверка на B |
| **E3** | **Обобщение.** Урок, полученный на задачах семейства «модуль», соблюдается в задаче другого семейства («CLI-команда», «миграция»), где форма задачи иная | правило выведено, а не скопировано | рука GEN, отложенное семейство задач |
| **E4** | **Сложение уроков.** Два урока из разных провалов дают правило, которого не было ни в одном вердикте (пример: «новый публичный символ ⇒ `__all__` + реестр + каталог» как один чек-лист) | композиция, а не накопление | доля задач, где в задании есть составное правило, и первый PASS при двух одновременных скрытых конвенциях |
| **E5** | **Самоужесточение контура.** Подтверждённый урок становится детерминированным fitness-правилом, и следующий провал ловится до гейта, на `pre-commit` у исполнителя | обучение меняет контур, а не только промпт | число уроков в статусе `promoted` и доля нарушений, пойманных fitness до приёмки |
| **E6** | **Стигмергия флота.** В параллельном флоте провал одного исполнителя предотвращает ту же ошибку у исполнителей, стартовавших позже | обучение распространяется горизонтально | рука FLEET: 5 параллельных задач со сдвигом старта |

Разрыв с кодовыми агентами меряется против **сильнейшего** доступного базиса: рука C+M — кодер с
собственной памятью (`CLAUDE.md` и auto-memory у Claude Code, `AGENTS.md` у остальных), которому
**показывают вердикт гейта** после каждой задачи. Сравнение с голым кодером (C) — вспомогательное.
Утверждение «Spine учится лучше кодера» допустимо, только если Spine лучше C+M.

**Чего не утверждаем.** Spine не «осознаёт» и не «обучается» в смысле изменения весов. Без
выполнения хотя бы трёх критериев из E1–E6 в README и CHANGELOG пишется «обучение в контексте
уровня оркестратора», а не «эмерджентность».

## 4. Архитектура решения

```
            ┌───────────────────────────── Spine Harness / Spine Core ─────────────────────────────┐
 задача ──► │ [L4 preflight] lessons_match(task, paths) ─► релевантные уроки + составные чек-листы   │
            │        │                                                                              │
            │        ▼                                                                              │
            │ [L5 handoff auto] пакет: задача + «Правила репозитория (выучено)» + accept_cmd        │──► исполнитель
            │                                                                                        │   (claude-code,
            │ [L2 gate-loop] harness_run(..., accept) ─► verdict/v1 ─► событие gate_verdict          │◄── qwen-code…)
            │        │                                                                              │
            │        ▼                                                                              │
            │ [L1 Lesson Ledger]  observed → candidate → confirmed → promoted → retired             │
            │   .arch/lessons/ledger.jsonl (repo) · ~/.arch-harness/lessons (user) · org-реестр     │
            │        │            │                         │                                       │
            │        │   [L6 обобщение/композиция]    [L7 промоушен → CONSTRAINTS.yaml через дельту]│
            │        ▼                                                                              │
            │ [L3 инъекция] системный промпт (Harness) · SessionStart/UserPromptSubmit (Core)       │
            │   закреплённый блок, переживает L1/L3-компактификацию                                 │
            │ [L8 стигмергия] LESSONS.md во все активные worktree флота                             │
            │ [L9 ленивые инструменты] ядро + tool_search — место в контексте под опыт              │
            └────────────────────────────────────────────────────────────────────────────────────────┘
```

Ключевая идея: **канал «контекст» (быстрый, хрупкий) конвертируется в канал «артефакт» (медленный,
долговечный), а артефакт — в канал «инвариант» (детерминированный)**. Кодовые агенты имеют только
первый канал, и только внутри одной задачи.

## 5. Пункты работ

Метки: **[Core]** — работает в `--features core` без своей LLM; **[Harness]** — только в сборке
`harness`; **[Общий]** — оба. Каждый пункт: что сделать, где, контракт, тесты, приёмка.

### Волна 1 — фундамент: урок как сущность

#### L1. Реестр уроков (Lesson Ledger) [Общий] — ADR-084

- **Что.** Новый модуль `src/lessons/` (`mod.rs`, `ledger.rs`, `render.rs`, `scope.rs`). Сущность
  `Lesson`:
  ```
  id            LSN-<sha8 сигнатуры>             стабильный, без перенумерации
  signature     {source: gate|fitness|tool|review, code: "G5"|rule-id|error-class, subject_kind}
  statement     текст правила (может быть [inferred] от LLM; статус от него не зависит)
  scope         {level: file|module|package|repo|user|org, globs: [...]}
  evidence[]    {run_id, harness, verdict_excerpt, file:line, ts, outcome: fail|pass_after_apply}
  hits / misses сколько раз урок был в задании → PASS / FAIL по той же сигнатуре
  status        observed → candidate → confirmed → promoted → retired
  provenance    кто записал (gate/hook/agent), sha256 вердикта, версия arch-be
  ```
  Хранилище: `.arch/lessons/ledger.jsonl` (append-only, события), рендер `.arch/lessons/LESSONS.md`
  (детерминированный, отсортирован по id). Уровень пользователя — `$ARCH_HOME/lessons/`.
- **Переходы — только по счётчикам** (пороги в `[lessons]` конфига):
  - `observed` — первый FAIL с сигнатурой;
  - `candidate` — FAIL повторился, или урок применён и дал PASS;
  - `confirmed` — `hits ≥ 2` и `misses = 0` на ≥ 2 разных задачах;
  - `promoted` — см. L7;
  - `retired` — `misses ≥ 2` подряд, или правило удалено из CONSTRAINTS, или истёк `expiry`.
- **CLI:** `arch-be lessons list|show|record|retire|export|import`.
- **MCP:** `lessons_query`, `lessons_record`. Это **[Core]**: хост-агент (Claude Code и др.) получает
  межсессионную память, проверенную гейтом.
- **Тесты:** переходы статусов (табличный тест); детерминизм рендера байт-в-байт; конкурентная дозапись
  (два процесса), без порчи JSONL; импорт урока без `evidence` отклоняется.
- **Приёмка:** `arch-be lessons list` на стенде после руки S показывает G5/G6 в статусе `confirmed`
  с доказательствами `run_id`.

#### L2. Гейт в петле исполнителя [Harness + Core-хук] — ADR-085

- **Что.**
  - Параметр `harness_run.accept` (строка-команда) и поле адаптера `[harnesses.x].accept_cmd`.
  - По умолчанию — `arch-be gate .`, если в репозитории есть `CONSTRAINTS.yaml`; иначе пусто.
  - После `finalize_run` команда запускается вне песочницы исполнителя (как пост-гейт A4).
  - Результат приводится к `gate-verdict/v1`: если команда выдала JSON — берётся как есть; иначе
    коды вида `[A-Z]+\d+` / `rule-id` разбираются построчно, exit-код — как статус.
  - Вердикт идёт **первой строкой** результата `harness_run` и пишется событием `gate_verdict`
    в журнал сессии.
  - Каждый FAIL с кодом автоматически вызывает `lessons_record` (источник `gate`).
  - `post_gate` без манифеста больше не «пропускается молча», если задан `accept` (закрывает B3).
- **[Core].** `arch-be hook stop` и `post-tool-use` после прогона гейта тоже пишут FAIL-коды в реестр
  уроков. Хост-агент без своей памяти начинает копить уроки, проверенные гейтом.
- **Тесты:** fake-harness (`tests/cli.rs:50-88`) плюс fake-гейт с exit 1 и строкой `[G5] …` —
  событие в журнале, запись в реестре, первая строка результата; совместимость: без `accept` вывод
  `harness_run` байт-в-байт как в 0.4.10.
- **Приёмка:** стенд, рука S **без** указания вызывать гейт через bash в промпте — Spine всё равно
  видит вердикт.

#### L3. Инъекция уроков и защита от компактификации [Общий] — ADR-086

- **[Harness].** При старте сессии и **перед каждым `harness_run`** в контекст подмешивается
  закреплённый блок `## Уроки контура (выучено, проверено гейтом)`: top-K уроков (K и лимит токенов —
  в конфиге), отобранных по scope к cwd и путям задачи.
  - L1-маскирование и L3-саммари блок **не трогают**: он пересобирается из реестра после
    компактификации, а не пересказывается (закрывает B5).
  - `failure_lessons.md` мигрирует в реестр (закрывает B1, B2).
  - `failure_memory` получает сигнатуры источника `gate` и `fitness`.
- **[Core].** Новые события хука:
  - `arch-be hook session-start` — уроки области репозитория в контекст хоста;
  - `arch-be hook user-prompt-submit` — уроки, релевантные упомянутым путям (BM25 из `kb.rs`).

  `connect` устанавливает их для Claude Code и Kimi Code (`src/connect/hooks.rs`), с fail-soft
  гардом, как у существующих.
- **Гигиена.** Уроки — данные, а не инструкции. Блок оборачивается маркером данных, проходит
  `src/injection.rs`. Урок с признаками prompt-injection не попадает в блок и помечается
  `quarantine`.
- **Субагенты и ralph (B8).** В свежий контекст субагента передаётся только блок уроков: это
  контролируемая утечка опыта при сохранении свежести.
- **Тесты:**
  - блок присутствует после `compact_now` (L1 и L3);
  - лимит токенов соблюдён;
  - урок с текстом «ignore previous instructions» уходит в карантин;
  - хук `session-start` выдаёт пустой вывод без реестра (fail-soft).

### Волна 2 — от урока к знанию

#### L4. Префлайт: подбор уроков под задачу [Общий]

- `lessons_match(task_text, paths?) -> [Lesson]`. Отбор:
  1. по scope (glob путей задачи и путей, упомянутых в тексте);
  2. по BM25 текста задачи против `statement` и `signature`;
  3. по статусу (`confirmed` > `candidate` > `observed`).

  Детерминированно, без LLM.
- Вызывается автоматически в L5 и доступен как инструмент и MCP.
- **Метрика `prevented`:** задача, в задании которой был урок с сигнатурой S, прошла гейт без
  FAIL по S, хотя ранее в этой области S проваливалась. Это событие журнала и основа E1–E3.
- **Тесты:** отбор по scope (модуль vs репо), стабильный порядок, ровно K результатов.

#### L5. Автоупаковка handoff в `harness_run` [Harness] — закрывает B4

- Если в репозитории нет `.arch-handoff/` или пакет старше HEAD, `harness_run` собирает лёгкий пакет
  сам: `TASK.md` и `LESSONS.md` из `lessons_match`, плюс `CONSTRAINTS.yaml`, `accept_cmd` и
  JSON-контракт.
- В `TASK.md` добавляется секция «Правила репозитория (выучено)» с чек-листом и требованием к
  исполнителю: **перед коммитом прогнать `accept_cmd`**. Так кодер получает гейт, которого у него нет
  без Spine. Именно здесь создаётся разрыв.
- Пакет тяжёлого маршрута (`handoff_create` с route) по-прежнему вызывается явно.
- **Тесты:** снапшот TASK.md; уроки уровня `user` не утекают в репозиторий без флага; явный
  `handoff_create` имеет приоритет.

#### L6. Обобщение и композиция уроков [Общий] — ADR-087 · критерии E3, E4

- **Расширение области (детерминированно).** Урок с одной сигнатурой, подтверждённый в ≥ 2 разных
  модулях одного пакета, поднимается до `package`, в ≥ 2 пакетах — до `repo`. Контрпример (`miss` в
  новой области) откатывает область назад.
- **Композиция.** Уроки, которые ≥ 2 раз проваливались *в одной задаче* или по одному типу субъекта
  (`subject_kind`, например «новый публичный символ», «новая миграция», «новый эндпоинт»),
  сворачиваются в составной чек-лист `LSN-C-*` со ссылками на исходные. Составной урок не имеет
  собственного статуса выше минимального из исходных.
- **Классификатор `subject_kind`** — детерминированный, по диффу исполнителя: новый файл в пакете,
  новый публичный символ, новый маршрут, новый SQL. Переиспользуй `recover` и `arch_diff`.
- **LLM — только формулировка.** `statement` составного урока может предложить LLM (`[inferred]`), но
  его применимость решает только счётчик.
- **Тесты:** табличные сценарии расширения и отката области; детерминизм композиции; урок с
  `misses > 0` в композицию не входит.

#### L7. Промоушен урока в fitness-правило [Общий] — ADR-088 · критерий E5

- Урок `confirmed` с сигнатурой, выразимой шаблоном (`rule_templates`: `must_contain`,
  `must_not_contain`, `file_exists`, `conditional`, `command_succeeds`), получает **предложение
  правила** через дельту (`delta_propose`).
- Правило-кандидат проверяется `redteam`-засевом:
  1. ловит ли оно исходные нарушения из `evidence`;
  2. не краснит ли текущий зелёный HEAD.

  Только при обоих «да» правило попадает в CONSTRAINTS.yaml со статусом `proposed`.
- На маршрутах Standard и Critical нужна подпись человека: **[РЕШЕНИЕ ЧЕЛОВЕКА]**, хранится в дельте.
- После принятия урок получает статус `promoted`. Нарушение ловится на `pre-commit` у исполнителя
  (хуки `connect`) — до приёмки и до Spine.
- Анти-ослабление (`rule_weakened`) распространяется на промоутированные правила.
- **Тесты:**
  - невыразимый урок не промоутится;
  - правило, краснящее HEAD, отклоняется;
  - без подписи на Critical — exit 1;
  - после промоушена `pre-commit` ловит засеянное нарушение.

### Волна 3 — масштаб и разрыв

#### L8. Стигмергия флота [Harness] — критерий E6

- При `harness_run(background=true)` и `[fleet] require_worktree=true`: событие `lessons_record`
  перерисовывает `LESSONS.md` во **всех активных** worktree флота (`src/worktree.rs`, реестр фоновых
  задач `hr-*`).
- Исполнители, которые читают `AGENTS.md`/`CLAUDE.md` с указателем на `LESSONS.md`, подхватывают урок
  при следующем чтении. Новые запуски получают его через L5.
- Запись атомарная (tmp + rename), конфликт с правкой исполнителя исключён: файл вне его зоны
  ответственности, путь фиксирован в пакете.
- **Тесты:** 3 фоновых fake-исполнителя, у первого FAIL — у стартовавших позже `LESSONS.md` содержит
  урок; у уже завершённых worktree файл не меняется.

#### L9. Ленивая загрузка инструментов и профили [Harness] — ADR-089 · закрывает B6

- **Ядро в каждом запросе:**
  - `bash`, `read_file`, `write_file`, `edit_file`, `glob`, `grep`;
  - `harness_run`, `propose_options`, `lessons_query`;
  - новый `tool_search(query) -> [spec]`.

  Доменные схемы подгружаются в запрос после `tool_search`/`skill_load` и живут до конца сессии
  (кэш).
- **Профили:** `orchestrate` (ядро + `significance_score`), `architect` (ядро + контрольный контур),
  `reverse` (существующий), `full` (как сейчас, по умолчанию до волны 3).
- **Цель:** первый запрос ≤ 40% от текущего (≤ 25 000 симв. вместе с системным промптом). Высвобожденный
  бюджет — под блок уроков L3.
- **Тесты:** число схем в запросе по профилю; `tool_search` детерминирован; вызов незагруженного
  доменного инструмента подгружает его, а не падает.
- **Регрессия:** `benchmarks/architect-value` не хуже 0.4.10 по всем строкам; архитектурные задачи
  A1–A6 стенда используют ≥ 10 разных доменных инструментов (база — 12).

#### L10. Межрепозиторная и организационная память [Общий] — ADR-090

- `arch-be lessons export --scope repo --min-status confirmed` → `lessons-bundle/v1`: JSON с
  `evidence`-хэшами, версией и подписью SHA-256 (как receipt у archify).
- `import` в `user` или `org` уровень **с понижением статуса до `candidate`**: чужой урок нужно
  подтвердить своим гейтом.
- Org-реестр — git-репозиторий или каталог, путь в `[lessons] org_dir`. Доступен через MCP для
  хост-агентов (Core).
- **Тесты:** импорт понижает статус; подпись проверяется; урок с несовпавшим хэшем отклоняется.

#### L11. Метрики обучения [Общий] — закрывает B7

- usage в журнал при `stream=false` (B7).
- `arch-be metrics --learning`:
  - `repeat_failure_rate` — доля FAIL по сигнатуре, уже бывшей в реестре;
  - `prevented`;
  - `dispatches_per_task`;
  - распределение статусов уроков;
  - `promoted_rules`;
  - доля блока уроков в промпте;
  - токены на задачу.
- Формат — markdown и `--json` (`learning-metrics/v1`).

## 7. Риски и анти-паттерны (проверяются тестами)

1. **Отравление памяти.** stdout исполнителя — недоверенные данные. Урок рождается только из
   *вердикта гейта или fitness*, а не из текста исполнителя. Текст исполнителя может попасть лишь в
   `verdict_excerpt` после `injection.rs`.
2. **Переобучение.** Урок, который начал мешать (`misses`), выводится из блока автоматически.
   Устаревший урок (правило удалено из CONSTRAINTS) получает статус `retired`.
3. **Раздувание.** Блок L3 имеет жёсткий лимит токенов. Отбор по L4, а не «все уроки».
4. **Goodhart.** Конвенции стенда запрещено знать в `src/` и `assets/` (правило 9). В CI бенчмарка
   есть grep-проверка.
5. **Ложное ужесточение.** Промоушен только после redteam-засева и проверки на зелёном HEAD (L7).
   Анти-ослабление действует в обе стороны.
6. **Утечка между репозиториями.** Уроки уровня `user` и `org` не пишутся в файлы репозитория без
   флага `--share`. Экспорт подписан, импорт понижает статус (L10).
7. **Ложная эмерджентность.** Если E1–E6 выполнены только в `--ci`, а в `--live` нет, в README
   пишется результат `--live`.
